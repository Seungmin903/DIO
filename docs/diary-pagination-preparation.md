## 구현

- `diaryApi.list`: hasNext/nextCursor를 검증해 불투명 문자열 커서를 반환한다. 숫자/UUID 비교·해독을 하지 않는다. 기존 hasNext 생략 응답은 단일 페이지로 호환한다.
- `libraryReader`: 첫 조회와 추가 조회의 loading/error를 분리한다. 더 보기 연타는 한 번만 요청한다. 오류 시 기존 항목·커서를 유지하고 같은 검색·정렬·필터·커서로 재시도한다.
- 같은 조건 새로고침은 전체 결과를 성공 전까지 보존한다. 성공하면 새 첫 페이지로 교체한다. 검색·정렬·필터 변경은 목록·상세·커서를 초기화한다.
- 새로고침·조건 변경·계정 종료는 추가 조회를 취소하고 늦은 결과를 무시한다. ID 중복은 한 번만 표시하고 새 응답 값으로 갱신한다. 빈 마지막 페이지도 hasNext=false를 반영한다. 반복 커서는 오류와 새로고침 안내로 처리한다.
- `MockLibraryApp`: 불러온 개수·추가 조회 중·오류·더 보기/다시 시도 표시. 이 UI는 개발용 mock-library 모드에만 있다.
- 목 API는 기본 두 개 샘플·단일 페이지를 유지한다. 개발용 ‘페이지 나누기 켜기’에서 샘플 네 개를 추가하고 활성 목록을 두 개씩 나눈다. 휴지통과 이전 개발용 검증 화면은 기존 단일 페이지를 유지한다.
- 목 커서는 검색 조건과 마지막 항목에 연결된 메모리 토큰이다. 실제 서버의 스냅샷 일관성·만료·권한 계약을 보장하는 구현은 아니다. 목록 조작 후에는 첫 페이지를 재조회한다.

이미 이 경로의 서버가 실행 중이면 Expo Go에서 Reload한다.

1. 목 보관함 → 한눈에 보기 → 목 응답 설정 → **페이지 나누기 켜기**. ‘2개 불러왔어요. 더 불러올 수 있어요.’를 확인한다.
2. **다이어리 더 보기** → 로딩 중 기존 두 카드 유지·중복 누름 차단 → 네 개. 다시 누르면 여섯 개·마지막 목록 안내·더 보기 숨김.
3. **목록 새로고침** → 첫 두 개. **더 보기 한 번 실패** → 더 보기 → 두 개 유지·오류·**더 보기 다시 시도** → 네 개.
4. 네 개 상태에서 **한 번 실패**(첫 목록 설정) → 목록 오류와 네 개 유지 → **목록 다시 시도** → 첫 두 개. 더 보기로 다시 네 개까지 확인한다.
5. **다이어리 검색** → ‘페이지’ 입력 → 두 개 → 더 보기 → 네 개. 이름순 등 정렬 변경 시 첫 두 개로 초기화되고 새 조건으로 이어받는다. 없는 검색은 더 보기 없이 빈 결과를 표시한다.
6. 추가 조회 도중 검색어·정렬·즐겨찾기 변경 후 이전 항목이 섞이지 않는지 확인한다. 샘플 계정 변경 시 이전 목록·커서가 남지 않아야 한다.
7. 페이지 나누기를 끄면 추가 샘플을 포함한 전체 목록이 한 번에 표시된다. 샘플 초기화는 앱 Reload로 수행한다. 이 설정은 로컬 사용자 다이어리를 변경하지 않는다.

첫 조회 실패 설정은 선택 즉시 재조회한다. ‘더 보기 한 번 실패’는 추가 조회에만 적용되며 다음 더 보기 요청 한 번만 실패한다. 첫 조회 실패 후에는 첫 목록 재시도를 먼저 완료해야 한다.

## 리뷰 수정 및 iPad 재확인

1. **무효 커서 복구**: INVALID_CURSOR 또는 잘못된 페이지 응답은 같은 커서로 반복 요청하지 않는다. 오류 버튼은 ‘목록 새로고침으로 복구’로 바뀌고 검색·정렬·필터를 유지한 첫 페이지를 조회한다. 재조회 실패 시 기존 결과와 첫 목록 재시도 안내를 유지한다. 일시 오류는 기존 ‘더 보기 다시 시도’로 같은 커서를 보낸다.
   - QA: 페이지 나누기 켜기 → 더 보기 커서 무효화 → 다이어리 더 보기 → 오류·기존 두 개 유지 → 목록 새로고침으로 복구 → 첫 두 개 → 더 보기로 네 개.
2. **선택 범위 표시**: 다음 페이지가 남으면 ‘불러온 항목 모두 선택/해제’와 불러온 개수 기준 접근성 안내를 표시한다. 마지막 페이지 및 기존 로컬 목록은 ‘전체 선택/해제’를 유지한다.
   - QA: 첫 두 개 상태 → 보관함 옵션 → 편집 → 불러온 항목 모두 선택 → ‘2개 선택됨’, 선택한 2개 휴지통으로 이동 버튼 확인(실제 삭제 불필요) → 불러온 항목 모두 해제 → 0개 → 편집 완료.
3. **검색 개수 표시**: 다음 페이지가 있으면 ‘검색 결과 2개 불러옴 · 더 있음’으로 표시하며 마지막 페이지에서는 전체 검색 결과 개수로 표시한다.
   - QA: 검색 ‘페이지’ → ‘검색 결과 2개 불러옴 · 더 있음’ → 더 보기 → ‘검색 결과 4개’와 마지막 목록 안내.

위 세 항목을 Edge 태블릿·폰 회귀 QA에 추가했다. 리뷰 수정 후 웹/iOS 개발 번들 생성 성공, Edge 1280×800·412×892에서 세 항목과 기존 CRUD QA 모두 통과했다(pageerror 0). 선택 버튼은 실제 클릭 후 선택/해제 개수·대상 개수, 검색 문구는 첫/마지막 페이지, 무효 커서는 복구 버튼과 첫 페이지 조회를 검증했다.
