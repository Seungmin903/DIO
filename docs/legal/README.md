## 현재 기능과 발송 전 조건

현재 가입은 ageConfirmed=true와 SERVICE·PRIVACY(v2) 필수 동의를 받는다. MARKETING_PRIVACY·AD_EMAIL·AD_PUSH·AD_NIGHT_PUSH(v1)는 기존 약관 테이블에 항목별 동의 상태·변경 시각을 저장하며 기존 PUT 약관 변경 API로 각각 철회할 수 있다. 가입 UI에 기본 미선택 체크박스와 문서 보기 연결을 구현했다. 기존 MARKETING=true나 OS 알림 허용을 새 채널 동의로 간주하지 않는다. 새 API 경로·테이블·컬럼은 추가하지 않았다. 실제 광고 발송, 광고 수신 거부 링크, 마이페이지의 항목별 수신 설정 UI는 아직 별도 구현이 필요하다. 문서 공개 게시와 실제 URL 설정도 후속 작업이다.

- 모든 선택 동의는 기본 미선택이고, 거부해도 가입·다이어리 기능을 허용한다. 필수 항목만 동의하고 진행할 수 있어야 한다.
- 마케팅 개인정보 이용, 광고 이메일, 광고 푸시, 야간 광고 푸시를 각각 구분해 기록·철회한다. 채널별 선택은 DIO의 선택권 보장 설계이며 모든 경우에 법이 별도 체크박스 개수까지 정한다는 뜻은 아니다. 야간 동의는 일반 광고 동의와 별도로 받는다.
- 이메일은 마케팅 개인정보 이용+이메일 동의를, 주간 푸시는 마케팅 개인정보 이용+푸시 동의+기기 권한을, 야간 푸시는 여기에 야간 동의까지 발송 직전에 검사한다. 계정·기기 변경이나 예약·재시도에도 적용한다.
- 야간은 한국 표준시 21:00 이상 또는 08:00 미만이다. 전자우편은 시행령상 야간 별도 동의 예외이므로 불필요한 야간 이메일 동의는 만들지 않았다. 이메일 주간 발송 제한은 법정 의무가 아닌 이번 초안의 DIO 운영정책 제안이다.
- 광고마다 광고 표시·전송자 명칭·연락처·무료 수신 거부 방법을 매체별 법정 형식에 맞춘다. 푸시의 거부 링크는 알림이 보이는 환경에서 쉽게 접근할 수 있어야 한다. 이메일 문의만 마련했다고 간편 거부 구현을 완료한 것으로 보지 않는다. 로그인 없는 간편 거부를 출시 전에 실기기로 검증한다.
- 동의·거부·철회 처리 결과는 법정 기한(현재 시행령 기준 의사표시일로부터 14일 이내) 내 전송자·의사표시 사실·날짜·처리 결과를 알린다. 거부 후 발송 중단을 14일 유예한다는 뜻은 아니다. 동의 받은 날부터 매 2년의 정기 확인 통지를 운영하고, 통지에 광고를 섞지 않는다. 정기 확인은 일률적인 2년마다 재동의 의무와 다르다.
- 동의의 종류·버전·일시·변경 이력과 거부 반영을 입증할 최소 기록을 정한다. 마케팅 이용은 철회·탈퇴·운영 종료 시 중단한다. 그 후 증빙·차단 기록의 별도 보존이 필요하면 적용 근거와 최소 기간을 운영자가 확정하고 개인정보처리방침에 반영한다. 근거 없이 모든 정보를 3년·5년 보관하지 않는다. 아직 확정되지 않은 증빙 보관 정책은 광고 개시 전 해결한다.
- 초대 알림은 가입된 수신자에게 앱 알림 이벤트로 전달한다. 초대 이메일 발송은 제거됐다. 개인정보처리방침의 SMTP 위탁 범위에서도 ‘이메일 초대 발송’을 제거했다. 회원가입·비밀번호 재설정 SMTP와 광고 발송은 구분한다.
- 다이어리 내용·사진·음성·필기·AI 폰트 원본을 광고 분석·학습·홍보 재사용하는 동의를 추가하지 않았다. 제휴사 제공·맞춤형 광고 추적·경품 배송을 도입하면 실제 목적·항목·업체에 맞게 별도 검토한다.

## 인프라 담당자와 운영자가 확정할 사항

1. 운영자·개인정보 보호책임자·문의 담당자는 신승민, 문의 이메일은 dioapp.official@gmail.com이다. 문서 시행일은 2026년 11월 2일이다. DIO는 앱 화면에 광고를 게재하지 않으며, 별도 동의 대상인 DIO 홍보 이메일·푸시와 구분한다.
2. 서버·S3·SMTP·푸시의 실제 계약 업체, 처리 국가, 위탁 범위·국외 이전 근거를 확인한다. 추정 업체·국가로 채우지 않는다. 광고 목적 처리를 추가로 맡기면 개인정보 보호법 제26조의 동의·고지 등 적용 여부도 검토한다.
3. 발송·동의·철회·차단·백업·분쟁 기록의 항목과 보관·파기 기간을 확정하고 개인정보처리방침과 일치시킨다.
4. 구현되지 않은 간편 거부 경로가 실제로 작동하게 된 뒤 사용자용 문서의 내부 검토 경고를 제거하고 기재한 시행일과 실제 게시 일정을 대조한다. HTML을 게시하는 것만으로 구현 완료 처리하지 않는다.
5. `S15P31F106` 폴더에서 원본 수정 후 `python docs/legal/build_html.py`로 HTML을 재생성한다. 이 README는 빌드 대상이 아니다.
6. HTML은 HTTPS 공개 주소에 로그인 없이 게시하고, 앱에서 각 내용 보기와 개인정보처리방침 상시 열람을 연결한다. 마케팅 4개 URL의 앱 연결·새 동의 저장은 이번 문서 작업에 포함하지 않는다.

## 근거와 참고 자료

다른 회사의 표현을 복제하지 않고, 목적·항목·기간·거부권을 분리하는 구조와 채널 선택 방식을 참고했다. 대기업의 광범위한 행태정보·계열사·유료 거래·법정 보관 항목을 DIO에 그대로 가져오지 않았다.

- [개인정보 보호법](https://www.law.go.kr/법령/개인정보보호법): 제15조·제16조·제21조·제22조·제26조·제30조. 수집·이용 동의, 최소 처리, 파기, 동의 구분, 위탁 및 처리방침 공개 기준.
- [정보통신망법](https://www.law.go.kr/법령/정보통신망이용촉진및정보보호등에관한법률): 제50조. 광고 사전 동의·야간 동의·수신 거부·표시·처리 통지·정기 확인 기준.
- [정보통신망법 시행령](https://www.law.go.kr/법령/정보통신망이용촉진및정보보호등에관한법률시행령): 제61조·제62조의2·제62조의3·별표 6. 이메일 야간 예외와 통지·정기 확인 및 매체별 표시.
- [KISA 불법스팸대응센터](https://spam.kisa.or.kr/spam/main.do): 2026년 3월 개정 안내에서 모호한 ‘혜택 알림’ 동의 표현과 앱 푸시 거부에 로그인 등 복잡한 절차를 요구하는 문제를 확인. 문구를 ‘광고성 정보’로 명확히 함.
- [네이버 개인정보처리방침](https://policy.naver.com/policy/privacy.html): 서비스 제공 목적과 마케팅 목적, 권리 행사·파기 설명의 구분 방식을 참고. 네이버의 광고 분석 범위는 가져오지 않음.
- [한국정보인증 공개 신청서의 선택 광고성 정보 수신 동의](https://www.signgate.com/doc/20260203_server-NPS.pdf): 광고 수신 선택, 채널 선택 및 거부권 구조 참고. 인증업무의 개인정보 항목·보관 기간은 가져오지 않음.

위 근거의 적용은 실제 발송 방식·처리 업체·시행 시점에 맞춰 다시 확인한다. 법령 검토와 실제 운영 사실 확인이 끝나지 않은 항목은 게시 최종본으로 간주하지 않는다.


HTML은 모든 v2 Markdown을 `python docs/legal/build_html.py`로 생성한다. 별도 개인정보처리방침 개정본도 같은 템플릿을 사용하며 HTML을 직접 수정하지 않는다. 재생성 전후 8개 HTML의 바이트 해시가 같음을 확인했다. 기존 Google 원본은 이 로컬 생성 작업과 무관하며 수정하지 않는다.
