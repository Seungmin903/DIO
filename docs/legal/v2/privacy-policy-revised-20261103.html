제3조 수집 방법과 처리 근거

1. 회원가입·프로필 등록·파일 업로드·초대·문의 등 이용자가 직접 입력하거나 선택한 자료를 처리합니다. 서비스 이용 과정에서 계정·세션·작업·알림 정보가 생성됩니다.

2. 동의를 근거로 처리하는 정보는 수집 목적·항목·보유 기간·거부권과 영향을 안내하고 동의를 받습니다. 선택 프로필 사진이나 마케팅 이용을 기본 서비스 필수 동의에 포괄하여 포함하지 않습니다.

3. 이용자가 요청한 다이어리 저장·공유·공동 편집 등 계약 체결·이행에 필요한 처리는 개인정보 보호법 제15조제1항제4호 등 해당 근거에 따라 처리합니다. 동의가 필요한 추가 처리까지 계약 이행이라는 이유로 확대하지 않습니다.

4. 법정 열람·정정·삭제·처리정지 등 권리행사 요청은 개인정보 보호법상 의무와 관련 규정에 따라 처리합니다. 문의 답변에 필요한 정보는 이용자가 요청한 상담·서비스 제공 범위에서 처리합니다.

5. 별도 법적 근거로 개인정보를 보존하거나 제공해야 하는 경우에는 해당 법령·목적·항목·기간을 구분합니다. 근거 없이 모든 이용 기록에 일률적인 법정 보관 기간을 적용하지 않습니다.

제4조 기기 내 처리·AI 기능·내보내기

1. 기기에만 저장한 편집 자료는 해당 기기에서 처리합니다. 서버에 저장된 자료와 기기 내부 자료는 별개이므로 앱 삭제만으로 서버 회원정보·공유 다이어리가 모두 삭제되지는 않습니다.

2. 손글씨 폰트 생성은 지원되는 Android 빌드에서 이용자가 입력한 손글씨를 기기 내 모델로 처리합니다. 초안·작업 파일·완성 폰트는 기기에 저장하며, 폰트 생성만을 위해 손글씨를 외부 생성형 AI 사업자에게 자동 전송하지 않습니다. 지원하지 않는 실행 환경에서는 실제 생성 기능이 제한될 수 있습니다.

3. 사진 속 대상을 분리하는 서버 기능을 이용하면 이용자가 선택한 이미지와 분리 요청 정보가 DIO 백엔드를 통해 AI 처리 서버로 전달됩니다. 분리를 위한 임시 이미지·특징 정보와 이용자가 저장하는 결과 파일은 구분됩니다. 현재 처리 코드에서는 이미지와 특징 정보를 프로세스 메모리에 임시 보관하고, 결과 이미지는 메모리에서 만들어 반환합니다. 임시 자료를 영구 파일로 저장하는 경로는 없습니다. 기본 캐시는 최근 사용 사진 최대 32개, 마지막 사용 후 30분이 지난 자료는 후속 조회에서 만료 처리하며 공간 부족 시 오래된 항목을 제거합니다. 주기 타이머로 정확히 30분 뒤 모두 지우는 구조는 아니므로 요청이 없으면 프로세스 종료·교체나 캐시 정리 전까지 메모리에 남을 수 있습니다. 처리 서버는 운영자가 확인한 AWS EC2 서울(ap-northeast-2)입니다. 캐시의 실제 환경변수 변경값은 별도 확인 대상입니다.

4. 배경색을 기준으로 스티커를 분리하는 단순 이미지 처리는 손글씨 글자 생성이나 서버 대상 분리와 구분됩니다.

5. 이용자의 다이어리·사진·손글씨를 DIO 홍보물로 재사용하거나 광고 분석·모델 재학습에 사용하는 것은 본 방침으로 허용받는 처리에 포함하지 않습니다. 다른 목적의 처리를 도입할 때는 별도의 적법한 근거와 필요한 안내·동의 절차를 먼저 갖춥니다.

6. PNG·PDF 또는 사용자가 선택한 파일을 사진첩·파일 앱·외부 서비스로 내보내면 해당 내용과 파일명에 포함된 정보가 선택한 위치로 전달될 수 있습니다. 외부에 저장한 사본은 이용자가 해당 위치에서 직접 관리·삭제해야 합니다.

7. PDF 공유용 임시 사본에는 생성·공유 처리 시점을 기준으로 24시간의 만료 시간을 설정하고 앱 시작이나 다음 공유 시 정리합니다. 앱 실행 여부·정리 결과에 따라 더 오래 남을 수 있으므로 정확히 24시간 후의 삭제를 보장하지 않습니다.

제5조 개인정보의 보유·이용 기간

아래 표는 현재 배포 구성과 운영자가 채택한 보관·삭제 기준을 구분한 검토 내용입니다. 운영 기준의 채택만으로 자동 삭제 기능이 실행되지는 않습니다. 자동 정리 미활성·미구현 항목은 제12조의 적용 과제를 해결하기 전까지 기재한 목표 시한의 삭제를 보장하지 않습니다.

정보채택한 보유·이용 기준현재 운영·적용 상태
회원 계정이용 기간 동안 보유하고 탈퇴 완료 시 이메일·로그인 자격증명·개인 별칭 등 식별정보를 삭제·익명화합니다.탈퇴 처리 경로가 있습니다. 파일 저장소의 물리 삭제는 별도 정리 상태에 따릅니다.
이메일 인증·비밀번호 재설정 검증정보인증번호·후속 토큰 만료 후 24시간이 지난 정보를 정리 대상으로 처리합니다.만료 인증·세션 정리는 기본 활성, 1분 간격·기동 5분 후 시작으로 전달받았습니다. 배치 처리·장애에 따른 추가 지연이 있을 수 있습니다.
로그인 세션·토큰 회전 이력액세스 토큰 유효시간은 15분, Refresh 세션은 30일입니다. 만료 세션과 연결 이력을 정리합니다.만료 정리 활성 상태입니다. 로그아웃 등에 따른 사용 폐기와 DB 행의 물리 삭제는 구분합니다.
약관 동의이용 중 종류·버전·상태·시각을 관리합니다. 기본 약관 동의 행은 현재 탈퇴 처리에서 삭제합니다.현재 기능은 같은 종류·버전의 최신 상태를 갱신하며 별도 장기 증빙 보관 기능은 아닙니다. 향후 마케팅 증빙은 아래 별도 기준을 적용하기 전 근거·구현 확인이 필요합니다.
다이어리 휴지통휴지통 이동 후 30일간 복원하고 기간 경과 후 영구 삭제 대상으로 처리합니다. 명시적 영구 삭제·마지막 멤버 나가기는 복원 대상이 아닙니다.자동 영구 삭제 배치는 현재 비활성입니다. 따라서 30일이 지나면 저장 자료가 자동으로 모두 지워진다고 보장하지 않습니다.
계정 사진·서버 미디어사용·공유 참조가 없는 삭제 자료는 삭제 표시 후 24시간 유예를 거쳐 물리 삭제 대상으로 처리합니다. 사용 중인 공유 참조는 유지할 수 있습니다.미디어 물리 삭제는 기본 비활성이고 현재 활성화됐다는 확인이 없습니다. 활성 시 기본 1시간 간격입니다. 계정 사진의 별도 정리·재시도 경로와 미디어 정리는 구분합니다.
처리된 초대·삭제된 앱 내 알림초대 수락·거절·취소 또는 알림 삭제 후 30일을 기준으로 정기 영구 삭제합니다. 대기 중인 무기한 이메일 초대는 제외합니다.운영 기준을 채택했습니다. 초대 원본·알림 본문 전체의 기간 기반 정리 적용은 후속 작업입니다. 탈퇴·다이어리 영구 삭제 시 처리 경로와 다릅니다.
비활성 푸시 등록정보비활성화 즉시 발송을 차단합니다. 재연결·진행 중 처리에 필요하지 않은 토큰·등록 상세정보는 비활성화 후 30일 이내 정리합니다. 중복 방지 기록은 관련 요청의 재시도 가능 기간 종료 후 정리합니다.30일 전체 정리는 적용 과제입니다. 이미 존재하는 만료 등록 응답 암호문 정리만으로 설치·등록 이력이 전부 삭제되는 것은 아닙니다.
만료 푸시 등록 응답·발송 대기열등록 응답 암호문은 만료 후 정리합니다. 종료된 대기열은 기존 처리 완료·만료 조건과 30일 기준을 적용합니다.만료 등록 응답 암호문 정리는 1분 간격·기동 5분 후 시작으로 기본 활성입니다. 발송 대기열 정리는 현재 비활성입니다.
공동 편집 상세 이력·작업 식별 기록실행 취소용 상세 스냅샷은 기능상 보존 범위를 적용합니다. 별도 일반 진단용 상세 기록은 30일을 운영 기준으로 삼습니다. 중복 반영 방지에 필요한 작업 식별번호·검증값만 필요한 동안 유지하고 원본 페이지·다이어리 영구 삭제 시 함께 정리합니다.상세 스냅샷 개수 정리와 식별 기록의 보존은 구분합니다. 일반 진단 기록의 30일 정리 적용과 재시도 기간 기준의 완결성 검증은 후속 작업입니다.
탈퇴 후 공유 작업 연결정보공동 작성물 유지에 필요한 최소 내부 작성자 식별값만 해당 공유 다이어리 유지 기간 동안 제한적으로 남깁니다. 이메일·개인 별칭·프로필 사진 등 식별정보를 정리하고, 다이어리 영구 삭제 때 관련 연결도 정리합니다.탈퇴·다이어리 삭제 경로가 있습니다. 내부 식별값이 남는 자료는 완전히 익명화됐다고 표현하지 않습니다. 참조·파일의 최종 삭제 결과를 점검합니다.
기기 내 자료·외부 내보내기 사본기기 내 편집·폰트 자료는 이용자의 삭제 또는 앱 데이터 삭제 때까지 해당 기기에 보관합니다. 외부 저장 위치의 사본은 이용자가 관리합니다.계정 탈퇴나 DIO 서버 삭제로 다른 기기·외부 서비스의 사본까지 회수되는 것은 아닙니다.
문의·신고 이메일·첨부자료답변·후속 처리 완료 후 담당자 신승민이 Gmail 휴지통까지 지체 없이 삭제하고 팀 PC·Drive에 별도 사본을 보관하지 않습니다.운영자 관리 메일함 삭제 기준입니다. Google 시스템의 내부 삭제 지연·백업은 Google의 정책과 별도로 구분합니다.
서버 로그운영자가 전달한 현재 기준은 백엔드·Nginx 컨테이너마다 약 10MB × 7개, 약 70MB의 용량 순환입니다.보존 일수나 최장 보존기간은 확정되지 않았습니다. 재배포 때 이전 컨테이너 로그가 사라질 수 있으나 정해진 기간 내 삭제를 보장하는 방법은 아닙니다. 최장 보존 기준을 추가로 정해야 합니다.
선택 마케팅 정보·증빙 — 도입 전광고 이용은 철회·탈퇴·운영 종료 중 먼저 도래하는 때에 중단합니다. 최소 동의·철회 증빙은 철회 후 1년 보관안을 채택하되 별도 보존의 적법한 근거·필요성을 확정한 뒤 적용합니다. 수신 거부 차단정보는 과거 발송 대상에서 재발송될 가능성이 없어질 때까지 최소한으로 유지합니다.현재 광고 발송은 미구현·미시행입니다. 1년은 법정 의무 기간이 아니며 기본 약관 행의 현재 삭제 동작과 다릅니다. 근거 확인·분리 보관·삭제 절차 구현 전 장기 보관이나 광고 발송을 시작하지 않습니다.

분쟁·권리행사 또는 법령에 따라 별도 보존이 필요한 경우에는 해당 근거·항목·목적·기간을 구분하고 다른 목적으로 사용하지 않습니다. 위 운영 기간을 보편적인 업계 평균이나 법정 의무로 표현하지 않습니다.

제6조 파기 절차와 백업

1. 이용 목적·보존 기간이 끝난 개인정보는 적용 근거와 참조 관계를 확인해 삭제·익명화 등 필요한 처리를 진행합니다. 전자파일은 복구·재생을 방지하는 방식으로 삭제하고, 종이 출력물이 있으면 분쇄 등으로 처리합니다.

2. 앱에서 삭제 상태로 바꾸는 처리와 DB 행·S3 객체의 물리 삭제는 구분합니다. 현재 휴지통 자동 영구 삭제·미디어 물리 삭제·푸시 대기열 정리가 활성화되지 않았으므로, 기재한 목표 기간 경과만으로 원본이 자동 파기됐다고 안내하지 않습니다. 요청은 문의처를 통해 접수할 수 있습니다.

3. 운영자가 관리하는 별도 DB·파일 자동 백업, AWS Backup 계획, EC2 스냅샷의 리전 간 복사 및 S3 버전 관리는 현재 구성하지 않았다고 확인했습니다. DIO가 설정한 별도 백업의 복제본 만료기간은 해당하지 않습니다.

4. 별도 백업이 없다는 것은 삭제 표시만 한 운영 DB·S3 객체나 서비스 제공자 내부 사본이 모두 즉시 사라진다는 뜻이 아닙니다. 삭제 배치가 꺼진 미디어, 공유 참조 중인 자료, 이용자 내보내기 사본, 개인 Gmail의 서비스 제공자 측 사본을 별도로 구분합니다.

5. 향후 백업을 도입하면 위치·국가·주기·보유 기간과 삭제 자료의 잔존 상한을 먼저 정해 방침에 반영합니다. 휴대폰 사진첩 원본은 DIO 서버에서 삭제하지 않습니다.

제7조 공유 기능과 외부 전달

1. 참여자가 있는 다이어리의 내용·첨부자료·프로필·참여 상태·편집 정보는 권한 있는 다른 참여자에게 표시됩니다. 초대 링크를 받은 사람도 수락 전 화면에서 제공되는 범위의 다이어리 정보와 정원 상태를 확인할 수 있습니다.

2. 이메일 초대는 입력한 이메일을 통해 가입된 수신자를 확인하고 앱 내 초대·알림으로 전달합니다. 초대 메일을 발송하는 기능과는 다릅니다. 휴대폰 푸시는 별도 등록·권한·발송 설정에 따릅니다.

3. 계정 사진은 공개 조회 주소를 통해 표시될 수 있습니다. 다이어리별 사진은 참여 권한 확인 경로를 사용하지만, 계정 사진을 선택하면 공개 계정 사진 주소의 특성이 적용됩니다. 별칭·사진을 정하지 않은 경우 계정 프로필이 표시될 수 있습니다.

4. 이용자는 공유 범위와 참여자를 고려해 자료를 등록해야 합니다. 원하지 않는 민감한 정보는 업로드·공유하지 않을 수 있으며, 등록한 자료의 삭제·참여자 관리·신고 기능 또는 문의처를 이용할 수 있습니다. 이미 다른 참여자가 저장·내보낸 자료까지 회수되는 것은 아닙니다.

5. 운영자는 이용자 정보를 제휴사 광고 목적으로 임의 제공하지 않습니다. 개인정보 제3자 제공에 해당하는 별도 전달을 도입하면 제공받는 자·목적·항목·기간과 필요한 법적 근거·동의 절차를 갖춥니다. 법령에 따른 적법한 요청은 정해진 절차에 따라 처리합니다.

제8조 기기 접근 권한

사진을 가져오거나 PNG를 사진첩에 저장할 때 운영체제의 사진 선택·저장 기능을 사용하고 필요한 범위의 권한을 요청합니다. PDF 저장·공유에는 운영체제의 파일·공유 기능을 사용합니다. 서비스 푸시를 표시하려면 운영체제의 알림 권한이 필요할 수 있습니다.

이용자는 기기 설정에서 권한을 변경할 수 있습니다. 거부하면 해당 기능이 제한될 수 있으나 그 권한이 필요하지 않은 기능까지 제한하지 않습니다. 알림 권한 허용은 광고성 정보 수신 동의가 아닙니다.

제9조 개인정보 처리업무 위탁 및 국외 처리

1. 현재 확인한 외부 서비스와 업무

서비스·업체처리 업무·정보확인한 위치·상태
AWS EC2 / Amazon Web ServicesDIO 백엔드 운영 및 선택 이미지의 대상 분리 AI 처리백엔드·AI 서버는 서울(ap-northeast-2). PostgreSQL은 Docker 내부망으로 연결합니다. AWS 계약 계정의 법적 계약 주체와 DB 호스트·볼륨의 세부 위치는 추가 확인 대상입니다.

실제 계약상 수탁자 법인명·연락처와 관리·감독에 필요한 계약은 기술 서비스의 브랜드명만으로 확정하지 않습니다. 위 표의 남은 항목을 확정한 뒤 공개용 위탁 표를 완성합니다.

2. 국내 저장과 국외 이전의 구분

운영자가 확인한 DIO 백엔드·AI 및 S3 주 저장 위치는 서울이며, 운영자가 설정한 해외 복제·배포 경로는 없습니다. 다만 이 사실을 모든 서비스·업무에서 국외 처리가 전혀 없다는 보증으로 확대하지 않습니다. AWS의 예외적 지원·법적 요청 처리, 계정 운영·로그 등은 실제 계약·이용 범위에 따라 별도로 확인합니다.

회원가입·비밀번호 재설정 메일에는 수신 이메일 주소·인증번호 등이 포함됩니다. 인증 메일에 비밀번호 원문·다이어리 본문·사진을 넣지 않습니다. 초대는 앱 내 초대·알림으로 처리하며 초대 이메일은 발송하지 않습니다. 문의 메일에는 발신 이메일·문의 내용·이용자가 첨부한 자료가 포함될 수 있습니다.

Google의 공식 개인정보처리방침은 거주 국가 밖의 서버에서 처리될 수 있음을 안내합니다. 일반 개인 Gmail에 대해 DIO의 정확한 국가·이전받는 자 연락처·항목·시기와 방법·목적·기간·이전 근거·거부 방법 및 영향을 모두 확정한 상태는 아닙니다. 이를 임의로 미국 한 국가나 30일 보관으로 채우거나 일반 가입 동의로 모든 이전 동의를 받았다고 간주하지 않습니다.

문의 처리 완료 후 운영자 관리 메일함에서 삭제하더라도 Google 측 삭제에는 별도 시간이 걸릴 수 있습니다. Google은 일반적으로 삭제 과정에 약 2개월, 암호화된 백업에 최대 6개월의 잔존 가능성과 지연 예외를 안내합니다. 이는 DIO의 메일을 언제나 정확히 그 시점에 삭제한다는 개별 보장이 아닙니다.

현재 외부 푸시는 발송하지 않습니다. 향후 켤 경우 Expo·기기 전달 서비스로 전송되는 항목·국가·기간·법적 근거를 먼저 확인하고 필요한 고지·동의 등 절차를 갖춥니다. 푸시 비활성이라는 사실은 Expo Go·개발 빌드·앱 업데이트 등 다른 도구의 모든 통신이 없다는 뜻은 아닙니다.

제10조 안전성 확보·로그·자동 수집

운영자는 권한 있는 담당자만 개인정보를 취급하도록 관리합니다. 비밀번호는 BCrypt 해시값으로 저장하고, 푸시 토큰·등록 자격증명 응답에는 코드의 AES-GCM 보호를 적용합니다. 앱 잠금 PIN의 검증정보는 계정별 기기에 보관하며 다이어리 파일 전체의 암호화를 의미하지 않습니다.

운영자가 확인한 앱-서버 HTTPS는 운영 443·개발 8443이며, Certbot 인증서를 Nginx에서 사용합니다. 개발 서버에는 Basic 인증이 있고 운영 서버에 같은 Basic 인증을 적용했다고 안내하지 않습니다. DB 내부 연결은 현재 jdbc:postgresql://db:5432/...이며 TLS 설정이 확인되지 않았습니다. EC2 EBS 볼륨 암호화, 실제 S3 객체의 암호화 방식·KMS 적용, SSH·방화벽 규칙과 관리자 권한은 콘솔·서버 확인이 남았습니다. S3 공식 기본 암호화 정책과 실제 버킷에서 선택한 방식을 구분하며 전체 DB·전송·파일이 모두 암호화됐다고 표현하지 않습니다.

현재 Nginx 접속 로그 설정은 IP 주소, 개발 접근 인증 사용자명(있는 경우), 접속 시각, 요청 방식·경로·프로토콜, 응답 상태·크기, Referer 출처, User-Agent를 포함합니다. 접속 로그에서는 초대 토큰 경로를 가리고 쿼리 문자열·Referer 상세 경로를 제외하도록 구성합니다. 백엔드·Nginx 컨테이너 로그는 각 약 70MB의 용량 순환으로 관리한다고 전달받았습니다.

운영자는 비밀번호·인증 토큰·요청 본문을 일반 로그에 기록하지 않는다고 답변했습니다. 다만 Nginx 오류 로그에는 업스트림 오류 시 원본 요청 경로·쿼리 등이 남을 가능성이 소스에 명시돼 있어, 오류 로그까지 토큰 비기록이 보장되는지는 별도 검증·보완 대상입니다. 마스킹된 접속 로그 설정만으로 모든 로그가 같은 수준으로 정제됐다고 보증하지 않습니다. 최장 보존일과 관리자 접근·삭제 절차도 공개 전 확인합니다.

앱은 저장·복원에 필요한 내부 파일·AsyncStorage 등 기기 저장소를 이용합니다. 앱 내 광고식별자 추적 광고는 운영하지 않으며 앱 코드에서 별도 이용 행태 분석 SDK 연결은 확인되지 않았습니다. 운영자가 저장소에서 확인한 범위에는 Sentry·Datadog·OpenTelemetry 연동 흔적이 없습니다. 실제 서버 에이전트·AWS 측 로그 수집·추가 도구의 유무는 별도 확인 대상으로 남습니다.
