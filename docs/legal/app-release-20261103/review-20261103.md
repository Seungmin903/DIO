# 약관·개인정보처리방침 및 스토어 심사 점검

점검일: 2026년 11월 3일. 대상은 이 폴더의 개정안 7종과 현재 로컬 소스다. 배포 서버·AWS 콘솔·App Store Connect·Play Console·제출용 IPA/AAB는 확인하지 않았다. 문서가 우선인 초대 7일·푸시 30일 등 정책 변경은 결함 판정에서 제외하고, 출시 전에 일치시킬 조건으로만 다룬다. 법률 적합성 인증이나 심사 통과 보장은 아니다.

## 결론

문서 구조는 기본 수집·선택 마케팅·공동 작성물 보존·원본 파일 파기를 구분하고 있어 사용할 기반은 갖췄다. 그러나 현재 상태로 공개 최종본 또는 양대 스토어 제출 준비 완료라고 판정할 수는 없다. 특히 국외 처리 고지의 빈 내용, 공개 문서 연결, 공동 편집의 신고·차단, 앱 외 계정 삭제 경로를 먼저 해결해야 한다. 코드에 이미 탈퇴 서비스와 호출이 있으므로 탈퇴 전체를 미구현이라고 보지는 않는다.

## A. 문서 자체에서 마무리할 사항

### A1. 국외 처리 안내가 실제로 완성되지 않음 — 게시 전 해결

개인정보처리방침 8절은 Gmail의 국가·수령자·기간·근거 등을 '별도 안내에 명시'한다고 했지만 그 구체 안내가 이 묶음에는 없다. Expo/APNs/FCM도 실제 제공 시 적용할 처리 조건이 확정되지 않았다. AWS 서울 저장과 모든 외부 서비스의 국내 처리는 서로 다르다. 일반 개인 Gmail 사용이 그 자체로 무조건 불법이라는 판정은 하지 않지만, 일반 Google 방침 링크만으로 DIO의 의무가 끝난다고 할 수 없다.

필요한 조치: 실제 위탁·이전 관계와 적용 법적 근거를 확정하고, 해당 근거에서 요구하는 수령자·국가·항목·시점/방법·목적·기간 및 필요한 거부 방법/영향을 채운다. '국외 이전 동의 체크박스를 무조건 하나 더 추가'하는 것으로 대체하지 않는다. [개인정보 보호법 제28조의8](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1034515803)

### A2. 로그·백업의 구체 기준이 남아 있음 — 게시 전 해결

개인정보처리방침 4·6절은 로그의 용량 순환은 설명하지만 시간 기준 보유 상한과 실제 백업 구성을 확정하지 못했다. '실제 구성에 따라 고지'는 게시용 확정 정보가 아니다. 목적 종료 시 삭제한다는 원칙과 별도로 접근 로그의 최대 보유 기준·삭제 실행 책임을 정하고, 백업이 실제 없으면 그 사실을 확인해 명시한다. 있는 경우 위치·주기·만료 기간을 정한다. 운영자 접속기록과 일반 Nginx 로그를 같은 70MB 순환으로 처리하지 않는다. [개인정보 보호법 제30조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1034292763)

### A3. 시행일·버전·검토 배너 — 제출 전 해결

현재 시행일은 '실제 게시 시 공지하는 적용일', HTML은 검토 배너, JSON은 publicationReady=false다. 이는 작성 단계로는 적절하지만 스토어 제출본에는 실제 적용일과 최종 문서를 제공해야 한다. 이미 v2 내용으로 동의받은 이력이 있으면 새 내용을 같은 v2에 덮어쓰지 않는다. 필요한 안내·동의 절차와 서버·앱 버전을 맞춘다.

### A4. 탈퇴 후 보존 문구를 무조건 보관 근거로 사용하지 않기

개인정보처리방침 5절은 직접 식별정보와 공동 작업의 내부 연결값을 구분하고 있어 방향은 맞다. 다만 공동 작성물에 원본 사진·EXIF가 남는다는 고지는 모든 개인정보 삭제 요구를 거절할 근거가 아니다. 공동 작성물 유지에 꼭 필요한 범위, 삭제 요청 검토와 개별 사진 제거 절차를 운영해야 한다. 계정만 비활성화하고 직접 식별정보를 그대로 보존하는 것으로 계정 삭제를 대체해서는 안 된다. 실제 현재 `User.withdraw`는 이메일 제거·표시 이름 변경을 하고 있어 단순 정지와는 구분된다. [Google 계정 삭제 정책](https://support.google.com/googleplay/android-developer/answer/13327111?hl=ko)

## B. 문서 우선 정책 외 실제 앱과의 연결 문제

### B1. 가입에서 문서를 못 읽어도 동의 진행 가능 — 출시 전 해결

`frontend/src/auth/AuthScreen.js`의 viewDocument는 URL이 없으면 '문서 준비 중'을 표시한다. `signupPolicy.js`의 signupEligibility는 연령·체크 상태만 확인한다. 내부 QA를 위해 허용한 상태지만, 출시 때는 체크 전에 실제 내용을 읽을 수 있어야 한다. 현재 생성한 문서 JSON·HTML은 앱에 아직 연결되지 않았다.

`AppInformation.js`의 처리방침 링크에는 이전 Google Docs `/edit?usp=sharing` 주소가 대체 경로로 남아 있다. 이 URL이 실제 편집 가능하다는 뜻은 아니지만, 출시 시 사용자가 수정할 수 없는 최종 공개 페이지로 교체하고 로그인 없이 열리는지 확인한다. 앱에 내장해도 스토어 등록용 공개 URL은 따로 필요하다. [Google 사용자 데이터 정책](https://support.google.com/googleplay/android-developer/answer/10144311?hl=ko)

### B2. 가입 후 이용약관 상시 열람 경로 부족 — 문서·앱 맞춤 필요

서비스 약관 제3조는 가입 후에도 약관 확인 경로를 안내한다고 한다. 현재 `AppInformation.js`에는 처리방침·문의·라이선스가 있으나 서비스 이용약관의 상시 열람 행은 없다. 다른 경로를 마련하거나 기존 정보 화면에 최종 약관을 연결해야 한다. 이번 점검에서는 UI를 바꾸지 않았다.

### B3. 공유 콘텐츠의 신고·차단 — 높은 심사 위험

현재 확인 범위에서는 콘텐츠/사용자 신고 및 사용자 차단 UI·서비스를 찾지 못했다. 소유자의 강퇴·초대 취소·본인 나가기는 존재하지만, 편집자가 자신을 괴롭히는 소유자를 신고·차단하는 기능과 같지는 않다. 공식 이메일 연락처는 있지만 단순 주소 복사만으로 필요한 모든 인앱 안전 기능을 충족한다고 단정할 수 없다.

DIO는 초대 기반 비공개 공동 편집이어도 타인의 사진·글을 볼 수 있으므로 UGC 기준 적용 가능성이 높다. 비공개라 자동 면제라고 설명하지 않는다. 실제 사용 형태에 맞는 신고 접수·유해 콘텐츠 처리·괴롭힘 사용자 차단을 구현하거나 충족하는 동등한 절차를 검증하고 심사 메모에 설명해야 한다. 자동 AI 필터 API나 새 테이블이 무조건 필요하다는 뜻은 아니다. [Apple 1.2](https://developer.apple.com/app-store/review/guidelines/#user-generated-content), [Google UGC 정책](https://support.google.com/googleplay/android-developer/answer/9876937?hl=ko)

### B4. 탈퇴는 구현됨. 외부 삭제 요청 페이지와 예외 복구 확인 필요

`auth/controller/MyProfileController.java`의 DELETE `/api/v1/me` → `MyProfileService` → `UserWithdrawalService`가 있고, `authApi.withdraw` 및 `ProfileEditScreen`의 탈퇴 확인 창이 연결돼 있다. 앱에서 탈퇴 진입·완료는 실제 제출 빌드로 확인한다.

점검 후 Google Play용 별도 삭제 요청 안내 `account-deletion.md`·`account-deletion.html`을 추가했다. DIO 이름·공식 이메일 접수 방법·삭제 정보·남는 정보와 기간을 안내한다. 아직 공개 게시 URL과 실제 담당자의 처리 검증은 남아 있다. 고객센터 이메일로 요청하는 공개 페이지도 정책상 가능한 방식이므로 새 서버 API가 필수는 아니다. 이메일 주소만 스토어 URL 칸에 쓰는 것으로 대체하지 않는다. [Google 계정 삭제 요구사항](https://support.google.com/googleplay/android-developer/answer/13327111?hl=ko)

공유 소유자는 양도 전 409로 탈퇴가 막힐 수 있다. `UserWithdrawalDiaryAdapter`는 휴지통의 소유 다이어리도 검사한다. 복구 후 양도·적법한 삭제·지원 요청 등 탈퇴가 영구 봉쇄되지 않는 경로를 검증해야 한다. 이 예외를 실기기로 검증하지 않았으므로 곧바로 탈퇴 불가 결함이라고 단정하지 않는다. [Apple 계정 삭제 기준](https://developer.apple.com/help/app-review/guideline-reference/5-1-1-account-deletion)

### B5. 사진 원본과 프로필 사진은 다르게 처리됨 — 설명 보완 권장

개인정보처리방침의 '원본 사진 EXIF가 남을 수 있음'은 일반 서버 미디어에 대한 설명이다. 계정 프로필 사진의 `ProfilePhotoImages.prepare`는 EXIF 방향 보정 후 512px 이하 PNG로 재인코딩하며 메타데이터를 저장하지 않는다. 프로필 사진까지 모두 원본 EXIF가 유지된다는 의미로 읽히지 않도록 구분하면 더 정확하다. '앱이 GPS 권한을 요청하지 않는다'와 '선택 사진에 위치 메타데이터가 전혀 없다'는 서로 다른 설명이다.

### B6. 소셜 로그인은 현재 점검 브랜치에서 미연결

이 브랜치의 `authApi.social`은 '소셜 로그인 API는 아직 연결되지 않았어요' 예외를 내며, 화면에는 카카오·Google·Apple 버튼이 있다. 다른 기능 브랜치의 완료 여부와 현재 제출 소스는 구분한다. 출시본에는 동작하는 경로를 제공하고, 안 되는 버튼·준비 중 화면을 남기지 않는다. Google·카카오 로그인을 iOS의 주 계정 로그인으로 제공한다면 Apple 4.8의 동등한 개인정보 보호 로그인 조건과 예외 적용 여부를 확인한다. Apple 로그인은 일반적으로 이를 충족하는 선택지이나 모든 앱에 무조건 요구된다고 표현하지 않는다. [Apple 2.1·4.8](https://developer.apple.com/app-store/review/guidelines/)

## C. 스토어 제출 항목 — 문서만으로 확인 완료 불가

1. **공개 URL:** 개인정보처리방침, 지원 페이지, Google 계정 삭제 요청 페이지를 HTTPS·로그인/Basic Auth 없이 열람 가능하게 게시. Google 방침은 PDF나 이용자가 편집 가능한 문서로 제출하지 않는다.
2. **데이터 신고:** Apple App Privacy와 Google 데이터 보안에 이메일·회원 ID·업로드 사진/글/필기·지원 문의·기기/푸시 식별정보·실제로 수집하는 로그 등을 분류한다. 기기 내 폰트 처리와 서버 전송을 구분하고 SDK를 포함해 실제 동작을 기준으로 한다. 앱 내 광고가 없다고 '개인정보 수집 없음'으로 답하지 않는다. EXIF의 위치정보가 서버 원본에 남는 경로도 따로 검토한다. [Apple 신고 기준](https://developer.apple.com/app-store/app-privacy-details/), [Google 사용자 데이터 정책](https://support.google.com/googleplay/android-developer/answer/10144311?hl=ko)
3. **연령:** 만 14세 이상 자기확인은 유료 휴대폰 본인인증을 도입해야 한다는 뜻은 아니다. 다만 실제 나이 인증 완료라고 안내하지 않고, 아동 대상 설정·스크린샷·콘텐츠 등급 설문을 실제 서비스와 일치시킨다. 14세 제한이 모든 콘텐츠의 연령 적합성이나 UGC 의무를 대신하지 않는다.
4. **권한:** `app.json`의 사진 선택·저장 목적 문구는 기능과 부합하고 위치 접근 옵션은 꺼져 있다. 다만 최종 merged AndroidManifest·iOS Info.plist·privacy manifest를 확인해야 한다. 앱 설정 파일만 보고 SDK가 추가한 권한까지 없다고 단정하지 않는다. 사진 가져오기는 가능한 한 OS 선택기를 사용하고 광범위한 사진 읽기 권한은 정당화가 필요한지 검토한다. [Google 최소 권한](https://support.google.com/googleplay/android-developer/answer/16935362?hl=en-GB)
5. **광고 푸시:** 현재 미운영이라면 실제 광고는 보내지 않는다. 시작 시 앱 안의 명확한 수신 동의·거부 경로와 매 발송의 상태 검증이 필요하다. OS 알림 권한과 선택 약관 기록만으로 발송 준비가 끝난 것은 아니다. [Apple 4.5.4](https://developer.apple.com/app-store/review/guidelines/)
6. **제출 빌드 검증:** Expo Go가 아닌 IPA/AAB로 가입·인증·문서 열람·공유·신고/차단·탈퇴·사진 선택·거부 상태·iPad 회전/큰 글자·Android 태블릿을 테스트한다. 심사 계정과 공유 테스트용 계정/문서를 준비하고 심사 중 서버를 유지한다. Basic Auth 등 별도 접근 장벽이 있다면 심사원이 접근할 수 있도록 처리한다.

## 이번 점검에서 한 것과 하지 않은 것

공식 법령·스토어 정책과 현재 코드 및 개정안 문구를 읽어 대조했다. 목표 보존정책 미구현을 다시 변경 요구로 나열하지 않았다. API·테이블·UI·약관 원문은 수정하지 않았고 출시 설정도 바꾸지 않았다. 실제 운영 보안·법적 계약 조건·콘솔 입력·실기기 결과는 미검증이다. 이 보고서와 별개로 공개 문서의 미확정 정보를 채우고 실제 제출 버전으로 검증해야 최종 제출 여부를 판단할 수 있다.
