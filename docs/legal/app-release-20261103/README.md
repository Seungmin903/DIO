# 과거 검토 묶음 — 외부 게시 금지

이 폴더는 과거 검토 시점의 기록이다. 현재 앱과 공개 후보의 원본은 [final/](../final/README.md)이다. 이 폴더의 현재형 문구·미정 시행일·구현 상태를 현재 운영 사실로 인용하지 않는다. 정적 호스팅이나 공개 Google Docs에 복사하지 않는다.

2026년 11월 3일 전달받은 인프라·운영 답변을 **목표 운영 정책**으로 반영했다. 기존 `v2/` 원본과 Google 문서는 변경하지 않았다. 기존 동의 기록·서버 버전·가입 UI·삭제 로직도 변경하지 않는다.

원본 Markdown을 수정하고 저장소 루트에서 `python docs/legal/build_app_release.py`를 실행한다. 이 폴더의 HTML 9개(법적 문서 7개·삭제 요청 안내·목록)와 `app-documents.json`만 재생성한다. 이전 문서 생성기 `build_html.py`는 변경하지 않았다. HTML·JSON을 직접 수정하지 않는다.

Google Play 계정 삭제 요구사항을 위한 [앱 외 삭제 요청 안내](account-deletion.md)와 [게시용 HTML](account-deletion.html)을 추가했다. 새 동의 항목이 아니므로 네이티브 동의 문서 JSON 7개에는 포함하지 않는다. 공식 이메일로 요청을 받는 절차이며 신승민 담당자의 실제 접수·본인 확인·삭제 처리가 필요하다. 게시 전 배너는 아직 유지한다. 반드시 답변이 필요한 내용만 [최종 확인 질문](required-questions.md)에 모았다.

`index.html`을 열면 7개 문서를 선택해 읽을 수 있다. 본문에는 내부 구현 점검표를 넣지 않았다. 검토용 배너는 생성 템플릿에서 표시한다. 확인이 끝나기 전 배너와 JSON의 `publicationReady: false`를 제거하지 않는다.

## 앱 연결 방법

`app-documents.json`은 같은 원본에서 생성한 오프라인 네이티브 화면용 데이터다. 기존 `legalDocuments.js`의 7개 키와 일치한다. 문서는 heading·paragraph·listItem 블록이며 링크는 별도의 label·url로 제공한다. 네이티브 화면에서 HTML 해석 라이브러리가 없어도 본문을 표시할 수 있다.

이번 작업은 **문서와 앱 연결용 데이터 제작**이다. 앱의 현재 외부 URL 열람 동작을 변경하거나 새 문서 화면을 연결하지는 않았다. 확인되지 않은 국외 처리 사항이 있는 개정안을 실제 회원가입에 자동 노출하지 않는다.

앱 화면 연결 시 기존 디자인의 공통 뒤로가기·제목·색상·타이포를 사용하고, SafeAreaView와 세로 ScrollView, 가변 높이 Text를 사용한다. 글자 확대를 허용하고 본문에 numberOfLines·고정 높이·자동 축소를 적용하지 않는다. 태블릿에서는 최대 본문 너비 약 46rem에 해당하는 디자인 값을 적용하되 큰 글자에서도 잘리지 않게 한다. 표는 원본부터 항목별 문단으로 풀어 가로 스크롤 없이 읽게 했다.

HTML은 시스템 글꼴·명시적인 UTF-8·한국어 언어 정보·viewport·다크 모드·자동 줄바꿈을 적용했다. 외부 JS·폰트·이미지·CDN 의존성이 없고 확대 제한도 없다. iOS에서도 HTML 열람이 가능하며 운영체제 때문에 차단되는 형식이 아니다. 공개 URL은 로그인·Basic Auth 없이 HTTPS로 제공한다. URL은 `EXPO_PUBLIC_*_URL` 7종의 해당 문서에 연결한다.

## 확정한 목표 정책

- 링크 초대 1시간, 이메일 주소를 이용한 앱 초대 7일. 초대 메일 발송 없음.
- 수락·거절·취소 초대는 처리 완료 후 7일, 삭제된 알림은 삭제 후 7일에 영구 삭제. 읽었지만 삭제하지 않은 알림 전체를 삭제하는 정책은 아님.
- 비활성 푸시 등록정보·토큰·등록 요청 이력은 비활성화 후 최대 30일. 대기열은 생성 후 최대 30일, 결과·중복 방지 기록은 최종 처리 후 최대 30일. 발송 제외는 즉시.
- 공동 작업은 참여자가 남아 있는 동안 유지. 실행 취소용 상세 스냅샷은 개수 제한이 먼저 적용될 수 있음. 마지막 참여자 이탈·영구 삭제 시 관련 작업·초대·참조를 정리.
- 참조 없는 삭제 대상 미디어는 24시간 유예 후 1시간 간격 정리. 정상 처리 시 삭제 표시 기준 약 24~25시간. 다른 문서의 유효 참조와 일시 장애는 구분.
- 탈퇴 계정의 직접 식별정보 정리와 공동 작성물에 필요한 최소 내부 연결정보의 제한적 보관을 구분. EXIF가 남는 원본도 명시.
- 마케팅은 현재 미운영. 이전 검토안의 '철회 후 1년'은 최종 답변에서 확정되지 않아 넣지 않음.

## 게시·앱 적용 전 반드시 맞출 사항

1. **목표 정책의 구현·배포:** 이 과거 검토 시점에는 이메일 초대가 `DiaryInvite.NO_EXPIRY`이고 초대·삭제 알림의 7일 정리 배치가 미구현이었다. 이후 원격 develop be6a501f에는 구현이 추가됐다. 실제 배포 여부는 별도로 확인한다. 문서 기준으로 변경·검증한 후 적용한다. 이 문서 작업에서 API·테이블·백엔드를 수정하지 않는다. 마지막 소유자 나가기는 `DiaryMembershipService.remove`에 영구 삭제 분기가 이미 있으므로 신규 기능이 없다고 오인하지 않는다. 연관 데이터 전체 범위는 별도 테스트로 확인한다.
2. **Gmail 국외 처리:** 일반 개인 Gmail을 이용한다는 사실과 Google의 다국가 처리 안내는 확인 가능하다. DIO에 적용되는 이전받는 자·연락처·국가·이전 항목·목적·시점/방법·기간·근거·거부 방법과 영향은 일반 방침만으로 확정할 수 없다. 구체 안내를 채우기 전 개인정보처리방침을 공개 최종본으로 취급하지 않는다. 국외 처리 요건을 외부 링크 하나로 대체하지 않는다.
3. **푸시 활성화:** Expo 발송은 현재 기본 비활성이고 활성화 예정이다. 실제 제공 때 Expo/APNs/FCM 경로의 위탁·국외 처리 안내와 근거, 기기 등록·해제 및 발송 기록 정리를 함께 확인한다. SDK 포함만으로 실제 발송 중이라고 적지 않는다.
4. **보안·로그·백업:** 백업·스냅샷·S3 버전 관리는 '저장소에 설정 없음'과 '실제 미사용'을 구분해야 한다. AWS 콘솔의 실제 구성과 보유 기간을 확인한다. 용량 순환 로그에는 최대 보존일이 없으므로 운영상 시간 상한 또는 수동 파기 절차를 정한다. 관리자 접속기록은 일반 Docker 로그와 별도로 관련 법정 보존 기간을 적용한다. 전체 DB·내부망 암호화, 오류 로그 비기록, 추가 수집 도구 부재를 확인 없이 보증하지 않는다.
5. **시행일·버전:** 2026-11-03은 작성일이며 실제 시행일을 임의로 소급하지 않았다. 공개 시 7개 문서의 적용일과 안내 일정을 확정한다. 이 폴더의 v2/v1은 아직 공개되지 않은 원본 기준의 후보이며 이미 같은 버전으로 공개·동의를 받은 문서가 있다면 내용 변경을 덮어쓰지 말고 새 버전을 발행한다. 서버·앱 버전 설정은 게시 승인 후 함께 변경한다.
6. **광고 개시 전:** 무료 간편 수신 거부, 채널별 철회, 발송 직전 동의 검사와 야간 차단을 갖춘 뒤 발송한다. 동의·철회 증빙의 별도 보관 근거·항목·기간을 확정한다. 선택 체크박스가 있다는 이유만으로 광고 발송을 시작하지 않는다.

- [개인정보 보호법 국외 이전 관련 조문](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029334869): 구체 처리 사실과 적용 근거 확인 필요.
- [Google 개인정보처리방침](https://policies.google.com/privacy?hl=ko): 여러 국가의 서버에서 처리할 수 있다는 일반 안내. DIO의 계약·국가·보관 기간을 확정하는 자료는 아님.
- [Expo 개인정보처리방침](https://expo.dev/privacy), [푸시 공식 FAQ](https://docs.expo.dev/push-notifications/faq/): Expo 서비스의 처리와 푸시 경로 참고. DIO 실제 활성화와 계약 조건은 별도 확인.
- [AWS 계약 법인 안내](https://aws.amazon.com/legal/aws-contracting-party/): 실제 계정의 청구·계약 정보를 대조해야 하므로 회사 법인명을 추정해 확정하지 않음.

## 검증 범위

생성물의 본문 일치·누락·버전 매핑·외부 의존성·UTF-8·가로 표 없음·재생성 안정성을 자동 확인한다. 실제 iOS·Android 기기, OS 최대 글자 크기·화면 읽기·키보드/탐색 접근성 검증은 앱 화면 연결 후 수행한다. 반응형 HTML만으로 모든 기기에서 검증을 완료했다고 표현하지 않는다.

## 검증 명령

생성기는 같은 MR의 `docs/legal/build_app_release.py`에 포함된다. `python -m unittest discover -s docs/legal/tests -v`로 원문과 생성물·방침 전 장·재생성 안정성을 검증한다. 외부 게시 승인은 [릴리스 체크리스트](../release-checklist.md)로 별도 관리한다.
