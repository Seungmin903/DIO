# 회원정보 수정·회원탈퇴

## 기준 목업

Figma 파일 `9gy5UQdNJxL67XLZS1VDPg`, MVP2의 `소셜 회원정보 수정`(101-36), `회원 탈퇴 확인`(101-34, 101-30), `저장하지 않고 나가기`(101-32)를 기준으로 한다. 프레임 이름과 관계없이 카카오·구글·애플·이메일 계정을 지원한다. 목업의 사이드바 다이어리 생성 +는 기존 결정에 따라 추가하지 않는다.

## 화면·상태

- 내 공간의 회원정보 수정 버튼으로 바로 진입한다. 별도의 계정 설정 메뉴 화면은 두지 않는다. 로그아웃은 기존 내 공간에 유지한다.
- surfaceSoft 배경 위 최대 폭 880 흰 카드(radius.xl)에 프로필 정보, 사진, 닉네임, 이메일(있는 계정), 로그인 방식, 비밀번호 변경(이메일 계정)을 배치한다. 태블릿은 라벨 왼쪽·입력 오른쪽, 폰은 라벨 위·입력 아래다.
- 카드 하단 구분선 아래 왼쪽 회원탈퇴, 오른쪽 취소·변경사항 저장을 배치한다. 폰은 저장 동작 행과 탈퇴 링크를 줄바꿈하고 세로 스크롤한다.
- 사진 연필은 원 하단에 고정하고 기본 이미지 복구도 같은 자리를 유지해 사진 삭제 전후 입력칸이 밀리지 않는다. 갤러리 취소는 현재 선택을 유지한다. 기본 이미지 복구의 터치 폭은 글자 너비로 제한하고 높이 44는 유지해 오른쪽 빈 공간을 눌러도 초기화되지 않게 한다.
- 변경 중인 사진·닉네임은 임시값이다. 닉네임은 중복 허용이며 형식만 검사한다. 사진만 바꿔도 저장할 수 있다.
- 저장하면 내 공간의 계정 프로필을 갱신한다. 저장한 값을 새 기준으로 삼아 이후 이탈 시 불필요한 경고를 표시하지 않는다.
- 취소·상단 뒤로가기·Android 뒤로가기·사이드바(폰은 좌측 바)·알림 이동으로 화면을 나갈 때 변경사항이 있으면 `변경사항을 저장하지 않았어요` 확인창을 연다. `계속 수정하기`와 X는 임시값을 유지한다. `저장하지 않고 나가기`는 변경을 버리고 요청한 경로로 이동한다.
- 탈퇴는 별도 안내 페이지/체크박스가 아니라 기존 수정 화면 위 확인창이다. `탈퇴합니다`를 정확히 입력한 경우에만 탈퇴하기를 활성화한다. 앞뒤 공백도 허용하지 않는다. 닫기·취소 후 다시 열면 확인 문구를 비운다. 취소는 수정 중인 프로필을 유지한다.
- 이메일 회원의 비밀번호 변경은 현재 비밀번호·새 비밀번호·확인을 받는 대화상자다. 소셜 계정에는 표시하지 않는다. 입력을 버릴 때도 미저장 확인을 제공한다.
- 게스트는 회원정보 수정·탈퇴를 노출하지 않는다.

## API 경계와 데이터 영향

기존 `previewAuth`를 메모리 계정 서비스로 확장한다. 임시 계정 식별자로 계정 수정·탈퇴를 검증한다. 사진/닉네임 수정과 비밀번호 변경은 재로그인에 반영되며 이전 비밀번호 및 탈퇴 계정 로그인은 거부한다. 같은 이메일로 다시 가입하면 새 식별자를 부여해 이전 세션으로 변경할 수 없게 한다. 비밀번호는 서비스 결과·디스크·서버에 노출하지 않는다. 앱 종료/Reload 때 메모리 계정은 사라진다.

계정 프로필 변경 시 공유 런타임은 유지한다. 기존 공유 다이어리의 닉네임·사진·참여 상태·편집 문서는 변경하지 않는다. 이후 새 다이어리에 복사할 기본 계정 프로필만 갱신한다. 기존 개인 다이어리 목록·문서 저장 형식에는 변경이나 마이그레이션이 없다. 목업 탈퇴도 기기의 개인 다이어리를 삭제하지 않는다.

실제 계정 API·OAuth·사진 업로드/영구 보관·실제 탈퇴 시 데이터 처리 정책은 후속 연결 범위다. 화면에 서버 삭제 완료를 주장하는 문구는 추가하지 않는다.

## 검증

- `node --test --test-concurrency=1 tests/*.test.js`
- `pnpm exec expo export --platform all --output-dir .expo/profile-export --max-workers 2`
- `node tests/profile-edit-browser.cjs`: 배포 웹으로 1280×800/1024×768/390×844/320×568에서 직접 폼 진입, 취소·메뉴 이동 확인, 사진 삭제 전후 배치, 중복 재확인, 저장, 비밀번호 변경·재로그인, 정확한 탈퇴 문구, 게스트 진입, 개인 저장 데이터 보존을 검증한다.
- 기본 브라우저는 Playwright Chromium이다(`pnpm exec playwright-core install chromium`으로 설치). 기존 브라우저를 사용할 때는 `PLAYWRIGHT_EXECUTABLE_PATH`에 실행 파일 경로를 지정한다. Windows Edge 경로는 코드에 고정하지 않는다.
- 모달은 기존 EditorModal의 방향 정책·스크롤·키보드 회피를 사용한다. iOS·Android 실기기 갤러리/키보드·시스템 뒤로가기는 별도 확인이 필요하다. 번들 생성·웹 성공과 실기기 실행을 구분한다.

## 추가 점검 보완

- Android 시스템 뒤로가기는 App의 단일 리스너가 등록된 프로필 핸들러에 위임한다. 프로필 화면은 별도 BackHandler 리스너를 등록하지 않는다. 미저장 확인창이 열렸을 때는 계속 수정하기와 같은 동작으로 닫는다. 공유·초대 창은 React Native Modal의 onRequestClose에서 먼저 처리하므로 모달 뒤 프로필 화면이 닫히지 않는다.
- 탈퇴 실패 후에는 확인 문구·수정값을 유지하고 재시도할 수 있다. 사진 선택 실패와 언마운트 후 늦은 결과가 기존 프로필을 변경하지 않는지 검증한다.
- 배포 웹 검증은 이메일 외 소셜 목업 계정의 수정·탈퇴와 이메일/비밀번호 항목 숨김도 포함한다.

- 게스트 내 공간의 계정 진입은 로그아웃 대신 로그인·회원가입으로 표시한다. 기존 인증 시작 화면으로 돌아가며 개인 다이어리 저장 데이터는 유지한다.
- 내 공간 진입 배치: 프로필 영역에 프로필 수정(접근성 이름: 회원정보 수정), 앱 정보 카드 아래 여백 20·높이 48·같은 폭의 별도 테두리 로그아웃 버튼을 둔다. 폰은 프로필 수정/게스트 로그인 동작을 이름 아래에 배치해 긴 닉네임과 겹치지 않게 한다.
