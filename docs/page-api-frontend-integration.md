# 페이지 API 프론트 연결

대상: S15P31F106-306·418·419. 백엔드 `PageController`·`PageUpdateRequest`·`PageData`에 맞춰 프론트만 연결한다.

## 화면과 요청

| 화면 동작 | API |
|---|---|
| 페이지 추가 | `POST /api/v1/diaries/{diaryId}/pages` |
| 페이지 목록·원격 변경 재조회 | `GET /api/v1/diaries/{diaryId}/pages` |
| 새 페이지의 내용·설정 조회 | `GET /api/v1/pages/{pageId}` |
| 페이지 목록의 ⋯ → 페이지 설정 → 저장 | `PATCH /api/v1/pages/{pageId}` |
| 페이지 복사 | `POST /api/v1/pages/{pageId}/copies` |
| 페이지 삭제 | `DELETE /api/v1/pages/{pageId}` |
| 페이지 순서 변경 | `PATCH /api/v1/diaries/{diaryId}/pages/order` |

생성·목록·상세·복사·삭제·순서 변경은 기존 연결을 유지하고 회귀 테스트로 점검했다. 설정 수정 화면과 서버 응답 반영을 추가했다. 일반 로그인으로 연 서버 다이어리에서 설정을 사용할 수 있으며, 게스트의 기존 페이지 작업은 유지한다.

## 설정 계약

- 이름: 앞뒤 공백을 정리하고 UTF-16 기준 1~100자. 가로·세로는 함께 전송하며 0.01~99999999.99, 소수 둘째 자리까지 허용한다.
- 격자 표시와 `#RRGGBB` 색을 저장한다. 화면 격자가 켜져 있으면 화면 설정을 우선하고, 꺼져 있으면 페이지 모눈을 표시한다. 간격 누락·알 수 없는 값은 보통(32), 유효하지 않은 색은 `#DCE5F1`을 사용한다. 편집 화면에만 표시하며 내보내기·썸네일에 격자를 추가하지 않는다.
- 바뀐 필드만 보낸다. `null`로 값을 지우거나 알 수 없는 필드를 보내지 않는다. 이름·크기·격자 저장은 `templateConfig`와 `templateId`를 전송하지 않는다. 서버의 권한·검증 오류는 실패로 처리하고 입력을 유지한다.
- 기존 페이지 속지 교체는 잠시 제외한다. 서버가 `templateConfig`를 전체 교체하고 클라이언트의 예상 버전·ETag를 받지 않아, GET→병합→PATCH로는 동시 변경 유실을 막을 수 없다. 설정 화면에서 속지 변경을 제거하고 전송 함수도 `templateConfig`·`templateId` 요청을 네트워크 호출 전에 차단한다. 새 페이지 추가의 기존 속지 선택은 유지한다. 후속 서버 계약은 JSON 키별 원자적 병합 또는 예상 버전 기반 충돌 거부가 필요하다.
- 크기를 바꿔도 기존 요소의 좌표·크기를 자동 변환하지 않는다. 저장 응답과 원격 목록 설정을 반영할 때 미전송 필기·사진·선택 상태를 덮어쓰지 않는다. 이미 서버에 저장한 설정은 필기 Undo/Redo로 되돌리지 않는다.
- 원격 페이지 변경 이벤트와 기존 주기적 재조회에서 설정도 반영한다. 계정이나 다이어리를 바꾼 뒤 도착한 응답은 이전 화면에 적용하지 않는다.
- 마지막 열람 위치는 기존 `PATCH /diaries/{diaryId}/membership` 연결을 유지한다. 다른 기기의 열람 위치 복원은 이 작업에서 추가하지 않았다.

`qa/page-settings-browser.cjs`는 리뷰 보완 후 1280×800·1024×768·390×844·844×390·320×740에서 저장/재열기·취소·저장 실패 시 입력 유지·기존 속지 교체 버튼 미표시를 통과했다. 페이지 오류와 가로 넘침이 없었다. 실제 계정이나 서버 데이터를 사용하지 않는 독립 테스트 자료이므로 실제 배포 API 성공과 구분한다.

브라우저 QA 실행 전 frontend의 Metro가 필요하다. `EXPO_QA_PORT` 기본값은 8081이며 다른 포트를 지정할 수 있다. 기본 브라우저는 설치된 Edge 채널이고, 다른 Chromium 실행 파일은 `PLAYWRIGHT_EXECUTABLE_PATH`로 지정한다.


백엔드·인프라·AI 코드와 테스트는 수정하거나 실행하지 않았다. 실제 배포 서버의 페이지 생성·수정·복사·삭제·순서 변경과 재로그인 복원은 아래 실기기 확인이 필요하다.

## 실기기 확인 순서

1. 일반 로그인 → 본인 소유의 서버 다이어리 열기 → 페이지 목록 열기.
2. 테스트 페이지 추가 → 해당 페이지의 ⋯ → 페이지 설정. 이름을 바꾸고 저장 → 다시 열어 유지되는지 확인.
3. 격자를 켜고 색을 바꿔 저장. 편집 화면 표시와 설정 재열기 값을 확인.
4. 가로·세로를 바꿔 저장. 크기를 줄여 가려진 필기가 원래 크기로 복원하면 다시 보이는지 확인. 기존 페이지의 속지 변경은 이번 범위에서 제외한다.
5. 설정을 다시 열어 이름을 바꾸고 취소. 이전 이름이 유지되는지 확인.
6. 테스트 페이지에 필기 → 복사 → 복사본 내용 확인 → 복사본만 삭제. 원본이 남는지 확인.
7. 테스트 페이지 순서 변경 → 홈 → 같은 다이어리 재진입. 순서·설정·열람 위치를 확인.

실제 서버 오류가 나면 오류 문구와 동작을 기록한다. 실기기 확인 완료 전에는 위 배포 검증을 완료로 표시하지 않는다.

## 드래그 미리보기 보완 (2026-11-02)

Android에서 페이지를 끌면 놓을 위치 선만 보이고 썸네일이 사라진다는 제보에 따라, 목록 셀을 교체하지 않고 패널 위에 별도 미리보기를 표시한다. 기존 셀은 원래 자리에 투명하게 남겨 제스처와 목록 높이를 유지한다. 미리보기는 터치를 받지 않으며 목록 영역 안에서만 표시한다. 기존 순서 계산·자동 스크롤·서버 순서 저장 경로는 유지한다. 편집 버튼 스타일 변경은 이동 동작 실기기 확인 뒤 별도로 진행한다.

- `node qa/page-drag-browser.cjs`: 독립 자료로 1280×800·390×844에서 드래그 미리보기의 실제 위치 이동, 패널 및 편집 버튼의 크기·위치 유지, 놓은 뒤 순서 반영과 미리보기 제거를 확인했다. 실제 서버 데이터는 사용하지 않는다. Metro와 브라우저 사전 조건은 설정 QA와 같다.
- `node --test tests/editor-page-management.test.js tests/move-pages.test.js`: 11개 통과.
- Android 드래그 및 실제 서버 순서 변경·재진입 후 유지는 사용자 확인 완료다. 편집 버튼은 전체/북마크 탭 폭에 맞춰 140으로 정렬하고 기존 높이 32·글자 크기·선택 모드 동작을 유지했다. 편집/선택 삭제 버튼과 목록 배경도 사용자 확인 완료다.
- 선택 삭제·초기화도 폭 140·시각 높이 32로 맞추고 터치 높이 44와 삭제 확인 동작을 유지했다. 목록 패널 배경은 디자인 가이드의 `rgba(255,255,255,0.58)`로 복원했다. 브라우저 QA에서 편집/선택 삭제의 동일 너비·높이, 선택 모드 복귀와 드래그를 재검증했다.

## 리뷰 보완 범위

- 현재 화면 격자는 모눈/끔만 제공한다. 화면 격자의 설정을 우선하고, 꺼진 경우에만 페이지 모눈을 조합한다. 순수 조합 함수와 실제 GridOverlay 렌더링을 테스트해 기본 간격·색 검증·꺼짐·보조선 보존을 확인했다.
- 페이지 설정의 기존 속지 교체를 제외하여 JSON 전체 교체로 다른 참여자의 속지 설정을 되돌리는 경로를 제거했다. 클라이언트 재조회만으로 동시 저장이 안전하다고 보장하지 않는다. 백엔드 코드는 읽기만 했으며 수정·테스트 실행은 하지 않았다.
- 리뷰 보완 후 Expo CLI 웹 export 통과(`.expo/page-review-export`). 실제 기기에서 화면 격자 켜짐/꺼짐 우선순위의 재확인은 별도로 진행한다.
- 숨겨진 격자 색 입력 보완: 격자를 끈 상태에서는 색 입력이 달라도 `gridColor`를 검증·전송하지 않아 기존 서버 색을 유지한다. 잘못된 색을 입력한 뒤 끄기·이름/크기 저장, 색만 바뀐 경우 무요청, 다시 켰을 때 색 검증을 확인했다. `node --test tests/page-settings.test.js tests/page-grid.test.js` 32개 통과. 이 소규모 보완 후 전체 번들·브라우저 QA는 재실행하지 않았다.
- 목록 설정 추출 보완: 제목·크기·격자는 속지/요소 전체 변환과 분리한다. 기존 페이지의 속지 해석이 실패하면 로컬 속지를 유지하고 유효한 기본 설정과 목록 순서·추가·삭제를 반영한다. 잘못된 크기 쌍·색은 덮어쓰지 않는다. 신규 페이지 상세 검증과 목록의 ID·다이어리 일치·중복 검사는 유지한다.
- 목록 보완 검증: `node --test tests/page-settings.test.js tests/collaboration-hook.test.js tests/collaboration-open-document.test.js tests/collaboration-reducer.test.js tests/server-template-catalog.test.js` 76개 통과. 알 수 없는 기존 속지가 섞인 목록의 순서·신규 페이지 추가·삭제 복구·미전송 요소 보존을 실제 리듀서까지 확인했다. 이번 변경은 화면을 바꾸지 않으며 브라우저·실기기·전체 번들은 재실행하지 않았다.
- 단건 설정 조회·저장 응답도 속지 전체 해석과 분리했다. 알 수 없는 속지의 기존 페이지는 로컬 속지·필기를 유지하면서 이름·크기·격자를 불러오고 저장한다. 응답의 페이지 ID·다이어리 ID·양수 크기 검증과 신규 페이지의 엄격한 속지 해석은 유지한다.
- 단건 보완 후 위 5개 테스트 파일을 재실행해 79개 통과했다. 실제 편집기 훅의 설정 조회·저장과 리듀서 반영, 잘못된 응답 거절을 포함한다. 화면·백엔드는 변경하지 않았으며 이번 보완 후 브라우저·실기기·전체 번들은 재실행하지 않았다.
- 격자 응답 기본값 보완: 폼 초기화와 변경 비교는 동일한 정규화 함수를 사용해 누락·null·잘못된 격자 값을 끔·기본색 `#DCE5F1`로 처리한다. 무수정은 요청하지 않고 이름만 수정하면 이름만 전송한다. 이후 격자 켜기·색 변경은 저장 가능하며 사용자가 입력한 잘못된 색 검증은 유지한다. 위 5개 파일과 `tests/page-grid.test.js`를 실행해 86개 통과했다. 이번 보완 후 브라우저·실기기는 재실행하지 않았다.
