# 페이지 PNG 렌더러 (S15P31F106-71)

## 구현 범위

- 버튼을 누른 시점의 현재 페이지를 깊게 복사한다. 자동 저장이나 편집 화면 줌을 출력 입력으로 사용하지 않는다.
- 별도의 페이지 영역에 흰 종이·사진·스티커·테이프를 로컬 배열의 뒤→앞 순서대로 그린다. 숨김/완전 투명 요소는 제외한다.
- 편집 캔버스를 캡처하지 않는다. 선택 핸들·참여자 커서·보조 격자·툴바·패널은 전용 영역에 존재하지 않는다.
- 사진/스티커/테이프의 기존 시각 렌더러를 재사용한다. 세부 변형 일치와 필기·텍스트 지원은 72번에서 검증·확장한다. 알 수 없는 요소는 조용히 누락시키지 않고 중단한다.
- 상단 공유 아이콘의 접근성 이름을 ‘PNG 미리보기’로 지정하고 결과 확인 모달에 연결했다. 사진첩 저장과 OS 공유는 아직 연결하지 않았다.

## 출력 규격

- 현재 로컬 논리 크기 1188×840, 기본 배율 1로 실제 PNG도 1188×840이다. 화면 줌/DPR과 독립적이다.
- `createExportSnapshot(page, { width, height, scale })`에서 배율을 명시할 수 있다. 긴 변 4096px·총 800만 픽셀 상한 내에서 비율을 유지한다.
- 56번 계약 초안의 기본 2배 출력은 아직 확정하지 않는다. 이 구현은 71번의 논리 규격을 기본값으로 사용한다.
- 현재 편집기의 종이는 불투명 흰색이다. 실제 내지 템플릿 지원 시 배경 렌더러도 함께 연결해야 한다.

## 구성

| 구성 | 역할 |
|---|---|
| `createExportSnapshot` | 최신 페이지를 분리하고 크기·요소 검증 |
| `prepareExportSnapshot` | 원본 준비 중복 제거, 실패 롤백, 출력 자원 소유권 |
| `preparePageExport` | 로컬 미디어 ID·기본 asset·기존 src를 플랫폼 원본으로 해석 |
| `exportImage.web/native` | 원본 준비, HEIC 변환, GIF 임시 중단 |
| `PageExportPreview` | 전용 영역 마운트, 이미지 로드·레이아웃 후 캡처, 결과 미리보기 |
| `capturePage.web` | html-to-image로 전용 DOM 영역을 PNG Blob으로 생성 |
| `capturePage.native` | Expo 호환 view-shot으로 전용 View를 임시 PNG로 생성 |

리뷰 후 출력용 소재는 요소 크기·출력 배율·cover 배치·자르기 확대에 필요한 픽셀 수로 선택한다. 충분한 표시본이 있으면 활용하고 필요한 크기로 다시 줄인다. 부족하면 800만 화소 이내 원본을 사용하며, 더 큰 원본의 전체 디코딩은 명시적으로 중단한다. 160px poster는 사용하지 않는다. 출력용 임시 URL·변환 파일·결과 PNG만 정리하며 원본과 화면 공유 캐시는 삭제하지 않는다.

이미지 준비나 필수 요소 로딩이 실패하면 전체 생성을 중단한다. 30초 준비 제한은 현재 구현의 보호 장치이며 실기기 성능 측정 후 조정 가능하다. 닫힌 작업의 늦은 결과도 반환하지 않고 정리한다.

## 후속 범위와 제한

- GIF는 73번에서 원본의 첫 표시 프레임을 연결한다. 현재는 `EXPORT_GIF_PENDING`으로 명시 중단한다. 움직이는 기본 Noto asset도 같은 규칙이다.
- 필기 경로·부분 텍스트 스타일, 폰트 준비, 변형의 종합 일치 검증은 72번 범위다. `skipFonts`는 현재 지원하는 이미지/기본 소재 렌더링에 한정한 웹 설정이다.
- 문서·보관함 복원/누락 안내는 69·70번을 유지한다.
- 실제 iPhone/iPad·Android의 캡처 영역, 메모리, 앱 백그라운드 전환 검증이 필요하다. Android 번들 성공은 실기기 캡처 성공을 뜻하지 않는다.
- html-to-image의 SVG foreignObject 캡처는 브라우저별 제한이 있을 수 있다. 현재 확인한 것은 Windows Chromium이다.

## 검증

- 기존 미디어 테스트 25개 통과.
- `pnpm --dir frontend test:export`: 신규 6개 통과. 상태 분리/순서/숨김/규격, 원본 중복 준비와 해제, 실패 시 자원 정리와 문서 유지, GIF 명시 중단, 네이티브 캡처 IO 계약 검증.
- Web·Android Expo export 통과.
- 실제 브라우저에서 기본 소재·사진·HEIC 원본 변환·고해상도 원본이 있는 페이지를 1188×840 PNG로 생성했다. 이미지 결과를 시각 확인했다.
- 편집 줌 변경 전후 출력 PNG의 RGBA SHA-256이 동일함을 확인했다: `ab3c9d0efc37e791ca29dc2738331a98839faddb40330c881152aed7add11980`.
- 모서리 픽셀 RGBA는 255,255,255,255이고, 비백색 영역이 존재한다. 편집 도구·선택·패널이 출력되지 않는 것을 확인했다.
- GIF가 포함되면 첫 프레임 준비 중 안내 후 중단됨을 확인했다. 기존 문서에서 시험용으로 숨긴 GIF는 백업 일치 확인 후 복원했다.
- 별도 빨강/파랑 픽셀 문서를 브라우저 저장소에 덮어쓰는 추가 검증은 자동 승인 검토의 데이터 손실 우려로 실행하지 않았다. 배열 순서와 입력 보존은 단위 테스트로 검증했다.

## 71번 리뷰 후속 확인 (2026-10-20)

- 같은 이미지의 사용처가 여러 개면 가장 큰 픽셀 요구량에 맞춰 한 번 준비한다. 예: 8000×6000 원본을 260×195, crop zoom 2로 출력하면 520×390이 필요하므로 2048×1536 표시본이 충분하다.
- 충분한 표시본이 없고 원본이 800만 화소를 넘으면 EXPORT_RASTER_TOO_LARGE로 중단한다. 타일 디코딩 도입 전의 메모리 보호 정책이며, 모든 고해상도/자르기 조합의 출력을 보장하지 않는다. 메타데이터가 없는 이전 소재는 이 사전 크기 판단이 제한된다.
- 네이티브 data URI는 base64 이미지 형식을 검증해 캐시 파일로 변환하고 성공·실패 시 출력 작업에서 정리한다.
- GIF 중단 안내에는 이름/asset ID 등 해당 요소를 식별할 정보를 포함한다. 실제 첫 프레임 지원은 73번 범위다.
- pnpm@11.25.0을 packageManager로 명시했다. 기존 lockfile을 의미 없이 다시 생성하지 않는다.
- 미리보기 아이콘을 공유 모양에서 이미지 모양으로 바꿨다.
- 네이티브 렌더 영역은 실제 모달 가용 공간에 맞춰 줄이고 captureRef에는 요청한 최종 픽셀 규격을 전달한다. 화면 밖 View를 캡처하는 구조는 피했으며 결과의 기기별 품질·경계 검증은 필요하다.
- 사용자 저장소와 분리된 http://127.0.0.1:8091에서 원·하트 사진과 이미지 테이프를 출력했다. SVG onLoad가 완료되어 대기 오류 없이 1188×840 PNG가 생성됐다. 원/하트의 중심 RGBA는 36,104,206,255, 테이프는 63,122,212,255, 배경은 흰색이었다. 네이티브 이벤트 검증을 대신하지 않는다.
- 기존 미디어 25개 + 출력 10개 = 35개 테스트, Web/Android 번들 통과. 실제 네이티브 기기 검증은 여전히 남아 있다.
- 이 후속 수정은 71번 브랜치와 기존 MR !8의 추가 커밋으로 검토한다. 69번의 최신 develop 충돌 해결 이력도 함께 병합했다.
