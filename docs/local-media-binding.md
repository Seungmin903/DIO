# 로컬 이미지 조회 및 캔버스 연결 (S15P31F106-69)

## 범위

- 67·68의 로컬 저장 구현을 바탕으로 `mediaFileId`로 사진·GIF·사용자 스티커·테이프를 조회한다.
- `mediaFileId`가 기준이며, ID가 없는 기존 문서는 `src: media:ID` 또는 data URI를 계속 지원한다.
- 표시용 축소본이 있으면 화면에 사용한다. `mediaService.get`은 원본과 표시본을 구분해 반환하므로 원본 보존 계약은 유지된다.
- 위치·크기·회전·자르기·레이어 순서는 기존 요소 데이터와 렌더러를 유지한다. 조회 시 요소 JSON을 다시 작성하지 않는다.

## 조회 흐름

1. 저장된 문서와 사용자 보관함에서 필요한 ID를 수집한다.
2. ID별 조회 캐시가 동시 요청을 하나로 합친다. 한 파일의 실패는 다른 파일 복원을 막지 않는다.
3. 화면 컴포넌트는 조회 상태를 구독한다. ID만 있는 새 요소도 비동기 조회가 끝나면 다시 그려진다.
4. 웹 Object URL은 세션 캐시에 보관하며 페이지 JSON에는 저장하지 않는다. 중복으로 만들어진 URL은 해제한다.

`hydrateMedia(references)`는 `{ loaded, failures }`를 반환한다. 문서/보관함 참조를 전달하며, 참조가 없으면 조회하지 않는다. 사용하지 않는 무인자 전체 조회 경로는 제거했다. 실패한 ID는 다음 명시적 조회에서 재시도할 수 있다.

화면 훅은 ID별 레지스트리 항목을 안정적인 스냅샷으로 사용한다. 다른 ID가 로딩/완료되어 전역 알림이 와도 해당 항목이 같으면 React는 저장소 알림에 따른 재렌더링을 생략한다. 부모 컴포넌트 변경으로 인한 렌더링까지 차단하는 것은 아니다.

## 검증

- 미디어 테스트: 기존 17개와 리뷰 후 ID별 스냅샷 검증 1개, 총 18개 통과 (`node --test tests/media.test.js tests/native-media.test.js tests/media-binding.test.js`).
- 신규 검증: ID 우선순위, 참조 중복 제거, 동시 조회 병합, 실패 격리와 재시도, 실제 IndexedDB의 표시본 조회와 원본 보존, 새 세션에서 복원, 요소 JSON 유지.
- Web·Android Expo export 통과. Android Hermes는 샌드박스 임시 파일 접근 제한으로 동일 명령을 권한 제한 밖에서 재실행했다.
- 브라우저에서 사진/GIF 4개의 `src`를 제거한 뒤 새로고침해 ID만으로 복원 확인. GIF 128×128, HEIC 표시본 1280×854, 고해상도 사진 표시본 2048×1536 조회 및 콘솔 오류 없음.

## 남은 검증 및 후속 범위

- iPhone/iPad·Android 실기기에서 강제 종료 후 복원과 편집 상태 유지 확인이 필요하다.
- 네이티브에서는 poster를 생성하지 않아 still 썸네일의 GIF도 움직인다. 네이티브 정지 썸네일 생성과 실기기 성능 확인은 남은 항목이다.
- 누락 파일 안내·복구 UX와 캐시 수명/정리 정책은 후속 이슈에서 다룬다. 이번 구현은 실패한 파일을 빈 상태로 두고 나머지 복원을 계속한다.
- 페이지 PNG 내보내기 및 GIF 첫 프레임 추출은 후속 작업이다.
- 67·68의 MR !4 구현에 의존한다. 69 브랜치의 검토 시 해당 선행 변경을 함께 고려한다.
