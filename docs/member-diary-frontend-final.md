## 연결 계약

- 목록의 “모든 다이어리”(UI 내부 id `personal`)는 API `filter=all`로 요청한다. 공유는 `shared`, 즐겨찾기는 `all`과 `favorite=true`를 사용한다.
- 서버 결과 순서를 유지한다. 검색·정렬·필터 변경 시 cursor를 초기화하고 늦게 도착한 이전 응답은 반영하지 않는다. 다음 페이지 실패 시 기존 카드를 유지하며 같은 cursor로 재시도한다.
- 검색 기록은 계정별 키로 저장한다. 필터 밖의 캐시, 로컬 필기 문서, 비회원 자료를 지우지 않는다.
- 일괄 이동 API가 없어 기존 단일 DELETE를 제한된 동시성으로 호출한다. 성공한 ID는 재전송하지 않고 실패별 결과를 남긴다. 403 등 확정 거절은 자동 재시도하지 않으며, 401 이후 대기 중인 요청을 중단한다. 쓰기 성공 후 조회만 실패한 경우 조회만 재시도한다.
- 보관 안내는 서버의 삭제 시각 기준 30일 고정 계약을 따른다.

## 별도 범위

즐겨찾기 변경 API는 현재 계약에 없어 변경 버튼을 제공하지 않는다. 즐겨찾기 조회 필터는 연결했다. 원격 캔버스·페이지 편집 및 다른 기기의 편집 문서 다운로드는 별도 API 범위다. 계정별 로컬 편집 문서가 없으면 기존 오류 처리를 유지하고 빈 문서를 만들지 않는다. 공유/248 작업은 수정하지 않았다.

## 초기 자동 리뷰 조치

- 선택 권한: 기존 entry()가 permissions.canTrash를 canDelete로 매핑함을 확인했다. 공유 목록에서 권한 없는 항목을 전체 선택에서 제외하는 브라우저 검증을 추가했다.
- 캐시: 필터·페이지 밖 캐시는 계정별 편집 문서와 열린 탭을 위해 유지한다. 화면 목록은 library.items로 분리되어 캐시 항목을 다시 표시하지 않는다. 편집기 진입은 상세 GET으로 권한과 존재 여부를 확인한다. 캐시의 탭 제목은 다음 조회 전까지 오래된 값일 수 있다.
- 복귀 위치: 회원 모드는 조건에 맞는 서버 목록이 준비된 뒤 ID로 위치를 찾고, 현재 페이지에 없으면 첫 카드로 복귀한다. 공유 목록 편집기에서 전체 목록으로 복귀하는 회귀를 추가했다.
- 안내 버튼은 기존 secondaryText 스타일을 사용한다. 간격 12/8은 기존 회원 생성·휴지통 안내와 동일한 값이다.

최신 자동 리뷰의 응답 유실 일괄 이동/단일 복원 경합을 수정했다. 재확인할 일괄 작업이 남으면 단일 작업과 새 일괄 작업을 거부한다. 재확인하거나 안내를 명시적으로 닫으면 이후 작업이 가능하고, 닫은 작업은 재시도할 수 없다. 해당 회귀 테스트를 추가했다. 재시도 가능 여부는 store 스냅샷 한 곳에서 계산하며 QA 스크립트에 사전 준비와 브라우저 채널 옵션을 명시했다.
