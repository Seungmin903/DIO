# 신고·차단 프론트

공유 화면의 전체 참여자 보기·사용자 메뉴, 신고 작성·증빙·완료, 차단 확인·해제, 마이페이지의 차단 목록, 다이어리 진입 안내를 추가한다. 기존 공유 참여·열람·편집 권한은 변경하지 않는다.

## 현재 연결 상태

신고·차단 서버 API는 아직 없다. 실제 로그인 앱에서는 현재 공유 참여자를 표시하고 신고 양식을 작성할 수 있지만, 접수·차단·해제 버튼은 비활성화한다. 이전 참여자와 차단 목록은 준비 중으로 표시하며 빈 목록으로 위장하지 않는다. 새 API를 임의로 호출하거나 실제 계정을 로컬 저장만으로 차단하지 않는다.

## 미리보기

`frontend`에서 PowerShell:

```powershell
$env:EXPO_PUBLIC_DIARY_SOURCE = 'mock-safety'
pnpm web --port 8094
```

개발 모드 전용이다. 공유 화면의 실제 참여자 진입과 마이페이지를 사용하며 샘플 데이터·증빙 선택기를 주입한다. 계정 전환·서버 미연결·신고 실패도 재현할 수 있다. 실제 서비스·인증·신고 서버를 호출하지 않는다. 종료 후 `Remove-Item Env:EXPO_PUBLIC_DIARY_SOURCE`로 해제한다.

## 후속 서버 어댑터 계약

`SafetyProvider`는 세션마다 생성하는 `adapter`를 받는다. 실제 앱은 현재 미연결 어댑터이며, 서버 구현 후 인증 transport를 사용하는 어댑터를 주입해야 한다. `mode`는 실제 서버 `server`, 샘플 `preview`, 미연결 `unavailable`이다.

| 메서드 | 입력·반환 |
|---|---|
| `listParticipants(diaryId)` | 현재·이전 참여자 배열. `userId`, `nickname`, `role`, `participation: CURRENT/PAST`, `activeAccount`, `photoUri` 또는 `profilePhotoUrl`. 재참여는 현재 행 우선 |
| `listBlocks()` | 내 차단 계정 배열. `userId`, 계정 닉네임·사진, 서버 `blockedAt`. 페이지가 있으면 어댑터가 전체 목록을 모아 반환 |
| `block(userId)` | 서버가 확정한 계정 닉네임·사진·`blockedAt` 반환. 공유 별칭을 계정 이름으로 추정하지 않음 |
| `unblock(userId)` | 서버 해제 성공 후 resolve |
| `report(input)` | `targetUserId`, `diaryId`, 사유 코드, 설명, 증빙 `{uri,fileName,mimeType,size}`. 업로드 후 서버 접수 ID `reportId` 반환 |

신고자는 토큰으로 결정한다. 설명은 trim 후 필수·1,000자 이하, 사진은 PNG/JPEG 최대 5장·장당 10MB다. 실제 파일 형식·크기와 조회·업로드 권한은 서버에서도 검증한다. 신고 접수에는 서버 측 중복 방지 키/재조회 정책이 필요하며, 전송 결과 불명 상태를 해결한 후 접수 완료를 표시한다. 프론트는 연타를 잠그지만 네트워크 단절 후 중복 접수 방지는 서버 계약을 통해 완성한다.

과거 참여자 프로필·증빙 이미지 주소는 열람 권한이 적용된 표시용 소스여야 한다. 과거 참여 이력 조회는 현재 다이어리에 접근할 수 있는 사용자에게만 허용한다. 프론트는 탈퇴 계정 이름·사진을 숨긴다.

양방향 직접 초대 전송 및 기존 미수락 초대 수락 제한은 서버가 강제해야 한다. 일반 초대 링크로 참여할 때도 실제 초대자와 수락자 간 차단 관계를 검사한다. 제3자가 보낸 초대로 함께 참여하는 것은 허용하고 기존 공유 권한은 유지한다. 차단 해제 시 이전 초대를 자동 복구하지 않는다. 아직 이 서버 동작은 구현되지 않았다.

## 안내 저장

이 기기의 계정·다이어리별 저장소에 안내를 끈 차단 사용자 ID 집합만 저장한다. 새로운 차단 사용자가 현재 참여자가 되면 다시 안내한다. 이전 참여자는 경고에서 제외한다. 세션 변경 시 목록·신고 초안·진행 중 결과는 폐기한다. 차단 정보가 연결된 서버에서 조회에 실패하면 재시도를 안내하고 미확인 상태로 진입시키지 않는다. 서버가 아예 미연결인 현재 버전은 기존 다이어리 열기를 유지한다.

## 검증

`node --test tests/safety.test.js` 및 `node qa/safety-browser.cjs`. 브라우저 QA는 위 미리보기를 먼저 시작하고 `DIO_SAFETY_QA_URL`(기본 `http://localhost:8094`)을 지정한다. 폰 412×892·태블릿 1280×800에서 실제 화면 전환, 실패 시 입력 보존, 차단 목록 동기화, 경고 재표시·억제, 미연결 안내를 검증한다. 실기기 키보드·iOS 모달·사진 선택기는 별도 확인 대상이다.

2026-11-04 기준 원격 develop `12a84fea` 위에 신고·차단 변경만 통합했다. 최신 게스트 자동 진입·로그인 필요 기능 안내·모바일 하단 탭·설정 분리·앱 오류 복구 진입점은 유지한다. 추가 게스트 로그인 버튼이나 구버전 보관함 코드는 포함하지 않는다. 마이페이지의 회원 사용자 관리 행과 공유 화면·알림에서 열린 공유 상세의 진입을 연결한다.

검증: 신규 로직·인증 라우팅·프로필·게스트 공유 제한·프로필 내비게이션·홈 알림 회귀 총 116개 통과. 폰·태블릿 브라우저 시나리오는 `qa/safety-browser.cjs`로 검증하며 스크린샷은 `frontend/qa/.out/safety/`에 생성한다. 실기기 키보드·갤러리·iOS 모달은 별도 확인한다.

최신 develop 통합 검증: 신고·차단 미리보기는 폰 412×892·태블릿 1280×800에서 통과했다. `node qa/safety-base-browser.cjs`로 일반 앱의 게스트 자동 진입·보관함·폰 하단 탭 5개 유지도 확인했다. 일반 앱 웹 배포 번들(`expo export --platform web --output-dir .expo/safety-production-current`) 생성 통과. 실제 신고·차단·과거 참여 이력 서버와 실기기 조작은 미검증이다.
