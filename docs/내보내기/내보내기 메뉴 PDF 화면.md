# 공유 메뉴 및 PDF 생성 연결 (S15P31F106-111)

기준 develop: `3953f55`(!19 병합 후). 2026-10-20.

## 구현 범위

- 공유 버튼 → 현재 페이지 / 페이지 골라 / 페이지 범위 / 영역 선택 네 옵션을 제공한다. 현재 페이지는 PNG 기본/PDF 선택, 개별·범위는 PDF 고정이다.
- 개별 선택은 현재 페이지 ID로 시작하며 문서 순서대로 생성한다. 범위는 현재~현재로 시작하며 정수·양끝 포함·빈값·역전·문서 범위·페이지 목록/순서 변경 재확인을 처리한다.
- PDF의 20장/80MP 중 작은 한도를 UI와 조립기에서 검증한다. 현재 1280×800의 2배는 최대 19장이다. 전체 선택이 불가능해도 일부 선택은 허용한다.
- `createMenuPdfSnapshot` → 실제 `usePageImageRenderer` surface → `generatePdf`로 연결한다. 진행률은 completedPages/totalPages와 phase를 표시한다. 생성 중 중복 실행을 차단한다.
- 취소/실패/완료를 구분하며 중간 실패는 원래 문서 페이지 번호로 안내하고 부분 PDF를 내놓지 않는다. 같은 내용으로 다시 만들기는 최초 스냅샷·시각·파일명을 유지한다. 새 시도는 별도 렌더러 컴포넌트를 마운트한다.
- 완료된 PDF는 파일명·면 수·용량을 표시한다. 웹은 Blob URL로 PDF 미리보기를 제공한다. 네이티브는 결과 정보를 표시한다. 결과는 메뉴가 소유하고 닫기·재생성·페이지 재선택 시 dispose한다. 생성 완료와 OS 저장 완료는 구분한다.
- `PageImageSurface` 결과 diagnostics에 네이티브 표시 크기×PixelRatio와 요청 픽셀의 비교값을 추가했다. PDF 생성/결과 화면은 확대 시 화질 경고를 표시하되 차단하지 않는다. GPU 실측·실기기 품질 보증은 아니다. 페이지별 값은 결과 captureDiagnostics에 유지한다.
- 원본·로컬 저장 형식·IndexedDB·서버 API는 변경하지 않는다. PNG 내보내기 경로를 유지한다.

- EditorScreen의 선택적 `onRegionExport` 콜백으로 116·117번 영역 UI를 연결할 수 있다. 미연결 상태에서는 영역 옵션을 비활성화하고 준비 중으로 안내한다. 이 MR에 영역 조작·프리셋 구현을 포함하지 않는다.
- PDF 앱 저장·공유는 112번이다. 브라우저 PDF 뷰어 자체의 저장 기능은 앱의 저장 성공 판정과 다르다. 113번 실기기 화질/메모리·SVG/전체 소재 QA, 72번 텍스트/진행 중 입력 확정 경계가 남아 있다.
- 고해상도 원본의 기존 안전 상한은 유지한다. 알려진 제약을 이번 UI 연결로 해결했다고 간주하지 않는다.
