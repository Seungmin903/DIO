# 기기 내 스티커 시트 분리

관련 태스크: [S15P31F106-283](https://ssafy.atlassian.net/browse/S15P31F106-283), [S15P31F106-284](https://ssafy.atlassian.net/browse/S15P31F106-284), [S15P31F106-285](https://ssafy.atlassian.net/browse/S15P31F106-285). 화면 규칙은 [디자인 가이드](./디자인%20가이드.md)를 따른다. 실행별 결과·화면 자료·미검증 사항은 [MR !170](https://lab.ssafy.com/s15-final/S15P31F106/-/merge_requests/170)의 검증 절을 참고한다.

## 제공 범위와 파일 계약

- 외부 전송·AI 모델·모델 다운로드 없이 기기 내에서 처리한다. 단색 시트의 색상·연결성 기반 분리이며 의미상 객체를 인식하지 않는다.
- Expo Go·웹·모듈 없는 개발 앱·release는 기존 폴더 생성과 이미지 그대로 추가를 유지하고 자동 분리를 비활성화한다. Android의 확장 기능은 지원 capability를 갖춘 개발 앱에서 제공한다.
- iOS는 기존 최대 800만 화소 구현을 유지한다. Android의 디스크 분할 처리·거리 묶기·브러시·완전 포함 판정은 iOS에 제공하지 않는다. Swift 컴파일·실기기 동작은 별도 확인이 필요하다.

| 구분 | Android 자동 분리 계약 |
|---|---|
| 입력 | 정지 PNG, JPEG/JPG, 정지 WebP. 파일 서명과 컨테이너 구조를 검사하고 실제 형식에 맞는 캐시 확장자를 사용한다. |
| 미지원 | SVG, GIF, APNG, 애니메이션 WebP, HEIC 및 그 밖의 형식. SVG→PNG 변환은 제공하지 않는다. |
| 손상 검사 | 빈 파일·잘린 컨테이너·PNG CRC·WebP 길이/애니메이션 플래그·JPEG 종료 표식 및 미리보기 디코딩을 확인한다. 모든 손상을 헤더 검사만으로 발견한다고 보장하지 않는다. |
| 입력 제한 | 원본 3,200만 화소·압축 파일 50MiB. 크기는 원본 파일에서 확인한다. |
| 미리보기 | EXIF 회전·반사를 보정한 긴 변 최대 2,048px PNG. 분석에는 원본 해상도를 사용한다. |
| 출력 | 투명 PNG. 한 장 외곽 800만 화소·총 외곽 합계 3,200만 화소·포함 후보 최대 4,096개. |

일반 사진·스티커 그대로 추가의 지원 형식은 이 자동 분리 계약과 별개다.

## 화면 흐름

스티커 탭 → 사용자 폴더 선택(없으면 새 폴더 생성) → 폴더 안 `+` → 이미지 분리해서 추가 → 이미지 선택 → 영역 조정 → 분리하기 → 최종 묶음 검토 → 폴더 확인 → N개 저장. 기존 추가는 같은 메뉴의 ‘이미지 그대로 추가’를 사용한다.

- 큰 미리보기 → 영역·선택·묶기·배경 접이식 도구 → 가상화된 최종 묶음 목록 순서다. 한 도구만 펼치고, 처음에는 영역을 펼치며 분리 성공 후 모두 접는다. 패널을 접으면 기본 개별 선택으로 돌아가고 설정·결과는 유지한다.
- 이미지 이동·화면 맞춤은 미리보기 안, 실행 취소·다시 실행은 제목 옆에 둔다. 확대·축소는 두 손가락으로 한다. 조작 중 부모 스크롤을 차단한다.
- 하단 주요 버튼은 분리하기·다시 분리하기·이 영역 추가·N개 저장으로 전환한다. 폴더 입력/폴더명은 저장 버튼 바로 위다. 작은 회색 설명과 카드 해상도는 표시하지 않으며 필요한 글자는 14px 이상, 버튼 터치 영역은 최소 44px이다.
- 이미지·크기 측정이 준비될 때까지 영역 입력을 막는다. 이미지별 로딩 식별자로 늦은 응답을 무시하며 실패 시 재시도한다. 정상 축소된 로딩 이벤트를 원본 크기 불일치만으로 거부하지 않는다. 이미지 선택 취소·검사 실패는 현재 결과를 보존한다.

## 영역과 배경 판정

- 첫 드래그로 프레임을 만들고 내부 이동·8개 손잡이 조정으로 수정한다. 이미지 경계 안의 원본 좌표로 처리하며 손을 뗄 때 확정한다. 두 손가락 전환·입력 취소는 해당 조정을 되돌린다. 전체 영역으로 복원할 수 있다.
- 영역 변경 자체는 분석을 시작하지 않는다. 배경·영역 변경 후에는 재분리 전 저장을 막는다. 다른 영역 추가도 프레임을 확정하고 별도 버튼으로 실행한다.
- 원본 전체의 8방향 연결 객체를 먼저 판정하고, 선택 영역에 완전히 포함된 객체만 출력한다. 경계 접촉은 포함하고 일부가 넘어가면 객체 전체를 제외한다. 가로 또는 세로가 2px 이하인 객체는 제외한다. 정상 객체에 붙은 가는 선을 따로 제거하지 않는다.
- 자동 배경은 영역 중앙 60%의 7×7 표본(가중치 4)과 가장자리 24개 표본(가중치 1)으로 추정한다. 가장 지지받는 배경 연결 영역을 제거해 외부 여백과 테두리 안쪽 종이를 구분한다. 수동 지정은 지정 픽셀의 배경 연결 영역을 사용한다. 투명 배경을 우선하며 같은 흰색이라는 이유만으로 닫힌 캐릭터의 흰 몸을 모두 제거하지 않는다.
- 큰 프레임도 영역에 완전히 포함되면 후보로 남을 수 있다. 배경과 그림 색이 비슷하거나 그림이 화면 대부분을 차지하면 수동 배경 보정이 필요하다. 붙은 그림을 영역으로 잘라 나누는 기능은 아니다.

## 선택·묶기·최종 목록

- 거리 슬라이더는 사용 영역 짧은 변의 0~5%, 기본 0(묶지 않음)이다. 실제 불투명 픽셀 간 최단 거리로 판정하며 A–B와 B–C가 가까우면 셋을 묶는다. 확대 배율과 독립적이다.
- 브러시는 화면 굵기 8~80(기본 24)이며 실제 그림에 조금이라도 닿으면 원래 객체 전체를 추가·제외한다. 투명 여백은 제외하고 입력 지점 사이 선분도 검사한다. 손을 뗄 때 한 번 반영하며 취소·두 손가락 전환은 적용하지 않는다. 픽셀 마스크 편집 기능은 아니다.
- 거리 확정·브러시·선택·수동 묶기는 최근 30회 실행 취소/다시 실행을 제공한다. 원본 후보는 보존하며 제외 후 복구할 수 있다. 재분리는 선택·묶음·이력 초기화를 먼저 확인한다.
- 직접 묶기에서만 카드 탭을 임시 묶기 대상 선택으로 사용한다. 저장 대상과 별도 상태로 관리해 고른 묶음만 합치고 나머지 저장 대상을 보존한다.
- 최종 묶음 하나당 카드 하나다. 외곽 가로×세로 면적 내림차순, 동률은 분석 순서다. 미리보기 번호·카드·저장 순서를 일치시키며 객체 ID와 좌표는 바꾸지 않는다.
- 썸네일은 기존 PNG를 상대 위치대로 배치한다. 카드 탭은 전체 제외, 길게 누르기는 확대다. 제외 항목은 실행 취소·추가 브러시·모두 선택으로 복구한다.
- 더보기에는 모두 선택·모두 제외·작은 스티커 필터가 있다. 필터는 최종 외곽 면적 64px² 이하를 보여 주며 저장 선택은 변경하지 않는다.
- 거리 조회는 120ms debounce·취소·최신 요청 검사로 처리한다. 계산 중에는 마지막 확정 목록을 유지하고 조작·저장을 막는다. 완료 후 정렬과 번호를 함께 바꾼다.

## 실행·저장·오류와 호환성

- Android는 512×512 타일과 디스크 배열로 처리하며 픽셀·방문 표시·탐색 스택은 각각 2MiB LRU 캐시를 쓴다. 필요한 작업 공간은 원본 화소 수×16바이트+64MiB 이상이다. 작은 영역도 전체 객체 경계 확인을 위해 원본 전체를 탐색한다.
- 후보별 불투명 구간은 임시 파일에 보존한다. JS에는 객체 ID·경계·묶음만 전달하고 전체 픽셀 배열은 넘기지 않는다. 거리 관계는 현재 선택을 연결하는 최대 4,095개 링크로 반환한다.
- Android 작업 큐와 iOS 직렬 큐에서 처리한다. UUID별 임시 디렉터리를 쓰고 취소를 확인한다. 파일 정리는 읽기/쓰기 작업 종료 후 수행한다. 디코딩·한 장의 PNG 인코딩 중에는 취소 완료가 지연될 수 있다.
- PNG는 저장할 때만 상대 위치대로 합성한다. 크기·용량 초과나 합성·가져오기·폴더 저장 실패는 성공으로 닫지 않는다. 현재 구성을 유지하고 이번 시도에서 생성한 파일만 정리해 재시도한다.
- 기존 `mediaFileId`·`media:` 참조·보관함 저장 키를 유지하며 사용자 문서에 픽셀·기기 절대 경로를 넣지 않는다. 새 폴더 저장은 영구 저장 성공 후 반영한다.
- 일반 보관함 저장 실패는 현재 편집 내용을 유지하며 ‘다시 저장’으로 최신 내용을 재시도한다. 마지막 스티커 칩은 별도 `dio:editor:sticker-category:v1` 키에 순서대로 저장하며 보관함 전체를 다시 쓰지 않는다. 구형 보관함의 칩 값은 별도 설정이 없을 때 복원한다. 칩 설정 저장 실패는 보관함 내용 저장 오류로 표시하지 않으며 다음 선택 시 다시 시도한다.
- 저장 오류는 한국어 안내로 변환한다. 알려진 폴더 입력·미디어 오류는 안내를 유지하고 내부 코드·경로·cause는 화면에 표시하지 않는다. 원문은 개발 로그에서만 확인한다.
- 모듈 API 3과 별도 `selectionEditingVersion: 1`, `completeRegionVersion: 1` capability로 기능을 판정한다. 새 capability가 필요한 Android 앱은 업데이트 안내를 표시한다. JS Reload로 네이티브 모듈을 추가할 수는 없다.
- 서버 API·기존 다이어리 형식의 변경이나 데이터 마이그레이션은 없다. 기존 DIO와 서명/버전이 다른 개발 APK는 별도 패키지로 빌드해 원래 앱과 저장 공간을 분리해야 한다.

## 개발·검증 재현

Expo Go 팀원의 기존 실행 명령과 의존성을 유지한다. 네이티브 개발 앱은 Android SDK 또는 macOS/Xcode·서명 환경을 준비한 뒤 빌드한다.

```sh
cd frontend
pnpm install --frozen-lockfile
pnpm exec expo run:android
# iOS는 macOS에서 별도 검증
pnpm exec expo run:ios
pnpm exec expo start --dev-client
```

자동 검증은 frontend 기준 다음 명령을 사용한다.

```sh
node --test tests/sticker-split-region.test.js tests/sticker-split-groups.test.js tests/sticker-split-editing.test.js tests/sticker-split.test.js tests/tape-drawer.test.js tests/decor-save-notice.test.js tests/content-licenses.test.js
pnpm test:media
powershell -File qa/run-sticker-split-native.ps1
pnpm exec expo export --platform web
pnpm exec expo export --dev --platform android
pnpm exec expo export --dev --platform ios
```

- Kotlin fixture는 Gradle 캐시의 Kotlin 2.1.20 컴파일러를 사용한다. 거리·브러시·포함 영역·배경·최소 크기·파일 컨테이너를 확인하는 JVM 검사다. Android BitmapRegionDecoder·PNG 합성·Swift·실기기를 검증하지 않는다. 대형 탐색은 같은 스크립트의 `-Large` 옵션, 로컬 이미지 재현은 `-SheetImages @('이미지 경로') -ExpectSplit` 옵션을 쓴다.
- JS 테스트는 저장 실패/재시도·최신 요청·선택/묶기·상대 위치/순서·영역 입력·칩 복원과 설정 저장 분리를 확인한다. 번들 성공은 앱 전체 실행 성공을 의미하지 않는다.
- 실기기에서는 첫 이미지 표시·확대 좌표·브러시 추종·두 손가락 취소·고해상도 디코딩·영역/배경 재분리·거리와 실제 PNG의 일치·저장 후 재실행 복원을 별도로 확인한다. Expo Go의 기존 추가와 개발 앱의 자동 분리는 검증 결과를 구분한다.
- APK·생성된 android/ios·환경 파일·검증 로그는 저장소에 포함하지 않는다. 날짜별 실행 기록과 로컬 환경 정보는 MR 검증 기록에서 관리한다.
