관련 태스크: S15P31F106-283(로컬 모듈·환경 분기), S15P31F106-284(분리·보정 화면), S15P31F106-285(저장·검증). 서버 API와 모델 다운로드는 사용하지 않는다.

## 제공 범위

- Expo Go·웹·모듈 없는 예전 개발 빌드: 기존 빈 폴더 생성·이미지 그대로 추가·스티커 삽입을 유지한다. 자동 분리 버튼은 비활성화하고 개발 빌드 안내를 표시한다.
- Android/iOS 개발 빌드: `__DEV__`와 실제 `DioStickerSplit.apiVersion === 3`, 필요한 메서드 존재를 모두 확인한다. API 1·2 개발 APK는 업데이트해야 하며 버전 불일치는 버튼 아래에 안내한다. `EXPO_PUBLIC_DISABLE_STICKER_SPLIT=1`로 진입을 끌 수 있다. release에서는 자동 분리를 제공하지 않는다.
- 네이티브 모듈은 `frontend/modules/dio-sticker-split` 로컬 Expo 모듈로 자동 연결한다. JS 화면은 서비스만 호출한다. 플랫폼 기본 래스터 API를 사용하며 별도 OpenCV·AI 모델·추론 엔진은 설치하지 않는다.

## 사용 흐름

스티커 탭 → 새 폴더 이름 입력(또는 기존 사용자 폴더 선택) → 이미지에서 스티커 만들기 → 이미지 선택 → 필요 시 사용 영역 드래그 → 자동 분리 → 후보 검토 → 폴더 저장.

- 배경은 선택 영역 가장자리 색을 16단계 RGB 구간으로 집계해 가장 많은 구간의 평균색으로 추정한다. 투명 픽셀은 투표에서 제외한다. 그림이 가장자리를 대부분 차지하는 시트에서는 오판할 수 있다.
- 배경 직접 지정과 허용 범위는 접힌 ‘분리 결과 조정’에 둔다. 자동 추정으로 되돌릴 수 있다. 보정 후에는 다시 분리해야 저장할 수 있다.
- 사용 영역과 영역 직접 추가는 한 손가락 드래그로 지정한다. 두 손가락은 1~6배 확대·축소와 이동이며, 도중 두 번째 손가락이 닿으면 진행 중 자르기를 취소한다. 확대/축소·화면 맞춤 버튼과 한 손가락 이미지 이동 모드도 제공한다. 원본 좌표로 환산하며 이미지 조작 중 목록 스크롤을 차단한다.

- 정지 이미지 한 장, 최대 50MiB를 지원한다. Android 원본은 3,200만 화소, iOS는 기존 800만 화소까지다. Android는 압축 원본을 로컬 캐시로 복사하고 EXIF 회전·반사를 타일 좌표에 반영한다. 원본 전체를 PNG로 다시 펼치지 않는다. iOS는 방향을 보정한 임시 PNG에서 처리한다. GIF는 기존 이미지 추가 기능을 사용한다.
- Android는 `BitmapRegionDecoder`로 512×512 타일을 순차 읽고 선택 영역만 디스크 픽셀 배열에 쓴다. 픽셀·방문 표시·탐색 스택은 각각 2MiB LRU 캐시를 사용한다. 행 단위 깊이 우선 탐색으로 디스크 접근을 모으며 전체 선택 영역의 연결성을 유지하므로 타일 경계에서 후보가 분리되지 않는다. 임시 배열은 성공·실패·취소 시 닫고 삭제한다.
- 결과 한 스티커의 외곽 사각형은 800만 화소, 결과 외곽 사각형 면적 합계는 3,200만 화소까지다. PNG 저장 시점의 메모리도 제한하기 위한 별도 한도다. 임시 저장소 여유 공간은 선택 화소 수×16바이트+64MiB 이상인지 먼저 확인한다. 공간 부족 시 성공으로 일부만 저장하지 않는다. Android에서 영역 디코딩이 불가능한 형식은 명시적으로 실패하며 전체 이미지 디코딩으로 우회하지 않는다.
- 채널별 색 거리로 배경 후보를 찾고, 자른 영역 가장자리에서 연결된 배경만 flood fill로 지운다. 나머지 불투명 픽셀을 8방향 연결 영역으로 나눈다. 닫힌 외곽선 안의 흰 몸·흰 테두리를 보존한다.
- 한 픽셀의 별·점도 영역 크기로 버리지 않는다. 후보가 4,096개를 넘으면 일부만 저장하지 않고 전체 작업을 실패시켜 영역·허용 범위 조정을 안내한다.
- 후보는 투명 PNG로 만들어 체크무늬에서 확인한다. 목록은 가상화한다. 후보를 눌러 선택/제외하고 길게 누르면 확대한다. 64픽셀 이하 후보 필터는 선택 자체를 변경하지 않는다.
- 여러 후보를 합쳐 원본 위치 관계를 보존할 수 있다. 붙은 그림은 원래 후보를 제외한 뒤 각 부분을 ‘영역 직접 추가’ 드래그로 다시 지정한다. 이는 사각 영역 보정이며 브러시 마스크 편집은 제공하지 않는다.
- 배경·자르기·허용 범위가 바뀌면 이전 결과 저장을 막고 재분리를 요구한다. 단색 시트 전용 알고리즘으로 의미상 객체를 판단하지 않는다. 흐릿한 외곽선, 붙은 그림, 내부 빈 구멍, JPEG 흔적은 수동 확인이 필요하다. 원본의 흰 칼선 전체를 항상 복원한다고 보장하지 않는다.

## 실행·자원 처리

- Android AsyncFunction 작업 큐와 iOS 전용 직렬 DispatchQueue에서 디코딩·픽셀 분석·PNG 기록을 실행한다. JS에는 파일 URI·크기·경계·면적만 반환한다. 픽셀 배열은 브리지를 건너지 않는다.
- 작업마다 UUID와 앱 캐시의 전용 디렉터리를 사용한다. 취소 플래그는 flood fill과 요소 탐색 중 확인한다. 디코딩과 한 장의 PNG 인코딩은 끝날 때까지 잠시 기다릴 수 있다.
- 임시 파일 정리는 해당 네이티브 작업이 끝난 뒤 수행해 기록 중인 파일과 충돌하지 않는다. 모달 종료 시 작업 디렉터리와 준비 이미지를 제거한다. 비정상 앱 종료 때 남은 파일은 OS 캐시 정리 대상이다.
- 결과를 기존 `importMedia`로 순차 가져오고 `mediaFileId`·`src: media:...`·이름·비율로 보관한다. 마스크·기기 절대 경로를 사용자 폴더 데이터에 추가하지 않는다. 기존 저장 키를 유지한다.
- 폴더 목록 쓰기는 직렬화한다. 새 목록을 영구 저장한 뒤 화면에 반영하며 실패하면 이번 호출이 가져온 결과 파일만 정리한다. 파일 가져오기 중간 실패도 기존 importer의 롤백을 사용한다. 원본 보관함과 기존 문서는 삭제하지 않는다.

## 개발 빌드

Expo Go 팀원의 `pnpm start`·`pnpm android`·`pnpm ios` 명령은 유지한다. 새 모듈을 쓰는 개발자는 먼저 네이티브 앱을 새로 빌드한다. JS 새로고침만으로 기존 Expo Go에 모듈이 생기지는 않는다.

```sh
cd frontend
pnpm install --frozen-lockfile
pnpm exec expo run:android
# iOS는 macOS/Xcode와 적절한 서명 환경에서 실행
pnpm exec expo run:ios
# 모듈을 포함한 개발 앱 설치 후
pnpm exec expo start --dev-client
```

Expo prebuild가 기존 package.json의 android/ios 스크립트를 run 명령으로 바꾸면 팀용 start 명령을 유지하도록 확인한다. 생성된 android/ios 프로젝트와 .expo 검증 산출물은 커밋하지 않는다.

## 검증 기록

- API 3: 드래그는 전용 입력층의 시작 위치와 page 좌표 이동량을 사용한다. move/release의 location 좌표가 달라지는 상황과 두 번째 손가락 진입 시 자르기 취소를 실제 미리보기 컴포넌트 이벤트로 검증했다.
- Android 분할 처리: 디스크 페이지 교체·512px 경계를 가로지르는 객체·EXIF 8방향 좌표·배경/전경 연결 규칙을 검증한다. 9,006,001화소에서 단일 점을 보존하는 디스크 탐색을 `-Xmx96m` JVM으로 완료했다(스캔라인 버전 1,064ms). 이는 Windows JVM의 픽셀 탐색 측정으로, Android 디코딩·PNG 인코딩·실기기 속도를 의미하지 않는다. 재실행은 `powershell -File qa/run-sticker-split-native.ps1 -Large`다.
- 최종 API 3 검증: 관련 JS 테스트 35개, Kotlin fixture 13개(무작위 80개 이미지의 독립 BFS 판정 비교 포함) 통과. Android Hermes export·개발 APK 빌드 성공. `.expo/builds/DIO-sticker-split-v3-development-arm64.apk` SHA256은 `B3FCE2EF7195D9E28A739252DADCE902574BB89F3EF299F3ECFE83B99298793D`다. 실기기 드래그·대형 이미지 디코딩·취소·PNG 저장은 미검증이며 iOS 분할 처리는 아직 제공하지 않는다.

- 자동 배경·확대 좌표 변경: 관련 JS 테스트 33개, 실제 Kotlin 알고리즘 픽셀 fixture 10개 통과. Swift 소스는 Windows에서 컴파일하지 못했고, 핀치·드래그·스크롤 차단의 실기기 확인은 수행하지 않았다. 800만 화소 제한과 이미지 저장 실패의 원인은 이번 변경에서 해결한 것으로 간주하지 않는다.
- 위 변경의 Android Hermes export와 API 2 모듈 포함 ARM64 개발 APK 빌드 성공. 산출물은 `.expo/builds/DIO-sticker-split-v2-development-arm64.apk`이며 사용자 설치·확인용이다. APK는 기존 개발 앱과 같은 패키지·디버그 서명을 사용하며 에이전트는 설치·실행하지 않았다.

- 사용자 실기기 확인에서 자동 분리 진입 버튼의 흰 글자가 흰 패널 위에 표시되는 문제를 발견했다. 기존 주요 버튼의 `primary` 배경을 적용해 글자와 버튼 영역이 보이도록 수정했다. 이 표시 수정의 실기기 재확인은 사용자가 진행한다.

- SDK 58의 `FileHandle.readBytes`는 비동기이므로 미디어 가져오기·복원, 캡처 검증, 내보내기 이미지 판별, PNG/PDF 저장에서 읽기가 끝난 뒤 핸들을 닫도록 수정했다. 미디어 테스트도 지연되는 비동기 읽기를 모사해 조기 닫힘과 읽기 실패 시 자원 정리를 확인한다.
- 위 수정 후 미디어·스티커 분리·캡처·PDF/PNG 저장·GIF 첫 프레임 관련 자동 테스트 61개 통과. 실제 기기에서의 재시도는 사용자가 진행하며, 이 JavaScript 수정에는 APK 재설치가 필요하지 않다.

- 잠금 파일 기준 의존성 설치 성공. 새로운 JS/네이티브 외부 라이브러리와 lockfile 변경 없음.
- `node --test tests/sticker-split.test.js tests/media.test.js tests/native-media.test.js tests/media-recovery.test.js`: 신규 11개·기존 미디어 20개, 총 31개 통과. 모듈 없는 Expo Go 서비스 로드·호출 차단, 좌표/입력 검증, 결과 저장·실패 롤백·폴더 재진입 복원을 포함한다.
- Kotlin/JVM으로 `tests/native/StickerSegmentationFixture.kt`와 실제 Android 브리지가 호출하는 `StickerSegmentation.segment`를 함께 컴파일해 8개 픽셀 fixture를 통과했다. 한 픽셀·낮은 알파 점, 흰 내부, 대각 연결, 투명 마스크, 배경 잡음, 취소, 후보 초과를 확인한다. 단순 JS 모사 결과가 아니다.
- Windows 재실행: `powershell -File qa/run-sticker-split-native.ps1` (frontend 기준, Gradle 캐시에 Kotlin 2.1.20 컴파일러 필요). 픽셀 테스트이며 Bitmap/Swift·실기기 처리를 검증하지 않는다.
- 웹·Android Hermes JS export 성공. 이는 앱 화면·실기기 실행 검증을 대신하지 않는다.
