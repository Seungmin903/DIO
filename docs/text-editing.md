# 텍스트 생성·한글 입력·재편집 (S15P31F106-91)

- Jira 완료 기준: 텍스트 생성, 한글 조합·줄바꿈·삭제, 기존 텍스트 재편집 결과 유지.
- 텍스트 도구 선택 후 캔버스에서 드래그해 폭을 정하면 캔버스 안에 입력 상자를 연다. 별도 모달 없이 기기 키보드로 직접 입력하며 별도의 임시 서식 바는 표시하지 않는다. 입력 완료는 Enter 또는 기기 키보드 완료를 사용한다. T 도구로 기존 텍스트를 누르거나 선택 도구에서 선택한 텍스트를 다시 누르면 같은 자리에서 재편집한다. 잠긴 요소와 읽기 모드는 편집하지 않는다.
- TextInput은 `defaultValue`로 시작하고 입력 중 문자열은 ref에 보관한다. 한글 조합 중 controlled value 재주입·문자열 정규화·문서 갱신을 하지 않는다. 웹에서는 조합 중 완료 처리를 막는다.
- 완료 시 한 번 추가/수정해 Undo/Redo 한 단계로 기록한다. 취소는 문서를 변경하지 않는다. 신규 공백 입력은 추가하지 않고 기존 내용을 모두 지워 완료하면 해당 요소를 삭제한다.
- 저장은 `type: text`, `text`, `baseWidth`, `color`와 기존 위치·크기·회전 필드를 사용한다. 줄바꿈은 완료 시 LF로 통일하고 공백·한글·자모는 보존한다. 서버 API 변경과 기존 데이터 마이그레이션은 없다.
- 초기 너비 320, 기본 시스템 글꼴 28, 줄 높이 38이다. 내용에 따라 높이를 확보하며 선택·이동·크기 변경·복제·저장은 기존 구조를 사용한다. 폰트·부분 문자열 색상 설정은 이번 태스크 범위가 아니다.
- 공통 ObjectContent에 텍스트 표시를 연결해 캔버스·썸네일·출력이 같은 문자열을 사용한다. 출력 스냅샷에서 문자열과 기준 너비를 검증한다. 플랫폼별 글꼴/줄바꿈·네이티브 캡처 품질은 별도 실기기 확인이 필요하다.

## 검증

- `node --test tests/text.test.js tests/highlighter.test.js tests/pen-settings.test.js tests/strokes.test.js tests/page-export.test.js`: 24개 통과.
- 한글·자모·이모지·빈 줄·재편집 문자열과 출력 스냅샷 보존을 검증했다. 자동 테스트는 실제 IME 조합 검증을 대신하지 않는다.
- Android 에뮬레이터의 한글 조합·줄바꿈·삭제·완료·취소·재편집과 Undo/Redo는 실제 입력으로 확인해야 한다. 실기기·스타일러스·iOS는 미검증이다.

- 목업과 다른 별도 입력 모달과 재편집 버튼을 제거했다. 전체 서식 설정 팝오버(폰트·굵게·정렬·부분 색상)는 아직 구현하지 않았다. Android 번들 생성 성공이며 변경 후 실제 한글 입력과 키보드 가림 여부는 재확인이 필요하다.

- 생성은 클릭 고정 너비 대신 드래그한 폭(최소 논리 40)으로 시작한다. 역방향 드래그도 지원한다. 웹 입력 중 Ctrl/Cmd+A는 입력창 문자열 전체 선택이며 캔버스 단축키로 전달하지 않는다. Android는 기본 TextInput의 전체 선택을 따른다. Enter 완료는 최종 종료 문자열로 저장하도록 보완했으며 실제 IME에서 재확인해야 한다. 웹 Shift+Enter는 줄바꿈이며 네이티브 Shift 수정키 조합은 아직 검증하지 않았다.

- 사용자 요청으로 임시 현재 서식·취소·완료 바를 제거했다. 설정 팝오버를 대체하는 표시 전용 컨트롤은 제공하지 않는다.

## 최종 입력 동작 변경

- 사용자 결정: Enter/Shift+Enter는 일반 줄바꿈이다. Enter 완료 정책은 폐기한다. 텍스트 상자 밖을 누르면 포커스를 종료하고 onEndEditing의 최종 문자열을 한 번 저장한다. 첫 바깥 터치는 편집 완료에만 사용한다. Escape는 취소한다. 화면 키보드는 포커스 시 표시를 요청하고 편집 종료 시 닫는다. 물리 키보드가 있으면 OS의 가상 키보드 표시 설정을 따른다.
