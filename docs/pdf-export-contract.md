# PDF 내보내기 계약 (108)

> 기준일: 2026-10-21 · 구현 대조: develop `f68044a`(!39·!42·!43 포함).
> 현재 로컬 구현의 계약이다. 서버 API의 속지 규격 전환과 실기기 QA 완료를 뜻하지 않는다.

## 1. 범위와 기준 문서

MVP1 로컬 문서를 이미지 기반 PDF 한 파일로 내보낸다. 공통 이미지 저장·조회·페이지 규격·출력 소재·폰트·배경·실패·자원 정책의 단일 기준은 [56번 계약](./mvp1-media-export-contract.md)이다. 이 문서는 PDF 전용 페이지 선택·면 구성·문서 한도·압축·메타데이터·저장만 정의한다.

- 페이지/API 기준 크기는 적용된 속지의 규격·해상도를 따른다. 현재 새 속지는 1024×768이며 이것을 서비스 전체의 고정값으로 삼지 않는다. 실제 서버 구현과 다른 부분은 [56번 2절](./mvp1-media-export-contract.md#2-속지-기준-규격과-출력-해상도)에 기록한다.
- PNG는 별도 현재 페이지/영역 출력이다. 기존 PNG 기본 1배 동작을 PDF 기본 배율로 바꾸지 않는다.
- 공유 메뉴의 네 진입점 정의는 이 문서 10절 한 곳에서 관리한다. 영역 조작·프리셋은 [115](./region-png-export-contract.md)가 기준이다.
- 검색/선택 가능한 텍스트, 벡터 필기, PDF 가져오기·암호화·움직이는 PDF, 사용자용 JPEG·ZIP 출력·서버 보관은 범위 밖이다.

## 2. PDF 기본값과 한도

| 항목 | 현재 계약 |
|---|---|
| 범위 | 현재 페이지 / 개별 선택 / 연속 범위. 전체는 개별 선택 화면의 전체 선택 |
| 순서·면 | 확정 시 문서 배열 순서, 빈 페이지 포함, 페이지 한 장당 PDF 한 면. 실제 문서 페이지인 표지만 포함 |
| 페이지 기준 크기 | 해당 페이지의 속지 기준 `canvasWidth`/`canvasHeight`. 혼합 크기도 페이지별 해석 |
| 삽입 이미지 | 기본 2배. 픽셀 제한과 비율 유지 산식은 [56번 2절](./mvp1-media-export-contract.md#2-속지-기준-규격과-출력-해상도) |
| PDF 물리 용지 | A4 가로 297×210mm(약 841.89×595.28pt), 비율 유지 contain·중앙 정렬. 늘이기·자동 자르기·두 쪽 합치기 없음 |
| 배경·요소·GIF | [56번 공통 렌더링](./mvp1-media-export-contract.md#4-공통-렌더링과-소재-정책). 실제 SVG 속지를 포함하고 편집 보조 UI는 제외 |
| 문서 한도 | 최대 20면, 모든 면의 출력 픽셀 합계 80,000,000px, 삽입용 인코딩 이미지 누적 바이트와 최종 PDF 각각 50MiB 이하 |
| 시간 | 페이지 작업 제한은 공통 계약의 30초, PDF 전체 180초. OS 저장/공유 대기는 제외 |

현재 1024×768 속지를 2배로 출력하면 한 면 2048×1536 = 3,145,728px이며 20면은 62,914,560px다. 같은 크기의 현재 속지는 개수 상한 20면이 먼저 적용된다. 1280×800은 이전 규격의 **예시**로만 보면 2배 20면이 81,920,000px라 80MP를 넘는다. 고정적으로 20면을 항상 허용하거나 API 규격을 이 예시에 맞추지 않는다.

사전 검사는 개수·출력 픽셀 합계를 확인한다. 현재 UI의 전체 선택 정책은 가장 큰 페이지의 픽셀 비용을 사용해 보수적으로 최대 선택 수를 산정하므로 혼합 규격에서는 실제 합산보다 적게 허용할 수 있다. 조립 시 삽입용 인코딩 누적 바이트, 직렬화 후 최종 PDF 바이트를 검사한다. 중간 PNG의 누적 생성량은 바이트 예산에 합산하지 않는다. 상한 초과 시 자동 저해상도·부분 저장 대신 문서 분할/선택 축소를 안내한다.

1MiB는 1,048,576바이트다. 순차 생성이라도 조립기와 직렬화 버퍼는 누적되므로 50MiB를 메모리 상한으로 설명하지 않는다. 초기 보호값이며 실기기 성능을 보장하지 않는다.

### 물리 크기와 이미지 밀도

속지의 논리 크기/종횡비가 렌더링의 원본 기준이고, A4는 현재 PDF의 별도 물리 배치 정책이다. API를 속지 기준으로 맞추는 것이 PDF를 임의로 1024×768pt 용지로 만들라는 뜻은 아니다. `min(pdfWidthPt / pageWidth, pdfHeightPt / pageHeight)`로 페이지 전체를 배치하고 남는 영역은 흰색으로 채운다. 현재 4:3 속지는 A4와 비율이 달라 여백이 생긴다.

출력 배율은 삽입 이미지의 픽셀 밀도만 바꾼다. A4와 거의 같은 1188:840 비율을 전제로 하지 않으며 고정 203dpi·300dpi 인쇄 품질도 보장하지 않는다. 낮은 소재 해상도·네이티브 축소 캡처의 경고는 공통 정책을 따른다.

## 3. 입력과 스냅샷

실제 로컬 함수 경계([pdfSnapshot.js](../frontend/src/editor/utils/pdfSnapshot.js)):

```js
createPdfExportSnapshot(doc, {
  scope: 'pages', // 'current' | 'pages' | 'range'
  currentPageId,
  selectedPageIds, // pages: 중복 없는 존재하는 ID 목록
  range: { start: 2, end: 6 }, // range: 문서 내 1부터, 양끝 포함
  width, height, // 현재 함수의 필수 호환 인자; 호출자는 현재 페이지의 속지 기준 크기를 전달
  title,
  now,
})
// -> { scope, title, createdAt, fileName, pages: [
//      { pageId, width, height, pixelWidth, pixelHeight,
//        background, template, objects, documentPageNumber }
//    ] }
```

- 현재 함수는 width/height를 필수 검증하되 각 페이지의 저장된 canvasWidth/canvasHeight를 우선하고 없는 값만 전달 크기로 보완한다. UI는 pageSize로 기존 페이지 호환값까지 먼저 채운다. 동일 width/height를 모든 페이지에 강제하지 않는다.
- 입력 확정 경계는 [56번 4절](./mvp1-media-export-contract.md#4-공통-렌더링과-소재-정책)이다. 자동 입력 확정 API가 별도로 있다고 가정하지 않는다.
- current는 존재하는 현재 ID 한 개, pages는 비어 있지 않은 중복 없는 유효 ID, range는 문서 안의 양의 정수 start/end와 start<=end를 요구한다. 문서 ID 중복·빈 문서·잘못된 규격은 실패다.
- 확정 시 대상·문서 순서·문서 페이지 번호·내용·제목·속지 크기·시각을 복사한다. 이후 저장소/편집 상태 변경으로 스냅샷을 바꾸지 않는다. 재생성은 같은 스냅샷, 최신 내용은 닫고 새 진입이다.
- 원본은 현재 GC 없는 저장 구조에서 유지하며 출력용 참조는 작업 소유다. 향후 원본 GC 도입 시 별도 보호 계약이 필요하다.

## 4. 순차 생성과 자원 수명

```text
공유 → 방식/페이지 선택 → PDF 확정·사전 검사
→ [소재/속지 준비 → 공통 surface/폰트/로드 대기 → PNG 캡처
   → 불투명 RGB 인코딩 → PDF 면 삽입 → 현재 페이지 임시 자원 해제] × N
→ 직렬화·최종 용량 확인 → 미리보기 → 저장/공유
```

```js
renderPageImage(pageSnapshot, { signal })
// -> { uri, blob?, width, height, diagnostics, dispose() }
generatePdf(snapshot, { renderPageImage, signal, onProgress })
// -> { uri, blob?, byteLength, pageCount, fileName, mimeType, dispose() }
savePdfFile(result)
// -> saved | download-started | share-finished | cancelled 를 status로 반환
```

- renderPageImage는 공통 계약과 [109 구현](./page-image-renderer.md)을 따른다. 별도 요소 렌더러나 편집 화면 스크린샷을 만들지 않는다.
- 한 면 삽입 완료 후 다음 페이지를 준비한다. 페이지 이미지/준비 자원, 최종 PDF, 공유 사본의 소유자를 구분한다. 성공·실패·취소·닫기에서 작업 소유 자원만 정리한다.
- 취소 불가능한 늦은 캡처/조립 결과는 현재 UI에 게시하지 않고 정리한다. 반환 결과는 호출자가 사용 후 dispose한다.

### 내부 이미지 인코딩

공통 캡처는 PNG다. PDF 삽입 전 흰색에 합성한 **알파 없는 RGB PNG**를 사용하고 `/SMask`를 만들지 않는다. 현재 구현은 무손실 경로이며 이를 JPEG로 이미 구현했다고 설명하지 않는다.

PDF 내부 JPEG 압축은 향후 허용 가능한 최적화다. 사용자 JPEG 파일 출력 기능과 다르며 품질/용량 비교 검증 전에는 조용히 전환하지 않는다. 한도 초과 시 자동 품질 저하로 통과시키지 않는다.

## 5. 상태·실패·재시도

```text
idle → preparing → rendering(i/N) → assembling → ready → saving
생성 실패/취소 → 같은 스냅샷으로 다시 만들기
저장 실패/취소 → 유효한 PDF 유지 → 다시 저장
저장 결과 → saved / download-started / share-finished / cancelled
```

중복 시작/저장을 막고 OS 작업 중 앱 내 닫기를 제한한다. 페이지 하나라도 감지된 필수 준비·폰트·캡처·조립 오류가 있으면 부분 PDF를 저장하지 않는다. 공통 오류에 감지 가능한 `phase`/`documentPageNumber`를 덧붙이며 사용자에게 내부 경로/스택을 노출하지 않는다. html-to-image의 조용한 누락 가능성은 공통 한계로 남는다.

PDF 전용 코드: EXPORT_PDF_INPUT_INVALID, EXPORT_PDF_LIMIT_EXCEEDED, EXPORT_PDF_TIMEOUT, EXPORT_PDF_ASSEMBLY_FAILED, EXPORT_PDF_SAVE_FAILED, EXPORT_PDF_SHARE_UNAVAILABLE. 공통 오류/GIF/폰트/래스터 제한의 원인 코드는 유지한다. 취소는 `EXPORT_CANCELLED`로 전달될 수 있으나 UI에서 실패·저장 성공과 구분한다. 모든 오류를 공간 부족으로 추정하지 않는다.

## 6. 파일명·저장·메타데이터

| 페이지 모드 | 파일명 접미사 예시 |
|---|---|
| current | `_p01_<시각>.pdf` |
| pages 전체 | `_all_<시각>.pdf` |
| pages 일부 | `_selected03_<시각>.pdf` (03은 개수) |
| range | `_p02-p06_<시각>.pdf` |

공통 접두사 `DIO_<제목>`, 제목 정규화·현지 시각은 [56번 5절](./mvp1-media-export-contract.md#5-작업실패저장-수명)을 따른다. 문서 내 페이지 번호를 최소 두 자리로 표기하고, 확정 시 파일명을 고정해 재시도에서 유지한다. OS는 최종 이름을 변경할 수 있다.

- 웹: ready Blob을 저장 클릭의 첫 await 전에 picker에 연결한다. write/close 완료는 saved, picker 취소는 cancelled, fallback은 download-started다. 다운로드 URL은 독립 소유하고 60초 후 정리한다.
- 모바일: expo-sharing의 **PDF 파일 저장·공유**, MIME application/pdf, UTI com.adobe.pdf. 사진첩 권한/PNG 사진첩 API를 사용하지 않는다.
- 공유 반환만으로 최종 저장 성공을 표시하지 않는다. 확인 가능한 AbortError만 cancelled, 일반 반환은 share-finished로 “공유 창을 닫았어요. 선택한 앱에서 결과를 확인해 주세요”를 안내한다.
- 원본 결과와 독립한 전용 공유 사본을 만들고 활성 파일을 보호한다. 정상 반환/예외 뒤 24시간 lease를 갱신하며, 앱 시작/다음 공유 때 만료된 사본만 정리한다. 종료 중 크래시가 나면 생성 시 기록된 lease를 사용한다. lease 누락/손상은 임의 삭제하지 않으므로 정확한 시간의 전수 삭제를 보장하지 않는다. 원본/PNG 캐시와 분리한다([112](./pdf-file-save.md)).

메타데이터: Title은 스냅샷 제목, 빈 제목은 대체값. Author/Subject/Keywords는 비우고 Creator/Producer는 DIO. 생성/수정 시각은 스냅샷의 같은 실제 시각(UTC 또는 동등한 오프셋)이다. 현지 시각 숫자를 UTC로 오인하지 않는다. 계정·기기·위치·EXIF를 복사하지 않는다.

## 7. 구현·검증 경계

공통화(109), PDF 조립(110), 메뉴(111), 저장/공유(112), 필기/텍스트·고해상도 대체(72·122)는 develop에 반영됐다. 과거의 미구현 제안 함수·기본 stroke만 지원한다는 설명은 이 문서에서 제거했다.

웹 검증과 물리 기기의 검증을 구분한다([113 QA](./pdf-export-qa.md)). 현재/개별 1·3·5/범위 2~6/전체·면 순서·A4/RGB/메타데이터·부분 색상·필기·GIF·취소·재시도·중간 실패·한도는 웹 증거가 있다. 실제 JPEG/HEIC·모바일 파일 저장/공유/캐시·네이티브 2배 캡처·19~20면 성능/메모리는 남은 검증이다. 문서 정리를 실기기 QA 완료로 처리하지 않는다.

## 10. 공유 버튼의 네 가지 내보내기 옵션

이 표가 메뉴 정의의 단일 기준이다. 공통·영역 문서에서는 링크로 참조한다.

| 공유 메뉴 | 대상 선택 | 형식 |
|---|---|---|
| 현재 페이지 내보내기 | 현재 페이지 확인 | PNG(기본) / PDF |
| 페이지 골라 내보내기 | 체크박스·전체 선택/해제 | PDF 한 파일 |
| 페이지 범위 내보내기 | 시작/끝, 양끝 포함 | PDF 한 파일 |
| 영역 선택 내보내기 | 현재 페이지 직사각형·비율 조절 | PNG 한 장 |

- 공유 → 방식 → 대상 → 형식 → 미리보기·저장. 형식이 하나면 고정 형식으로 안내한다. 메뉴 클릭 자체가 OS 공유가 아니다. 여러 PNG/ZIP은 추가하지 않는다.
- 개별 선택은 현재 페이지만 체크해 시작하고 한 장만 선택해도 PDF다. 새 진입에 이전 선택을 자동 복원하지 않는다. 체크 순서와 무관하게 문서 순서로 출력한다.
- 범위는 현재~현재로 초기화하고 문서 내 1부터 시작하는 정수만 허용한다. 빈값·소수·역전·범위 초과는 차단하며 자동 뒤집기/잘라내기를 하지 않는다.
- 선택 수·현재 최대값/픽셀 상한을 표시한다. 개수·픽셀 한도를 넘는 전체 선택을 비활성화하고 일부 선택을 허용한다. 현재 UI 최대값의 보수적 계산은 2절을 따른다. 최종 합산 검사는 생성 API가 다시 수행한다.
- 페이지 목록이 바뀌면 삭제된 선택/범위를 알려 재확정받고, 생성 확정 뒤에는 복사한 ID·문서 페이지 번호·내용을 유지한다. 오류 번호는 원래 문서 번호, 진행률은 출력 순번/선택 면 수다.
