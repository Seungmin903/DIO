# DIO 추가 인증업체 비용 없는 가입 연령 확인 설계

검토일: 2026-11-01 · 적용 전제: 대한민국 대상 일반 공유 다이어리

이 문서는 설계안이다. 아래의 ‘보완 필요’ 항목이 이미 구현되었다는 뜻은 아니다. 유료 인증업체는 연결하지 않으며 새 API·테이블·컬럼도 전제하지 않는다. 기존 서버·메일 운영비까지 무료라는 뜻은 아니다.

## 1. 결론과 한계

휴대폰 명의자 확인이나 실명 본인인증을 제공하지 않는다. 가입 가능 연령의 **본인 진술**, 기존 이메일 계정 확인, 서버 가입 검증, 아동 이용 확인 시 대응 절차를 조합한다.

이 조합은 실제 연령을 증명하거나 법적 적합성을 보장하지 않는다. 체크박스·본인 입력 생년월일·일반 이메일 인증만으로 거짓 연령을 판별할 수 없다. ‘본인인증 완료’, ‘연령 인증 완료’, ‘법적으로 문제없는 가입’이라고 표시하지 않는다.

개인정보 보호법 제22조의2는 만 14세 미만 아동의 개인정보 처리에 법상 동의가 필요한 경우 법정대리인의 동의와 그 확인을 요구한다. 이 조문이 모든 일반 앱에 특정 유료 인증서비스를 일괄 요구하는 것은 아니다. 한편 개인정보위는 만 14세 이상 체크와 생년월일 입력 절차가 있었던 사업자에게도 실질적인 연령 확인 절차 보완을 권고했다. 따라서 자기확인만으로 책임이 면제된다고 판단하지 않는다.

## 2. 수집·비용 원칙

| 항목 | 설계 |
| --- | --- |
| 가입 대상 | 만 14세 이상. 보호자 동의를 대신 받는 아동 가입 경로는 제공하지 않음 |
| 생년월일·출생연도 | 새로 입력받거나 저장하지 않음 |
| 휴대폰 번호·신분증 | 새로 수집하지 않음. 이메일로 신분증·학생증·주민번호 사본 제출을 요청하지 않음 |
| 사진으로 연령 추정 | 하지 않음 |
| 이메일 인증 | 기존 인증번호 기능 유지. 이메일 사용 가능 여부 확인으로만 설명 |
| 구글 로그인 | 계정 인증으로만 설명. 구글 계정 보유를 14세 이상 증명으로 취급하지 않음 |
| 연령 확인 문구 | ‘만 14세 이상이라는 본인 확인’ |
| 인증업체 비용 | 외부 본인확인·SMS·연령 추정 서비스를 연결하지 않아 추가 과금 없음 |
| 광고 | 기존 일괄 MARKETING 동의를 광고 수신 동의로 사용하지 않음. 채널별 동의·철회 기능 전까지 광고 발송을 활성화하지 않음 |

## 3. 가입 전 화면

화면 제목: **가입 연령을 확인해 주세요**

안내: **DIO는 만 14세 이상만 가입할 수 있어요. 생년월일은 받지 않아요.**

기본 선택은 없음이다. 아래 두 답을 동등하게 제공하며, ‘예’를 미리 선택하거나 전체 약관 동의에 연령 답변을 묶지 않는다.

- **만 14세 이상입니다** → 필수 약관을 확인한 후 가입 입력 단계로 이동.
- **만 14세 미만입니다** → 가입 입력·이메일 발송·구글 인증을 시작하지 않고 다음 안내를 표시.

차단 안내: **DIO는 만 14세 이상부터 가입할 수 있어요. 입력하신 연령 답변은 서버에 보내거나 저장하지 않았어요.**

차단 화면에는 ‘시작 화면으로’만 제공한다. ‘답을 바꾸면 가입할 수 있어요’ 같은 우회 유도 문구나 즉시 재선택 버튼은 제공하지 않는다. 이 UI 조치는 새로고침·다른 기기·거짓 응답을 막는 본인인증 수단이 아니다. 별도 영구 기기 차단용 식별정보도 수집하지 않는다.

필수 동의는 SERVICE 이용약관과 PRIVACY 개인정보 수집·이용 동의를 구분한다. 개인정보처리방침은 별도 보기 링크로 제공한다. 거짓 답변에 책임이 있다는 문구로 운영자의 법적 의무를 이용자에게 전가하지 않는다.

## 4. 이메일·구글 공통 흐름

### 이메일 신규 가입

연령 자기확인 → 필수 약관 확인 → 이메일·비밀번호 입력 → 기존 이메일 인증 → 프로필 → 서버 가입 검증 → 회원 생성

현재 가입 API를 유지한다. `ageConfirmed`를 자동으로 true로 만들지 않고 화면에서 확인한 값만 보낸다. 서버는 누락·null·false를 거절한다. 사용자가 직접 true로 바꿔 호출하는 것을 이 값 하나로 알아낼 수는 없다.

### 향후 구글 로그인·가입

구글 가입도 연령 자기확인과 필수 약관을 우회하지 않도록 한다. 이메일 인증 단계를 구글 계정 인증으로 대체하되, 구글 로그인 성공 즉시 신규 DIO 회원을 생성하지 않는다.

비로그인 상태에서는 기존 회원인지 신규 이용자인지 미리 확신할 수 없다. 따라서 신규/기존 공용 구글 진입 버튼에서는 구글 인증을 시작하기 전에 연령 자기확인을 먼저 받는 방식으로 설계한다. 서버가 구글 계정을 확인한 뒤 기존 회원은 로그인시키고, 신규 이용자는 필수 약관·프로필·가입 검증을 마친 뒤 생성한다. 이미 유효한 DIO 로그인 세션으로 앱을 이용하는 동안에는 연령 질문을 반복하지 않는다.

구글 연동 시 필요한 정보·이용 목적과 적용할 개인정보 처리 근거도 반영한다. 구글의 이메일·프로필 정보가 연령 선택 전에 수집되지 않도록 진입 순서를 지킨다. 해당 구글 연동은 아직 미구현이며 새 엔드포인트를 임의로 추가하지 않는다.

## 5. 저장과 증빙

- 생년월일과 연령 답변을 새 DB 컬럼에 저장하지 않는다.
- 기존 `user_terms_agreements`의 약관 종류·버전·동의 시각은 유지한다. 이는 약관 동의 기록이며, 실제 나이나 본인인증의 증빙은 아니다.
- 현재 `ageConfirmed`는 가입 요청 검증에만 쓰고 별도 연령 증빙으로 보관하지 않는다. ‘동의 시각을 저장했으니 실제 연령도 검증했다’고 설명하지 않는다.
- 동의·연령 화면을 이탈하고 새 가입을 시작하면 이전 답변과 동의를 재사용하지 않는다.
- 요청 본문·인증번호·토큰·생년월일이 로그에 남도록 추가 로깅하지 않는다.
- 향후 별도 증빙을 보관하려면 목적·최소 항목·보유 기간을 먼저 정한다. 유니크 ID나 생년월일을 편의상 추가 수집하지 않는다.

## 6. 아동 이용이 확인되거나 신고된 경우

추가 유료 서비스 대신 운영자가 기존 문의 이메일 `dioapp.official@gmail.com`으로 접수한다. 다음은 운영 절차로 확정해야 하는 항목이다.

1. 이메일로 해당 계정을 식별할 최소 정보와 신고 취지를 확인한다. 신고만으로 타인의 계정을 즉시 삭제하지 않는다. 계정 소유·요청 권한 확인을 거치고, 별명·사진·말투만으로 연령을 단정하지 않는다.
2. 만 14세 미만이라는 구체적인 사실이 확인되면 추가 개인정보 수집·공유를 계속 허용하지 않도록 이용 제한 및 처리 절차를 진행한다. ‘이미 14세 이상에 체크했다’는 이유로 무시하지 않는다.
3. 법정대리인 동의 없이 처리한 정보의 삭제·처리정지 등 필요한 조치를 검토하고 수행한다. 이때 아동의 개인정보와 다른 참여자의 공동 작업을 구분한다.
4. 기존 일반 탈퇴의 ‘공동 작업 보존’ 정책만으로 아동의 얼굴·이름·연락처 등 개인정보를 일괄 보존하지 않는다. 기존 탈퇴 API 호출만으로 아동 개인정보 처리가 모두 끝난다고 보지 않는다.
5. 신고 처리 결과를 안내한다. 필요한 사건 기록만 접근을 제한해 보관하며 목적·보유 기간은 운영 정책으로 정한다. 새 DB 테이블 생성이나 신분증 수집은 이 설계에 포함하지 않는다.

이 절차는 담당자와 실제 이용 제한·정리 수단이 마련되어야 운영 가능하다. 현재 코드를 수정하지 않고 자동 처리된다고 약속하지 않는다. 공개 가입 전에 수동 처리할 담당자와 처리 수단부터 점검한다.

## 7. 초기 운영과 공개 범위

**권장 초기 운영: 만 14세 이상임을 이미 확인할 수 있는 팀·지인 중심의 제한 베타.** 참여 대상을 운영자가 확인하고 불특정 다수에게 공개 모집하지 않는다. 비공개·무료·학생 프로젝트도 개인정보 보호 의무의 예외는 아니다.

공개 모집 전 운영자는 다음을 확인한다.

- 실제 모집 대상·홍보 문구·스토어 설명이 만 14세 미만을 대상으로 하지 않는가.
- 성인·청소년 대상이라는 표시와 실제 이용자 구성이 일치하는가. 스토어 연령 등급만으로 실제 이용자 나이를 검증했다고 보지 않는다.
- 개인정보처리방침의 위탁업체·국외 이전·보관 기간이 실제 배포 구성과 일치하며 공개되었는가.
- 아동 신고·이용 제한·개인정보 정리 요청을 처리할 담당자와 수단이 있는가.
- 아동 유입이 실제 확인되면 신규 공개 모집을 축소·중단하고 연령 확인 방식을 재검토할 수 있는가.

이 판단이 불가능한 상태에서는 ‘돈이 들지 않으니 체크박스로 공개 가입을 계속 허용’하는 결론을 내리지 않는다. 검증된 연령이 반드시 필요한 운영 상황인데 비용도 다른 확인 수단도 확보할 수 없다면, 공개 범위를 제한하는 것이 이 설계의 대응이다.

| 필수 약관 분리·문서 URL 설정·v2 기록 | 구현됨. 실제 문서 게시·운영 정보 확정은 별도 |
