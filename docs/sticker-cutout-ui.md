# 사진 속 대상 오리기 — 프론트 목업

2026-10-30 · S15P31F106-377·378·379 · `feature/fe/sticker-cutout`

## 범위

기존 스티커1(단색 배경의 그림 모음 분리)과 다른 스티커2의 사진 선택·붓 입력·결과/저장 확인 화면이다. 실제 SAM 추론, 업로드/API, 투명 PNG 생성, 폴더 영구 저장, 영상 선택은 연결하지 않는다. 선택 마스크를 SAM의 대상 윤곽처럼 표시하거나 실제 스티커가 저장됐다고 안내하지 않는다.

## 진입과 화면

- 편집기 → 스티커 → 사용자 폴더 → 점선 `＋` → `사진 속 대상 오리기`.
- `이미지 그대로 추가`와 스티커1의 `이미지 분리해서 추가`는 유지한다. 스티커2 목 화면은 Expo Go에서도 진입할 수 있다.
- 첫 진입은 사진 선택 영역 전체가 하나의 버튼이다. 사진 아이콘·사진 선택·안내 어디를 눌러도 같은 선택기를 열며 별도 오른쪽 버튼은 없다. 선택 취소 시 이 상태를 유지하고, 사진을 고른 뒤에만 조작부의 `다른 사진 선택`을 표시한다.
- 사진 선택 → 1단계 대상 선택 → `다음 · 스티커 확인` → 2단계 스티커 확인으로 진행한다. 원본과 결과를 나란히 놓지 않는다. `스티커로 만들 대상을 칠해 주세요`로 짧게 안내하며, `선택 추가`는 파란색 포함 힌트, `선택 제외`는 빨간색 지우개 영역이다. 붓 크기는 6~80 슬라이더와 현재 값 숫자, 수정은 되돌리기·다시 실행·전체 초기화를 제공한다.
- 처음에는 남길 영역이 없어 결과 버튼을 비활성화한다. 최소 한 개의 추가 획이 있으면 결과를 열 수 있다. 모든 추가 영역을 제외 획으로 지우면 결과가 비어 보일 수 있다. 픽셀 수준의 최종 마스크 유효성 판정은 실제 모델/저장 연결 범위다.
- 결과는 사용자가 칠한 영역만 원본 위에서 잘라 보이는 SVG 마스크 미리보기다. 체크무늬 배경에서 확인하며, 현재는 붓질 예시이고 AI 윤곽·흰 테두리는 미적용임을 표시한다. 파일을 생성하지 않는다.
- 결과의 `선택 수정`은 기존 획을 유지하며 입력 화면으로 돌아간다. `저장 흐름 확인`은 취소/확인 대화상자를 표시하고, 확인 후에도 실제 파일·폴더·캔버스 스티커는 추가하지 않는다. 저장 대상은 진입한 폴더 이름으로 표시한다.
- 선택 초기화·저장 전 닫기는 확인창을 거친다. 기기 뒤로가기는 결과에서 입력으로, 입력에서는 닫기 확인으로 진행한다. 초기 사진 선택 취소는 빈 화면, 사진 교체 취소는 기존 사진·선택을 유지한다. 새 사진을 고르면 기존 선택을 비운다.
- 태블릿(폭 900 이상)은 사진 왼쪽·조작부 오른쪽, 폰은 세로로 배치한다. 낮은 화면은 본문을 스크롤하며 헤더의 닫기·뒤로가기는 유지한다. 모든 새 버튼은 최소 높이 44다.

## 입력과 자원

- JPG·PNG·WebP 정지 사진, 최대 20MiB·4천만 화소. GIF·HEIC/HEIF·영상은 이번 목업에서 제외한다.
- 기존 사진 선택기를 재사용하되 영구 미디어 저장 경로는 호출하지 않는다. 웹 File의 임시 Blob URL은 교체·닫기·읽기 실패·폐기 후 늦게 도착한 사진 응답에서 해제한다. 네이티브 선택 URI의 원본 파일은 삭제하지 않는다.
- 좌표는 사진 자체 너비/높이 기준 0~1로 보관하고 붓 굵기는 사진 너비의 비율이다. 화면 크기·사진 비율이 달라도 확정된 선택은 유지한다. 회전 중 미확정 획과 다중 터치로 끊긴 획은 버린다. 최대 150획·획당 1200점을 허용한다.
- `stickerCutout.js`의 선택 이력과 `previewCutoutSelection` 계약을 UI에서 분리했다. 팀원 PoC의 README와 brush.html을 기준으로 `cutoutSegmentInput(imageId, state)` 변환 함수를 추가했다. 이 함수는 아직 네트워크에 연결하지 않으며 현재 프론트 목업을 SAM 연동 완료로 해석하지 않는다.
- 처리 중 중복 선택·결과 요청·닫기를 막는다. 사진 로드 또는 결과 실패 시 안내하고 다시 선택/재시도할 수 있다. 기존 사진·이력을 실패만으로 삭제하지 않는다.

## 검증

### 팀원 SAM PoC 입력·처리·출력 (연결 전 참고 계약)

- 기준: `origin/feature/ai/S15P31F106-16-sticker-sam2-poc`의 README와 `ai/app/static/brush.html`. 프론트로 추출한 화면 소스를 읽었으며 AI 서버는 실행·수정하지 않았다. 실서비스 서버 계약은 후속 연결 시 담당자와 재확인한다.
- 사진 업로드: `POST /api/stickers/images`, multipart `file` → `imageId`. 사진 임베딩은 업로드 때 계산한다. PoC 캐시는 메모리의 최근 32장이므로 재시작·캐시 만료 후에는 재업로드가 필요하다.
- 대상 분리: `POST /api/stickers/segment`, `{ imageId, strokes: [{ mode: 'include' | 'exclude', size, points: [{ x, y }] }] }`. 좌표는 0~1, `size`는 사진 너비 대비 **반지름**이다. 프론트 `width`는 지름 비율이므로 `size = width / 2`로 변환하고 획 순서·한 점 탭을 보존한다.
- 선택 붓은 대상 전체를 칠한 마스크가 아니라 SAM의 포함 힌트다. 제외 붓은 제외 힌트와 실제 영역 지우기에 사용한다. 팀원 PoC는 획이 끝날 때 자동 요청하지만 DIO의 단계별 UI와 요청 시점은 별도로 결정할 수 있다.
- 응답의 `preview`는 원본 위에 겹치는 선택 영역 PNG data URL, `sticker`는 흰 테두리·그림자를 적용한 스티커 PNG data URL, `segmentMs`는 처리 시간이다. 실제 연결 때 선택 화면에는 `preview`, 다음 결과 화면에는 `sticker`를 사용한다. 현재는 응답을 만들거나 가짜 AI 윤곽을 그리지 않는다.
- 업로드·인증·캐시 만료 복구·응답 오류·실제 PNG 저장은 이번 변경에 포함하지 않는다. 변환 함수가 있다는 사실만으로 API 연결이 완료된 것은 아니다.

- 관련 Node 테스트 84개 통과. 선택 좌표/이력·목 계약·잘못된 사진·취소·중복 요청·재선택·실패 재시도·늦은 응답 해제와 기존 스티커1·저장 실패 회귀를 포함한다.
- Edge 1280×800·1024×768·390×844·844×390에서 실제 스티커 메뉴 → 사진 → 추가/제외 → Undo/Redo → 초기화 취소 → 결과 → 수정 → 닫기 취소 → 저장 확인 취소/확정 → 우측 위 닫기 확인. pageerror 0, 가로 넘침 없음, 캔버스 스티커 추가 0건. 사진은 저장소의 기존 QA 이미지이며 개인 사진을 외부로 보내지 않는다.
- 웹 export 통과. Android/iOS 실기기의 사진 접근 권한·펜/손가락 입력·SVG 마스크·시스템 뒤로가기는 별도 사용자 확인이 필요하다. 실제 AI 추론·윤곽 품질·영상·파일 저장 검증은 포함하지 않는다.

## 실기기 확인 순서

1. 일반 Expo 서버로 접속 → 게스트 → 다이어리 → 스티커.
2. 기존 내 폴더를 선택하거나 `새 폴더`로 테스트 폴더를 만든다.
3. 폴더 안 점선 `＋` → `사진 속 대상 오리기` → `사진 선택`.
4. 사진에서 남길 대상을 칠하고 제외로 일부 지운다. 붓 크기·되돌리기·다시 실행을 확인한다.
5. `선택 초기화` → 취소해 선택이 유지되는지 확인한다.
6. `다음 · 스티커 확인` → 수동으로 칠한 부분만 표시되는지 확인한다. AI가 사람 경계를 찾는 단계는 아직 아니다.
7. `선택 수정`으로 돌아와 선택 유지, 다른 사진 선택 취소 시 기존 내용 유지를 확인한다.
8. 결과 → `저장 흐름 확인` → 취소, 다시 확인 → 목업 안내 표시 → 우측 위 닫기. 실제 폴더 항목이 늘어나지 않는 것이 정상이다.
9. 다시 진입해 사진을 칠한 뒤 닫기·기기 뒤로가기의 취소/확정을 확인한다. 원본 사진은 바뀌지 않는다.

## 버튼 배치 보완

- 선택 추가/제외는 아이콘과 이름을 함께 표시하는 회색 전환 판으로 묶고 선택한 칸만 흰색으로 표시한다.
- 붓 크기는 현재 값 숫자와 6~80 슬라이더, 되돌리기/다시 실행은 44px 아이콘 버튼, 초기화/사진 교체는 테두리 없는 보조 조작으로 표시한다.
- 선택 화면의 주요 버튼은 다음 단계 이동 하나만 채운 파란색으로 강조한다. 결과 화면에서는 저장 흐름 확인을 강조한다. 접근성 이름과 비활성 처리는 유지한다.

- 결과 화면은 선택 수정·저장 흐름 확인만 표시하고, 별도 완료 버튼 없이 우측 위 닫기로 종료한다.

## 2026-10-30 리뷰 보완

- 동일 URI를 다시 선택해도 선택별 키로 Image를 새로 마운트해 로드 완료를 기다린다. 이전 사진의 늦은 onLoad는 무시하며 재선택 후에도 붓 입력을 다시 사용할 수 있다.
- 붓 지름 비율은 최대 1(표시 사진 너비)로 제한한다. 좁은 세로 사진에서 큰 붓을 써도 표시 중인 획과 확정 획이 같으며 손을 뗄 때 사라지지 않는다.
- 파일 선택은 image/jpeg·image/png·image/webp MIME과 jpg/jpeg/png/webp 확장자의 허용 목록을 사용한다. MIME이 비었거나 application/octet-stream이면 허용 확장자가 필요하다. 구체적 MIME 또는 확장자가 지원 외 형식이면 거부하고 둘 다 미상이면 형식 선택 안내를 표시한다. 이후 이미지 크기/디코딩 검사도 유지한다.
- 모서리 11은 디자인 가이드 4.3의 세그먼트 판 보조 값이다. 현재 theme.js에는 타이포·간격 토큰이 없으므로 기존 가이드의 값을 사용하고 이 화면만을 위한 새 공통 토큰은 만들지 않는다.
- 관련 Node 검사 117개 통과(스티커 87개 + 읽기/뷰포트 30개). 동일 URI 재선택·늦은 로드·좁은 사진 큰 붓·허용/미상/지원 외 형식을 포함한다.
- 보완 후 Edge 스티커4규격 통과. 편집/읽기5규격에서 맞춤 버튼의 실제 터치 위치와 확대 후 복원까지 통과. 실제 Android의 같은 사진 재선택과 좁은 세로 사진 큰 붓은 사용자 재확인 대상이다.
