# 회원 휴지통 표지 보존

## 원인과 처리

회원 휴지통 응답은 기본 색·패턴만 제공하며 상세 cover, pageSize, templateConfig, paperAppearance는 제공하지 않는다. 휴지통 이동 후 활성 목록에서 항목을 제거하면 이 기기에 있던 상세 표지·방향이 휴지통 표시와 복원에 이어지지 않았다.

단건·선택 이동 모두 서버 삭제 전에 계정별 local-meta에 상세 표지와 방향을 보존한다. 저장 실패 시 서버 삭제를 보내지 않는다. 휴지통 목록에는 저장된 외형만 합치며 제목·색·버전·삭제 시각·복원 권한 등 서버 값이 우선한다. 복원 후에도 저장된 외형을 활성 목록에 이어준다. 계정별 저장소를 사용하고 서버 API·데이터 형식은 변경하지 않는다.

## 검증

저장소 루트에서:

```sh
node --test --test-skip-pattern="실제 Spring" frontend/tests/member-diary-lifecycle.test.js frontend/tests/member-library-integration.test.js frontend/tests/member-app-store.test.js frontend/tests/trash-lifecycle.test.js
```

2026-11-05: 51개 통과. 기존 실제 Spring 계약 검사는 backend/build/contracts/member-diary-trash-http.json이 없어 제외했다. 백엔드 테스트는 실행하지 않았다.

추가 검사는 색/사진/표지 없음, 세로/가로 조합의 단건 이동→새 저장소 인스턴스로 재시작→복원, 선택 이동의 표지 보존, 보존 쓰기 실패 시 삭제 미전송을 확인한다. 기존 최대 3개 동시 삭제 검사는 보존 저장이 끝나고 요청 3개가 시작된 뒤 해제하도록 대기 조건을 보완했다.

## 실기기 확인과 한계

- 색·패턴·사진 표지에 띠지·고무줄을 다르게 설정하고 세로/가로 다이어리를 휴지통으로 옮긴다.
- 휴지통 표시, 앱 재시작 후 표시, 복원 후 보관함 표시가 원래 모습과 같은지 확인한다.
- 여러 개 선택 이동도 확인한다.
- 과거에 이미 유실되어 기기에 남지 않은 표지 정보는 복구할 수 없다. 다른 기기의 상세 표지를 서버에서 동기화하는 기능은 이번 범위가 아니다. 사진 원본 파일의 수명·동기화 방식은 변경하지 않는다.

## 리뷰 보완

손상된 local-meta를 빈 객체로 덮어쓰지 않는다. JSON 구문 오류, null, 배열, 숫자·문자열이면 원문과 활성 목록을 그대로 유지하고 단건·선택 이동을 차단한다. 표지 저장 자료가 손상되어 이동하지 않았다는 문구를 표시한다. 손상 자료를 사용자가 복구·초기화하는 UI는 이번 범위에 포함하지 않는다.

명시적 영구 삭제가 서버에서 성공한 뒤 같은 저장 큐 안에서 local-meta의 해당 ID만 제거한다. 다른 ID와 다른 계정 자료는 건드리지 않는다. 서버 삭제 실패 시 메타를 유지한다. 서버 성공 후 로컬 표지 정리가 실패해도 index 갱신과 서버 목록 재조회를 계속하고 lifecycle을 종료한다. 정리 실패는 별도 경고로 안내하며, 손상 자료를 빈 객체로 덮어쓰지 않는다. 다른 요청을 OPERATION_PENDING으로 막지 않는다. 사진 원본 파일·기존 문서 삭제 정책은 바꾸지 않는다.

검증 명령에 frontend/tests/member-diary-purge.test.js를 추가해 59개 통과. Spring 생성 계약 파일이 필요한 두 검사는 기존과 같이 제외했다. 손상 메타 차단, 삭제 성공/실패 시 해당 메타 정리, 손상 시에도 목록 갱신·작업 잠금 해제을 추가 확인했다.

표지 메타 조회 실패는 metadataError로 노출하며 휴지통 안내에 “일부 표지가 원래 모습과 다를 수 있어요”를 표시한다. 서버 행은 계속 표시하고 복원도 허용한다. 정상 메타를 다시 읽으면 조회 경고만 해제한다. 영구 삭제 후 정리 실패는 metadataCleanupError로 별도 안내한다. 조회·복원은 읽기 실패에도 서버 작업을 허용하지만, 휴지통 이동은 아직 살아 있는 표지를 잃지 않도록 보존 실패 시 차단한다.

2026-11-05 후속 리뷰 보완 후 동일 59개 통과. 손상 JSON/null/배열/숫자/문자열에서 삭제 완료, 목록 갱신, lifecycle 종료, 다음 요청이 OPERATION_PENDING으로 막히지 않음, 원문 보존, 정상 재조회 시 경고 해제를 검증했다.

## 자동 삭제·다른 기기 삭제와 항목별 형식

서버 보관 기간 경과 또는 다른 기기 삭제로 목록에서 사라진 ID의 local-meta는 자동 정리하지 않는다. 회원 활성 목록은 검색·필터와 20개 단위 페이지 조회를 사용하므로 현재 목록에 없다는 사실이 삭제 확정을 의미하지 않는다. 누락만을 근거로 지우면 정상 표지 설정을 잃을 수 있어 이번 정리 대상은 이 기기에서 서버 성공을 확인한 명시적 영구 삭제로 제한한다. 따라서 외부에서 삭제된 ID의 설정·사진 경로가 기기에 남는 한계가 있다. 안전한 정리에는 완전한 목록 확인이나 삭제된 ID를 판별할 수 있는 계약이 필요하다.

ID별 값도 객체인지 검사한다. 문자열/null/배열/숫자/불리언이면 이동을 중단하고 원문을 보존한다. 조회 시에는 비정상 항목만 제외하고 정상 항목은 사용하면서 표지 설정 경고를 표시한다.

항목별 비정상 값 검사를 추가해 관련 테스트 60개 통과(기존 Spring 생성 계약 검사 제외).

## 오류 안내 후속 보완

INVALID_LOCAL_CACHE로 이동이 서버 요청 전에 차단되면 실제 오류 문구를 표시하고 작업 재시도 대상으로 분류하지 않는다. 선택 이동에서도 해당 실패 문구를 표시하며 네트워크 실패만 있는 경우의 재시도는 유지한다. 메타 조회·정리 경고는 함께 표시한다. 정상 메타 재조회는 조회 경고만 해제한다. 정리 실패 경고는 읽기 성공으로 지우지 않고 정리 성공 또는 사용자의 ‘표지 정리 안내 닫기’에서만 해제한다. 닫기는 남은 자료를 삭제하지 않는다.

손상 캐시의 재시도 불가, 정상 재조회 후 경고 해제, 실제 안내 렌더링을 검증한다. 관련 5개 파일 및 auth-recovery/auth-routing 테스트 총 95개 통과. Spring 생성 계약 파일 필요 검사는 제외한다.

선택 이동의 동일 표지 손상 문구는 중복 없이 한 번만 표시한다. 표지 손상만 실패한 경우 권한·처리 결과 확인을 요구하는 일반 안내는 숨긴다. 다른 실패가 섞인 경우에만 일반 안내를 함께 표시한다. 단건 lifecycle의 422는 이번 작업 전과 동일하게 재시도 가능으로 유지한다(선택 이동의 기존 422 판정은 변경하지 않음). dispose 뒤 emit은 공통 함수 내부의 !disposed 조건으로 상태 변경과 구독 통지를 모두 차단한다.

최종 관련 97개 통과. 중복·혼합 실패 안내와 단건 422 재시도를 추가 검증했다. 기존과 같이 Spring 생성 계약 검사는 제외한다.

정상 메타에서 저장만 실패하는 경우에도 서버 삭제·목록 갱신·작업 종료 후 정리 경고가 유지되고 사용자가 닫을 수 있는지 검증했다. 관련 98개 통과(Spring 생성 계약 검사 제외).
