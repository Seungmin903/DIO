## 1. 진단 순위

| 순위 | 어긋나는 지점 | 다른 앱처럼 읽히는 이유 |
|---:|---|---|
| 1 | 정보 줄이 펼쳐서만 책 아래 **가운데 한 줄**(`이름 · 1/1 · ☆ · ⋯`), 나머지는 표지 아래 **좌측 2줄 + 우측 ⋯ + 표지 위 별** | 같은 다이어리의 이름·상태·행동이 보기마다 다른 UI 컴포넌트처럼 보인다. |
| 2 | 선택 표현이 스와이프만 **흰 3px 프레임 + 그림자**, 펼쳐서는 책 자체, 한눈에는 없음 | “현재 보고 있는 다이어리”의 문법이 보기마다 달라 전환 대상이 이어지지 않는다. |
| 3 | 물성 체계가 다르다: 표지는 해 방향 `sunShadow`, 펼친 책은 `0 8px 16px rgba(11,23,102,.12)` 고정 그림자 | 같은 책이 멀리서 보면 햇빛 아래 있고, 가까이 가면 별도 조명 세트에 놓인 듯하다. |
| 4 | 모서리 체계가 분리돼 있다: 표지는 위 약 `9px`·아래 약 `18px`, 펼친 속지는 `4px`, 판은 약 `14×scale` | 속지는 각질이어야 하지만, 바깥 판·선택 프레임까지 별도 규칙이면 서로 다른 에셋군처럼 보인다. |
| 5 | 크기·구도가 급변한다: 펼쳐서 약 `1010px`, 스와이프 중앙 `318×1.06`, 한눈에 약 `235px`인데 공통 기준점이 없다 | 같은 다이어리가 축소·확대되는 것이 아니라, 화면마다 새 객체가 등장하는 인상이다. |
| 6 | 별의 소속이 다르다: 스와이프/한눈에는 표지의 속성, 펼쳐서에서는 캡션의 버튼 | 즐겨찾기가 “책 자체의 상태”인지 “현재 화면에서 하는 행동”인지 혼재된다. |
| 7 | `⋯`의 기준점이 다르다: 표지 우측 끝 vs 펼친 책 하단 텍스트 흐름 안 | 관리 행동의 터치 지점과 시각적 위계가 바뀐다. |

## 2. 한 줄 콘셉트

**한 권의 다이어리를 같은 책상 위에서, 멀리서는 고르고·중간에서는 훑고·가까이서는 펼쳐 보는 기능이다.**

| 불변: 반드시 공유 | 가변: 보기 목적에 따라 달라도 됨 |
|---|---|
| 동일 `diaryId`의 표지, 제목, 페이지 수, 즐겨찾기 상태, `⋯` 행동 | 표지/속지의 크기와 배치 |
| 표지의 위 `9×s`·아래 `18×s` 곡률, 책등·고무줄·판의 물성 | 펼쳐서는 속지와 제본 디테일 노출 |
| 현재 다이어리의 흰 `3px` 윤곽, 그림자, 제목 진하기 | 한눈에는 다중 선택 체크 표시 |
| 별은 표지 좌상단에 놓이는 “책의 상태” | 스와이프의 양옆 카드, 펼쳐서의 넘김 방식 |
| 제목 아래 페이지 수, 우측 `⋯`이라는 정보 구조 | 태블릿 5열 / 폰 2열, 폰의 단면 펼침 |

## 3. 공유 규칙 수치표

### 물성·모서리·그림자

` s = 해당 보기의 기준 표지 스케일`로 둔다. 스와이프 중앙은 `1.06`, 옆 카드는 `0.84`, 한눈에 기본은 `1.00`이다.

| 항목 | 펼쳐서 | 스와이프 | 한눈에 |
|---|---:|---:|---:|
| 표지 바깥 모서리 | 판: 위 `9×s`, 아래 `18×s` | 위 `9×s`, 아래 `18×s` | 위 `9×s`, 아래 `18×s` |
| 펼친 속지 모서리 | `4×s`; 판보다 안쪽 `6~8×s` 노출 | 해당 없음 | 해당 없음 |
| 표지 판 반경 | 아래 표지 반경의 약 `0.78` = `14×s` | 표지 자체가 판 | 표지 자체가 판 |
| 선택 흰 윤곽 | 판 바깥 `3px`, 판과 `2px` 간격 | 표지 바깥 `3px` | 선택된 표지 바깥 `3px` |
| 그림자 방향 | 기존 시간대 `sunShadow` 방향을 그대로 사용 | 동일 | 동일 |
| 그림자 크기 | 오프셋 `8×s`, 블러 `16×s`, 불투명도 `.12` | 중앙 `8.5px/17px/.12`, 옆 `6.7px/13.4px/.10` | `8px/16px/.12` |
| 그림자 원칙 | 빛의 방향만 시간대에 따라 바꾸고, 책상·배경은 애니메이션하지 않음 | 동일 | 동일 |

- 즉, 펼쳐서의 고정 `0 8px 16px rgba(11,23,102,.12)`는 **크기와 농도는 유지**하고, `x/y` 방향만 기존 `sunShadow`의 방향 벡터에 맞춘다.
- 다크 표지의 하단 점선 바인딩은 유지한다. 이는 표지 디테일이지 보기별 장식이 아니다.

### 정보 줄 공통 구조

| 항목 | 펼쳐서 권장값 | 스와이프 | 한눈에 |
|---|---|---|---|
| 캡션 기준 | 펼친 책 전체 폭의 좌측 끝 | 중앙 표지 좌측 끝 | 각 셀 표지 좌측 끝 |
| 제목 | 표지/책 아래 `8px`, `14px/700`, 자간 `-0.35px`, `ink` | 동일 | 동일 |
| 페이지 수 | 제목 아래 `4px`, `12px`, `inkSoft` | 동일 | 동일 |
| `⋯` | 캡션 레일 우측 끝, 제목 첫 줄 중심에 맞춤 | 동일 | 동일 |
| 별 | 표지/판 좌상단 `10px, 10px`, `22px` 윤곽 별 | 동일 | 동일 |
| 비선택 항목 | 제목은 `ink`, 페이지 수는 `inkSoft` | 옆 카드는 제목·페이지 수 `inkSoft` | 비선택은 동일 |
| 선택 항목 | 제목 `ink`, 페이지 수 `inkSoft`, 흰 윤곽과 그림자로 식별 | 동일 | 동일 |

### 펼쳐서 정보 줄: 두 후보

| 후보 | 방식 | 장점 | 손실 |
|---|---|---|---|
| A. 공통 캡션 레일 | 별은 판 좌상단, 책 아래 좌측에 제목·페이지 수, 우측에 `⋯` | 세 보기가 같은 다이어리 카드의 확대처럼 읽힌다. 별·메뉴의 의미도 일관된다. | 기존의 가운데 한 줄보다 약간 덜 “책 제목판” 같다. |
| B. 현행 중앙 한 줄 | `이름  1/1  ☆  ⋯`를 책 아래 중앙 유지 | 펼쳐서의 전시적·몰입적 느낌이 강하다. | 별과 메뉴가 다른 두 보기와 계속 다른 역할·위치가 된다. |

**A를 추천한다.** 펼쳐서의 몰입감은 정보 줄이 아니라 실제 크기 속지, 제본선, 판 노출, 넘김 방식으로 충분히 지킨다. 캡션은 책을 설명하는 조용한 레일로 후퇴시키는 편이 낫다.

## 4. 강조·선택 언어 통일

| 상태 | 세 보기 공통값 |
|---|---|
| 현재 다이어리 | 흰 `3px` 윤곽, 물체 바깥 `2px` 여백, 같은 방향의 `sunShadow` |
| 제목 | `14px/700`, `ink` |
| 페이지 수 | `12px`, `inkSoft` |
| 즐겨찾기 | 좌상단 `22px` 윤곽 별; 밝은 표지에서는 `ink`, 어두운 표지에서는 흰 윤곽 |
| 비현재 다이어리 | 흰 윤곽 없음, 기본 그림자만 사용 |
| 한눈에 관리 모드 | 체크는 관리 상태만 표현하고, 현재 다이어리 윤곽은 유지 |

한눈에 보기에서 현재 다이어리는 “마지막으로 열었던 다이어리” 또는 전환 직전 다이어리로 잡는다. 관리 모드의 체크와 현재 보기 표시는 역할이 다르므로 겹쳐도 된다.

## 5. 보기 전환의 연속성

| 방법 | 연출 | 시간·곡선 | 난이도 |
|---|---|---|---|
| 1. 선택 책 1권의 히어로 전환 | 선택 다이어리만 시작 위치에서 목표 위치·크기로 이동. 펼쳐서 진입 시 표지는 중간 지점에서 속지로 `cross dissolve` | 이동 `180ms`, 디졸브 `70ms`, `cubic-bezier(0.2, 0, 0, 1)` | 중간 |
| 2. 표지 유지 후 즉시 재배치 | 선택 표지를 `90ms` 유지하고 나머지 레이아웃은 즉시 교체. 표지만 목표 크기로 이동 | `120ms`, 같은 곡선 | 작음 |
| 3. 무연출 앵커 전환 | 애니메이션 없이 같은 다이어리를 새 보기의 첫 번째/중앙/펼침 대상으로 배치 | `0ms` | 작음 |

**1을 추천한다.** 이동하는 것은 선택 다이어리 한 권뿐이며, 책상·배경·다른 책은 움직이지 않는다. `useReducedMotion`에서는 반드시 방법 3으로 즉시 전환한다. 구현은 선택 `diaryId`와 시작/목표 `measure` 사각형을 공유하고, 임시 `DiaryHero` 한 개만 `Animated`로 올리면 된다.

## 6. 폰 전용 조정

| 보기 | 폰 적용 |
|---|---|
| 펼쳐서 | 한 면만 유지. 책등 쪽 두 모서리는 `0~2px`, 바깥 판은 위 `9px`·아래 `18px`, 속지 바깥 모서리는 `4px`; 판은 속지 밖으로 `6px`, 책등 띠는 `6~8px` 노출. 별은 판 좌상단 `10px`, 캡션은 책 아래 좌측 공통 레일. |
| 스와이프 | 중앙 표지 폭 `268px`, `1.06` 스케일과 흰 `3px` 윤곽 유지. 옆 카드는 `0.84` 및 아래 `30px`; 탭하면 중앙으로만 이동. |
| 한눈에 | 2열, 좌우 패딩 `24px`, 열 간격 `16px`. 표지 폭은 `(콘텐츠폭 - 64px) / 2`; 표지 아래 제목은 한 줄 말줄임, 페이지 수는 다음 줄 유지. |
| 공통 | 별 `22px`, `⋯`는 캡션 우측 끝, + 버튼 `60×60 / radius 16` 유지. 좁아서 별과 제목을 한 줄에 밀어 넣지 않는다. |

## 7. 작업 순서

1. **공용 `DiaryIdentity` 추출** — 제목·페이지 수·별·`⋯`을 같은 데이터와 캡션 레일로 렌더링.  
   체감: 보기 전환 뒤에도 같은 책의 정보가 그대로 따라온다.

2. **공용 `CoverArt` 물성 토큰화** — 위 `9×s`/아래 `18×s`, 판 노출 `6~8×s`, 책등·고무줄·그림자 규칙 적용.  
   체감: 가까이 펼쳐도 멀리서 본 표지와 같은 물건처럼 느껴진다.

3. **`activeDiaryId`와 선택 윤곽 통일** — 흰 `3px` 윤곽·그림자·텍스트 진하기를 세 보기에 적용.  
   체감: 지금 보고 있는 한 권이 즉시 식별된다.

4. **펼쳐서 캡션을 공통 레일로 교체** — 가운데 한 줄과 캡션 안 별을 제거하고, 별을 판 위로 이동.  
   체감: 가장 이질적이던 펼쳐서 하단 UI가 나머지와 연결된다.

5. **선택 책 1권 히어로 전환 추가** — `180ms` 전환과 동작 줄이기 즉시 전환을 구현.  
   체감: 세 버튼이 화면 교체가 아니라 관찰 거리 변경으로 읽힌다.

## 8. 하지 말 것

1. 펼쳐서까지 표지 카드처럼 만들어 속지 실제 크기·제본·넘김의 몰입을 잃지 않는다.  
2. 한눈에의 모든 표지에 스와이프식 흰 `3px` 프레임을 주지 않는다. 현재 다이어리만 강조해야 밀도가 유지된다.  
3. 스와이프의 양옆 카드를 직접 열리게 하거나, 한눈에 관리를 다른 보기에 복제하지 않는다. 보기마다의 행동 목적은 유지한다.

## 9. 확신이 낮은 항목

- 해 방향 그림자가 실제 사용자가 “시간대 창빛”으로 인지하는지, 또는 고정 그림자가 더 차분하게 느껴지는지.
- 펼쳐서 캡션을 좌측 레일로 옮겼을 때 기존 사용자가 기대한 전시적 균형이 얼마나 약해지는지.
- 한눈에에서 “마지막으로 연 다이어리”를 항상 강조하는 것이 관리 밀도를 해치지 않는지.
- 작은 폰에서 `268px` 스와이프 카드와 좌측 내비게이션이 함께 있을 때의 실제 가용 폭 및 잘림 여부.
