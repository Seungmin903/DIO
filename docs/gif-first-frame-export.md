# GIF 첫 프레임 PNG 내보내기 (S15P31F106-73)

## 계약

- 페이지 PNG에는 GIF 원본의 0번 이미지 프레임을 사용한다. 화면 재생 시점·썸네일·poster를 캡처하지 않는다.
- 사진, 이미지 스티커, 이미지 테이프, 기본 Noto GIF 스티커에 동일하게 적용한다.
- 논리 화면 크기, 첫 프레임의 오프셋·투명도·로컬 팔레트·인터레이스를 처리한다. 첫 프레임을 표시한 직후의 상태이므로 이후 disposal·반복 재생은 적용하지 않는다.
- 준비된 정지 PNG만 기존 ObjectContent에 넘긴다. 위치·크기·회전·자르기·투명도·겹침 순서는 기존 출력 렌더러가 유지한다.
- 동일 원본은 가장 큰 사용처의 출력 픽셀 요구량으로 한 번 준비한다. GIF는 표시본이 있어도 원본을 선택한다.
- 원본 GIF와 편집 문서는 변경하지 않는다. 웹 Blob URL과 네이티브 캐시 PNG는 작업 종료 시 해제한다. 생성 실패 시에도 임시 파일을 정리한다.

## 구현 및 제한

- 공통 gifFirstFramePng에서 omggif로 첫 이미지 블록까지만 읽고 upng-js로 무손실 PNG를 인코딩한다. 뒤 프레임은 디코딩하지 않는다.
- 출력 요구량이 원본보다 작으면 RGBA를 알파 선곱셈을 적용한 픽셀 면적 가중 평균으로 축소한다. 투명 가장자리 색이 어두워지지 않도록 처리한다. 원본보다 확대하지 않는다.
- 입력 상한은 10MiB, 논리 화면 긴 변 4096px, 800만 화소다. 큰 버퍼를 할당하기 전에 검사한다.
- 크기 초과는 EXPORT_GIF_TOO_LARGE, 첫 프레임 읽기 실패는 EXPORT_GIF_DECODE_FAILED로 중단한다. 오류에는 해당 요소의 이름 또는 ID를 포함한다.
- 텍스트·필기는 72번 담당 모델 확정 후 별도로 연결한다. 페이지 전체 GIF/영상 생성과 사진첩 저장·공유는 이번 범위에 포함하지 않는다.

## 검증 (2026-10-20)

- 출력 테스트 19개 + 기존 미디어 테스트 25개 = 44개 통과.
- 서로 다른 두 프레임의 GIF로 첫 프레임 픽셀과 반복 결과 일치, 원본 불변, 투명 여백·오프셋, 로컬 팔레트·인터레이스, 축소·상한·손상, 웹 URL 해제, 네이티브 임시 PNG 생성·삭제·쓰기 실패 정리를 확인했다.
- 배포 기본 GIF 스티커 36개 모두 첫 프레임 PNG 변환에 성공했다.
- Web 및 Android 번들 생성 통과. Android 번들은 실기기 실행 검증을 대신하지 않는다.
- 사용자 저장소와 분리한 127.0.0.1:8091에서 사진·회전/자르기 하트 사진·이미지 테이프·기본 움직이는 스티커를 한 페이지에 출력했다. 1188×840 PNG이며 사진 왼쪽은 빨강(255,0,0,255), 오른쪽은 초록(0,255,0,255)으로 첫 프레임이 반영됐다.
- 실제 iPhone/iPad/Android에서의 임시 파일 수명·SVG 로드 이벤트·메모리 사용 검증은 남아 있다.
- GIF가 재생된 뒤 다시 출력해도 전체 RGBA SHA-256이 일치했다: `a7fc8180970c8c3b4d58b8c1777cba517cb4e12b46d1594c9f89356f87a15e3b`. 테스트 문서는 ID 확인 후 제거했다.

## 73번 리뷰 반영 (2026-10-20)

- 디코더 앞에서 확장 하위 블록의 경계를 검사하고, 첫 이미지에 필요한 GCE만 전달한다. Plain Text와 알 수 없는 확장도 건너뛴다. Plain Text 자체는 출력하지 않으며 자신에게 적용된 GCE를 소비해 뒤 이미지에 투명도가 잘못 적용되지 않도록 한다.
- 투명 인덱스 유무에 관계없이 첫 이미지가 덮지 않는 논리 화면은 투명하게 유지한다. GIF 배경색 인덱스로 여백을 칠하지 않는다.
- 최근접 축소를 면적 가중 평균으로 바꾸고 알파를 먼저 곱해 반투명 가장자리의 검은 테두리를 방지한다.
- 오류 문구의 중복된 GIF 접두사를 제거했다.
- 기본 Noto GIF 원본은 128px이므로 2배 출력에서 원본보다 큰 크기로 배치하면 선명도에 한계가 있다. 선명도 개선에는 고해상도 원본 에셋이 필요하며 이번 변경으로 원본 픽셀 수를 늘리지는 않는다.
- 확장 블록·GCE 소비·불투명 부분 프레임의 투명 여백·색 평균/반투명 가장자리 회귀 테스트를 추가했다.
- 리뷰 수정 후 출력 23개 + 기존 미디어 25개 = 48개 테스트 통과, Web·Android 번들 생성 및 git diff --check 통과. 작은 PNG 인코딩에서 팔레트 청크 크기 때문에 잘리던 경우도 RGBA 경로로 처리해 1×1 결과 픽셀을 확인했다.
- 위의 RGBA 해시는 최초 73번 구현 검증 기록이다. 면적 평균 축소를 적용한 이번 수정 결과의 해시로 재사용하지 않는다. 실기기 검증은 계속 미완료 상태다.
