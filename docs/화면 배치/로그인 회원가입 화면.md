# 로그인·회원가입 화면과 입력 상태

관련 태스크: S15P31F106-222

## 구현 범위

인증 API 연결 전 프론트 화면·입력 상태를 검증한다. 실제 OAuth, 서버 계정 생성, 메일 발송, 계정별 다이어리 분리, 서버 약관 수집은 포함하지 않는다.

- 시작 화면: 로고·환영 문구 → 이메일·비밀번호 → 로그인 → 아이디 찾기 | 비밀번호 찾기 | 회원가입 → 간편 로그인(카카오·구글·애플) → 게스트로 시작하기.
- 이메일 가입: 이메일·비밀번호·비밀번호 확인 → 닉네임·선택 프로필 사진·약관 → 가입 완료 → 이메일만 채워진 로그인 화면.
- 소셜 진입: 실제 인증 대신 닉네임·프로필 입력으로 이동한다.
- 찾기 링크: API 연결 전 안내창을 연다.
- 게스트: 기존 기기의 로컬 다이어리로 이동한다.
- 내 공간: 가입 닉네임·사진, 로그아웃과 앱 정보를 표시한다. 설정 메뉴 구성은 회원정보 수정·탈퇴 작업에서 함께 정리한다.

## 입력과 전환

- 로그인에서 회원가입으로 이동하면 입력·오류를 비운다. 프로필에서 가입 입력 단계로 돌아갈 때는 입력을 유지한다.
- 화면 전환과 다이어리 진입 시 키보드를 닫는다. 새 화면은 스크롤 맨 위에서 시작한다.
- 입력 형식 오류는 각 입력칸 아래에, 로그인·가입 요청 오류는 제출 버튼 바로 위에 표시한다. 요청 오류는 수정·재요청·화면 전환 시 즉시 해제하고 5초 후에도 자동 해제한다.
- 중복 제출을 막는다. 닉네임 수정 시 확인 결과를 초기화하고, 재확인 중에는 가입을 막는다. 중복 확인 연타와 오래된 응답을 처리한다.
- 이용약관·개인정보 동의 두 항목이 필수이며 소식 수신은 선택이다. 보기 버튼은 실제 약관 대신 임시 안내를 연다.
- Android 뒤로가기는 안내창 → 이전 입력 단계 → 시작 화면 순서로 처리한다. 화면을 떠나거나 컴포넌트가 해제된 뒤 도착한 응답은 적용하지 않는다.

임시 형식 규칙: 이메일 주소 형식, 영문·숫자를 포함한 공백 없는 8~32자 비밀번호, 한글·영문·숫자·밑줄 2~12자 닉네임. `관리자`, `dio`는 중복 닉네임 예시다. 서버 계약 확정 후 맞춰야 한다.

## 사진과 데이터 유지

프로필 사진은 선택 사항이다. 시스템 사진 선택기를 사용하고 네이티브에서는 정사각형 자르기를 제공한다. 웹은 선택한 사진을 원형 cover로 표시한다. 취소 시 기존 사진을 유지하고 × 삭제로 기본 아이콘을 복원한다. 연필·삭제 배지는 사진 위에 배치해 선택 전후 화면 높이를 유지한다. 삭제 버튼의 터치 영역은 44다.

`previewAuth.js`의 임시 가입 정보는 실행 중 메모리에만 존재한다. 가입 완료 전에는 로그인할 수 없고, 이메일 가입 완료 후에는 자동 로그인하지 않고 로그인 화면으로 돌아온다. 가입한 이메일은 유지하고 비밀번호는 비우며 가입 완료 토스트를 2.5초 표시한다. 동일 이메일·비밀번호로 로그인한 뒤 로그아웃/재로그인이 가능하다. 소셜 프로필 완료는 기존대로 다이어리에 진입한다. 완료한 이메일·닉네임은 중복 검사에 반영한다. 비밀번호는 비교를 위해 메모리에만 유지하고 서비스 결과·디스크·AsyncStorage·서버에는 전달하지 않는다. 앱 종료·Reload 시 가입 정보가 사라진다. 사진 URI도 동일한 임시 프로필에만 유지하며 업로드·영구 저장하지 않는다.

인증 방식과 관계없이 기존 기기의 같은 로컬 다이어리를 사용한다. 서버 연동 시 인증 어댑터와 계정별 데이터 분리를 구현해야 한다. 기존 다이어리 저장 형식은 바꾸지 않는다.

## 화면 기준

기존 surfaceSoft 배경 위 둥근 흰 카드를 세로 배치한다. 태블릿·iPad 우선이며 폰은 여백과 패딩을 줄이고 세로 스크롤을 제공한다. 기존 방향 규칙(태블릿 가로·폰 세로)과 상태 바 숨김을 따른다.

키보드 회피는 iOS padding·Android height를 사용한다. 포커스 이동·키보드 표시 완료·뷰 크기 변경 후 입력칸의 현재 좌표를 측정해 키보드/뷰 경계 안에 여백 16을 두도록 스크롤한다. 실제 OS 애니메이션은 실기기 확인 대상이다.

로고 참조: [Google 로그인 브랜딩](https://developers.google.com/identity/branding-guidelines), [카카오 로그인 디자인](https://developers.kakao.com/docs/ko/kakaologin/design-guide).

## 검증

- 관련 상태·서비스 테스트: `node --test tests/auth.test.js tests/auth-state.test.js`
- 전체 테스트: `node --test --test-concurrency=1 tests/*.test.js`
- 번들: `pnpm exec expo export --platform all`
- 브라우저: 8096 포트에 Expo 웹 서버를 켜고 `node tests/auth-screens-browser.cjs`. 독립 fixture에서 1280×800·1024×768·390×844·320×568·844×390 화면, 링크 한 줄 배치, 가입·로그인, 닉네임 재확인, 필수 동의, 실제 파일 선택·삭제 전후 위치를 확인한다. 결과는 무시되는 `.expo/auth-results`에 저장한다.
- 실기기 추가 확인: iOS·Android 키보드·비밀번호 표시·사진 선택 및 자르기·시스템 뒤로가기. 번들/브라우저 성공이 실기기 확인을 대신하지 않는다.
