# 링크 입력창 키보드 회피 (182)

링크 입력창은 자체 SafeAreaProvider/SafeAreaView 안에서 키보드 위의 가용 공간에 배치한다. iOS는 KeyboardAvoidingView의 padding, Android는 height 방식을 사용한다. 가로·세로 회전을 지원하며 가용 높이가 작으면 내용 전체를 스크롤해 URL 입력·오류 안내·적용/취소/링크 제거 버튼에 접근한다. 키보드가 열린 상태에서도 버튼의 첫 탭을 처리한다.

텍스트 상자 전체·선택 문자열·사진/스티커 링크는 같은 모달을 사용한다. 링크 정규화, 추가/수정/제거/열기/취소와 배지 설정은 기존 로직을 유지한다. API·저장 형식 변경이나 데이터 마이그레이션은 없다.

## 검증

- `node --test tests/text-link-dialog.test.js tests/text-formats.test.js tests/text-editor-render.test.js`: 키보드 회피·회전·스크롤 구성과 링크 액션 계약을 확인한다. 네이티브 키보드가 차지하는 실제 화면 높이는 자동 테스트에서 재현하지 않는다.
- iPad 통합 QA: 텍스트 상자와 선택 문자열에서 각각 링크 창을 열고 가로/세로 화면에서 URL 입력란, 오류 안내와 적용/취소/제거 버튼 접근을 확인한다. 키보드 닫기·재열기, 열린 상태에서 회전, 링크 재편집도 확인한다. 작은 가용 높이에서는 스크롤해 모든 버튼을 사용할 수 있어야 한다.
- 사용자가 178번 연필 질감이 포함된 통합 QA 버전에서 182번 iPad QA 완료를 확인했다. 모델·iPadOS·방향·키보드 종류와 항목별 결과는 별도로 전달되지 않았다. Android 실기기는 미검증이다.
