## 1. 끝점·접합부와 잉크 표현

끝 좌표의 한 점으로 외곽을 접던 처리를 제거했다. 각 입력 구간을 가변 폭 사각형으로 연결하고, 바깥 꺾임과 실제 시작·끝에 원호를 추가한다. 만년필은 고정된 축의 작은 타원(주축 배율 1/0.88), 붓펜은 원형이다. 모든 하위 경로의 winding을 통일해 되짚기·작은 원에서 채움이 상쇄되지 않는다. 소수 셋째 자리 반올림 후 생길 수 있는 가는 접합선은 최대 0.04 논리 좌표의 겹침으로 보완했다. 저장된 압력 변화는 유지하고 인위적 첨단은 만들지 않는다.

`penSweeps`는 실제로 필요한 바깥 원호만 생성한다. 각 점에 원 전체를 그리는 초안보다 경로량을 줄였다. 지우개는 같은 윤곽의 각 하위 다각형을 독립적으로 판정한다.

- 만년필: 기본 농도 약 80~88%, 시작·끝의 짧은 구간은 최대 98%. 몸통을 계속 채우며 은은한 농도 차이로 잉크 느낌을 낸다. 임의 노이즈나 내부 구멍은 넣지 않는다.
- 붓펜: 누적 이동 거리 120까지 약 96%, 120~480 구간에서 smoothstep으로 약 56%까지 옅어진다. 길이는 페이지 논리 좌표 기준이며 확대 배율과 무관하다. 짧은 획은 진하게 유지되고 새 획마다 초기화된다.
- 1% 농도 단계로 최대 만년필 19개/붓펜 41개 Path를 사용한다. 같은 단계의 모든 조각은 하나의 nonzero Path로 합쳐 미리보기 분할·되짚기에서 알파가 불필요하게 누적되지 않는다. 서로 다른 획이 겹치면 자연스럽게 더 진해진다.
- 완성된 미리보기 조각은 WeakMap으로 재사용한다. 끝 잉크 고임은 마지막 24 논리 좌표 구간을 따로 계산해 분할 경계에 굳지 않게 한다. 농도 재표본 간격은 최소 6이며 과도하게 먼 두 점의 추가 표본도 제한한다.
- `InkStrokeContent`를 실시간 미리보기와 `StrokeContent`에서 공유한다. 저장 화면·썸네일·내보내기도 이 공통 렌더러를 사용한다.

## 2. 실제 필압 확인과 붓펜

Apple Pencil Pro/1·2세대 사용을 사용자에게 확인했다. UIKit의 `UITouch.force / maximumPossibleForce`로 정규화된 필압을 받을 수 있다. 다만 현재 설치된 RN 0.88의 `RCTSurfaceTouchHandler.mm:73`은 `RCTForceTouchAvailable()` 조건 아래에서만 force를 전달하고, `RCTUtils.mm:726`은 기기의 forceTouchCapability를 확인한다. 따라서 필압 지원 펜이라는 사실만으로 현재 Expo Go의 터치 이벤트에 값이 전달된다고 단정할 수 없다.

`RCTSurfacePointerHandler.mm:392`에는 이 조건 없이 정규화하는 별도 포인터 경로가 있지만 현재 PenInput은 responder/touch를 사용한다. 이번 변경은 현재 경로가 전달한 force를 소비한다. 네이티브 포인터 경로 전환·네이티브 코드 패치는 포함하지 않는다. 실기기에서 모두 0/누락이면 현재 Expo Go에서는 실제 필압 미수신이며, 이를 확보하려면 개발 빌드에서 입력 경로를 추가 검증해야 한다.

- 유효한 force가 오면 속도보다 우선한다. 만년필 배율은 0.85~1.10, 붓펜은 0.18~1.40이며 센서값의 제곱근에 따라 연속적으로 변한다.
- force 미수신 환경에서는 만년필 약 0.94~1.06, 붓펜 약 0.85~1.15로 속도 보정을 제한한다. 이를 실제 필압이라고 표시하지 않는다.
- 입력 단계에서 시간 기반 평활화를 적용하고 결과 배율을 기존 pressure 필드에 저장한다. 정지 중 필압 변화는 꼬리 점만 갱신하며 중복 좌표를 추가하지 않는다.
- 일시적으로 센서값이 누락되면 마지막 값을 유지한다. touch-up의 force=0은 펜을 드는 절차상 값이므로 강제 첨단을 만드는 데 사용하지 않는다.
- 이전 임시 조정(끝 굵기 25%, 길이 12)은 제거했다. 시작·끝이라는 이유로 획 전체를 가늘게 만들지 않는다. 누르는 힘을 유지한 획은 두툼하게, 이동하며 힘을 뺀 획은 저장된 압력 흐름에 따라 가늘게 끝난다.
- 미리보기 완성 구간 재사용·꼬리 분할을 유지한다. 누적 시작 거리는 이제 잉크 농도 계산에 사용한다.

개발 QA 서버에서 `EXPO_PUBLIC_PEN_PRESSURE_DEBUG=1`을 켜면 획 종료 시 로컬 콘솔에 `[pen-pressure]`로 source, 샘플 수, 최소·최대 force만 출력한다. 좌표·문서·텍스트를 기록하거나 외부로 전송하지 않는다. `speed-fallback`이면 실제 필압을 받지 못한 것이고, `force`여도 최소·최대가 동일하면 변화하는 실제 필압 수신이 입증된 것은 아니다. 2026-10-26 사용자가 Reload 후 압력을 바꿔 필기를 완료했고 서버 로그를 확인했다. 조회된 만년필·붓펜 로그는 모두 `source: speed-fallback`, `samples: 0`, `min/max: null`이었다. 현재 Expo Go/responder 경로에서는 유효한 필압이 수신되지 않았다. 따라서 이번 기기 QA는 속도 보정의 동작 확인이며 실제 필압 기반 굵기 표현의 성공으로 처리하지 않는다. 이는 펜 자체의 고장을 뜻하지 않는다. 실제 필압 지원 완료를 위해서는 개발 빌드의 네이티브 입력 전달 경로를 보완하고 재검증해야 한다.

참고: [Apple UIKit 필압](https://developer.apple.com/documentation/uikit/uitouch/force), 사용자가 제공한 만년필·붓펜 영상의 일정한 획 굵기와 힘을 빼는 끝맺음.

## 데이터 영향

좌표·pressure·위치·크기·회전은 유지한다. 영역 지우기 후에는 남은 조각에 선택 필드 `inkStartDistance`를 저장해 뒤쪽 농도가 초기화되지 않게 한다. 이 값은 JSON 저장/복원과 출력 스냅샷에 보존되며 출력에서는 유한한 0 이상 값만 허용한다.

renderVersion 2의 기존 만년필·붓펜도 새 윤곽과 재질로 표시된다. renderVersion 1은 유지한다. 렌더러 변경만으로 문서 수정이나 Undo 이력을 만들지 않는다. 영역 지우기는 기존의 한 단계 Undo/Redo를 유지한다.

## 실측 필압 경로와 신규 재질 (2026-10-26 후속, 269·299)

아래 내용이 새 입력의 현재 기준이다. 위 renderVersion 2 설명은 이미 작성한 필기의 호환 경로로 유지한다. 기존 문서의 좌표·버전·종류를 변경하지 않는다.

### 입력과 공통 필기감

- 설치된 RN 0.88의 `RCTSurfaceTouchHandler.mm`은 `RCTForceTouchAvailable()`일 때만 force를 채운다. `RCTSurfacePointerHandler.mm`은 Pencil의 force/maximumPossibleForce를 직접 정규화한다. `withPointerEvents` 플러그인은 iOS AppDelegate 시작 시 `RCTSetDispatchW3CPointerEvents(true)`를 호출하도록 확장했다. 기존 Android 설정도 유지한다.
- `penPointerInput`이 pen 포인터의 실측 pressure·기울기·좌표를 전달한다. 마우스·손가락은 기존 responder 경로를 사용한다. 같은 Pencil에서 두 이벤트 계열이 발생해도 한 경로만 획을 확정한다. 지우개용 palm-aware usePan에도 같은 소유권 처리를 적용했다.
- 지원하는 웹 브라우저에서는 `getCoalescedEvents()`의 실제 표본을 시간 순서대로 모으고 중복을 거른다. RN 0.88 포인터 JS payload에는 하드웨어 timestamp와 coalesced/predicted 표본이 노출되지 않으므로 이를 지원한다고 주장하지 않는다. 이 경우 synthetic event/수신 시간을 사용한다. 예측 표본은 저장하지 않으며 예측 미리보기는 이번 범위에 없다.
- 새 펜 입력에는 최대 위치 보정 0.8 페이지 단위의 적응형 필터를 사용한다. 느린 미세 떨림은 완화하고 빠른 이동·급회전·해제 위치는 보존한다. 형광펜의 경로 보정은 변경하지 않는다. 펜을 뗄 때 force=0으로 끝을 인위적으로 줄이지 않는다.
- 버전 3의 새 좌표에만 사용 가능한 원시 force, 상대 time, tiltX/Y, 이동 speed와 inkDistance를 포함한다. force/speed/inkDistance는 소수 4자리, time/tilt는 1자리로 저장한다. 좌표와 굵기 배율 pressure는 반올림하지 않는다. 버전 1/2 및 형광펜·연필에는 센서 필드를 추가하지 않는다. 기존 필기에 센서값을 만들어 넣지 않는다. responder가 양수 실측값을 전달하기 전의 0은 미지원 입력으로 보고 force를 저장하지 않으며, 실제 pen 포인터의 0 또는 실측 후의 0과 구분한다.

### 새 만년필·펠트펜만 renderVersion 3

- PenInput에서 새로 쓰는 fountain/felt에만 버전 3과 id 기반 materialSeed를 부여한다. 저수준 createStroke의 기본 버전은 2로 유지하며 구버전/버전 2 렌더러는 그대로다. 붓펜·연필·형광펜의 재질은 변경하지 않는다.

### 2026-10-27: 선택 표시 해제 후 남은 입력 중단 조사

## 미리보기 → 확정 획 표시 인계 보완 (display-handoff-v1)

확인한 구조상 문제: 웹 PenInput.onEnd가 미리보기를 먼저 비우고 addObjects를 dispatch했으며, 확정 SVG의 커밋을 확인하는 인계 절차가 없었다. 이 순서에 따른 표시 공백 가능 경로를 수정했다. Safari 사용자가 보고한 모든 씹힘의 단일 원인이라고 확정한 것은 아니다.

웹의 preview store는 현재 획과 표시 인계를 기다리는 확정 후보를 분리한다. 종료 시 최종 미리보기를 대기 목록으로 옮기고 원본 저장 획을 추가한다. PageObject의 layout commit에서 해당 stroke id를 확인한 뒤 그 획의 대기 미리보기만 제거한다. 다음 획이 먼저 시작되거나 인계 순서가 달라도 별개로 처리한다. SVG와 Profiler는 같은 획이 현재→대기로 이동하는 동안 같은 노드/측정 수명을 유지한다. 도구·배율 전환/언마운트는 대기를 정리하고, 확인 누락 시 1초 뒤 timeout으로 정리해 임시 획이 영구 잔상으로 남지 않게 한다. 네이티브 인계 방식과 저장 데이터는 변경하지 않았다.

stroke-handoff 보고에 inputTraceId/sequence와 committed/cancelled/timeout 사유, 인계 elapsedMs를 기록한다. 이는 확정 노드의 레이아웃 커밋이며 물리 화면 표시 완료 보장은 아니다. 멈춤 버튼은 화면 상태가 바뀐 뒤 처음 누를 때 display-pixel-probe도 수집한다. 캐시 Canvas 내부의 알파 유무만 검사해 cachedBatches/emptyCachedBatches/unreadableCachedBatches, 임시 미리보기/확정 벡터 노드 개수를 남긴다. 픽셀 배열과 좌표는 보내지 않는다. 읽기 비용(probeJsMs)을 분리하고 같은 상태에서 반복 누를 때 재읽지 않는다. 실제 디스플레이 합성/프레젠테이션까지 관측하는 것은 아니다.

검증: test:pen 93개 통과. 문서 표시 지연 중 이전 획 보존, 다음 획 독립성, 역순 커밋, 언마운트 정리를 검증했다. 별도 캐시 계획/픽셀 진단 테스트도 통과했다. 최종 데스크톱 Chrome의 실제 pen 포인터 경로로 캐시 켜짐/100획 위에 간격 없이 20획을 추가했다. 20개 인계 모두 committed, DOM 관찰 공백 0, 남은 임시 미리보기 0이었다. 스크린샷 픽셀 검사에서 20개 선을 확인했다(tmp/web-cache-check/handoff-rapid20.png). 픽셀 진단 버튼은 13개 캐시 중 빈 캐시/읽기 실패/대기 미리보기 모두 0을 반환했다. Safari 실기기의 연속 필기 개선 여부는 재검증 전까지 미확정이다.

## 개별 획 캐시 비교 및 공통 입력 좌표 기준 보정

사용자는 캐시를 켜고 꺼도 연속 필기 씹힘에 차이가 없다고 보고했다. 따라서 캐시를 단일 원인으로 좁히지 않는다. 공통 pointer 입력의 시작점이 이벤트 대상의 offsetX/Y에 의존하는 경로를 확인해 입력을 소유한 View의 getBoundingClientRect와 clientX/Y를 기준으로 바꿨다. CSS 변환 배율은 계산된 View 크기/실제 rect 크기로 환산한다. 소유 View 정보를 제공하지 않는 네이티브/기존 입력은 native location/offset 경로를 유지한다. 자식 요소 offset과 무관한 좌표가 계산되는 테스트를 추가했다. 이 경로가 실제 Safari 신고의 원인이라는 확정은 아직 아니다.

QA 캐시는 초기 perf- fixture를 제외한 새 획마다 원래 SVG 그룹을 단독으로 같은 크기·위치의 reference Canvas에 그린다. source-over 합성의 알파는 개별 획보다 작아지지 않는 성질로, reference 알파>=16인 픽셀에서 combined 알파가 8 초과 낮은 지점을 집계한다. 겹친 획도 비교 가능하다. stroke-raster-audit에는 ordinal/expectedPixels/missingPixels와 auditMs만 보내며 픽셀·좌표·원본 SVG·원본 id는 보내지 않는다. 누락이 있거나 검사에 실패하면 캐시 전환을 하지 않고 원본 SVG를 유지한다.
