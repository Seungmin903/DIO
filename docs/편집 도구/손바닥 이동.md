# 손바닥 도구 연속 이동

관련 Jira: [S15P31F106-159](https://ssafy.atlassian.net/browse/S15P31F106-159)

## 변경

이전 QA 실행 코드에서는 손바닥 이동 시 마지막 렌더링의 offset에 이벤트별 이동량을 더했다. 재렌더링 전에 이벤트가 여러 번 들어오면 이동량 일부가 누락될 수 있었다.

최신 develop(385460b)은 이미 Viewport의 liveRef에서 제스처 좌표를 누적하고, 이동 중 transform으로 표시하다 손을 뗄 때 부모에 확정하는 구조로 개선돼 있다. 이 MR은 해당 구조를 유지하면서 중앙 배치·경계 제한·현재 보기 기준 이동 계산을 viewport.js로 분리하고 회귀 테스트를 추가한다. 이전 onPan 콜백 방식으로 되돌리지 않는다.

- resolvePan은 이전 렌더링 offset 대신 Viewport가 전달한 현재 보기(from)를 사용한다.
- 현재 제스처의 zoom을 우선 사용한다. 초기 보기에는 fitZoom × scale을 사용한다.
- 페이지 가장자리 80px을 남기는 기존 제한을 유지한다.
- 두 손가락 확대·이동과 휠 동작은 같은 경계 계산을 사용한다.
- 문서 저장 형식·서버 API·마이그레이션 변경은 없다.

## 검증

`cd frontend` 후 `node --test tests/viewport.test.js tests/viewport-input.test.js`로 실행한다. 총 6개 테스트가 통과했다.

레이어 열림·닫힘에 해당하는 편집 영역 너비, 렌더링 없이 연속 이벤트 누적, 확대 상태·현재 제스처 배율, 가장자리 제한을 검증한다. Viewport 실제 이벤트 핸들러에 30회 이동을 전달해 손바닥/두 손가락 결과가 같고 해제 시 한 번만 부모 상태를 확정하는 것도 검증했다. 테스트는 JS 핸들러를 실행하며 iPad 네이티브 터치 전달 자체를 재현하지는 않는다.

사용자는 이전 QA 코드의 좌표 누적 수정 후 iPad 이동감이 개선됐다고 확인했다. 최신 develop의 transform 구조와 공통 함수를 통합한 이 브랜치의 iPad 실행은 아직 확인하지 않았다. 요소 누적에 따른 필기 지연, 레이어 썸네일 및 올가미 변경은 이 MR 범위 밖이다.
