# 펜 성능 QA 자료

[펜 재질과 필압 QA](./펜%20재질과%20필압%20QA.md)가 해석과 최종 상태의 기준이다. 아래 JSON은 2026-10-26~28 Safari 및 데스크톱의 익명 계측 요약이다. 사용자 필기 좌표·내용을 담지 않는다. 회차별 배율·도구·대상·캐시 준비 상태가 다르므로 통제된 개선율이나 전체 기기의 통과로 사용하지 않는다.

반복 필기 기록은 요약 지표로 보관한다. penSummary의 p50OfStrokeMax·p95OfStrokeMax는 **획별 최대값의 분포**이며 전체 이벤트의 p50·p95가 아니다. 지우개 동작별 지표와 제한은 그대로 남긴다. 원래 획별 계측은 작업 PC의 로컬 QA 로그/보존 사본에만 있으며 CI 아티팩트로 업로드하지 않았다.

## Safari 캐시 준비 상태별 최신 확인 범위

아래 표는 최초 미실행 상태에서 시작했으며 최신 확인 범위를 상태 열에 반영했다. v5의 두 영역 동작은 캐시 75/79개에서 시작했으므로 초기 미준비·부분 준비 통과로 기록하지 않는다.

| 조건 | 확인 절차 | 남길 근거 | 상태 |
| --- | --- | --- | --- |
| 미준비 | 300획 선택 직후 표시 캐시 0개에서 영역 지우기 시작 | 시작/완료 캐시 수, 조각 생성·preview→layout·확정→layout, 첫 표시 | 초기 지우기 확인; 복원/이력은 회차 분리 |
| 부분 준비 | 300획 캐시가 일부 준비됐고 남은 벡터가 있을 때 영역 지우기 | 실제 준비/대상 묶음 수, 지연, 지운 뒤 이웃 획 유지 | v4 캐시 12개에서 확인 |
| 유휴 복구 | 위 두 조건에서 손을 뗀 뒤 캐시 완료까지 기다림 | 원본/조각 복구 횟수, 임시 표시 제거, 정밀 농도·끝점 육안 확인 | 부분 준비 v4 및 육안 확인 |
| 캐시 불가/실패 | 예산 초과 또는 시험용 실패를 유도한 뒤 영역 지우기 | 정밀 SVG 대체, 빈 획/잔상 없음, 화면 오류 없음 | QA 강제 두 조건에서 기능·이력·육안 확인; 실제 기기 고장/OOM 미검증 |
| 이력·후속 입력 | 각 조건에서 즉시 필기, Undo/Redo, 확대·이동 | 원본 복귀 및 재지우기 결과, 입력 수락/확정 대응, 질감 유지 | 단일 이력 v4 확인; 같은 시나리오의 후속 입력 미확인 |

조건마다 같은 배율·도구·획 수를 기록한다. commit/layout은 물리 화면 표시 시각과 구분하고, 복구 처리 횟수는 고유 객체 수로 해석하지 않는다. 강제 실패의 단위 테스트나 데스크톱 재현을 Safari 실기기 통과로 옮기지 않는다.

캐시 미준비/부분 준비의 재현을 위한 전용 화면은 `?qa=cache-preparation`이다. 300획/배율 0.6에서 생성 큐를 각각 0개/12개로 제한하고 명시적으로 복원을 시작한다. 이는 자연 캐시 준비 타이밍 측정과 구분한다. 최신 조작 순서와 데스크톱 확인은 [펜 QA 문서](./펜%20재질과%20필압%20QA.md)의 “캐시 준비 상태별 Safari QA 진입점”을 따른다. 위 표는 2026-10-27 사용자 재검증 결과를 반영한 현재 상태다. 확인된 부분 준비·정밀 복원·단일 이력과 미확인인 연속 시나리오·실패 대체 등을 구분한다.

## 2026-10-27 최종 사용자 재검증

- [준비 상태와 단일 이력 Safari QA 2026-10-27.json](./준비%20상태와%20단일%20이력%20Safari%20QA%202026-10-27.json): v4 미준비 단일 이력 및 부분 준비 12개·영역 지우기·정밀 복원·단일 이력 집계.
- 위 QA 표 중 부분 준비·유휴 복구·해당 조건의 단일 이력은 이번 한정 시나리오에서 확인했다. 사용자도 빈틈·잔상이 없음을 확인했다. 미준비는 초기 지우기/복원을 앞선 회차에서, 실제 commit 기반 단일 이력을 v4에서 나누어 확인했으므로 하나의 완결된 v4 시나리오로 쓰지 않는다.
- 강제 실패/예산 초과의 최신 Safari 결과는 아래 절을 따른다. 네이티브·장시간 메모리·실제 기기 고장/OOM은 미실행이고 SVG 대체 시 지연도 남는다. 현재 확인 범위와 제한은 위 표·이 절·펜 QA 문서가 동일하게 구분한다.

## v5~v7 표시 경량화·재사용·피드백 수신

- [임시 잉크 경로 경량화 2026-10-27.json](./임시%20잉크%20경로%20경량화%202026-10-27.json): 임시 표시 경로 크기 및 수정 전후 정밀600획 동등성의 합성 확인. Safari 지연 개선율 자료가 아니다.
- [재사용과 수신 확인 Safari QA 2026-10-27.json](./재사용과%20수신%20확인%20Safari%20QA%202026-10-27.json): v7 미준비8건/부분 준비14건 재사용, 복원·단일 이력 정상, 느림2건의 누름/저장 대응.
- **느림2건은 사용자 설명에 따라 수신 확인용으로 분류한다.** 원시slow값을 실제 체감 문제 보고로 해석하지 않으며, 이 두 건으로 성능 개선 또는 잔존 문제를 결론내리지 않는다.
- 부분 준비 첫 지우기는 캐시11개에서 시작해 정확한12개 고정 조건은 아니다. 검증 범위·남은 항목과 회차 비교 제한은 펜 QA 문서를 따른다.

실패/예산 초과의 다음 실기기 QA는 `?qa=cache-fallback&v=1`에서 준비했다. 기본100획으로 래스터 시작 실패와 QA 픽셀 예산1px 제한을 분리하며 정밀SVG 대체·영역 지우기·Undo/Redo 뒤 정밀/임시 개수와 데이터 일치를 확인한다. 두 조건의 데스크톱 재현 이후 Safari에서도 기능·이력·육안을 확인했다. 아래 최신 결과에서 성능과 실제 기기 고장/OOM의 미검증 범위를 구분한다. 상세 순서는 펜 QA 문서를 따른다.

## 캐시 실패·예산 초과 Safari 확인

- [캐시 실패와 예산 초과 Safari QA 2026-10-27.json](./캐시%20실패와%20예산%20초과%20Safari%20QA%202026-10-27.json): 100획·0.6배율의 실패주입/1px 예산 제한, 영역 지우기·정밀SVG대체·단일이력 정상. 사용자도 빈틈·잔상 없음을 확인했다.
- 정밀 복원이 완료된 `fallback`·`svg-undo`·`svg-redo` 단계에서는 캐시0·임시표시0이며 정밀SVG개수가 해당 상태의 객체수와 일치한다. 실패 조건의 데이터 반영 직후 `erased`·`undo`·`redo` 단계에는 임시SVG가28~86개 남아 있었고, 정밀+임시SVG 합계가 객체수와 일치했다. 예산 제한 조건은 기록된 모든 단계에서 임시0이었다. 데이터 일치는 표시 복원 완료와 별도로 전체 문서 대조로 확인했다.
- 대체SVG 최대 프레임간격216ms로 성능 통과가 아니다. 실제GPU/디코더고장·OOM·자연최초진입·네이티브·장시간 검증은 별도다.
