# 속지 글꼴 (S15P31F106-848)

속지 설정에서 고른 글꼴로 **속지에 인쇄된 글자**(날짜 · 요일 · 이름표 · 플래너 숫자 · 발색 기록의 라벨)를 바꾼다. 사용자가 쓴 글(글상자)이 아니라 속지에 원래 찍혀 있는 글자 이야기다.

## 바꾼 이유 (2026-11-11)

> "아니 그냥 글자를 표에 저장하는 방식인 게 이상한데" · "설정한 글꼴로 글자를 속지용으로 쓰면 되잖아" · "글꼴이 추가됐을 때도 대응이 되는 게 맞으니까" — 사용자

그전까지는 글꼴마다 **글자 윤곽 표**를 떠 두고 원본 윤곽을 바꿔 끼웠다. 그래서 세 가지가 따라왔다.

| 문제 | 겪은 일 |
| --- | --- |
| 속지에 새 글자가 들어오면 표에 없다 | 그 글자만 원본 글꼴로 남는다. 오류가 안 나서 조용히 지나간다 — 실측 43자가 그랬다 |
| 새 글꼴은 표를 뽑기 전에는 못 쓴다 | 글꼴을 더해도 속지에서는 못 고른다 |
| 표가 여섯 벌에 1.8MB | 글자를 늘릴수록 앱이 커진다 |

지금은 **진짜 글꼴로 쓴 `<text>`** 로 바꾼다. 글자가 늘든 글꼴이 늘든 저절로 따라온다.

## 어떻게 되어 있나

속지 SVG 의 인쇄 글자는 원본(마루부리) 글자 윤곽이다. 그대로 두면 글꼴 파일 없이도 곧바로 그려진다 — 기본값이 가장 빠르고 확실하다. 원본이 아닌 글꼴을 고를 때만 바꾼다.

```
<g fill="#292929" aria-label="데일리 플래너" data-adv="182.991" data-w="B" data-fit="408">…</g>
  ↓ swapPaperFont(xml, 'gowun-dodum')
<text x="40" y="70" fill="#292929" aria-label="데일리 플래너" font-family="GowunDodum, serif"
      font-size="30" font-weight="400" stroke="#292929" stroke-width="1.2" stroke-linejoin="round"
      xml:space="preserve">데일리 플래너</text>
```

| 파일 | 하는 일 |
| --- | --- |
| `src/editor/templates/paperFont.js` | 묶음을 읽고(`readGroup`) 바꾼다(`swapPaperFont`) |
| `src/editor/templates/paperTextFont.js` | 묶음 하나 → `<text>`. 글꼴 이름을 고른다 |
| `src/editor/templates/paperFontWidths.js` | 글꼴별 **글자 폭**(숫자 15KB). 넘치는 묶음만 줄이는 데 쓴다 |
| `scripts/bake-paper-metrics.mjs` | 정적 속지 SVG 에 치수(`data-adv` · `data-w` · `data-fit`)를 구워 넣는다. `--force` 로 다시 센다 |
| `scripts/paperMetrics/maruburi.js` | 그 치수를 구할 때 쓰는 원본 글꼴 확인표 — **빌드 전용**, 앱에 안 들어간다 |
| `scripts/generate-paper-fonts.py` | 확인표와 글자 폭 표를 만든다 |

### 자리가 안 깨지는 이유 — 넘칠 때만 줄인다

고른 글꼴로 썼을 때가 **그 자리보다 넓어질 때만** 글자 크기를 줄인다. 좁은 것은 그대로 둔다 — 왼쪽에 붙어 조금 허전할 뿐 깨지지 않는다(사용자 2026-11-11 "좁은 건 괜찮아").

견주는 자리는 원래 글자 폭이 아니라 **기준점 둘레로 쓸 수 있는 전체 폭**(`data-fit`)이다. 글꼴이 바뀌면 글자는 기준점(`data-anchor`)에서 자라므로, 그 방향으로 처음 나오는 세로선 · 네모 테두리 · 다른 글자까지를 잰다.

| 기준점 | 글자가 자라는 쪽 | `data-fit` |
| --- | --- | --- |
| 시작(적지 않음) | 오른쪽 | 오른쪽 한계 − 시작 x |
| 끝(`end`) | 왼쪽 | 끝 x − 왼쪽 한계 |
| 가운데(`middle`) | 양쪽 반씩 | 2 × min(가운데 − 왼쪽 한계, 오른쪽 한계 − 가운데) |

굽는 쪽(`bake-paper-metrics.mjs`)과 코드로 그리는 쪽(`dated.js` 의 `fit`)이 이 뜻을 함께 쓴다. 처음에는 굽기가 기준점과 상관없이 시작 x 에서 오른쪽 폭만 재어, 가운데 맞춤은 실제 여유보다 엄격하게, 끝 맞춤은 엉뚱한 쪽(오른쪽) 여유로 판정됐다(코드리뷰 2026-11-11).

원래 글자 폭을 기준 삼으면 안 된다 — 마루부리 숫자 `1` 이 유난히 좁아서, `1` 이 든 라벨마다 줄어든다(실측: 나눔고딕에서 4,984 중 **3,116** 묶음). 옆 숫자와 크기가 달라져 오히려 깨져 보인다.

실제로 줄어드는 정적 속지 묶음은 지금 **없다**(나눔고딕 4,984 중 0). 쓸 폭을 오른쪽으로만 재던 때는 주간 저널의 가운데 맞춤 `11` 12개가 92% 로 줄었는데, 양쪽 여유를 보니 넉넉히 들어간다. 크게 줄어들면 옆 글자와 크기가 달라져 눈에 띄므로 `tests/paper-font.test.js` 가 **바닥 85%** 와 **2% 미만**을 지킨다.

> **`textLength` 는 쓰지 않는다.** 처음에는 그것으로 폭을 묶으려 했는데, react-native-svg 가 아직 적용하지 않는다 — `android/.../TextLayoutAlgorithm.java` 에 `TODO Apply 'textLength' attribute` 가 그대로 있고, 2026-11-11 실기 측정에서 다섯 라벨 모두 자연 폭으로 그려졌다(측정값은 아래). 나중에 지원되면 조용히 모양이 바뀌므로 아예 쓰지 않는다.

### 굵기

굵기는 **글꼴 이름**으로 정하고 `font-weight` 는 400 으로 못 박는다. `font-weight="bold"` 로 맡기면 기기가 굵게 흉내 내어 진짜 Bold 글꼴과 겹친다(데일리 플래너의 할 일 글이 쓰는 방식과 같다). Bold 글꼴이 없는 글꼴(고운돋움 · 나눔손글씨 펜 · 푸어스토리)은 같은 색 덧선으로 굵게 만든다 — 예전 윤곽 교체 때와 같은 두께다.

### 글꼴 목록은 한 곳에서

글꼴 이름은 앱 글꼴 목록(`src/editor/utils/text.js` 의 `TEXT_FONTS`)에서 그대로 가져온다. 속지용으로 따로 적어 두면 글꼴을 더했을 때 또 한 곳을 빠뜨린다. **글자 도구가 쓰는 글꼴이면 속지도 쓸 수 있다.**

### 글꼴 불러오기

원본이 아닌 글꼴을 고르면 그 글꼴 파일이 기기에 있어야 한다. `paperDeviceFontIds(assetId, 고른글꼴)` 이 필요한 글꼴을 모아 주고, `PageBackground` 가 불러오며 다 불러오면 속지를 다시 그린다. 원본(마루부리)이면 윤곽이라 아무것도 필요 없다. 내보내기는 `ensureExportFonts` 가 먼저 기다린다.

## 치수는 속지가 들고 다닌다

글꼴을 바꾸려면 두 가지를 알아야 하는데 SVG 에는 적혀 있지 않다.

- 그 묶음이 Regular 인지 Bold 인지 — 원본 윤곽은 모양이 같고 시작점 · 순서만 달라 `path` 문자열로는 못 가른다.
- 묶음이 차지한 폭 — 글자 폭(advance)은 윤곽에 없다. `textLength` 에 필요하다.

처음에는 앱이 원본 글꼴 확인표를 들고 다니며 그때그때 알아냈다. 그러면 **속지에 새 글자가 들어올 때마다 그 표를 다시 뽑아야** 했다. 그래서 치수를 아예 속지에 적어 둔다.

```html
<g aria-label="데일리 플래너" data-adv="182.991" data-w="B" data-fit="408">…</g>
<g aria-label="MON" data-adv="27.938" data-anchor="end" data-fit="118.763">…</g>
```

`data-anchor` 는 **맞춰 놓은 자리**(가운데 · 오른쪽)다. 글꼴이 바뀌면 폭이 달라지므로, 첫 글자 x 만 지키면 가운데 · 오른쪽 맞춤이 왼쪽으로 쏠린다. 굽기가 이웃 묶음까지 보고 한 번만 판정해 적어 둔다(예전 윤곽 교체가 줄마다 하던 일). 판정 순서는 이렇다.

1. 같은 줄 이웃(셋 이상)의 그 가장자리가 **일정한 간격의 정수배**로 떨어지는가 — 칸에 맞춘 가장자리다.
2. 다른 줄의 같은 크기 묶음과 그 가장자리가 **같은 x**(세로 정렬)인가 — 달력 여섯째 주처럼 둘만 있는 줄도 가른다.
3. 그 가장자리가 0.5 단위에 떨어지는가.

처음에는 3만 보았는데, 가로 월간 달력은 칸 폭이 134.857 이라 칸에 맞춘 시작 x 도 0.5 단위에 안 떨어지고, 글자 폭 때문에 우연히 떨어진 끝이 표를 더 얻었다. 그래서 앞달 회색 날짜 651개가 끝 · 가운데 맞춤으로 읽혀 있었다(코드리뷰 2026-11-11). 데일리 속지의 시간 숫자(06~05)도 줄마다 시작 · 끝이 섞여 있었는데, 실제로는 모두 가운데가 같은 x(706.59)에 맞춰져 있어 이제 가운데 맞춤으로 읽는다.

- **정적 속지**(`assets/templates/**`): `node scripts/bake-paper-metrics.mjs` 가 한 번 구워 넣는다(`data-fit` 포함). 이미 적혀 있으면 건드리지 않아 다시 돌려도 결과가 같다. 지금 4,984 묶음이 자기 치수를 들고 있다.
- **코드로 그리는 속지**(스터디 · 데일리 · 여행 노선 · 날짜 · 발색 기록 덮개): 그릴 때 바로 적는다(`plannerDraw.write` · `dated.js` · `inkRecordPaper.js`). 이쪽은 글자 폭을 이미 알고 있어서 공짜다.

그래서 **앱에는 글자 윤곽 표가 없다.** 확인표(`scripts/paperMetrics/maruburi.js`)는 굽는 데만 쓰는 빌드 전용 자료다. 치수가 없는 묶음은 손대지 않아 원본 글꼴로 남는다.

앱에 남는 표는 **글자 폭 표**(`src/editor/templates/paperFontWidths.js`, 숫자뿐 15KB) 하나다. 고른 글꼴로 쓰면 자리(`data-fit`)를 넘는지 판단할 때만 쓴다. 이 표가 낡으면 폭을 몰라 **줄이기가 조용히 빠진다**(넓은 글꼴이 칸을 넘어도 그대로 그린다). 그래서 글꼴이나 속지 글자를 더하면 `python scripts/generate-paper-fonts.py` 로 이 표도 다시 뽑아 함께 커밋한다. 빠뜨리면 `tests/paper-font-coverage.test.js` 가 잡는다(속지 글꼴마다 폭 표가 있는지, 속지 글자가 모두 들어 있는지).

새 속지를 넣고 굽기를 빠뜨리면 `tests/paper-font-coverage.test.js` 가 먼저 잡는다.

> 구우면서 찾은 것: `dated.js` 가 요일 이름을 흐리게 할 때 `<g fill="#666666" aria-label="MON">` 을 **문자열 그대로** 갈아 끼우고 있었다. 속성이 하나 늘자 조용히 안 바뀌었다 — 이제 `fill` 만 바꾼다.

## 검사

- `tests/paper-font.test.js` — 글자 · 자리 · 크기 · 색 유지, 넘칠 때만 줄이는지(`data-fit`), 맞춘 자리(`data-anchor`), `<tspan>` 을 쓰지 않는지, 굵기 처리, **속지 전부가 어느 글꼴에서도 묶음을 하나도 안 남기는지**(예전 표 방식이 글자를 빠뜨리던 자리), 글꼴 불러오기 목록
- `tests/paper-font-coverage.test.js` — 속지 글자 · 실행 중 글자가 확인표와 글자 폭 표에 다 있는지, 속지 글꼴마다 폭 표가 있는지, 확인표를 만드는 스크립트의 범위, 글꼴별 윤곽 표가 다시 생기지 않았는지
