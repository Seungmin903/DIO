# DIO 전수 QA — 화면 · 상태 목록

> 기준 코드 `origin/develop` a1407675. 코드에서 뽑은 **171개 화면 · 창 · 패널** 체크리스트이고, 진행 칸은 1차 점검(폰 전체 · 태블릿 일부) 결과다.
> 표기: `봄` 실기기에서 화면을 열어 봄(문제는 02 보고서), `·` 이번 차수에 못 봄 또는 해당 없음. M 표는 이번 차수에 일부만 돌았다(02 보고서 §0).
> 이 목록은 코드를 읽어 만들었다. 다음 파일은 문자열 위주로 읽어 아이콘 버튼이 빠졌을 수 있고, 실기기에서 보충한다: Canvas, DecorDrawer, LayerPanel, PhotoCropper, FrameOptions, EffectOptions, TextEditor, ShapeTextEditor, FrameTextEditor, SelectionOverlay, StickerSplitModal, StickerCutoutModal, DayDatePicker, DayTimePicker.

### 기능 수준의 사실
- 「사진 속 대상 오리기」의 저장은 실제로 저장되지 않습니다. 확인창이 「미리보기 단계라 실제로는 저장되지 않아요.」라고 말합니다 (`StickerCutoutModal.js:243,247`).
- 폰트 생성은 Android 네이티브 모듈이 있을 때만 됩니다. iOS는 `available:false`입니다 (`src/handwriting/generator.js:9,16`).
- 스티커 시트 분리는 네이티브 모듈 API 버전이 맞아야 켜집니다 (`src/editor/utils/stickerSplit.js:16-18`).
- 네트워크 상태 감지 코드(NetInfo, onLine)가 없고 전역 오프라인 UI도 없습니다. 각 요청이 실패할 때 해당 문구만 나옵니다.
- 세션 만료 때 게스트로 돌리는 전역 처리가 없습니다. refresh가 401/403이면 세션만 null이 됩니다 (`authApi.js:462`). `clearSession`은 로그아웃, 비밀번호 재설정 완료, 탈퇴에서만 호출됩니다 (`App.js:116-127`, `ProfileScreen.js:90-91`).

## 정리 1. 재현이 어려운 특수 상태와 재현 아이디어

아래 방법은 코드에서 추론한 아이디어이며 실행해 보지 않았습니다. 서버 DB를 바꾸는 항목은 로컬 환경에서만 하세요.

| 상태 | 표시 | 재현 아이디어 |
|---|---|---|
| 오류 경계 (L1) | 복구 화면 | 앱 안에 트리거가 없음. `tests/fixtures/app-error-recovery.entry.js`가 있으니 이를 참고하거나, 개발 빌드에서 임시로 throw |
| 캔버스 409 충돌 (G10) | 저장 안 됨 + 충돌 문구 | 두 기기로 같은 요소를 고친 뒤, 한쪽에서 되돌리기. 또는 한쪽 비행기 모드로 편집 후 다른 쪽에서 수정, 복귀 |

## 정리 4. 로컬에서 이메일 인증 통과하기 (`C:/dqa/backend` 기준 사실)

**구조**
- 기본 프로필은 `local`입니다 (`application.yml`). `application-local.yml`은 `./.env`, `../.env`를 읽습니다.
- `SignupMailSender` 구현체는 `SmtpSignupMailSender` 하나입니다. local 프로필 전용 우회, 콘솔 출력, 고정 번호가 없습니다.
- 인증번호는 평문으로 저장되거나 로그에 남지 않습니다. `signup_email_verifications` 엔티티에 `HMAC-SHA256(secret, "email:code")` hex로 저장됩니다 (`SignupSecrets.java`).

**필요 설정**
| 설정 | 없을 때 |
|---|---|
| `SIGNUP_VERIFICATION_SECRET` (32바이트 이상) | 503 `VERIFICATION_NOT_CONFIGURED` |
| `SIGNUP_MAIL_FROM` | 503 `EMAIL_DELIVERY_UNAVAILABLE` |
| `SPRING_MAIL_HOST`, `PORT`(기본 587), `USERNAME`, `PASSWORD` | 메일 전송 불가 시 503 `EMAIL_DELIVERY_UNAVAILABLE` |
| `SPRING_MAIL_PROPERTIES_MAIL_SMTP_AUTH`(기본 true), `..._STARTTLS_ENABLE`(기본 true), `..._STARTTLS_REQUIRED`(기본 false) | 환경 변수로 변경 가능 |

**정책 값**: 번호 유효 600초, 재전송 60초, 실패 5회 후 새 번호 필요, 인증 후 가입 토큰 3600초입니다. 비밀번호 재설정도 같은 SMTP 설정을 쓰고, 번호 600초, 재전송 60초, 실패 5회입니다.

**통과 방법 세 가지**
1. **실제 SMTP 설정**: 위 환경 변수를 넣고 실제 메일함에서 번호를 받습니다. 코드가 공식으로 지원하는 경로입니다.
2. **로컬 시드 계정** (인증 자체를 건너뜀)
   - `@Profile("local")` + `DIO_LOCAL_SEED_ENABLED=true` + `DIO_LOCAL_SEED_FILE`이 필요합니다.
   - `LocalDemoSeedRunner`가 `users[{email,nickname,password,...}]`로 사용자와 EMAIL 계정을 만듭니다 (BCrypt).
   - 앱에서 바로 로그인할 수 있습니다. 다른 멤버 계정을 만들 때 가장 간단합니다.
   - 기본 파일 `src/main/resources/db/seed/local-demo.json`은 이 체크아웃에 없습니다. 직접 만들어야 하고, 파일이 없으면 기동이 실패합니다 (`IllegalStateException`).
   - `diaries[]`도 시드할 수 있습니다.
3. **DB 직접 조작** (코드에서 도출한 우회 방법이며 실행해 보지 않음)
   - 같은 secret으로 원하는 번호의 HMAC을 계산해 해당 행에 넣습니다.
   - `send()`는 `@Transactional`이고 메일 실패 시 `RuntimeException`으로 롤백되므로, SMTP가 없으면 행을 직접 만들어야 합니다.
   - 실제 칼럼 이름은 마이그레이션으로 확인하세요.

**앱 쪽 주의**
- 프론트의 고정 번호 `123456` 미리보기(`verificationPreview.js`)는 `service`가 없을 때만 씁니다. `AuthScreen`이 항상 `service.verificationService`를 넘기므로 일반 앱에서는 나오지 않습니다.
- 실기기 접속 주소는 `frontend/.env`의 `EXPO_PUBLIC_API_BASE_URL`입니다 (현재 `http://192.168.137.1:8080/api/v1`).
- 소셜 가입은 이메일 인증을 거치지 않지만 `AUTH_GOOGLE_CLIENT_IDS`(기본값 비어 있음) 설정과 개발 빌드가 필요합니다. 애플 기본값은 `com.f106.DIO`입니다.
