# PNG 파일 저장·진행·오류 안내 (S15P31F106-74)

## 사용 흐름

1. 상단 PNG 내보내기에서 현재 페이지를 스냅샷으로 고정한다.
2. 모든 필수 소재 로드와 PNG 생성이 끝난 뒤 미리보기와 PNG 파일 저장 버튼을 표시한다.
3. 저장 중에는 중복 실행과 닫기를 막는다. 완료·취소·실패를 구분해 지속적으로 안내한다.
4. 생성 실패는 다시 만들기, 저장 실패·취소는 다시 저장으로 재시도한다. 스냅샷 생성 자체에 실패한 경우 닫고 요소를 확인하도록 안내한다.

## 파일과 저장 계약

- 파일명: `DIO_<제목>_p<두 자리 페이지>_<YYYYMMDD_HHMMSS_mmm>.png`. 시각은 기기 현지 시각이며 경로/제어문자를 제거하고 제목을 48자로 제한한다. 내보내기 시작 시 고정해 저장 재시도에서 유지한다.
- 현재 페이지 한 장만 PNG로 저장한다. 기존 원본 GIF·미디어·편집 문서와 저장 스키마는 변경하지 않는다.
- Web: 사용자 클릭에서 showSaveFilePicker를 호출하고 write와 close가 모두 성공한 뒤에만 저장 완료로 표시한다. 대화상자 취소는 성공으로 처리하지 않는다.
- Web fallback: 지원하지 않는 브라우저는 PNG Blob의 별도 URL로 다운로드를 시작한다. 브라우저가 저장/취소 결과를 제공하지 않아 다운로드 시작으로 안내한다. 다운로드 목록 확인을 요청하며 별도 URL은 60초 뒤 해제한다.
- iOS/Android: 폴더 선택 대신 사진첩 저장을 기본으로 사용한다. expo-media-library의 추가 전용 권한(`writeOnly: true`, 읽기 대상 목록 없음)을 확인하고 필요하면 요청한다. 거부 시 다시 저장 안내, 재요청 불가 시 설정 열기 버튼을 제공한다.
- 원본 캡처를 호출 전용 캐시 폴더의 지정 파일명으로 복사한 뒤 사진첩 API 완료를 기다린다. 성공·실패 뒤에는 호출 전용 캐시만 정리하며 원본 캡처·미디어·사진첩 결과는 삭제하지 않는다.
- Android `content://` 폴더 복사와 저장 직후 size 비교 경로를 제거했다. 저장 성공은 사진첩 API 완료를 기준으로 판단한다. OS 사진 앱이 파일명 표시나 충돌 처리를 바꿀 수 있으므로 최종 표시 이름까지 보장하지 않는다.
- SDK 57 `saveToLibraryAsync`는 `expo-media-library/legacy` 진입점으로 사용한다. 루트의 같은 이름 함수는 런타임에서 실패하는 deprecated stub이다.
- 앱 설정에 사진 추가 권한 설명을 추가했다. 개발 빌드 사용자는 새 네이티브 모듈과 권한 설정을 반영해 다시 빌드해야 한다. JS 번들 갱신만으로 네이티브 설정이 바뀌지는 않는다.
- OS 공유 시트와 폴더 저장 선택지는 이번 기본 저장 UX에 추가하지 않는다.

## 실패와 자원 수명

- 필수 요소 하나라도 준비·로드·캡처에 실패하면 저장 버튼을 제공하지 않는다. 부분 결과를 성공으로 표시하지 않는다.
- 공간 부족·권한 문제·일반 저장 오류의 안내를 구분한다.
- 저장 대기 동안 캡처 결과를 유지하고, 종료 시 미리보기 자원을 해제한다. 다운로드 fallback URL은 미리보기와 독립적으로 소유한다.
- 재생성은 이전 시도를 해제한 뒤 새 시도로 실행한다. 저장 재시도는 완성된 PNG를 재사용한다.
- 네이티브 캐시 삭제는 최선의 시도다. 정리에 실패해도 사진첩 저장을 실패로 되돌리거나 사용자의 저장 결과를 삭제하지 않는다.

## 검증

- 출력 테스트 31개와 기존 미디어 25개, 총 56개 통과. Web·Android 번들 생성 통과.
- 파일명, 저장 중 중복 실행 차단·실패 후 재시도, 웹 write/close 완료 대기·취소·실패 abort, 다운로드 시작 상태·URL 해제, 네이티브 사진첩 저장 완료 대기·권한 거부/차단·복사/저장 실패 캐시 정리·원본 보존을 검증했다.
- 실제 iPhone/iPad/Android의 사진첩 추가 권한·설정 복귀·사진 앱의 PNG 확인·권한 거부·공간 부족 검증은 남아 있다. 네이티브 IO mock과 번들 통과는 실기기 검증을 대신하지 않는다.

## 참고

- [Expo SDK 57 MediaLibrary 공식 문서](https://docs.expo.dev/versions/v57.0.0/sdk/media-library/) 및 설치된 57.0.5 패키지의 legacy 구현·권한 플러그인을 확인했다.
- Windows Playwright 브라우저에서 1188×840 PNG 생성 후 저장 대화상자 API를 주입해 취소·공간 부족·실패 abort·재시도·저장 완료를 확인했다. 지연된 쓰기 동안 두 번 클릭해도 호출은 1회였고 저장/닫기 버튼은 비활성화됐다. 이 검증은 실제 OS 저장 대화상자 검증이 아니다.
- 다운로드 fallback은 브라우저에서 실제 39,423바이트 PNG 한 장을 다운로드했다. 파일 시그니처와 1188×840 헤더를 확인했고 UI는 저장 완료 대신 다운로드 시작으로 표시했다.
- 정상 GIF 스티커와 누락된 이미지가 함께 있는 페이지는 PNG 준비 실패로 표시됐고 저장 버튼이 나타나지 않았다. 다시 만들기를 눌러도 부분 결과가 성공으로 바뀌지 않으며 문서 요소가 보존됐다. 테스트 문서는 ID 확인 후 제거했다.

## 74번 리뷰 반영

- 사용자 결정에 따라 모바일 기본 저장을 사진첩 저장으로 교체했다. 기존 폴더 선택/SAF 크기 비교 문제 경로를 제거했다.
- 파일명은 UTC 대신 기기 현지 시각으로 생성하며 닫기 버튼의 접근성 이름을 `PNG 내보내기 닫기`로 통일했다.
- 웹 캡처 한계: 소재의 준비/로드 오류는 차단하지만 html-to-image 내부에서 이미지가 오류 없이 누락되는 경우를 결과 픽셀로 전수 검증하지는 않는다. 따라서 일부 실패 차단을 완전히 보장하지 못하며, 모든 이미지의 최종 포함 여부 검증은 후속 보완 대상이다.
- 이전 브라우저 검증 기록은 웹 저장 경로에 해당한다. 사진첩 UX는 IO mock/번들·권한 설정 확인 후에도 실기기 검증이 필요하다.
- 리뷰 반영 후 출력 31개 + 기존 미디어 25개 = 56개 테스트, Web·Android 번들 및 diff 검사 통과. `expo config --type introspect`로 iOS 사진 추가 권한 설명 반영을 확인했다. 네이티브 사진 저장·권한/설정 화면의 실기기 검증은 아직 수행하지 않았다.
