# 알림 오류 안내·재시도

2026-10-27. watermark 정책·인증 연결·BE 응답은 변경하지 않고 프런트 안내와 직접 재시도를 정리했다.

## 상태별 동작

| 오류 | 화면 안내 | 직접 재시도·복구 |
|---|---|---|
|401 | 로그인 후 알림 새로고침 안내 | 동일 요청 재시도 버튼 없음. 가짜 로그인 버튼·토큰 갱신·자동 로그아웃 없음. 외부 로그인 세션 연결 후 명시적 전체 새로고침으로 확인 |
|403 | 알림/초대 권한 없음 | 동일 요청 재시도 버튼 없음. 초대 상세 이동 차단. 권한 상태가 바뀐 뒤 새로고침/새 항목 확인으로 복구 |
|404 | 대상을 찾을 수 없으며 목록 확인 안내 | 동일 처리 재시도 없음. 목록 새로고침 버튼으로 목록·카운트만 갱신. 실패한 초대 상세는 재호출하지 않음 |
|5xx | 서버 오류, 잠시 후 다시 시도 안내 | 이전 목록/카운트 유지. 조회는 수동 재시도, 쓰기는 미확정 상태의 동일 명령만 수동 재시도 |
|네트워크 | 연결·네트워크 확인 안내 |5xx와 같은 복구 방식. 성공으로 간주하거나 항목을 미리 제거하지 않음 |

400/409/410/422의 같은 쓰기 재시도 제외 정책과429 처리·watermark 발급/적용 정책은 변경하지 않았다. 기존 전체 읽음 경계·재시도 회귀도 함께 통과했다. 이 작업은 watermark 계약 승인이나 실제 인증 구현을 포함하지 않는다.

## 구현 경계

`notificationErrorNotice.js`가 안전한 안내 문구와 직접 재시도 가능 여부를 제공한다. QueryNotice는 목록·카운트·초대 상세·더 보기에서 같은 정책을 사용한다. 쓰기 오류도 같은 안내를 사용하지만 canRetry/pending 명령은 기존 store 정책을 유지한다. 서버 내부 detail을 새 안내로 노출하지 않는다.

기존 조회 결과를 유지하되 목록·카운트가401/403이면 행 처리와 더 보기 버튼을 잠근다. 초대 상세403은 독립 상태여서 알림 읽음·삭제 성공 자체를 취소하지 않는다. 초대 오류 상태에서는 과거 상세로 이동할 수 없다.

store는 카운트401/403/404 후 주기 tick의 동일 재요청, 초대 상세의 직접 재시도, 권한/없는 대상 오류 뒤 더 보기 재요청을 막는다. 명시적 전체 새로고침·앱 복귀는 현재 상태를 다시 확인할 수 있다. 404 전용 `refreshNotifications()`는 목록·카운트만 갱신하고 열린 초대 상세를 다시 조회하지 않는다. 일반 새로고침 `refresh()`는 기존처럼 열린 상세도 갱신한다.

쓰는 중401/403/404는 pending을 해제해 retryMutation이 같은 명령을 다시 보내지 않는다. 서버/네트워크 오류는 pending을 보존하고 다른 쓰기를 막아 동일 명령만 재시도한다. 쓰기 성공 후 조회 실패는 쓰기 실패로 바꾸지 않는다. 카운트의 기존 활성30초 polling은 유지하며,5xx에서는 이후 tick으로도 갱신을 시도할 수 있다. 자동 쓰기 재시도·backoff·Retry-After 처리는 추가하지 않았다.

## 검증

- 프런트46개 통과: 상태별 안내·내부 메시지 비노출, 카운트 hard error 뒤 반복 차단/명시적 복구, 쓰기 상태별 동일 명령 재시도 여부, 초대403/404 이동 차단·목록 갱신의 gateway 미호출·회복, 기존 알림/HTTP/수명 회귀.
- 기존 실행에서 생성한 실제 Spring 응답으로 프런트 계약8개를 재실행해 통과. BE 생산자는 이번에 재실행하지 않았다.403은 공유 게이트웨이/목 오류 시나리오 기준이며 현재 알림 BE가403을 반환한다는 뜻이 아니다.
- 웹 개발 번들 `.expo/notification-errors-web` 생성 성공. 실제 JWT/공유 서버·네이티브 기기 검증은 별도다.
- 독립 Edge1280×800·412×892 모두 통과, pageerror0.401/403 재시도 버튼 부재·목록 오류 시 행 버튼 잠금,404 목록 새로고침 복구,5xx/네트워크 안내·재시도와 기존 초대/일반 알림 흐름을 확인했다. `DIO_NOTIFICATION_QA_ROOT=../.expo/notification-errors-web`, `DIO_NOTIFICATION_QA_PORT=18150`으로 `node qa/notification-browser.cjs` 실행.
- 개발용 목에401·403·404·네트워크 오류 선택을 추가했다. 제품 인증이나 서버 데이터를 사용하지 않는다.
- 커밋·푸시·MR·Jira 상태 변경은 하지 않았다.
