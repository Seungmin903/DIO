# 회원 보관함 즐겨찾기 연결

Jira: S15P31F106-485. 회원 보관함의 기존 별 버튼을 서버의 본인 멤버 상태에 연결한다.

## 계약과 동작

- `PATCH /api/v1/diaries/{diaryId}/membership`, JSON `{ "favorite": true }` 또는 `false`. 다른 멤버 상태 필드는 보내지 않는다.
- 백엔드 `DiaryProfileController`·`DiaryProfileUpdateRequest`·`DiaryProfileResponse` 기준이다. 응답의 `diaryId`, `userId`, `favorite`를 요청 다이어리·로그인 계정·목표 값과 대조한다.
- 목록 조회의 `myMembership.isFavorite`를 카드의 `favorite`로 읽는 기존 경로를 유지한다. 개인 소유자와 공유 편집자 모두 본인 즐겨찾기를 변경할 수 있다.
- 동일 다이어리의 연속 탭은 처리 중인 요청 하나로 합친다. 서버 성공 후 별·계정별 목록 캐시를 갱신한다. 즐겨찾기 필터에서 해제한 행은 제거하고 현재 검색·정렬·범위의 첫 페이지부터 재조회한다.
- PATCH 실패는 기존 별을 유지하고 안내 후 재시도할 수 있다. 서버 성공 후 캐시·목록 재조회 실패는 저장 실패로 되돌리지 않는다. 기존 목록 오류·재시도 경로로 재조회한다.
- 이전 목록·상세 응답 및 먼저 시작한 제목 수정 응답이 새 즐겨찾기를 덮어쓰지 않도록 한다. 계정 종료 뒤 응답은 상태·캐시에 반영하지 않는다.
- 기존 카드 디자인·게스트 즐겨찾기 경로를 유지한다. 백엔드·인프라·알림·폰트 변경은 없다.

## 자동 검증

2026-11-03, frontend에서 아래 6개 파일의 77개 테스트 통과:

```sh
node --test tests/member-favorite.test.js tests/member-app-store.test.js tests/member-library-integration.test.js tests/member-diary-api.test.js tests/library-controls.test.js tests/auth-routing.test.js
```

명시적 PATCH와 응답 검증, 개인·공유 계정의 별/필터/캐시, 재생성한 저장소의 복원, 연타, PATCH 실패·재시도, 늦은 조회·제목 수정 응답, 계정 전환, 저장 후 조회·캐시 실패를 확인한다. 보관함 테스트 도우미는 `SelectionBar`의 `done` 슬롯도 탐색하도록 보완했다. 실제 화면 컴포넌트의 선택 동작은 바꾸지 않았다.

리뷰 보완: 이미 종료된 저장소의 별 호출도 동기 예외 대신 `STALE_ACCOUNT`로 Promise를 거부한다. 호출부의 `.catch()`에서 처리되며 서버 요청·캐시 쓰기가 없음을 검증했다. 연타 시 동일 Promise를 반환하는 기존 검증도 유지한다.

## 실기기 확인

2026-11-03 사용자 확인 완료: Expo Go 리로드·일반 로그인 후 별 켜기(금색), 즐겨찾기 필터 표시, 리로드 후 유지, 별 해제 시 필터 목록에서 제거까지 정상 동작했다. 공유 다이어리와 다른 계정의 독립성은 별도 실기기 확인 기록이 없으며 자동 테스트 범위와 구분한다.

1. Expo Go 리로드 후 일반 로그인한다.
2. 보관함에서 서버 다이어리의 빈 별을 누르고 금색으로 바뀌는지 확인한다.
3. 즐겨찾기 필터에서 같은 다이어리가 표시되는지 확인한다.
4. 홈 재진입·앱 리로드 후에도 별과 필터 결과가 유지되는지 확인한다.
5. 즐겨찾기 필터 안에서 별을 해제하면 목록에서 빠지고, 전체 목록에서는 빈 별로 보이는지 확인한다.
6. 공유 다이어리도 같은 동작을 확인한다. 가능하면 다른 계정의 즐겨찾기는 바뀌지 않는지도 확인한다.

자동 테스트는 모의 서버 응답 기준이고 위 실기기 결과는 사용자 보고 기준이다. 실제 PATCH 응답 로그는 별도로 수집하지 않았다. 서버에서 응답이 유실되면 기존 별을 유지하고 안내하며, 다시 누르면 같은 목표 boolean을 보낼 수 있다.
