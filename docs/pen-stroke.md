# 펜 획 입력·렌더링 (S15P31F106-88)

## 완성 획 표시와 입력 갱신 분리 (2026-10-22)

- PenInput은 진행 좌표와 responder를 소유하고, 프레임별 미리보기는 입력 영역별 외부 저장소에 게시한다. PenPreview만 useSyncExternalStore로 구독하므로 미리보기 갱신마다 PenInput과 usePan을 다시 렌더하지 않는다. 해제·취소·배율/페이지/도구 전환·언마운트 시 미리보기를 비우고 대기 프레임을 취소한다. 좌표 수집과 저장은 여전히 기존 JS/PanResponder 경로이며, 네이티브 입력 스레드로 이전한 것은 아니다.
- 필기·형광펜 모드의 완성 획은 CompletedStrokeLayer가 최대 32개씩 표시 묶음으로 관리한다. 변하지 않은 묶음 객체와 React 하위 트리를 재사용하고, iOS shouldRasterizeIOS / Android renderToHardwareTextureAndroid로 네이티브 합성 캐시를 요청한다. 텍스트 측정 context는 필기 묶음 내부에서 차단해 글자 측정 콜백 변경이 완성 획까지 재렌더하지 않게 한다.
- 사진·글자·GIF 사이를 가로질러 획을 합치지 않는다. 원본 요소별 불투명도·회전·반전·위치와 레이어 순서를 유지한다. 새 획은 원래대로 한 번만 문서에 확정하며, 캐시 결과를 문서·Undo 이력·PNG/PDF 원본으로 저장하지 않는다. 기존 다이어리 변환이나 저장 형식 변경은 없다.
- 캐시 범위는 회전된 획 경계를 페이지 안으로 제한하고, 배율과 기기 픽셀 비율을 반영해 페이지당 총 4,194,304픽셀(색상 버퍼 약 16MiB), 한 변 4,096픽셀 이내만 허용한다. 초과 묶음도 원본 벡터로 계속 표시한다. 이는 앱이 요청하는 색상 버퍼 예산이며 OS/GPU 전체 메모리 사용량의 상한은 아니다. 화면 크기·배율·객체 참조가 바뀌면 계산과 표시가 갱신된다.
- 올가미·선택·지우개·읽기 모드, 썸네일과 내보내기는 원본 표시 경로를 사용한다. 획 선택·그룹 이동·회전·크기 변경·획/영역 지우기는 캐시 이미지가 아니라 원본 객체와 좌표로 판정한다. 편집기의 자르기·반투명 이동·변형 중에도 원본 표시로 돌아간다.

## 긴 연속 획의 입력 지연 개선 (2026-10-22)

- 원인: 기존 PenInput은 프레임마다 전체 누적 좌표에 createStroke를 적용해 경계·압력·상대 좌표를 다시 계산했다. StrokeContent는 만년필·붓펜 전체 경로를 2px 간격으로 재표본하고 윤곽과 사용하지 않는 중심선까지 재생성했다. 입력이 길수록 누적 작업과 임시 할당이 증가하며 JS 입력 처리와 경쟁한다. 입력 이벤트가 드물어지면 좌표 사이가 긴 선으로 보일 수 있다. 실기기 프로파일로 지연 비중을 측정한 것은 아니다.
- 입력 미리보기는 96개 간격의 완성 구간을 같은 객체로 재사용하고, 끝부분만 프레임당 갱신한다. 각 구간의 윤곽 계산도 메모화한다. 만년필·붓펜 미리보기의 재표본 수는 구간당 약 512+입력 점 수로 제한하고, 붓펜의 거리 기반 시작 테이퍼를 구간마다 재시작하지 않는다. 저장·출력의 원래 윤곽 계산은 기본값을 유지한다.
- 형광펜은 구간들을 하나의 투명도 그룹에, 연필은 공용 질감과 구간 클리핑에 넣어 접합부의 중복 농도를 방지한다. 완성 획 렌더러에서 불필요한 중심선 계산을 생략한다.
- 실제 입력 좌표는 줄이거나 버리지 않는다. 손을 떼면 한 번만 전체 저장 획으로 변환한다. 저장 형식·한 획 Undo·경계 밖 경로·선택 규칙은 유지한다.
- 직선 보정의 600ms 타이머가 150ms 넘게 늦게 실행되면 바로 직선으로 확정하지 않고 대기를 다시 시작한다. JS 지연·앱 배경 이후 밀린 이벤트를 끝점 정지로 오인할 가능성을 줄인다. 정상적으로 끝점에서 길게 눌러 직선을 만드는 기능은 유지한다.

## 입력 및 저장 형식

- 추가 요청: 펜 4종에도 끝점 600ms 유지 직선 보정을 제공한다. ‘선 보정 → 끝점에서 길게 눌러 직선 만들기’로 펜·형광펜 공통 보정을 켜고 끈다. 기본은 켬이며 편집 화면 세션 동안 유지한다. 미리보기만 보정하고 저장·Undo는 한 획이다. 기존 경계 밖 경로·올가미 선택 규칙은 유지한다. 최신 검증은 [통합 QA](./qa-editor-integration.md)를 참고한다.

- 펜·형광펜은 캔버스 바깥으로 나갔다 돌아와도 손을 뗄 때까지 하나의 획으로 기록한다. 바깥 좌표를 경계로 보정하거나 입력을 종료하지 않고 실제 이동 경로를 유지한다. 미리보기·저장 획·썸네일·출력은 페이지 영역으로 잘라 표시한다. 기존 저장 획은 다시 쓰지 않는다.
- 경계 밖으로 이동한 형광펜 획은 직선 유지 보정을 중단하고 원래 수집한 경로를 사용한다. 나간 지점과 재진입 지점을 임의의 직선으로 잇지 않는다.
- 새 획을 확정한 뒤 자동 선택을 해제한다. 미선택 획은 캔버스 직접 터치·근처 탭·일반 선택 도구의 영역 드래그 대상에서 제외한다. 올가미로 선택한 뒤에는 기존 이동·회전·크기 조절을 사용할 수 있다. 레이어 패널·키보드 명령은 이번 변경 범위에 포함하지 않는다.
- 위 경계·선택 변경은 사용자 요청에 따라 테스트·빌드·앱 화면·실기기 검증을 수행하지 않았다. 아래 검증 기록은 종전 구현에 대한 이력이며 이번 변경의 통과 결과를 의미하지 않는다.
- 펜을 선택하고 드래그하면 입력 중인 획을 미리 보여 준다. 미리보기는 문서 이력과 분리하고, 손을 떼면 `addObjects`로 한 획을 확정해 기존 되돌리기·다시 실행 이력에 연결한다. 취소된 제스처와 다중 터치로 중단된 획은 저장하지 않는다.
- 화면 입력 좌표와 이동량을 zoom으로 나눠 1188×840 페이지 논리 좌표로 변환한다. 페이지와 zoom 변경 시 진행 중 입력 상태를 초기화한다.
- Android의 바깥 ScrollView가 필기를 취소하지 않도록 펜 모드에서는 가로·세로 스크롤을 비활성화한다. 다른 도구 및 읽기 모드에서는 스크롤을 유지한다.
- 신규 로컬 요소는 다음 필드를 사용한다. 서버 API는 변경하지 않으며 기존 요소의 별도 마이그레이션은 필요하지 않다. 이전 버전 렌더러는 새 `stroke` 타입의 표시·내보내기를 지원하지 않을 수 있다.

| 필드 | 의미 |
| --- | --- |
| `type`, `id`, `name` | `type: 'stroke'`, 요소 식별자, 표시 이름 |
| `x`, `y`, `w`, `h`, `rotation` | 기존 요소와 같은 위치·크기·회전 필드 |

| `baseWidth`, `baseHeight` | 포인트가 사용하는 기준 좌표계의 크기 |
| `color`, `strokeWidth` | 선 색상과 기준 좌표계의 선 굵기 |

- 획의 경계를 계산해 페이지 좌표를 요소 내부 좌표로 바꾼다. 경계는 펜 두께 여백과 최소 20×20 크기를 갖는다. SVG `viewBox`로 현재 요소 크기에 맞춰 표시하며 단일 포인트도 점으로 렌더링한다.
- 88번의 기본 획은 색상 `#0B1957`, 굵기 3인 볼펜이다. 89번에서 설정 UI를 추가했으며 아래 계약을 따른다. 끝에서 길게 눌러 직선으로 바꾸는 보정은 포함하지 않는다.

## 펜 설정 (S15P31F106-89)

- 리본의 펜 버튼으로 설정 패널을 열고 닫는다. 다른 도구·꾸미기·읽기 모드로 전환하면 패널을 닫는다.
- 목업 기준 볼펜·만년필·붓펜·연필을 제공한다. 굵기는 1~16, 0.5 단위이며 미리보기에 즉시 반영한다. 초기 설정은 만년필·`#1D1D1F`·2.5이다.
- 볼펜은 일정한 굵기와 둥근 끝, 만년필은 45도 펜촉 방향과 이동 속도에 따른 굵기, 붓펜은 이동 속도·거리 기반 양 끝 테이퍼를 가진 단일 불투명 획, 연필은 연속된 흑연 입자 패턴으로 표현한다. 실제 스타일러스 압력·기울기 센서는 사용하지 않는다.
- 입력 시작 시 설정을 복사한다. 설정 변경은 미리보기와 다음 획에만 적용되며 입력 중인 획과 기존 문서 요소를 다시 쓰지 않는다. 도구 설정은 편집 화면 세션 동안 유지되고 앱 재실행 시 초기값으로 돌아간다.
- 신규 획에 `penKind`(`ball`, `fountain`, `brush`, `pencil`)와 포인트별 `pressure` 배율을 저장한다. `pressure`는 실제 센서 측정값이 아니라 굵기 표현용 배율이며 0 초과 2.3 이하이다. 기존 획에 이 필드가 없으면 기존의 일정 굵기를 유지한다. 별도 데이터 마이그레이션과 서버 API 변경은 없다.
- 신규 획에 `renderVersion: 2`를 기록한다. 이 값이 없는 이전 획은 기존 렌더링을 유지한다. 질감 변경이 이미 저장된 획에 소급 적용되지 않으며 별도 마이그레이션은 없다.
- 공통 `StrokeContent`가 저장된 배율로 곡선 외곽선을 그려 캔버스·썸네일·출력이 같은 데이터를 사용한다. 연필 입자는 고정 좌표의 SVG Pattern을 사용해 재렌더링 시 바뀌지 않는다. 178번에서 불규칙한 흑연 가루·입자·짧은 섬유 결로 교체했고, 미세 입자 크기를 일정하게 유지하고 가는 글씨의 바탕 농도·가장자리·반복 필기의 누적 농담을 조정한다. renderVersion 2의 기존 연필도 새 질감으로 표시한다([비교·검증](./pencil-graphite.md)). 패턴 ID는 인스턴스별로 분리한다. PNG 스냅샷에서 잘못된 배율은 `EXPORT_GEOMETRY_INVALID`로 거부한다.
- 공통 색상은 `utils/penSettings.js`의 `EDITOR_COLORS`에 정의한다. MVP1 목업의 격자 팔레트와 같은 12색이며 후속 격자 UI도 이 목록을 재사용한다. 이번 변경은 격자 기능을 구현하지 않는다.
- HEX 입력은 6자리 입력 시 즉시 적용하고 3자리 입력은 입력 종료 시 확장한다. 유효하지 않은 값은 마지막 정상 색상으로 복원하고 안내한다.
- 사용자 색상 프리셋은 AsyncStorage 키 `dio-editor-color-presets-v1`에 저장하며 최대 20개, 중복 없이 저장·삭제한다. 문서·되돌리기 이력과 분리된다. 저장 실패 시 성공한 것으로 표시하지 않고 안내한다.

### 설정 검증

- `frontend`에서 `node --test tests/pen-settings.test.js tests/strokes.test.js tests/page-export.test.js tests/gif-first-frame.test.js tests/png-file-save.test.js`: 총 37개 통과. 새 설정과 이전 획의 분리, 기존 획 기본값, 가변 굵기 여백·스냅샷, 잘못된 배율 및 HEX 입력, 저장·복원 후 질감 경로 재현을 검증한다.
- 웹에서 펜 종류·굵기·색상 변경, 미리보기, HEX 입력과 프리셋 저장, 설정한 붓펜 획 추가를 확인했다. 기존 획의 SVG 색상·굵기가 유지됨을 확인했다.
- Web·Android Expo export 성공. Android Hermes 임시 파일 쓰기가 샌드박스에서 거부되어 권한 승인 후 재실행했다. 번들 성공은 실제 태블릿 검증을 의미하지 않는다.
- Android 에뮬레이터에서 패널 열기·닫기, 굵기 슬라이더와 색상 변경, 미리보기, 설정한 분홍색 획의 입력 및 레이어 썸네일 추가를 확인했다. 확정된 요소의 공통 캔버스 표시 문제는 다른 담당자 범위이므로 이번 변경에서는 수정하지 않았다. 실제 태블릿·스타일러스와 네이티브 PNG 출력은 미검증이다.

## Android 입력 문제와 수정 범위

- 증상: 웹에서는 필기되지만 Android에서는 드래그한 획이 저장되지 않았다.
- 입력 영역 크기와 제스처 상태를 임시 표시해 확인한 결과, 입력 시작 후 종료 상태가 `cancelled=true`로 나타났다. 펜 선택 중 바깥 가로·세로 ScrollView를 비활성화하자 획이 정상적으로 확정됐다. 진단용 표시는 제거했다.
- 기존 공통 캔버스의 `StyleSheet.absoluteFillObject` 사용으로 요소가 보이지 않는 문제도 확인했으나, 해당 표시는 다른 담당자의 수정 범위여서 임시 수정은 원복했다. 이번 변경은 펜 전용 영역에 `StyleSheet.absoluteFill`을 적용하고 필기 제스처 충돌을 해결하는 데 한정한다.

## PNG 연동과 검증

- `createExportSnapshot`에서 `stroke`를 허용한다. 비어 있거나 유한하지 않은 포인트, 0 이하이거나 유한하지 않은 기준 크기·선 굵기는 `EXPORT_GEOMETRY_INVALID`로 거부한다.
- 필기는 이미지 원본 조회 없이 공통 `ObjectContent`의 SVG Path로 출력한다. 스냅샷은 포인트를 복사해 이후 편집이 출력 입력을 변경하지 않도록 한다.
- `frontend`에서 `node --test tests/strokes.test.js tests/page-export.test.js tests/gif-first-frame.test.js tests/png-file-save.test.js` 실행: 필기 2개와 기존 출력 31개, 총 33개 통과.
- 웹에서 필기, 배율 변경 시 입력 위치, 획 이동, 되돌리기·다시 실행, 저장 후 복원 및 필기 포함 PNG 미리보기를 확인했다.
- Android 15 / API 35 태블릿 에뮬레이터의 Expo Go에서 드래그 필기를 확인했다. 당시 공통 캔버스 표시 스타일은 임시 수정 상태였으며, 해당 수정은 다른 담당자의 작업이어서 이번 변경에서 제외했다. 팀원 표시 수정과 통합한 뒤 확정 획 표시 및 되돌리기·다시 실행을 다시 확인해야 한다.
- 실제 태블릿·스타일러스, iOS, 네이티브 필기 포함 PNG 캡처 품질은 미검증이다. 에뮬레이터 입력 확인은 실기기 및 네이티브 출력 검증을 대신하지 않는다.

- 필기 선택 바는 종류 표시(펜 선/형광펜)를 생략한다. 복제와 복사 혼동을 줄이기 위해 바로 사본을 만드는 복제만 남기며 삭제·잘라내기·정렬·보정은 유지한다.

- 펜·형광펜 설정 하단의 현재 색상 원을 누르면 기존 공통 ColorPicker의 색상 막대와 채도·밝기 영역이 펼쳐진다. 영역을 누르거나 끌어 색상 코드 없이 선택할 수 있으며 도구·미리보기·툴바 현재 색상 점에 즉시 반영한다. 기존 HEX 입력과 프리셋 저장은 유지한다.
