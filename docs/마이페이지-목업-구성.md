# 통계 없는 서비스형 마이페이지 목업

기준 화면은 [회원정보 반응형 목업](./회원정보-반응형-목업.html)이다. 이 문서는 화면 구성과 API 연결 경계를 설명하는 목업 설계 문서다. 현재 React Native 마이페이지(`ProfileScreen`·`ProfileEditScreen`·`PasswordResetScreen`·`NotificationSettingsScreen`)는 이 구성을 따른다.

## 화면 구성

- **내 공간**: 프로필 요약과 회원정보 수정·알림 설정·앱 정보·로그아웃을 그룹형 목록으로 표시한다. 다이어리 수·즐겨찾기 수 등 통계는 표시하지 않는다.
- 체험 계정·게스트 진입은 제거했으므로 로그인하지 않은 상태의 내 공간 화면은 두지 않는다. 로그인하지 않으면 로그인 화면으로 이동한다.
- **회원정보 수정**: 프로필 사진, 닉네임, 이메일, 로그인 방식, 비밀번호 재설정, 회원 탈퇴를 제공한다. 이메일 계정의 비밀번호 변경은 현재 비밀번호 입력 모달 대신 인증번호 기반 흐름을 사용한다.
- **알림 설정**: 서비스 알림과 마케팅 정보 수신을 분리한다. 기본값은 서비스 알림 켜짐, 마케팅 알림 꺼짐이다.
- **앱 정보**: 앱 버전 1.0.0, 문의 이메일 dioapp.official@gmail.com, 개인정보 처리방침, 오픈소스·콘텐츠 라이선스를 한 화면에 제공한다.
- **비밀번호 재설정**: 이메일 확인 → 인증번호 입력·재전송 → 새 비밀번호 설정 → 완료 후 로그인 안내의 네 단계다.

모바일은 하단 목적지 내비게이션을, 태블릿은 좌측 레일을 사용한다. 재설정 흐름은 뒤로 가기로만 이탈하게 하여 집중도를 높인다. 모든 가시적 버튼·목록 행·토글은 최소 48dp 터치 영역을 기준으로 잡는다.

## API 연결 메모

| 화면 행동 | API | 상태 |
| --- | --- | --- |
| 닉네임 저장 | PATCH /api/v1/me | 화면 연결됨. 사진 변경·회원 탈퇴는 서버 API 배포 전까지 비활성 |
| 인증번호 발송 | POST /api/v1/auth/password-reset-requests | 화면 연결됨 |
| 인증번호 확인 | POST /api/v1/auth/password-reset-verifications | 화면 연결됨 |
| 새 비밀번호 설정 | POST /api/v1/auth/password-resets | 화면 연결됨 |
| 서비스·마케팅 수신 설정 | 저장 API 미정 | 이 기기에만 저장(AsyncStorage `dio:preferences:notifications:v1`) |

비밀번호 재설정 완료는 기존 로그인 세션을 끝내므로 마지막 화면에서 로그인으로 돌아가게 한다. 마케팅 수신의 동의 문구·동의 일시·철회 보관 정책과 알림 설정 서버 저장 계약은 서버 연결 전에 별도로 확정한다.

## 산출물

모바일 414×896, 태블릿 1280×800 PNG 16장(8개 화면 × 모바일·태블릿)은 각 화면 이름과 기기 크기를 조합한 파일명으로 docs/에 둔다. 예: 마이페이지-홈-모바일.png, 마이페이지-홈-태블릿.png. 목업 이미지와 실제 앱이 다른 부분(닉네임 중복 확인 버튼 등)은 앱 동작을 기록한 [회원정보 수정·회원탈퇴](./profile-edit.md)를 따른다.
