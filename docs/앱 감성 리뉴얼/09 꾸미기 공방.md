# 09 꾸미기 공방 — 기능 카드 대신 결과물 한 장이 먼저

> **후속(사용자 지시, 2026-10-31)**: 아래 안의 결과 보드(폴라로이드 + 테이프)는 앱에서 **삭제**했다. 공방은 장식 카드 없이 **내 폰트 · 내 스티커 · 내 표지 · 내 속지 · 내 프리셋** 다섯 구역으로만 구성한다([14 §7](14%20로드맵과%20결정.md), 디자인 가이드 '꾸미기 공방'). 아래 시안 이미지는 이 지시 전의 비교안이다.

> 시안: 태블릿 1280 × 800 · 폰 390 × 844, 왼쪽 위부터 지금 · A · B · C. 수치는 코덱스 명세다.

## 한 줄 결론

**공방은 '기능을 고르는 곳'이 아니라 '재료를 만지는 곳'으로 보여야 한다.** 지금은 같은 모양의 흰 카드 3장에 기능 이름만 있어 결과물이 보이지 않는다. 조사한 꾸미기 앱은 모두 **큰 결과 미리보기 → 아래 정사각 재료 격자**의 한 문법을 쓴다(ZEPETO 옷장 · Color Widgets · 포토이즘, [03](03%20레퍼런스%20앱.md)). 그리고 지금 비활성 카드에 그대로 노출되는 **개발 문구("개발 빌드에서 사용 가능", "미리보기 · AI 분리·저장 미연결")는 감성 이전에 정리해야 한다.**

## 근거와 연결

- **결과물을 크게 먼저, 재료는 격자** — ZEPETO 옷장은 위 큰 미리보기 + 아래 탭 · 정사각 타일. DIO 공방의 "결과물이 안 보이고 기능 이름만 있다"는 진단에 대한 직접 답이다. 선택 타일 규칙(`primarySoft` + 테두리 2)은 DIO에 이미 같은 결이 있다.
- **재료를 사물로 고른다** — Dazz는 카메라 아이콘 + 이름, 포토이즘은 프레임 카드. C의 견본(Aa · 스티커 2 × 2 · 잘린 프레임)이 이 방향이다.
- **설정은 4행으로 얇게** — Color Widgets. 폰트 · 스티커 설정이 길어질 때의 기준.
- **가져오지 않는다** — 가격 · 재화 · 랜덤박스 · 구독. 3D 아이콘은 보관함 썸네일(콘텐츠) 안에서만.

## 접근성 · 구현

- **'준비 중' 처리** — 개발 문구는 사용자에게 내부 상태를 보여 주는 것이라 삭제하고, 기능 상태는 **"준비 중" 한 단어**로 정직하게 말한다. 비활성 투명도(.44~.52)는 가이드의 `DISABLED_OPACITY .4`와 같은 결이나 값이 다르다 — 구현 때 `.4`로 맞출지 정한다.
- **결과 미리보기는 정적 이미지**로 시작할 수 있다(1단계). 실제 스티커 · 테이프 조합이 실시간으로 반영되는 미리보기는 3단계 인터랙션이다.
- **새 에셋은 없다.** 기존 소품 PNG(폴라로이드 · 테이프 · `sticker-heart` · `star-clip`)만 쓴다. 편집기의 다색 3D 스티커(하트 · 별 · 고양이 · 곰 · 무지개 등)는 **UI 장식에 쓰지 않는다** — 색 규칙(UI 색상 계열 + 노랑) 밖이기 때문이다. 이 스티커 라이브러리는 사용자 콘텐츠이므로 그대로 둔다. UI 장식용 단색 스티커 세트가 필요해지면 코덱스가 낸 생성 프롬프트(`Flat hand-drawn diary sticker set, transparent background, limited palette only: butter yellow #FEF0BF, tape yellow #FBE5A3, periwinkle #DBDCF9, navy #0B1766, white #FFFFFF and black outline #010101 …, no gradients, no gloss, no 3D`)로 만든다(지금은 필요 없다).
- 비활성 카드 3개의 문구 · 구성은 팀원 영역(공방 화면) 코드와 맞닿으므로 구현 전에 담당자와 조율한다.

## 하지 않는 것

- 가격 · 재화 · 랜덤박스 · 구독 같은 상점 문법을 가져오지 않는다.
- 카드마다 장식을 붙이지 않는다(첫 카드 · 보드 한 곳).
- 노랑으로 타일 전체를 채우지 않는다(아이콘 면 · 테이프만).
- 설명 문장을 늘리지 않는다(가이드 §8).
