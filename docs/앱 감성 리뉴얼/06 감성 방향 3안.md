# 06 감성 방향 3안 — 색 규칙을 먼저 정하고, 그 안에서 방향 (개정 2판)

> 조사 02~05와 팀의 색 조건을 코덱스에게 넘겨 색 체계와 방향을 받았고(2026-10-31), 시안은 클로드가 HTML 목업으로 구현해 코덱스가 렌더를 눈으로 다시 검수했다. **색 · 모양 · 그림자 · 불투명도 수치는 코덱스 값**이다. 클로드가 바꾼 곳은 [12](12%20공통%20시스템과%20가이드%20변경.md)의 "구현 보정" 표에 모두 적었다.
> **개정 이유**: 1판은 핑크 · 민트 · 웜 오프화이트 같은 보조색으로 세 안을 구별했다. 팀이 **"색은 다이어리 캐릭터의 노랑과 우리 UI의 색상 계열(HUE)을 벗어나지 않고, 메인은 무조건 UI 색"** 이라고 조건을 걸어 색 체계를 처음부터 다시 짰고, 렌더 · 검수 · 문서를 모두 새로 만들었다.

## 한 줄 결론

**권장은 혼합안이다 — B 포토부스 콜라주(사진 · 테이프 · 프레임)를 주안으로, A의 로그인 빛과 종이결만 섞은 2안화.** 색이 UI 계열과 캐릭터 노랑으로 고정되자 세 안을 가르는 것은 색이 아니라 **구조 · 질감 · 캐릭터 노출**이 됐고, 코덱스는 렌더를 보고 "C는 독립안으로 너무 무표정하고 A와 구별되지 않아 B의 보조 언어로 흡수하는 편이 낫다"고 판단했다. 1판의 결론("A 기본 + B 일부")에서 무게가 B 쪽으로 옮겨 갔고, 구체 구성(로그인 · 홈 · 공방 · 내 공간 · 휴지통)은 실질적으로 같으며 **홈 선택 표지의 프레임과 `⋯` 버튼, 휴지통 표지의 원색 유지**가 달라졌다. 혼합안은 BI · CI를 바꾸지 않고, 색은 새 색상 계열을 하나도 들이지 않는다(검사 결과는 §1.1).

### 1.1 색 규칙 v2

**규칙은 이렇다.** 색상각(H)은 색의 종류를 0~360°로 나타낸 값이다. 캐릭터 최종 시안의 채움색이 이미 버터 노랑 · 라벤더 · 흰색 · 먹선 둘(UI 계열 + 노랑)뿐이라([01](01%20현재%20화면%20진단.md) 색 현황), 이 두 계열을 UI 전체의 색 어휘로 삼았다.

| 구분 | 허용 | 쓰는 곳 | 쓰지 않는 곳 |
|---|---|---|---|
| **UI 계열(메인)** | H 228~242° | 바탕 · 카드 · 선 · 글자 · 칩 · 버튼 · 그림자 · 라벤더 테이프 | — |
| **캐릭터 노랑(보조 하나)** | H 40~52° | 마스킹테이프 · 작은 상태 칩 · 점 · 고리 · 별 · 캐릭터 · 아이콘 배경 | 페이지 바탕 · 대형 배너 · 타일 · 카드 전체 · 메인 버튼 · 큰 빈 상태 면 |
| 무채색 | 채도 8% 이하(흰색 · 아주 옅은 회색) | 카드 · 입력 | — |
| **면적 상한(코덱스)** | UI 계열 + 흰색 | 로그인 · 내 공간 · 휴지통 98% 이상 · 홈 97% 이상(표지 제외) | 노랑은 각각 2% · 3% 이하, 공방은 5% 이하 |
| **예외** | ① 표지 · 사진 · 사용자 스티커(사용자 콘텐츠) ② 카카오 · 구글 · 애플 간편 로그인(외부 브랜드 규정색) ③ `danger`는 **영구 삭제 확인 단계 한 곳**의 기능 색 ④ **알림 점(읽지 않음)의 쿨톤 핑크 `#B63F7C` 하나** — 팀(사용자)이 "알림 동그라미는 쿨톤 핑크"로 직접 지시한 예외 | | 알림 점 · 삭제 아이콘 · 임박 글자의 적색은 쓰지 않는다. 핑크는 알림 점에만 쓴다 |

## 2. 세 방향

색이 같아져서 안을 가르는 축은 **구조 · 질감 · 노랑 쓰임 · 캐릭터 노출**이다. 이름은 유지했다.

| | **A 햇살 드로어리** | **B 포토부스 콜라주** ★ | **C 조용한 문구점** |
|---|---|---|---|
| 한 줄 | 여백이 큰 종이 위에 아침빛과 얇은 테이프만 남긴 일기장 | 흰 보드 위에 폴라로이드 · 라벨 · 테이프를 얹는 공동 기록 벽 | 규칙선 · 라벨 · 정돈된 진열의 조용한 도구 상자 |
| 키워드 | 종이결 · 흰 대각광 · 버터 테이프 | 폴라로이드 · 테이프 · 사진 프레임 | 규칙선 · 라벨 · 보관함 |
| 바탕 | `#F3F3F7` + 흰색 대각광 `linear-gradient(135deg,#FFFFFF,#F3F3F7 68%)` | `#F3F3F7` + 라벤더 번짐 `rgba(219,220,249,.34)` | `#F3F3F7` 평면 |
| 카드 모서리 · 그림자 | 22 · `0 8px 20px` .09 | 26 · `0 10px 24px` .11 | 16 · `0 4px 12px` .07 |
| 노랑 쓰임 | 상단 테이프 · 작은 점만 | 사진 고정 테이프 · 별 클립 · 상태 점 | 밑줄 같은 미세 포인트만 |
| 라벤더 단계 | `50` 중심, `100`은 레이어 | `50 / 100 / 200` 레이어가 가장 분명 | `50` 면, `200`은 아이콘 배경만 |
| 캐릭터 노출 | 빈 상태(둘이 + 테이프) | 빈 상태(둘이 + 폴라로이드 틀) | 빈 상태(디오 + 규칙선) |
| 감성 세기 | 중간 | 높음 | 낮음 |
| 유치함 위험 | 낮음 | 중간 | 매우 낮음 |

## 3. 정서 문구 — 허용 범위

코덱스 원칙: **로그인 첫 화면 · 빈 상태 · 완료 토스트에만, 한 화면 1개, 12자 이내, 기능 설명 · 행동 지시는 금지.**

| 위치 | 허용 예시 | 금지 예 |
|---|---|---|
| 로그인 | "오늘의 한 장을" | "친구들과 소중한 추억을 기록해요" |
| 빈 상태 | "아직 비어 있어요" | "+ 버튼을 눌러 다이어리를 만들어 보세요" |
| 휴지통 | "잠시 여기 있어요" | "걱정 마세요! 귀여운 일기는 안전해요" |
| 완료 토스트 | "붙였어요" · "저장했어요" | "완벽하게 완성되었어요!" |

- 휴지통의 영구 삭제 확인문은 정서 문구 없이 "영구 삭제할까요?"처럼 기능적으로 쓴다.
- **이 시안 렌더에는 정서 문구를 넣지 않았다.** 로그인 부제도 지웠다(옛 부제 "함께 기록하고, 추억을 나눠 보세요."는 '기록' · '추억'이 포화된 낱말이기도 하다, [05](05%20마케팅과%20포지셔닝.md)). 정서 문구를 허용할지는 **팀이 정할 일**이다(결정 칸). 클로드 · 코덱스는 '허용 범위'만 정리했고, 기본값은 지금처럼 **없음**이다.

## 4. 코덱스 검수와 최종 권고

세 안 × 화면의 렌더를 코덱스가 눈으로 검수했다(2026-10-31, 색 규칙 반영 후). `[구현]`은 의미 · 발견성 · 상태 표현 문제, `[취향]`은 밀도와 조형 판단이다. 보정 hex는 모두 허용 색상각 안이다.

| 화면 · 안 | 코덱스가 짚은 것 | 보정 |
|---|---|---|
| 로그인 · A | `[취향]` 테이프가 카드 상단에 너무 붙으면 카드 장식처럼 보임 | 테이프를 작게, 카드 상단에서 -7px, `#FBE5A3` opacity .72 |
| 로그인 · B | `[취향]` B의 정체성이 거의 안 드러남. 로그인에 콜라주를 억지로 넣는 것은 더 나쁨 | 장식 추가 안 함, 로그인은 A의 질감으로 통일 |
| 로그인 · C | `[취향]` B와 사실상 구별 안 됨 | 소셜 위 구분선만 `1px #D9DCEF` |
| 홈 · A | `[취향]` 안정적이나 A만의 기억점이 약함 | 장식 추가 없이 배경광만의 안으로 한정 |
| 홈 · B | `[구현]` 모든 표지에 흰 테두리가 상시 보이면 선택 상태가 모호 | 기본 `2px #D9DCEF` .7, 선택 때만 `3px #FFFFFF` + `0 8px 16px` .12 |
| 홈 · C | `[취향]` A와 구분되는 조형 언어가 거의 없음 | 탭 아래에만 `1px #D9DCEF` 규칙선 |
| 공방 · A | `[취향]` 장식 한 개로는 '만드는 곳' 정체성이 약함 | 첫 카드에만 작은 사진 1장 · 테이프 1장 이내 |
| 공방 · B | `[취향/한도 초과]` 사진 2 · 하트 · 별 · 테이프 2가 한 영역에 몰림 | **사진 2 + 테이프 1만**, 하트 · 별 제거. 보드 높이 태블릿 176 · 폰 132 |
| 공방 · C | `[구현]` 1 · 2 · 3단 규칙선이 비활성 스켈레톤이나 입력 줄처럼 읽힘 | 2 · 3번째 선 제거, 카드 좌상단 한 줄만 |
| 내 공간 · A | `[취향]` 연필(북마크)이 떠 보임, 배너와 통계 위계 약함 | 연필 삭제, 통계 카드 간격 14 |
| 내 공간 · B | `[취향]` 사진 세 장 + 테이프가 작은 배너에서 복잡 | 사진 2장 + 로고 카드, 테이프 1, 사진 폭 54 이하 |
| 내 공간 · C | `[취향]` 6px 띠는 파일철 · 시스템 바처럼 읽힘 | 상단 띠 `4px #D9DCEF` opacity .9 |
| 휴지통 · A | `[구현]` 표지 위 삭제 아이콘이 일반 상태에서 너무 직접적 | 아이콘 제거, 선택 모드에서만 체크박스 24 |
| 휴지통 · B | `[취향]` 표지를 회색화하면 사용자 콘텐츠를 비활성화한 인상 | 표지 원색 유지, 필요하면 `saturate(.78)` 이하만 |
| 휴지통 · C | `[구현]` 비선택 상태의 빈 체크 사각형이 로딩 실패처럼 보임 | 평상시 숨김, `선택` 진입 후만 24 |
| 빈 홈 · A / B | `[취향/구현]` 캐릭터 군이 작음 · 세부가 뭉개짐 | 군 최소 폭 태블릿 132 / 148, 폰 104 / 112 |
| 빈 휴지통 · C | `[취향]` 중심 오브젝트가 너무 작아 화면이 비어 보임 | 디오 높이 태블릿 54 · 폰 44 이상 |
| 홈 폰 · A B C | `[취향]` 표지가 시선을 독점해 'UI 메인 색' 인상이 약해짐 | 표지 기본 프레임 `2px #D9DCEF` .7, 선택 때만 흰 프레임 |
| 공방 폰 · A B C | `[취향]` C 규칙선 카드와 B 장식 밀도가 극단으로 갈림 | B 장식 축소 · C 단일 규칙선 |
| 내 공간 폰 · A B C | `[취향]` A는 배너 · 통계 · 정보 카드가 비슷한 흰 상자 | A는 통계 카드만 `#F0F1F9` |

**색 규칙 눈 점검**

| 항목 | 판정 |
|---|---|
| 메인이 UI 색으로 읽히는가 | 로그인 · 공방 · 내 공간 · 휴지통은 그렇다. **홈은 다색 표지가 시각적 주인공이라 수치로는 통과해도 체감은 경계선이다.** 표지는 사용자 콘텐츠로 두고 머리 · 탭 · FAB · 선택 프레임을 UI 색으로 고정한다(표지 색을 억제하지 않는다). |
| 노랑 면적 | 상한을 넘는 화면은 없다. B 공방만 테이프 · 별 · 하트가 겹쳐 '노랑 · 장식 남용'으로 보임 → 사진 2 + 테이프 1로 축소 |
| 노랑 부족 | C의 빈 홈 · 빈 휴지통은 캐릭터와 UI의 연결이 약함 → 노랑 면을 늘리지 말고 캐릭터 옆 테이프 1장만 |
| 알림 점 | 검수 때 코덱스 `#D69A1E`(흰색 위 2.47:1)를 `#B98208`로 보정했으나, **이후 사용자가 알림 점은 쿨톤 핑크로 하자고 해 `#B63F7C`로 확정**(§1.1 예외 ④) |
| 임박 칩 | 버터 `#FEF0BF` + 네이비 글자 + 금색 고리가 적절 |

**세 안의 거리.** A와 C는 지금 너무 비슷하다(둘 다 "흰 카드 + 라벤더 면 + 거의 없는 장식"). A는 로그인 외 화면에서 약하고, C는 별도 방향으로 밀기엔 너무 시스템적이다. B는 가장 차별되지만 공방 · 내 공간의 장식 밀도를 줄여야 한다. → **3안 유지보다 B 주안 + A 보조의 2안화**를 권한다.

**BI · CI 점검(코덱스).** `#818AC3` · `#606BB2` · `#0B1766`의 역할은 흔들리지 않는다. 노랑 테이프 · 사진은 로고에서 24px 이상 떨어뜨린다. B 공방 보드 · B 내 공간 배너는 1차 렌더에서 장식 한도(1~2개)를 넘었고 혼합안에서 사진 2장 · 테이프 1장으로 줄였다(사진은 콘텐츠성 장식으로 본다). 로고 크기는 지금 앱 값(높이 53) 그대로이며, 코덱스가 말한 '로고 폭 32~36px'은 지금 값을 작게 읽은 것이라 따르지 않았다.

**발견성 문제와 대안.** 홈에서 별 · 편집 · 삭제가 표지 위에서 빠진 것은 발견성 문제다. 코덱스 대안은 **선택 표지 우상단에 상시 `32px` 흰 원형 `⋯` 버튼 하나**를 두고, 탭하면 별 · 편집 · 삭제를 바텀시트로 여는 방식이다(혼합안 렌더에 반영). 폰에서는 길게 누르기만으로 숨기지 않는 편이 안전하다.
