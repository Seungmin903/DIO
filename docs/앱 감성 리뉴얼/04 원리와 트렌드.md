# 04 원리와 트렌드 — 감성은 무엇으로 만들고, 우리 제약 안에서 무엇이 되나

> 원자료: [조사 원자료/C 감성 원리와 트렌드](조사%20원자료/C%20감성%20원리와%20트렌드.md) (검색 39회 · 원문 열람 약 60건, 출처 66개). 아래 `C[숫자]`는 그 문서 §5 출처표 번호다. **(내 계산)**은 대비 비율처럼 조사자가 직접 계산한 값, **추정**은 근거 없이 짐작한 것이다.
> 계획의 반증 대상이던 가설 "Liquid Glass 같은 유행 효과가 감성의 핵심이다"는 **반증**됐다.

## 한 줄 결론

**감성은 한 겹이 아니라 첫인상(본능) · 조작감(행동) · 기억(반성) 세 겹으로 쌓이고, 우리 앱에서 효과가 가장 큰 자리는 '첫 화면 · 끝맺는 순간(완료 · 삭제 · 복원) · 제목 서체 한 곳'이다.** 유행 효과(유리 · 뉴모피즘)는 근거가 오히려 부정적이고, **질감 · 스티커 · 캐릭터 · 틴트 그림자 · 짧은 스프링 모션**이 우리 제약 안에서 오래 간다.

## 1. 원리 네 가지와 우리 화면의 자리

| 원리 | 요지 | 우리 화면에서 | 확인 정도 |
|---|---|---|---|
| **Norman 3수준** | 본능(첫인상) · 행동(사용 경험) · 반성(사용 뒤 떠올리는 이미지)이 쌓여 감성이 된다 | 행동(조작감)은 이미 공들였고 **본능(홈 · 로그인)과 반성(끝맺는 순간)이 비어 있다** | 이론 C[1][2] / 우리 진단은 **추정** |
| **Peak-end** | 경험은 가장 강한 순간(정점)과 끝으로 기억된다 | 정점 = 다이어리를 여는 순간 · 스티커를 붙이는 순간. 끝 = 저장 · 내보내기 완료, 삭제 · 복원, 로그아웃 | C[6] / 자리 지정은 **추정** |
| **예쁨은 작은 결함만 용서한다** | 매력적인 UI는 더 쓰기 쉽다고 지각되지만 큰 문제는 용서받지 못한다(NN/g 2024) | **폼 · 삭제 흐름은 감성을 입혀도 명확성이 먼저** | C[3] |
| **귀여움(baby schema)** | 큰 머리 · 둥근 얼굴이 귀엽다는 지각과 돌봄 동기를 높임(n=122). 귀여운 이미지를 본 뒤 손재주 과제 향상 43.9% vs 11.9%(n=48) | **캐릭터를 쓰는 근거**일 뿐 UI 전반의 귀여움 처방이 아님(대학생 표본 · 사진 자극) | C[7][8] |

## 2. 트렌드 선별 — 차분한 유틸리티 앱을 감성적으로 만드는 데 무엇이 유효한가

| 수단 | 판정 | 이유 |
|---|---|---|
| **질감 · 종이결 · 그레인**(큰 면, 저불투명도) | 유효 | 촉각 · 아날로그. 단 글자 뒤에는 쓰지 않고, 질감 자체의 접근성 연구는 못 찾음 |
| **스티커 · 콜라주 · 테이프** | 유효 | DIO의 정체성과 겹침. 사용자 콘텐츠 영역에서 자유 |
| **캐릭터 · 일러스트**(빈 상태 · 첫 장면 · 완료) | 유효 | 정서의 대부분을 문구가 아니라 그림이 담당 |
| **틴트 그림자**(네이비 → 면의 hue) | 유효 | 회색 그림자는 따뜻한 면에서 탁함. 우리 그림자는 이미 네이비 틴트 |
| **절제된 모션**(눌림 스프링 · 진입 ≤ 500ms) | 유효 | NN/g 100~500ms, ease-out 기본. 가이드 §10의 240~260ms와 일치 |
| 큰 곡률 · 알약 | 조건부 | baby schema 연상. 터치 영역 44는 유지 |
| 은은한 그라데이션 면 | 조건부 | 밴딩. `expo-linear-gradient` 추가 필요 |
| **Liquid Glass · 블러 유리 패널** | **비추천** | NN/g가 대비 · 가독성을 비판했고 Apple도 커스텀 컨트롤에는 "sparingly"라 함. Android는 구형 성능 저하 |
| **뉴모피즘** | **비추천** | 클릭 신호가 약한 화면은 과업 시간이 22% 늘었다는 NN/g 결과(뉴모피즘 자체를 잰 연구는 아니라 적용은 추정), 비텍스트 3:1 미달 위험 |
| Material 3 Expressive | 참고만 | 연구 근거(18~24세 선호 최대 87%)가 있지만 스스로 "명확성을 이기는 표현은 없다"고 경고 |
| 효과음 | 보류 | 무음 모드 존중, 소리만으로 전달 금지. 라이브러리 미조사 |

## 3. 지금 토큰에 있는 접근성 부채 (감성과 별개로 보정 대상)

감성 작업을 하든 안 하든 아래 네 곳은 WCAG 2.2 AA에 못 미친다(내 계산, 알파는 흰색 또는 `surfaceSoft` 위에 합성). **BI인 `text`(네이비) 계열은 건드리지 않는다.**

| 조합 | 대비 | 판정 | 어디에 영향 |
|---|---|---|---|
| `primaryStrong` 글자 / `surfaceSoft`(앱 배경) | **4.47** | 일반 글자 4.5 미달 | 앱 배경 위 파란 글자 |
| `danger` 글자 / 흰색 | **3.85** | 일반 글자 미달(13px/700은 큰 글자 아님) | "n일 후 영구 삭제" 같은 작은 위험 글자 |
| `border` / 흰색 · `surfaceSoft` | **1.39 · 1.38** | 비텍스트 3:1 미달 | 입력칸 경계가 유일한 단서일 때 |
| `primary` 선 / `surfaceSoft` | **2.98** | 비텍스트 3:1 미달 | 앱 배경 위 선택 테두리(색 + 두께로 보완 중) |
| (참고) `text` / 흰색 · `surfaceSoft` · `surfaceMuted` | 15.81 · 14.28 · 14.04 | 통과 | |
| (참고) 흰 글자 / `primaryStrong` | 4.95 | 통과 | 채운 버튼 |

- **면 색을 파스텔로 넓혀도 안전하다.** 후보 면 7종(버터 · 블러시 · 피치 · 민트 · 크림 · 라벤더 · 웜 화이트) 위의 `text` 대비는 11.97~14.91, `textMuted`는 5.17~5.71로 모두 4.5 이상이다(hex는 검증용 예시값이고 **색 선택은 코덱스 몫**). 위험은 면이 아니라 **그 위에 얹는 `primary` · `danger` · 흰 글자**다.
- **현재 팔레트는 색상 232°의 단색조**다. 따뜻한 색은 표지 · 테이프 · 소품 같은 콘텐츠 색에만 있다. 감정 연상 연구(Valdez & Mehrabian 1994 / Wilms & Oberfeld 2018)는 밝기와 각성의 방향이 서로 달라 **"파스텔 = 차분"이라고 단정할 수 없고**, UI 화면 연구도 아니다.
- 조사 당시에는 **웜 오프화이트 바탕과 따뜻한 보조 면이 대비 면에서 가능**하다고 봤고, `secondary #ABB1D8`은 "넓게 쓰지 않음" 규칙이 있어 면적을 키우지 않는다고 적었다. **이 중 '따뜻한 보조 면 7종'은 이후 팀의 색 규칙(UI 색상 계열 + 캐릭터 노랑만)으로 버터 하나로 좁혀졌다**([06](06%20감성%20방향%203안.md) §1.1). 대비 계산은 그대로 유효하다(버터 `#FEF0BF` 위 네이비 13.9:1).

### 3.1 색 조합 근거 — 라벤더 계열 메인 + 버터 노랑 보조 (2026-10-31 추가, 검색 4회)

팀이 "캐릭터 노랑과 UI 색상 계열만 쓰고 메인은 UI 색"으로 색을 고정한 뒤, 이 조합이 감성 면에서 무리가 없는지 공개 자료로 확인했다. **직접 근거는 약하다** — 두 색을 짝지은 앱 · 브랜드 사례와 10~20대 여성의 반응 자료는 찾지 못했다.

| 확인한 것 | 내용 | 출처 · 확인 방식 |
|---|---|---|
| 버터 노랑은 **지금 검색이 오르는 색** | 'butter yellow' 전 세계 검색이 2024/25년 2~5월 전년 대비 **+324%**. 'soft, pastel yellow with medium undertones', 불확실한 시기의 위안 · 낙관 · 향수와 연결, 어두운 글자와 짝지으라는 권고 | WGSN 블로그 `wgsn.com/en/blogs/butter-yellow-pulse` — **원문 열람** |
| 색 유행은 **주기가 있다** | SCMP는 2026년 여름을 '버터 옐로 → 터콰이즈'로 쓴 것으로 검색 결과에 나온다(원문은 403으로 **열람 못 함**, 제목 · 요약 기준). 같은 계열 기사는 버터 노랑이 더 따뜻한 색으로 이어질 것이라는 디자이너 예측도 전한다 | 검색 결과 요약만 |
| 'Pantone 2026 올해의 색'은 흰색 `Cloud Dancer` | 소란한 세상의 차분함 · 새 출발을 말한다. **옅고 조용한 바탕 + 작은 색 포인트**라는 우리 방향과 같은 결 | Pantone 발표를 다룬 다수 기사(검색 결과) — 원문 미열람 |
| 보색 관계의 두 색은 **한쪽을 조연으로** | 노랑 · 보라는 색상환 반대편이라 강하게 튀므로 60-30-10 비율로 나누고, 옅은 보라 · 무채색이 대부분을 맡고 노랑은 포인트로 쓰라는 설명 | `uxplanet.org` 등 검색 결과(원문 403, **열람 못 함**) · `cieden.com/book/sub-atomic/color/60-30-10-rule` **열람**: 60% 기본(보통 무채 · 저채도) · 30% 보조 · 10% 포인트, "엄격한 공식이 아니다", 포인트는 아껴 쓴다 |
| 색이 같은 방향의 따뜻함 · 차가움일 때만 어울린다는 반론 | "차가운 보라와 따뜻한 노랑은 불협일 수 있고, 둘 다 차갑게 기운 쪽이 어울린다"는 **단일 저권위 출처**. 우리 버터는 연한 색이라 이 위험이 작다고 **추정**하지만 시안으로 확인할 일이다 | 검색 결과 요약만 |

- **DIO에 주는 뜻(해석).** ① 노랑을 **큰 면이 아니라 포인트**로 쓰는 것은 60-30-10의 포인트 몫(10%)보다 더 좁게(화면 UI 면의 2~5%) 잡은 것이라 안전한 쪽이다. ② 노랑이 유행색이어서 주기가 있다는 위험은, DIO의 노랑이 **유행색이 아니라 캐릭터(모아)의 몸 색**이라는 점에서 줄어든다. 캐릭터 색은 유행이 지나도 바꾸지 않는다. ③ 노랑 위에는 항상 네이비 글자를 얹는다(WGSN의 "어두운 글자와 짝" 권고와 일치, 흰 글자는 1.14:1이라 불가).
- **한계.** 라벤더 + 버터 노랑을 쓰는 한국 앱 · 브랜드, 이 조합의 감성(차분함 · 따뜻함)을 직접 잰 연구는 **찾지 못했다.** 따라서 이 조합이 10~20대 여성에게 감성적으로 읽히는지는 가설이고 [14](14%20로드맵과%20결정.md)의 검증 항목에 넣었다.

## 4. 제목 서체 한 곳 — 허용할 만한가

현행 가이드 §3.1은 "UI 글자는 시스템 서체만"이다.

| 서체 | OFL 1.1 원문 확인 | 앱 현황 | 메모 |
|---|---|---|---|
| 고운돋움 | 확인 | **이미 번들 · 시작 때 preload** (7.2MB) | **Regular 한 벌뿐**이라 800 제목은 합성되거나 무시될 수 있음(추정) |
| 고운바탕 | 확인 | **이미 번들 · preload** (Regular 8.4MB / Bold 8.2MB) | Bold 실파일이 있어 굵은 제목 가능 |
| 나눔손글씨 펜 | 확인 | 이미 번들(@expo-google-fonts) | 예약 이름(RFN) 때문에 수정본에 같은 이름 금지 |
| Pretendard · 동글 · 하이멜로디 | 확인 | 미사용 | 동글은 굵기마다 약 4.4MB, 하이멜로디 12.6MB(제목 한 줄치고 무거움) |
| 마루부리 · 온글잎 | **미확인**(배포처 접속 차단 · 공식 원문 못 열람) | 미사용 | 사용 전 원문 확인 필요 |

| 항목 | 득 | 실 / 위험 |
|---|---|---|
| 첫인상 | 홈 · 로그인 제목에 손글씨 · 둥근 인상 | 가이드의 시스템 서체 일관성이 깨짐 |
| 용량 | 고운돋움 · 고운바탕은 **추가 0** | 새 서체는 +3~13MB. 서브셋은 Expo 기본 도구가 없어 별도 작업(추정) |
| 로딩 | 지금도 앱 시작 때 불러옴 | 첫 프레임에 못 불러오면 기본 서체로 깜빡임 |
| 굵기 | 고운바탕은 Bold 있음 | 고운돋움은 Regular만, iOS는 선언한 weight를 무시 → 실기기 확인 필요 |

- 참고로 가이드 §3.1의 사용자 글자 서체 목록에는 고운돋움 · 고운바탕이 없어 코드(`textFonts.js`)와 이미 어긋나 있다.
- 조사 B의 패턴 9("손글씨 제목은 마케팅 이미지에서 크게, 앱 안에서는 작게")도 같은 방향이다. **결론은 가이드 변경 결정 칸([12](12%20공통%20시스템과%20가이드%20변경.md))으로 넘기고**, 서체 없이 가는 대안안도 모든 화면 시안에 둔다.

## 5. 모션 · 햅틱 · 사운드

- **길이와 이징**: 100~500ms, 대부분 100~400ms, ease-out이 기본(NN/g). 가이드 §10의 240~260ms와 일치한다 C[42].
- **햅틱 · 사운드는 보완용이고 끌 수 있어야 한다**(Apple). 소리만으로 전달하지 않는다 C[38][39].
- **동작 줄이기**: 코드에서 reduce-motion 처리는 `ToolGuideAnimation.js` 한 파일뿐이다. 새 모션을 넣는다면 **필수 대응**이 먼저다.
- **도구 현황**: `package.json`에 Reanimated · Lottie · Skia · expo-haptics · expo-linear-gradient · expo-blur가 **하나도 없다**. 대부분 Expo Go에 포함되나 최종은 개발 빌드로 확인해야 한다(Android 실기기 · iOS 모두).
- **몰아줄 자리**(peak-end): 다이어리 여는 순간 · 스티커 붙이는 순간 · 저장 · 내보내기 완료 · 삭제 · 복원.

## 6. 마이크로카피 — 감성 톤 ≠ 친절한 안내 멘트

- 토스 · Apple · Mailchimp 모두 **명확성이 먼저**이고 톤은 상황에 맞춘다. "oops!" 같은 감탄사는 불성실하게 들린다는 지적이 있다 C[41][56][58].
- **우리 규칙(가이드 §8)과 양립하는 '정서 문구'**는 인사 한 줄 · 계절감 · 빈 상태의 사실형 한 줄이다. 사용법 · 결과 예고 · 다음 할 일 안내는 여전히 금지다.
- **정서의 대부분은 문구가 아니라 그림과 모션이 맡는 편이 안전하다.** 반복되면 닳고, 오글거림 위험이 있다(직접 근거는 없음, [02](02%20타깃%20조사.md) §5).
- 삭제 · 이별 순간의 감성 문구 사례는 공식 자료에서 못 찾았다. 영구 삭제는 **되돌릴 수 없으므로 귀여운 문구로 흐리지 않는다.**
- **폼 감성화의 선**: 입력 폼은 신뢰 · 속도가 우선이다. 가입 폼에 일러스트를 얹으면 전환이 떨어졌다는 보고가 있으나 2차 출처 · 수치 없음이라 약한 증거다. 조사 B에서도 로그인 폼을 꾸민 앱은 0곳이었다.

## 8. 한계

- 마루부리 · 온글잎 라이선스, 당근 · 카카오의 공개 UX 라이팅 원문, 삭제 · 이별 순간의 감성 문구 사례, 빈 상태 일러스트의 효과 측정, 가입 폼 감성화의 전환 영향, 그레인 질감의 접근성 연구는 **찾지 못했다.**
- 귀여움 · 색 연구는 대학생 표본이고 성별 근거가 없다. 10~20대 여성에 한정된 연구는 없다.
- 대비 수치는 조사자 계산이다. 구현 때 실제 렌더 색으로 다시 확인한다.
