# 12 공통 시스템과 가이드 변경 — 색 체계 · 값 · 모션 · 접근성 · 바꿔야 할 가이드 항목

> 디자인 가이드는 **아직 고치지 않았다.** 이 문서의 "가이드 변경" 표를 팀이 정한 뒤, 채택한 항목만 가이드를 먼저 고치고 같은 커밋에서 코드에 반영한다(가이드 §0). 이 판은 팀의 **색 규칙 v2**(UI 색상 계열 + 캐릭터 노랑만, 메인은 UI 색 — [06](06%20감성%20방향%203안.md) §1.1)를 반영한 2판이다.

## 한 줄 결론

**추천 혼합안은 새 색상 계열을 하나도 들이지 않고, 시스템 서체 · BI 토큰 · 선 아이콘도 그대로 둔다.** 필요한 가이드 변경은 §2.2에 **토큰 몇 개를 더하는 것**(라벤더 100 · 경계 · 노랑 3종 · 확인용 danger)과 색 쓰는 규칙(§2.3)에 한 줄을 보태는 것이다. 서체 변경은 가이드 변경이 필요한 사안이고, 코덱스도 "앱 UI는 시스템 800 유지"를 권장했다. 그리고 감성과 별개로 **접근성 부채 네 곳**은 어느 안을 고르든 보정해야 하며, 이번에는 이 네 곳을 **색상 계열을 넓히지 않고 같은 계열 안의 값으로** 푸는 방법을 찾았다(§3).

- **새 토큰은 다섯 종류뿐이다.** 라벤더 50 = 기존 `surfaceMuted`, 라벤더 200 = 기존 `secondary`이므로 새로 만들 값은 라벤더 100 `#DBDCF9` · 경계 `#D9DCEF` · 노랑 3종 · 확인용 `danger-confirm #B52E52`이다. 색상각 · 대비는 [06](06%20감성%20방향%203안.md) §1.1 표(색 검수 스크립트로 계산).
- 보조색의 네이비 글자 대비는 버터 13.9 · 테이프 12.7 · 라벤더 100 11.8로 모두 4.5를 크게 넘는다. 위험은 면이 아니라 그 위에 얹는 **흰 글자 · `primary` 선 · 금색**이다(노랑 위 흰 글자 1.14:1은 불가).
- 종이결은 SVG `feTurbulence`(새 래스터 없음)를 `opacity .025~.035`로 **바탕에만** 쓰고 글자 · 입력칸 · 표지 · 카드 위에는 쓰지 않는다. 새 래스터가 필요하면 `Seamless subtle warm off-white uncoated paper grain texture, flat 2D, no objects, no shadows, no text, very low contrast, 2048x2048` 프롬프트로 만든다(필수 아님; 색 규칙상 'warm'은 질감 색이 아니라 무채색 종이결을 뜻한다).
- **가이드와 코드가 다른 곳 하나.** 가이드 §2.4는 표지 색을 8색(세이지 `#A9BFA6` · 로즈 `#F0B0AA` · 페리윙클 `#A9AFD7`(기본) · 머스터드 `#EBC56F` · 라벤더 `#C3AEDD` · 차콜 · 카멜 · 크림)으로 적지만, 코드(`diary/constants.js`의 `COLORS`)는 6색(크림 · 라떼 · 더스티 로즈 · 세이지 · 스카이 · 차콜)이다. 이 조사는 **코드 값**을 현황으로 쓰고([01](01%20현재%20화면%20진단.md)), 시안의 표지 샘플은 가이드 8색과 앱 게스트 시드를 따랐다. 어느 쪽이 맞는지 팀이 확인한다.

## 3. 접근성 부채 — 안과 무관하게 보정 (색 규칙 안의 해법)

| 조합 | 대비 | 기준 | 영향 | 보정 방향(후보 · 모두 UI 색상 계열 안) |
|---|---|---|---|---|
| `primaryStrong` 글자 / `surfaceSoft` | 4.47 | 4.5 | 앱 배경 위 파란 글자 | 그 글자를 **`#525FAD`(5.27:1)**로 — 같은 색상각(231°)의 한 단계 진한 값. 또는 `text`/`textMuted`로 대체 |
| `danger` 글자 / 흰색 | 3.85 | 4.5 | 작은 위험 글자("n일 후 영구 삭제") | **글자를 위험색으로 칠하지 않는다** — 버터 칩 + 네이비 글자(13.9:1) + 금색 고리. 영구 삭제 확인에만 `#B52E52`(흰색 위 6.0:1) |
| `border` / 흰색 | 1.39 | 비텍스트 3:1 | 입력칸 경계가 유일한 단서일 때 | **입력칸 경계만 `primary #818AC3`**(흰색 위 3.30:1). 카드 경계는 장식이라 `#D9DCEF` 유지 |
| `primary` 선 / `surfaceSoft` | 2.98 | 비텍스트 3:1 | 앱 배경 위 선택 테두리 | 선택 테두리는 **`primaryStrong #606BB2`(4.47:1)** 2px로, `primary`는 비활성 장식에만 |

값은 조사자 계산이다(`스크립트/색 검수.py`의 대비 함수). 구현 때 실제 렌더 색으로 다시 잰다. **BI인 `text`(네이비) 계열은 건드리지 않는다.** 금색 점 · 고리 `#B98208`은 비텍스트 3:1을 넘지만(흰색 3.35 · 앱 바탕 3.03) 버터 위에서는 2.94라 고리는 항상 글자와 함께 쓴다. 이 보정이 시안에 적용된 것은 임박 표시와 알림 점뿐이고 나머지 셋은 구현 때 반영할 후보다.

## 4. 모션 · 햅틱 · 사운드 (코덱스)

| 장면 | 동작 | 동작 줄이기 대안 |
|---|---|---|
| 홈 진입 | 표지 3권이 아래에서 12px 올라오며 `280ms ease-out`, 순차 지연 40ms | 이동 없이 `opacity 0→1, 120ms` |
| 표지 길게 누르기 | 표지 `scale(.98) 100ms`, 도구 `opacity 0→1 / translateY(4→0), 160ms ease-out`, 가벼운 선택 햅틱 1회 | 도구 즉시 표시, 햅틱 없음 |
| 공방 미리보기 | 스티커 `scale(.82→1) 180ms cubic-bezier(.2,.8,.2,1)`, 성공 햅틱 1회 | 정적 교체 |
| 복원 | 표지가 8px 위로 이동 후 페이드아웃 `240ms ease-out`, 성공 햅틱 1회 | 즉시 목록 제거 |
| 영구 삭제 | 확인 후 카드 `opacity 1→0, 180ms`, 경고 햅틱 1회 | 즉시 목록 제거 |
| 사운드 | **기본 미사용** | 사용하지 않음 |

- 모두 가이드 §10의 240~260ms · ease-out과 같은 범위다. 모션은 1차 라운드의 코덱스 명세이고 색 규칙과 무관하게 유효하다.
- **동작 줄이기 대응이 먼저다.** 지금 코드에서 reduce-motion 처리는 `ToolGuideAnimation.js` 한 파일뿐이다.
- `package.json`에 Reanimated · Lottie · Skia · expo-haptics · expo-linear-gradient가 **없다.** 눌림 스프링 · 삭제 모션은 지금의 `Animated`로 가능하나 홈 진입 연출과 스티커 붙이는 순간은 Reanimated를 권장한다(추정). 햅틱은 `expo-haptics` 추가가 필요하다.

## 6. React Native 구현 메모

| 항목 | 웹 시안 | RN에서 |
|---|---|---|
| 표지 저채도(`filter`) | CSS `filter` | 그대로 안 됨 → 표지 위 회색 막 겹치기 · 회색조 에셋 · `tintColor` 중 택일, 안드로이드 · iOS 각각 확인 |
| 종이결 | SVG `feTurbulence` | PNG 타일 + `expo-image`, 또는 Skia(추가). 글자 · 입력칸 위 금지 |
| 그림자 색 | `box-shadow` | `shadowColor`는 Android 28 이상에서만 색이 먹음 |
| 소품 · 테이프 | `<img>` 겹치기 | `expo-image` 투명 PNG + `transform`, 이미 `assets/desk/props`에 있음 |
| 캐릭터(빈 상태) | SVG 그대로 | 최종 시안 벡터를 `react-native-svg` 또는 PNG 에셋으로(앱에 에셋이 아직 없다 — [01](01%20현재%20화면%20진단.md)) |
| 보조색 · 바탕 | CSS 변수 | `theme.js` 토큰 추가 |
| 그라데이션 | CSS | `expo-linear-gradient` 추가 필요(A 로그인 흰 대각광 · B 로그인 라벤더 번짐). **색상 번짐이 약해 정적 PNG 배경으로 대체해도 된다**(추정) |
| 선택 표지 프레임 | `div` 패딩 + 배경 | `View` 패딩 + `backgroundColor`, 그림자는 `elevation`(Android) · `shadow*`(iOS) 각각 |
| 길게 누르기 · `⋯` | — | `Pressable onLongPress` + 접근성 대체 동작, `⋯`는 탭 시 시트 |

웹에서 그린 시안이라 실제 구현과 조금 다를 수 있다. **터치 · 응답자 · SVG · 그림자처럼 플랫폼마다 다른 부분은 안드로이드 · iOS 양쪽 동작 방식을 따져 구현한다**(웹 검증은 참고용).
