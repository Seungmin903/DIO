# 선택 영역 PNG 생성·저장 (118)

## 구현

- `createRegionExportSnapshot`은 전달된 페이지 규격과 논리 영역·프리셋을 재검증하고 문서 요소를 깊게 복사한다. 화면 줌/DPR을 입력으로 받지 않는다.
- 자유 영역 2배(4096px/800만 화소 상한), 정사각형 1080×1080, 세로 1080×1350, 스토리 1080×1920. 3배 초과 확인과 6배 초과 차단을 UI와 별개로 강제한다.
- 전체 페이지 PNG/PDF와 같은 `usePageImageRenderer`/`PageImageSurface`/`ObjectContent`를 사용한다. 출력 surface 크기는 선택 영역이며 객체의 위치에서 영역 원점을 뺀다. 객체 크기·회전 중심·크롭·겹침 순서를 유지하고 합성 결과를 surface 경계에서 자른다.
- 소재 준비는 페이지 전체를 대상으로 한다. GIF 첫 프레임·필수 소재 실패·큰 원본 제한은 기존 공통 경로와 같다. 영역 밖 소재 오류도 출력을 중단할 수 있다.
- 확정 시 파일명을 고정한다. 생성 실패는 같은 스냅샷으로 다시 만들기, 영역 다시 선택은 선택 상태를 유지하며 돌아가 새 작업 만들기, 저장 실패/취소는 완성 PNG로 다시 저장한다.
- 웹 파일/다운로드·모바일 사진첩 저장·중복 저장 차단·취소·임시 URL/파일 해제는 기존 PageExportPreview/savePngFile을 재사용한다. 저장 중 닫기와 영역 재선택은 막는다.
- 원본 문서·미디어·자동 저장·되돌리기 상태는 바꾸지 않는다. 영역 테두리·툴바·격자 등 UI는 출력 surface에 존재하지 않는다.

## 검증 (2026-10-20)

- `node --test tests/*.test.js`: 전체 115개 통과. 추가 4개 테스트는 소수 좌표와 깊은 복사·경계·비율·확대 확인·상한·샘플링·영역 밖 실패와 준비 자원 해제를 검증한다.
- Expo 웹/Android 번들 생성 통과. Android 첫 시도는 sandbox의 Hermes 임시 파일 쓰기 권한 때문에 실패했고 정상 권한 재실행에서 통과했다. 기기 실행 성공을 뜻하지 않는다.
- 분리한 Chromium 컨텍스트 1280×800에서 공유→영역→수치 입력→PNG 생성/다운로드/영역 재선택을 확인했다.
- 400×400 영역의 자유 출력은 800×800. 사분면 샘플 픽셀 RGBA는 빨강 [255,0,0,255], 초록 [0,255,0,255], 파랑 [0,0,255,255], 노랑 [255,255,0,255]였다. 같은 영역 정사각형 프리셋은 1080×1080이다.
- 회전 30도·크롭 zoom 1.3 이미지의 250×250 영역은 500×500 PNG로 생성됐다. 정밀한 회전/크롭 픽셀 비교와 실기기 제스처는 119 QA에 남긴다.
- 기존 전체 페이지 PNG는 1280×800, PDF는 1페이지 A4 가로 생성 완료를 확인했다.
- 사진첩 권한·실기기 저장/취소·메모리·native 캡처 품질과 119 종합 QA는 미검증이다. html-to-image의 조용한 소재 누락 가능성과 8MP 원본 제한은 유지된다.
