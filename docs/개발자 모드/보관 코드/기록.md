# 개발자 모드 기록

2026-11-02, 사용자 결정에 따라 개발자 모드를 앱에서 완전히 뺐다. **다시 넣지 않는다.** 이 폴더는 무엇이 있었는지 남기는 기록이다. 되살리는 절차는 두지 않는다.

이제 앱은 고르는 화면 없이 바로 게스트(방문자)로 시작하고, 로그인이 필요한 기능을 누를 때만 로그인 화면이 겹쳐 뜬다.

## 뺀 것

- 시작할 때 일반 사용자 · 개발자 모드 고르기(`StartModeScreen`)
- 개발자 모드 게스트: 로그인한 사용자처럼 로그인이 필요한 기능이 모두 열림(`LoginGateProvider authenticated`)
- 개발자 모드 게스트의 받은 초대 알림 목업(`createSharingPreview({ seed: true })`)
- 개발자 모드 게스트의 공유 · 함께하는 사람 표시(`signedIn`)
- 내 공간의 개발자 모드 `로그아웃`(누르면 시작 화면으로 돌아감)
- 예전 개발자 모드가 보관함에 넣던 예시 다이어리(mock-travel · mock-class · mock-study)를 지우는 정리(`clearMockLibrary`) — **정리는 앱에 남겼다**(2026-11-02 리뷰 반영): 개발자 모드를 쓰던 개발 기기에 남은 예시 다이어리는 개발 빌드(`__DEV__`)에서 게스트로 시작할 때마다 `src/diary/services/legacyMockCleanup.js`가 지운다. 사용자가 만든 다이어리는 건드리지 않고, 남은 것이 없으면 아무 일도 하지 않는다. 손으로 지울 필요는 없다. 운영 빌드는 개발자 모드가 없었으므로 정리하지 않는다.
- 브라우저 QA 스크립트의 `개발자 모드로 시작` 단계, 시작 화면 버튼 글자 대비 검사, 관련 단위 테스트

## 들어 있는 것

`frontend/` 아래는 지운 파일의 원본이다(develop `35125746` 기준, 앱 안의 원래 경로 그대로). 앱 번들과 테스트에는 들어가지 않는다.

| 파일 | 하던 일 |
|---|---|
| `frontend/src/dev/devAccess.js` | `DEV_ACCESS`(개발 빌드 `__DEV__`에서만 참), `clearMockLibrary()` |
| `frontend/src/dev/StartModeScreen.js` | 시작 화면: 로고 아래 '어떤 상태로 시작할까요?' + `일반 사용자로 시작` · `개발자 모드로 시작` |
| `frontend/tests/dev-access.test.js` | `DEV_ACCESS`가 개발 빌드에서만 켜지는지, 예시 다이어리 정리 테스트 |

연결돼 있던 코드(`App.js` · `ProfileScreen.js` · `useSharing.js` 등)는 `git show 35125746:frontend/App.js`처럼 기준 커밋에서 볼 수 있다.
