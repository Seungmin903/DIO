# 개발자 모드 보관 코드

2026-11-02, 사용자 결정에 따라 앱을 켤 때 뜨던 '어떤 상태로 시작할까요?' 화면(일반 사용자 · 개발자 모드 고르기)을 뺐다. 이제 앱은 고르는 화면 없이 바로 게스트(방문자)로 시작하고, 로그인이 필요한 기능을 누를 때만 로그인 화면이 겹쳐 뜬다.

빠진 기능은 다음과 같다.

- 시작할 때 일반 사용자 · 개발자 모드 고르기(`StartModeScreen`)
- 개발자 모드 게스트: 로그인한 사용자처럼 로그인이 필요한 기능이 모두 열림(`LoginGateProvider authenticated`)
- 개발자 모드 게스트의 받은 초대 알림 목업(`createSharingPreview({ seed: true })`)
- 개발자 모드 게스트의 공유 · 함께하는 사람 표시(`signedIn`)
- 내 공간의 개발자 모드 `로그아웃`(누르면 시작 화면으로 돌아감)

예전 개발자 모드가 넣던 예시 다이어리(mock-travel · mock-class · mock-study)를 지우는 정리(`clearMockLibrary`)는 테스트 기기에 남아 있을 수 있어 앱에 남겼다. `src/diary/services/legacyMockCleanup.js`로 옮겨 게스트로 시작할 때마다 돈다.

나중에 되살릴 수 있게 지운 파일 원본과 되돌리기 패치를 여기에 둔다. **기준 커밋은 뺄 때의 develop `6ee7ea8c`다.** 연결된 파일의 고치기 전 전체본은 복사해 두지 않는다(시간이 지나면 지금 코드와 어긋난다). 필요하면 `git show 6ee7ea8c:frontend/App.js`처럼 기준 커밋에서 꺼내 본다.

## 들어 있는 것

`frontend/` 아래는 앱 안의 원래 경로 그대로다. 이 폴더는 앱 번들과 테스트에 들어가지 않는다(Metro는 import로 이어진 파일만 묶고, 테스트는 `frontend/tests/`의 경로를 직접 지정해 돌린다).

| 파일 | 하던 일 |
|---|---|
| `frontend/src/dev/devAccess.js` | `DEV_ACCESS`(개발 빌드 `__DEV__`에서만 참), `clearMockLibrary()` |
| `frontend/src/dev/StartModeScreen.js` | 시작 화면: 로고 아래 '어떤 상태로 시작할까요?' + `일반 사용자로 시작` · `개발자 모드로 시작` |
| `frontend/tests/dev-access.test.js` | `DEV_ACCESS`가 개발 빌드에서만 켜지는지, 예시 다이어리 정리 테스트 |

세 파일 모두 `6ee7ea8c` 기준이다.

`되살리기.patch`는 고친 17개 파일(`package.json`의 `test:auth` 목록 포함)을 `6ee7ea8c` 상태로 되돌리는 차이만 모은 것이다. 패치는 파일 문맥에 기대므로, 그 뒤 해당 파일이 바뀌었으면 맞지 않을 수 있다.

## 연결 지점

| 파일 | 개발자 모드가 쓰던 곳 |
|---|---|
| `App.js` | `devAccess` · `StartModeScreen` import, `developer` · `starting` 상태, `chooseStartMode`, `startGuest(dev)`의 `developer: true` 세션과 `clearMockLibrary()`, `clearSession`에서 개발자 모드면 시작 화면으로, `LoginGateProvider authenticated`, 시작 화면 덮개(zIndex 200), `DiaryApp`의 `signedIn` |
| `src/diary/screens/ProfileScreen.js` | 로그아웃 줄 조건 `!guest \|\| previewUser?.developer` |
| `src/sharing/useSharing.js` | `createSharingPreview({ user, seed: !!user?.developer })`와 의존성 `user?.developer` |
| `src/sharing/sharingPreview.js` · `src/auth/loginGate.js` | 주석만 |
| `tests/auth-routing.test.js` | 시작 화면 · 개발자 모드 게스트 테스트, useState 순서(`developer` · `starting`) |
| `tests/profile-password-change.test.js` | 개발자 모드 게스트에게 로그아웃이 보이는지 |
| `qa/*-browser.cjs` 4개 · `tests/*-browser.cjs` 5개 | 시작할 때 `개발자 모드로 시작` 버튼을 누름 |
| `tests/design-review-browser.cjs` | 시작 화면 `일반 사용자로 시작` 버튼의 글자 대비(4.5 이상) 검사 |

## 되살리는 법

저장소 루트에서 실행한다.

```bash
# 1. 파일 되살리기
cp -r "docs/개발자 모드/보관 코드/frontend/src/dev" frontend/src/
cp "docs/개발자 모드/보관 코드/frontend/tests/dev-access.test.js" frontend/tests/

# 2. 연결 지점 되돌리기 (먼저 --check 로 확인)
git apply --check "docs/개발자 모드/보관 코드/되살리기.patch"
git apply "docs/개발자 모드/보관 코드/되살리기.patch"

# 3. 확인
cd frontend && node --test tests/auth-routing.test.js tests/profile-password-change.test.js tests/dev-access.test.js
```

패치가 맞지 않으면(그사이 파일이 바뀌었으면) 위 연결 지점 표를 보고 `git show 6ee7ea8c:frontend/<파일>`과 비교해 손으로 옮긴다.

- 되살리면 `App.js`가 다시 `src/dev/devAccess`의 `clearMockLibrary`를 쓰므로 `src/diary/services/legacyMockCleanup.js`와 `tests/legacy-mock-cleanup.test.js`는 지운다.

- 개발자 모드 세션은 `{ mode: 'preview', provider: 'guest', nickname: '방문자', developer: true }`다. 이 세션 하나로 로그인 게이트 · 공유 · 알림 목업 · 로그아웃이 모두 갈린다.
- 출시 빌드에서는 `DEV_ACCESS`가 거짓이라 고르는 화면 없이 일반 사용자로 시작한다. 되살려도 출시 앱에는 시작 화면이 뜨지 않는다.
- 브라우저 QA 스크립트는 다시 `개발자 모드로 시작`을 눌러야 로그인이 필요한 기능(공유 등)까지 둘러볼 수 있다.
