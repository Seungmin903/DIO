# 다이어리 편집해 휴지통으로 이동

관련 Jira: [204](https://ssafy.atlassian.net/browse/S15P31F106-204). 기존 휴지통 이동·복원(147)과 30일 보관(165) 정책을 그대로 쓴다.

## 동작

- 폰·태블릿 모두 보관함 필터 줄 오른쪽 `보관함 옵션(⋮)` → `편집`으로 관리 모드에 들어간다. 기존 검색·정렬(225)의 메뉴를 확장해 정렬 라디오 그룹 아래 구분선과 실행 항목을 둔다.
- 전체 보관함뿐 아니라 현재 필터·검색 결과가 0개인 경우에도 `편집`과 구분선을 숨긴다. 검색어 입력 전 최근 검색어 화면에서도 숨긴다.
- 관리 모드 진입 시 옵션 메뉴를 닫고 검색·정렬 버튼을 숨긴다. 검색어·필터·정렬과 결과 목록은 유지하며, 검색 중 관리 모드에서는 입력·검색어 지우기를 막는다. 편집 완료 시 같은 검색 결과로 돌아간다.
- 관리 모드에서 카드를 누르면 다이어리를 열지 않고 선택만 넣고 뺀다. 표지 오른쪽 위 체크 원과 파란 테두리로 고른 카드를 표시한다. 카드 안 수정·즐겨찾기·휴지통 버튼과 새 다이어리 카드는 잘못 누르지 않도록 숨긴다.
- 위쪽 막대에 선택 개수를 보여 준다. 아무것도 고르지 않으면 `휴지통으로` 버튼을 끈다.
- `휴지통으로` → 확인 창에서 확인하면 고른 다이어리만 휴지통으로 옮기고 관리 모드를 끝낸다. 취소하면 아무것도 바꾸지 않고 선택도 유지한다.
- 필터를 바꾸면 지금 보이지 않는 다이어리는 선택에서 뺀다. 사이드 메뉴·하단 탭으로 다른 화면에 가거나 `완료`, Android 뒤로가기를 누르면 관리 모드를 끝낸다.
- 열려 있던 편집 탭 중 휴지통으로 옮긴 다이어리의 탭은 닫는다.

## 저장과 실패

- 고른 항목마다 같은 `trashedAt`을 기록한다. 이미 휴지통에 있던 항목은 기한을 늘리지 않는다. 편집 문서와 사진은 지우지 않으므로 30일 동안 복원할 수 있고, 이후 기존 자동 정리 규칙으로 영구 삭제된다.
- 목록 저장을 기존 저장 큐에서 먼저 실행하고, 저장에 성공했을 때만 화면에 반영한다. 저장에 실패하면 목록을 바꾸지 않고 `휴지통으로 옮기지 못했어요` 안내를 띄우며 관리 모드와 선택을 유지한다.
- 저장소를 읽지 못한 실행(`writable` 아님)에서는 기존처럼 저장하지 않고 실패로 처리한다.
- 옮기는 동안에는 `휴지통으로`·`완료`·`전체 선택/해제`를 끄고 확인을 다시 눌러도 한 번만 실행한다.
- 저장 형식·서버 API 변경 없음. 마이그레이션 필요 없음.

## 기기 확인

1. 테스트 다이어리 3개 이상 → `보관함 옵션` → `편집` → 2개 고르기 → `휴지통으로` → 취소 → 변경 없음.
2. 다시 `휴지통으로` → 확인 → 고른 2개만 휴지통, 남은 일수 30일 표시.
3. 앱 재실행 → 결과 유지, 고르지 않은 다이어리 내용 보존 → 휴지통에서 복원 후 편집 내용 확인.
4. 즐겨찾기 필터 전환, 빈 즐겨찾기, Android 뒤로가기로 관리 모드 종료 확인.
5. 검색 결과 0개·빈 필터에서 옵션의 `편집`이 없는지 확인. 결과가 있는 검색에서 선택·취소 후 검색어·정렬·결과가 유지되는지 확인.

## 편집 모드 전체 선택 (2026-10-24)

- 보관함 옵션의 진입 이름은 `편집`, 종료 버튼은 `완료`다. 완료는 선택만 해제하고 검색·정렬·필터를 유지한다.
- `전체 선택`은 현재 검색·필터 결과 전체(스크롤 밖 항목 포함)를 선택한다. 모두 선택했을 때는 `전체 해제`로 바뀐다. 일부 선택이면 전체 선택으로 나머지를 함께 고른다.
- 필터 변경 시 결과에서 빠진 항목은 선택에서도 제외한다. 새로 보이는 항목을 자동 선택하지 않는다.
- 0개 선택이면 휴지통 이동은 비활성화된다. 이동 중에는 개별/전체 선택과 완료를 막는다. 확인 창 취소 시 선택을 유지한다.
