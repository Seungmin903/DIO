# 회원 기본 앱 연결 및 전용 DB 적용

> 2026-10-28 별도 통합 사본의 확정 P0·P1 변경은 [!166 통합 계약](../diary-166-p0p1-integration.md)을 따른다. 아래 내용·검증은 기존 MR 구현 이력이며 원본 MR은 변경하지 않았다.


2026-10-27, 231·233 작업 폴더에서 구현했다. 다른 세션의 펜 QA·알림 통합 작업과 범위를 확인했고 해당 작업 폴더와 DB는 수정하지 않았다. 미커밋·미푸시다.

## 기본 앱 동작

- 실제 이메일 로그인은 회원 POST 생성·GET 상세·PATCH 제목/표지 수정 경로를 사용한다. 게스트와 체험 계정은 기존 로컬 흐름을 유지한다.
- 회원 인덱스·편집 문서·미확정 생성 요청은 `dio:member:v1:<userId>` 아래 분리한다. 비회원 문서 복구 prefix를 사용하지 않는다.
- 생성 키와 입력을 HTTP 요청 전에 저장한다. 응답 유실·재실행·재로그인 뒤에도 `생성 결과 확인`(안내: "다이어리가 만들어졌는지 확인하지 못했어요.")은 같은 키와 본문으로 재시도한다. 미확정 요청을 다른 폼으로 덮어쓰거나 새 키로 자동 우회하지 않는다. 확인 기간이 지난 요청(`IDEMPOTENCY_KEY_EXPIRED`)은 `보관함 목록 확인`과 `이전 요청 정리`(목록을 다시 확인한 뒤 기록으로 보관, 다이어리는 지우지 않음)를 따로 둔다. 안내에는 요청 · 키 · 응답 같은 내부 용어를 쓰지 않는다(S15P31F106-723, 2026-11-09).
- 서버가 발급한 다이어리·페이지 ID로 기존 편집기를 연다. 재시도 시 이미 편집한 문서는 덮어쓰지 않는다. 회원 문서가 없거나 손상됐으면 빈 문서로 대체하지 않고 안내한다.
- 상세 조회로 권한을 확인하고 수정은 서버의 마이크로초 `updatedAt`을 그대로 보낸다. 충돌 시 최신 메타데이터만 갱신하고 사용자의 수정을 자동 재적용하지 않는다.
- 401은 같은 계정의 토큰만 한 번 갱신한다. 계정 종료 후 늦게 온 결과는 다음 계정 UI에 반영하지 않는다.

## 현재 연결 범위

후속 [232 회원 서버 목록 연결](./회원%20서버%20목록%20기본%20앱%20연결.md)에서 서버 전체 목록과 다른 기기에서 만든 다이어리 발견을 연결했다. 캔버스 본문/미디어·페이지 추가/삭제는 기존 기기 저장이며 서버 동기화를 구현한 것으로 간주하면 안 된다. 회원 휴지통·공유 연결도 별도여서 회원 카드 삭제와 목 공유 연결은 제공하지 않는다. 실기기 QA는 아직 진행하지 않았다.

## 전용 개발 DB

최초 연결 당시 작업 전용 PostgreSQL 17의 `dio_member_app`에 회원 분기의 V1~V8을 적용했다. 최신 develop 통합에서는 인증 V7·V8을 보존하고 회원 카탈로그/영수증을 V9·V10으로 옮겼다. 원본 QA DB와 기존 서버는 구 이력을 유지한다. 백업 복제본에서만 이력 대응·V1~V10 적용과 데이터 보존·기본 설정 재시작을 검증했다. 공유/운영 DB에는 적용하지 않았다. 구 이력을 가진 원본에 새 코드를 바로 실행하지 말고 아래 통합 검토의 전환 절차를 먼저 확인한다.

Java 17과 **PowerShell 7 이상(`pwsh`)** 환경에서 다음 명령에 PostgreSQL 바이너리 경로를 전달한다. Windows PowerShell 5.1(`powershell.exe`)은 지원하지 않는다. 시작·사전 검사 스크립트의 `#Requires -Version 7.0`이 실행 전에 이를 거부한다.

```powershell
pwsh -NoProfile -File backend/qa/start-member-development.ps1 -PostgresBin '<PostgreSQL 17 bin 경로>'
```

첫 실행은 Gradle 런타임·테스트 의존성을 내려받을 네트워크 연결이 필요하다. 시드는 `testClasses`를 사용하므로 `bootJar`만 실행한 캐시에서도 의존성을 받을 수 있게 온라인 모드로 실행한다. `initdb` 성공 뒤에만 전용 설정을 저장하며, 기존 기록에 `PG_VERSION`이 없으면 설정을 보존하고 명확한 오류로 중단한다. 이때 `runtime.json`에 기록된 클러스터를 확인·복구한 뒤 재실행한다.

전용 DB 비밀번호·JWT 키·자동 QA 계정은 무시되는 `.local-data/member-app/backend.env`에만 저장한다. 터미널에 출력하거나 공유하지 않는다. 계정 생성 코드는 test 소스이며 앱 jar에 포함되지 않는다. 서버와 DB는 127.0.0.1에만 바인딩된다. 경로·포트·서버 PID는 `runtime.json`에 기록한다. 기록된 PID의 Java `-jar` 절대 경로가 이 작업 폴더의 `backend/build/libs`에 속한 서버이면 DB 명령이나 `bootJar` 전에 중복 시작을 거부하므로 기록된 **이 작업의 서버**만 종료한 뒤 다시 실행한다. 처음 실행 시 기존 설정이 없다면 `frontend/.env.local`에 로컬 API 주소를 넣는다. iPad/LAN 접속은 별도다.

## 검증

`frontend/qa/member-app-browser.cjs`는 별도 origin과 새 브라우저 context에서 기본 로그인 화면을 사용한다. 실제 POST를 서버에 전달하고 최초 201 응답만 끊은 뒤 새로고침·재로그인·동일 키 재시도로 최초 결과를 복구한다. 서버 ID/페이지 ID, PATCH, 편집기 진입, 비회원 저장 키 보존을 확인한다. 전용 DB의 QA 다이어리는 남는다.

```powershell
# frontend에서, 서버를 먼저 실행
pnpm exec expo export --platform web --output-dir .expo/member-app-web
node qa/member-app-browser.cjs
```

기본 앱 최초 연결 단계에서는 백엔드 192개 통과(조건부 DB 59개 제외), 프런트 관련 133개 통과. 이후 232 연결 결과와 develop 통합 회귀는 [회원 서버 목록 연결](./회원%20서버%20목록%20기본%20앱%20연결.md) 및 [develop 통합 검토](./회원%20다이어리%20develop%20통합%20검토.md)를 따른다. 실제 로컬 브라우저 흐름 통과, 웹/iOS 번들 생성 성공. iOS 번들 성공은 iPad 실기기 QA를 대신하지 않는다.


### 2026-10-27 재진입 편집본 보존

권한 확인 후 디스크 문서를 편집기로 넘길 때 이미 메모리에 최신 편집본이 있으면 유지한다. 저장 중·실패 후 재진입이 오래된 디스크 사본으로 최신 필기를 덮어쓰지 않도록 했다. 캐시가 없거나 문서 없음(null)이면 유효한 기기 문서를 기억한다. 계정별 문서 검증은 유지하며 영구 보관에는 기기 저장 성공이 필요하다. 새 회귀는 `pnpm test:member-diary`에 포함된다. 최신 인증 통합·검증은 [develop 통합 검토](./회원%20다이어리%20develop%20통합%20검토.md)를 따른다.

기록된 PID가 다른 프로그램·다른 작업 폴더의 Java·종료된 프로세스이면 재사용된 PID로 보고 차단하지 않으며 해당 프로세스를 종료하지 않는다. Java 명령줄이나 프로세스 정보를 읽을 수 없어 소유권을 판별하지 못하면 DB·빌드 전에 명확한 확인 안내로 중단한다. 상대 jar 경로와 plain jar는 이 시작 스크립트가 실행하는 서버 형태가 아니다. 기존 runtime.json에 새 필드를 요구하지 않는다.


### 실행 전 Java·API 주소·산출물 확인

`JAVA_HOME`이 없거나 그 아래 `bin/java.exe`가 없으면 전용 runtime 파일 생성·DB 명령 전에 명확한 오류로 중단한다. Java 버전이나 실제 기기 실행을 확인하는 검사는 아니므로 앞서 명시한 Java 17 환경을 준비해야 한다.

기존 `frontend/.env.local`의 API 주소가 현재 loopback API 포트와 다르거나 키가 없거나 중복되면 값을 출력하지 않고 경고한다. 개인 설정을 자동으로 덮어쓰지 않으며 localhost/127.0.0.1의 같은 포트와 `/api/v1`을 같은 개발 endpoint로 인정한다. 경고 후 진행은 허용하므로 의도된 원격/LAN 설정인지 사용자가 확인해야 한다. 파일이 없을 때만 정상 서버 준비 후 새 로컬 설정을 만든다.

시작 스크립트는 `writeMemberDevelopmentArtifact`를 실행한다. 이 Gradle 작업은 `bootJar` 성공 후 실제 `archiveFile` 절대 경로를 무시 대상 `backend/build/member-development/boot-jar-path.txt`에 매번 기록한다. 실행기는 해당 파일이 지정한 jar만 사용하며, build/libs의 파일 순서·수정 시각에 의존하지 않는다. 기록 누락·모호한 경로·범위 밖 파일·plain jar·존재하지 않는 파일이면 서버 시작 전에 실패한다. 이전 jar를 자동 삭제하지 않는다.

```powershell
pwsh -NoProfile -File backend/qa/test-member-development-startup.ps1
pwsh -NoProfile -File backend/qa/test-member-development-preflight.ps1
```

두 회귀는 격리한 임시 파일과 모의 명령을 사용하며 실제 앱 서버를 시작·종료하거나 비공개 설정을 변경하지 않는다.

레거시 회원 V7/V8 이력이 감지되면 시작 스크립트는 빌드 전에 백업·복제 검증 안내로 중단하며 Flyway repair나 history UPDATE를 자동 실행하지 않는다. 절차와 제한은 [develop 통합 검토](./회원%20다이어리%20develop%20통합%20검토.md)의 최신 절을 따른다. 브라우저 회귀는 DIO_MEMBER_QA_RUNTIME_DIR로 별도 소유 복제 DB의 runtime 폴더를 지정할 수 있으며 기본 개인 runtime은 변경하지 않는다.


### 알림·회원 공통 인증 세션 (develop b7a626c 통합)

회원과 알림은 같은 authService의 getSessionKey 및 비동기 getAccessToken({ userId, sessionKey }) 계약을 사용한다. 회원 transport는 생성 당시 로그인 세션을 고정하고 토큰 조회 전/후와 401 갱신 전/후에 같은 세션인지 확인한다. 다른 계정뿐 아니라 같은 계정의 재로그인 뒤에도 옛 transport가 새 세션 토큰을 사용하지 않는다. 회원 store도 계정·세션 키가 바뀌면 교체한다. refresh는 세션 키를 유지하고 공통 인증 API의 진행 중 갱신을 공유한다. 생성 재시도는 같은 키·본문을 유지한다.

App의 LocalDiaryApp/MemberDiaryApp 선택과 회원 store를 유지하면서 인증 회원 콘텐츠를 AuthenticatedNotificationProvider로 감쌌다. 실제 알림 화면과 회원 보관함이 같은 세션을 사용하며 게스트·체험은 기존 로컬 경로를 유지한다. 알림의 초대 상세/수락·거절은 알림 모듈의 기존 제한을 따르며 회원 공유 기능 전체 연결 완료를 뜻하지 않는다.

회원 공식 회귀 명령 test:member-diary에 member-notification-auth.test.js를 포함했다. 브라우저 QA는 복제 runtime의 notificationQa(본인/타인 알림 ID)와 DIO_MEMBER_QA_NOTIFICATIONS=true를 지정하면 실제 알림 읽음·삭제·타인 404 후 회원 흐름을 연속 검증한다. 시드는 소유 복제 DB에만 준비하며 원본 QA 데이터에 주입하지 않는다.


### PostgreSQL 배포 파일 누락 진단 (2026-10-27)

재시작 전 사전 검사는 postgres/psql/pg_ctl/initdb/createdb 실행 파일과 `share/timezonesets/Default`의 존재를 확인한다. 누락 시 DB 초기화나 설정 변경 전에 중단한다. 이는 지원 파일 전체의 무결성 검사 또는 자동 복구가 아니다.

원본 QA 연결 실패는 살아 있는 PostgreSQL 프로세스·데이터 디렉터리와 달리 설치 배포본의 bin/lib/share 파일이 일부 사라진 상태에서 발생했다. 서버 로그의 `timezone_abbreviations: Default` 오류와 지원 파일 누락을 함께 확인했다. 실행 중 postgres.exe와 같은 SHA256의 아카이브에서 **없는 파일만** 복원하여 재시작 없이 연결을 회복했다. 데이터 디렉터리·DB 설정·Flyway 이력·비공개 env/runtime 파일은 수정하지 않았다. 이 절차를 새 initdb, 자동 repair 또는 기존 파일 덮어쓰기로 대체하면 안 된다. 다른 버전의 지원 파일을 섞어서도 안 된다.

현재 원본 배포 경로는 OS 임시 디렉터리다. 장기 사용 시 안정된 설치 경로로 옮기는 별도 운영 작업이 필요하다. 이번에는 경로·프로세스를 바꾸지 않았다. 원본의 과거 회원 V7/V8 이력 전환은 여전히 별도 절차이며, 연결 복구와 이력 변환을 같은 작업으로 취급하지 않는다.
