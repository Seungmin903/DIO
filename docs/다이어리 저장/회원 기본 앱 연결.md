# 회원 기본 앱 연결 및 V8 로컬 적용

2026-10-27, 231·233 작업 폴더에서 구현했다. 다른 세션의 펜 QA·알림 통합 작업과 범위를 확인했고 해당 작업 폴더와 DB는 수정하지 않았다. 미커밋·미푸시다.

## 기본 앱 동작

- 실제 이메일 로그인은 회원 POST 생성·GET 상세·PATCH 제목/표지 수정 경로를 사용한다. 게스트와 체험 계정은 기존 로컬 흐름을 유지한다.
- 회원 인덱스·편집 문서·미확정 생성 요청은 `dio:member:v1:<userId>` 아래 분리한다. 비회원 문서 복구 prefix를 사용하지 않는다.
- 생성 키와 입력을 HTTP 요청 전에 저장한다. 응답 유실·재실행·재로그인 뒤에도 `이전 생성 확인`은 같은 키와 본문으로 재시도한다. 미확정 요청을 다른 폼으로 덮어쓰거나 새 키로 자동 우회하지 않는다.
- 서버가 발급한 다이어리·페이지 ID로 기존 편집기를 연다. 재시도 시 이미 편집한 문서는 덮어쓰지 않는다. 회원 문서가 없거나 손상됐으면 빈 문서로 대체하지 않고 안내한다.
- 상세 조회로 권한을 확인하고 수정은 서버의 마이크로초 `updatedAt`을 그대로 보낸다. 충돌 시 최신 메타데이터만 갱신하고 사용자의 수정을 자동 재적용하지 않는다.
- 401은 같은 계정의 토큰만 한 번 갱신한다. 계정 종료 후 늦게 온 결과는 다음 계정 UI에 반영하지 않는다.

## 현재 연결 범위

후속 [232 회원 서버 목록 연결](./회원%20서버%20목록%20기본%20앱%20연결.md)에서 서버 전체 목록과 다른 기기에서 만든 다이어리 발견을 연결했다. 캔버스 본문/미디어·페이지 추가/삭제는 기존 기기 저장이며 서버 동기화를 구현한 것으로 간주하면 안 된다. 회원 휴지통·공유 연결도 별도여서 회원 카드 삭제와 목 공유 연결은 제공하지 않는다. 실기기 QA는 아직 진행하지 않았다.

## 전용 개발 DB

공유 개발/운영 DB 접속 정보가 없으므로 작업 전용 PostgreSQL 17 클러스터와 `dio_member_app` DB를 만들고 일반 앱의 Flyway로 V1~V8을 적용했다. 적용 성공 8개, 속지 288개를 확인했다. 다른 세션의 DB에는 적용하지 않았다.

Java 17 환경에서 다음 PowerShell 명령에 PostgreSQL 바이너리 경로를 전달한다.

```powershell
./backend/qa/start-member-development.ps1 -PostgresBin '<PostgreSQL 17 bin 경로>'
```

첫 실행은 Gradle 런타임·테스트 의존성을 내려받을 네트워크 연결이 필요하다. 시드는 `testClasses`를 사용하므로 `bootJar`만 실행한 캐시에서도 의존성을 받을 수 있게 온라인 모드로 실행한다. `initdb` 성공 뒤에만 전용 설정을 저장하며, 기존 기록에 `PG_VERSION`이 없으면 설정을 보존하고 명확한 오류로 중단한다. 이때 `runtime.json`에 기록된 클러스터를 확인·복구한 뒤 재실행한다.

전용 DB 비밀번호·JWT 키·자동 QA 계정은 무시되는 `.local-data/member-app/backend.env`에만 저장한다. 터미널에 출력하거나 공유하지 않는다. 계정 생성 코드는 test 소스이며 앱 jar에 포함되지 않는다. 서버와 DB는 127.0.0.1에만 바인딩된다. 경로·포트·서버 PID는 `runtime.json`에 기록한다. 기록된 PID의 Java `-jar` 절대 경로가 이 작업 폴더의 `backend/build/libs`에 속한 서버이면 DB 명령이나 `bootJar` 전에 중복 시작을 거부하므로 기록된 **이 작업의 서버**만 종료한 뒤 다시 실행한다. 처음 실행 시 기존 설정이 없다면 `frontend/.env.local`에 로컬 API 주소를 넣는다. iPad/LAN 접속은 별도다.

## 검증

`frontend/qa/member-app-browser.cjs`는 별도 origin과 새 브라우저 context에서 기본 로그인 화면을 사용한다. 실제 POST를 서버에 전달하고 최초 201 응답만 끊은 뒤 새로고침·재로그인·동일 키 재시도로 최초 결과를 복구한다. 서버 ID/페이지 ID, PATCH, 편집기 진입, 비회원 저장 키 보존을 확인한다. 전용 DB의 QA 다이어리는 남는다.

```powershell
# frontend에서, 서버를 먼저 실행
pnpm exec expo export --platform web --output-dir .expo/member-app-web
node qa/member-app-browser.cjs
```

기본 앱 최초 연결 단계에서는 백엔드 192개 통과(조건부 DB 59개 제외), 프런트 관련 133개 통과. 이후 232 연결 결과와 develop 통합 회귀는 [회원 서버 목록 연결](./회원%20서버%20목록%20기본%20앱%20연결.md) 및 [develop 통합 검토](./회원%20다이어리%20develop%20통합%20검토.md)를 따른다. 실제 로컬 브라우저 흐름 통과, 웹/iOS 번들 생성 성공. iOS 번들 성공은 iPad 실기기 QA를 대신하지 않는다.


### 2026-10-27 재진입 편집본 보존

권한 확인 후 디스크 문서를 편집기로 넘길 때 이미 메모리에 최신 편집본이 있으면 유지한다. 저장 중·실패 후 재진입이 오래된 디스크 사본으로 최신 필기를 덮어쓰지 않도록 했다. 캐시가 없거나 문서 없음(null)이면 유효한 기기 문서를 기억한다. 계정별 문서 검증은 유지하며 영구 보관에는 기기 저장 성공이 필요하다. 새 회귀는 `pnpm test:member-diary`에 포함된다. 최신 인증 통합·검증은 [develop 통합 검토](./회원%20다이어리%20develop%20통합%20검토.md)를 따른다.

기록된 PID가 다른 프로그램·다른 작업 폴더의 Java·종료된 프로세스이면 재사용된 PID로 보고 차단하지 않으며 해당 프로세스를 종료하지 않는다. Java 명령줄이나 프로세스 정보를 읽을 수 없어 소유권을 판별하지 못하면 DB·빌드 전에 명확한 확인 안내로 중단한다. 상대 jar 경로와 plain jar는 이 시작 스크립트가 실행하는 서버 형태가 아니다. 기존 runtime.json에 새 필드를 요구하지 않는다.
