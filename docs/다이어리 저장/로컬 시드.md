# 로컬 데모 시드

로컬 PostgreSQL에서 사용자·프로필 이미지·다이어리·페이지·캔버스 요소를 빠르게 확인하기 위한 데이터다. 실제 시드 파일은 Flyway 마이그레이션과 나란한 `backend/src/main/resources/db/seed/local-demo.json`에 둔다. `db/seed/`는 Git 무시 대상이고 Flyway 기본 위치인 `db/migration/`과 다르므로 마이그레이션으로 실행되지 않는다.

`db/seed/`가 `resources` 아래에 있어도 Gradle `processResources`와 Docker 빌드 컨텍스트에서 명시적으로 제외한다. 따라서 시드 본문은 Git·JAR·Docker 이미지에 모두 포함되지 않는다. 시더는 로컬 파일 시스템 경로를 직접 읽는다.

시더는 `local` 프로필이면서 `DIO_LOCAL_SEED_ENABLED=true`일 때만 실행된다. `dev`·`prod` 프로필에서는 빈 자체가 생성되지 않아, 같은 환경변수가 존재해도 시드를 읽거나 쓰지 않는다. 기본값은 `false`다.

```properties
# 루트 .env
DIO_LOCAL_SEED_ENABLED=true
DIO_LOCAL_SEED_FILE=src/main/resources/db/seed/local-demo.json
```

`backend/`에서 서버를 실행한다.

```powershell
cd backend
./gradlew bootRun
```

시드는 UUID를 고정해 재실행해도 기존 다이어리·페이지·요소를 건너뛴다. 시드 내용을 처음부터 다시 반영하려면 로컬 데이터베이스의 해당 UUID 행을 지우거나 Docker 볼륨을 재생성한다. 이 작업은 로컬 데이터만 대상으로 한다.

JSON 구조는 `users`, `diaries → pages → elements`다. `users`의 `password`를 지정하면 로컬 이메일 로그인 계정도 만들고 BCrypt로 해시해서 저장한다. `photoPngBase64`에는 PNG Base64 값을 둘 수 있으며, 실제 업로드와 같은 디코딩·PNG 재인코딩을 거쳐 로컬 프로필 사진 저장소에 파일과 메타데이터를 함께 만든다. 따라서 `/api/v1/auth/profile-photos/{photoId}`로 이미지 응답을 확인할 수 있다. 페이지에는 `templateId`를 넣지 않으므로 데모는 별도 속지 테이블 데이터 없이도 동작한다. 요소의 `propertiesJson`과 페이지의 `templateConfig`는 객체 또는 배열을 그대로 작성하면 된다.

시더의 프로필 이미지는 앱의 `MEDIA_STORAGE=s3` 설정과 관계없이 항상 `LOCAL` 저장소에 기록한다. 로컬 더미 실행이 S3 자격 증명·버킷 접근에 의존하거나, 실수로 개발·운영 S3에 데이터를 쓰지 않게 하기 위함이다.
