# 회원 다이어리 인증 연결

현재 연결 상태(2026-10-27): 231 생성·232 회원 목록·233 상세/수정과 회원 기본 앱 연결을 구현했다. 아래 단계별 검증 수치는 당시 기록이며 최신 통합 검증은 [develop 통합 검토](./회원%20다이어리%20develop%20통합%20검토.md)를 따른다.

관련 이슈: S15P31F106-231, S15P31F106-233

## 변경

두 서비스의 인증 인터페이스를 공통 `DiaryRequestIdentity`에 연결했다. 기존 로그인 패키지는 유지하고 후속으로 회원 경로 전용 보안 필터 체인을 추가했다. 실제로 주입되는 `loginBearerTokenResolver`, `loginJwtDecoder`를 재사용한다.

- 현재 HTTP 요청의 Bearer 토큰을 읽어 서명·issuer·audience·token_use·유효 기간을 검증한다.
- 기존 로그인 검증기는 DB의 로그인 세션 ID와 토큰 사용자 ID 일치, 세션 만료·로그아웃, 사용자 활성·삭제 상태도 확인한다.
- 사용자 ID는 검증된 토큰의 subject만 사용한다. 요청 userId·ownerUserId·헤더·SecurityContext의 임의 객체는 신뢰하지 않는다.
- 호출할 때마다 검증한다. 이전 요청이나 다른 계정의 인증 결과를 캐시하지 않는다.
- 요청 자체가 없는 배치·비동기 호출은 401로 거부한다. 배치용 인증을 HTTP 요청으로 위장하지 않는다.
- 기존 개발 전용 `X-DIO-Access-Token` 설정을 켠 환경에서는 동일 검증을 거친다. Authorization의 Bearer가 있으면 우선하며, 잘못된 Bearer를 다른 헤더로 대체해 통과시키지 않는다. 기본 설정에서는 해당 보조 헤더를 사용하지 않는다.
- 잘못된 토큰은 각 서비스의 기존 인증 오류(401)로 변환한다. DB 장애 등 인프라 예외를 401로 숨기지 않는다.

233의 활성 멤버십·OWNER 수정 권한 검증은 유지한다. JWT의 역할 필드로 이를 대체하지 않는다. 231도 서버에서 조회한 사용자 ID·색상으로 OWNER를 생성한다.

## 다른 세션과 범위

2026-10-27 확인 시 `세션1 이어가기`는 DIO-ToolGuide의 펜 입력 MR 수정, `Resume current work here`는 알림 API의 Spring 응답·프런트 계약 회귀(인증 연결 제외)를 진행 중이었다. 이 변경은 `.worktrees/diary-detail-permissions`의 다이어리 인증·231·233 설정·테스트·문서에 한정했다. 다른 작업 폴더나 공통 인증 구현은 변경하지 않았다.

## 남은 작업

운영용 HTTP 경로·컨트롤러·오류 처리기는 후속으로 연결했다. 회원 기본 앱의 생성·상세·수정·전체 목록 연결도 후속으로 완료했다. 최종 팀 계약·공유 DB 적용·실기기 검증은 남아 있다. 제품 JDBC 초기 페이지 모듈과 카탈로그 V7 등록·프런트 속지 매핑은 후속으로 연결했다. 회원 전용 경로를 추가하고 기존 공개 경로는 소유자 없는 자료만 접근하도록 제한했다. 따라서 현재 공개 API에 Bearer를 전달하는 것만으로 회원 다이어리 흐름이 완성된다는 의미는 아니다.
