# 233 상세 조회·수정 권한 기반

현재 연결 상태(2026-10-27): 이 문서는 233 내부 권한 기반 단계의 기록이다. 후속으로 실제 JWT·회원 HTTP·기본 앱과 232 회원 목록을 연결했다. 최신 범위와 통합 회귀는 [develop 통합 검토](./회원%20다이어리%20develop%20통합%20검토.md)를 따른다.

- 기준: 최신 develop `24b0300`(이메일 인증·회원가입·로그인 병합), 2026-10-27.
- 브랜치: `feature/be/diary-detail-permissions`, 작업 폴더 `.worktrees/diary-detail-permissions`.
- 229 계약 초안의 권한 제안을 사용한 사전 구현이다. 역할별 메타데이터 정책과 동시 수정 계약은 최종 합의 전이다.

## 구현 범위

`diary/detail/` 아래 새 서비스·인증 경계·멤버십 조회를 추가했다.
기존 컨트롤러·엔티티·Flyway는 유지한다. HTTP 후속에서 공개 조회·수정·삭제 서비스를 소유자 없는 자료로 제한해 회원 경로 우회를 차단했다.
234 휴지통 및 232 목록 작업을 복사하거나 덮어쓰지 않는다. 기존 HTTP API가 이 서비스로 전환됐다는 의미가 아니다.

### 서비스 호출

- `DiaryDetailService.get(diaryId)`: 현재 회원의 활성 멤버십을 확인한 상세 조회. 기존 `DiaryResponse` 형식 반환.
- `DiaryDetailService.update(diaryId, DiaryUpdateRequest, expectedUpdatedAt)`: 현재 회원의 제목·표지 색/스타일 수정.
- 클라이언트가 보낸 userId·ownerUserId·역할 문자열을 받아 권한으로 사용하지 않는다.
- API 라우팅·오류 응답은 후속 회원 HTTP 경로에 연결했다. 실제 인증 어댑터는 아래와 같이 연결했다.

## 인증·멤버십

`DiaryDetailIdentity.requireUserId()`는 인증 담당이 검증한 현재 회원을 제공하는 인터페이스다.
기본 빈은 `DiaryRequestIdentity`를 통해 현재 요청의 토큰을 기존 `loginJwtDecoder`에 전달한다. 서명·만료·활성 로그인 세션·사용자 검증을 재사용하며, 잘못된 요청은 401이다. 새 JWT 검증기나 로그인 API, 사용자 ID 헤더 우회는 만들지 않았다.
회원 HTTP 전용 security matcher를 추가했으며 SecurityContext의 임의 숫자를 인증 근거로 사용하지 않는다. 다이어리 서비스는 HTTP 요청의 토큰 자체를 검증한다. 기존 공개 API는 소유자 없는 자료만 접근하도록 제한했다. 자세한 범위는 [회원 다이어리 인증 연결](./회원%20다이어리%20인증%20연결.md)을 참고한다.

서비스는 DB의 `users.status='ACTIVE' AND deleted_at IS NULL`도 다시 확인한다.
`DiaryMembershipAccess`는 공유 담당의 활성 멤버십 연결 경계이며, 현재 구현은 V1 `diary_members`를 읽는다.
`left_at`이 있는 멤버·알 수 없는 역할·OWNER와 `diaries.owner_user_id` 불일치·소유자 NULL 자료를 추정해 허용하지 않는다.
다이어리 소유권만 있고 활성 OWNER 멤버십이 없는 자료도 거절한다. 기존 비회원 자료의 연결/이관은 230의 책임이다.

| 동작 | OWNER | EDITOR | VIEWER | 비참여자/탈퇴 멤버 |
| --- | --- | --- | --- | --- |
| 활성 다이어리 상세 조회 | 허용 | 허용 | 허용 | 404 |
| 제목·표지 색/스타일 수정 | 허용 | 403 | 403 | 404 |
| 삭제된 다이어리 조회·수정 | 404 | 404 | 404 | 404 |

이 표는 229 초안의 보수적인 제안이다. 공개 링크·멤버 권한 변경·휴지통 관리는 별도 범위다.
공유 공개 범위 `visibility` 변경은 이 서비스에서 400으로 차단한다. 기존 DTO에 필드가 있어도 공유 정책을 임의로 변경하지 않는다.

## 입력·충돌·잠금

서비스 내부에서도 기존 `DiaryUpdateRequest`의 검증 규칙을 실행한다.
제목 공백 제거 후 1~100자, 색 #RRGGBB, 스타일 최대 30자/비공백을 유지한다. 생략 필드는 보존하고 빈 수정·잘못된 값은 거절한다.
스타일 카탈로그의 최종 허용값은 기존 DTO보다 임의로 좁히지 않았다.
비참여자에게 404, 읽기 전용 멤버에게 403을 판정한 뒤 요청 값을 검증한다.

`expectedUpdatedAt`에는 마지막 조회 응답의 마이크로초 단위 updatedAt을 전달한다.
현재 값과 다르면 409이며, 값이 없는 요청은 400이다. 회원 PATCH는 본문 expectedUpdatedAt 필드로 전달받는다.
새 version 컬럼이나 엔티티 @Version은 추가하지 않았다. 230과 합의 후 실제 버전 계약으로 교체할 수 있다.
같은 값으로 수정하면 시각을 변경하지 않고, 변경이 있으면 새 updatedAt을 기존 값보다 최소 1마이크로초 크게 만든다.
고정되거나 뒤로 간 서버 Clock에서도 같은 토큰을 재사용해 덮어쓰지 않게 한다.
레거시 쓰기 경로까지 같은 규칙을 따르는 것은 아니므로 전체 서비스의 최종 버전 보호 완료로 간주하지 않는다.

하나의 트랜잭션에서 사용자 → 다이어리 → 해당 멤버십 순으로 잠근다.
PostgreSQL은 사용자·멤버십·상세 조회에 `FOR SHARE`, 수정할 다이어리에 `FOR UPDATE`를 사용한다.
수정 SQL에도 `deleted_at IS NULL`과 이전 updatedAt을 조건으로 둔다.
H2는 공유 잠금 구문 차이로 `FOR UPDATE`를 사용한다. readOnly 트랜잭션은 사용하지 않는다.
권한 변경·탈퇴·삭제·복원 코드와 통합할 때 잠금 순서 및 동일 트랜잭션 경계를 맞춘다.
현재 JDBC 서비스와 기존 JPA Diary 변경을 한 트랜잭션에서 혼용하지 않으며, 통합 시 영속성 컨텍스트의 오래된 상태가 덮어쓰지 않는지도 확인한다.

## 서비스 오류 제안

| 상태 | code | 대상 |
| --- | --- | --- |
| 401 | DIARY_AUTHENTICATION_REQUIRED | 인증 미연결·비활성·삭제된/없는 회원 |
| 404 | DIARY_NOT_FOUND | 없는/삭제된 다이어리·비참여/탈퇴·불일치 멤버십 |
| 403 | DIARY_METADATA_FORBIDDEN | EDITOR·VIEWER 메타데이터 수정 |
| 400 | INVALID_DIARY_METADATA | 잘못된 수정/동시 수정 토큰·visibility 변경 |
| 409 | DIARY_METADATA_CONFLICT | 오래된 수정 기준 또는 조건부 갱신 실패 |

`DiaryDetailException`에 상태와 code를 담는다. 회원 컨트롤러 전용 HTTP 처리기에 연결했다.

## 검증과 남은 작업

- 기본 검증: `backend/gradlew.bat test --console=plain --offline`.
- PostgreSQL 전용: 명시적 폐기용 localhost DB_URL/POSTGRES_USER/POSTGRES_PASSWORD를 주입하고 `backend/gradlew.bat postgresDiaryDetailTest --console=plain --offline`.
- PostgreSQL 테스트는 매 테스트마다 `detail_qa_<UUID>` 스키마에 기존 V1~V6를 적용하고 해당 스키마만 삭제한다. 공개 개발/운영 DB를 대상으로 실행하지 않는다.
- 기본 역할·누락/삭제·탈퇴/알 수 없는 역할·소유권 불일치·비활성 계정·입력 오류·stale/no-op·동시 수정과 실제 멤버십 변경 잠금을 검증한다.
- Spring 빈의 트랜잭션 프록시와 기본 401도 확인한다. SQL 계약 테스트는 직접 트랜잭션 경계를 실행하며 실제 JWT·HTTP 보호 통합을 대신하지 않는다.
- 기존 엔티티·로그인 검증기·공통 컨트롤러·DDL을 변경하지 않았다. 229·230 최종 정책, 공유 어댑터 통합, 234 통합과 실제 서버·기기 QA가 남아 있다.
- 커밋·푸시·MR 생성 전이며 Jira 233 전체 완료로 표시하지 않는다.
