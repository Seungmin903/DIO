# 속지 카탈로그 등록·프런트 매핑

현재 연결 상태(2026-10-27): 231 생성·232 회원 목록·233 상세/수정과 회원 기본 앱 연결을 구현했다. 아래 단계별 검증 수치는 당시 기록이며 최신 통합 검증은 [develop 통합 검토](./회원%20다이어리%20develop%20통합%20검토.md)를 따른다.

관련 이슈: S15P31F106-231

## 등록 데이터

`frontend/src/editor/templates/serverCatalog.js`는 기존 날짜형 에셋 276개, 만년형 10개, 명시적인 빈 속지 2개를 서버 카탈로그로 연결한다. 원본 SVG·에셋 ID·버전·기존 편집 문서는 변경하지 않는다.

| 대상 | 서버 코드 | 버전 | 논리 규격 |
|---|---|---|---|
| 날짜형·만년형 | 기존 에셋 ID 그대로 | 에셋의 `templateVersion` | 가로 1024×768 / 세로 768×1024 |
| 빈 가로 속지 | `dio-blank-landscape` | `1.0.0` | 1024×768 |
| 빈 세로 속지 | `dio-blank-portrait` | `1.0.0` | 768×1024 |

숫자 `template_id`는 DB가 발급한다. 프런트는 이를 계산하거나 고정하지 않고 코드·버전으로 참조한다. 빈 페이지의 로컬 `backgroundAssetId`는 계속 null이며, 서버 생성 시에는 방향별 빈 속지 코드로 명시한다.

`V9__seed_page_template_catalog.sql`은 Flyway 실행 시 `page_templates`에 288개 항목을 등록한다. V1~V6는 수정하지 않았다. 작업 중에는 격리된 테스트 DB에만 적용했으며 실제 개발·운영 DB에 직접 SQL을 실행하지 않았다.

## 기존 데이터 보존

- 같은 코드·버전이 이미 있으면 기존 PK·이름·기본 설정·표시 순서·비활성 상태를 유지한다.
- 이전 버전과 별도 등록 항목을 삭제하지 않는다. 기존 다이어리·페이지·FK·규격·JSON도 변경하지 않는다.
- 같은 코드·버전의 중복 행이나 규격·방향 충돌이 있으면 마이그레이션을 실패시킨다. 앞서 삽입한 항목도 PostgreSQL 트랜잭션으로 롤백한다.
- 등록 SQL을 재실행해도 중복 생성하거나 비활성 속지를 다시 활성화하지 않는다. Flyway 자체는 V9을 한 번만 실행한다.
- 기존 기본 설정을 자동 변환하지 않는다. 생성 모듈의 허용 범위와 다른 설정은 담당자가 확인해야 하며, 생성 시 검증을 우회하지 않는다.

## 프런트 연결

`diaryCreateInput`의 각 `initialPages`에 `templateCode`와 버전을 추가했다. 기존 `templateId` 에셋 참조와 `templateConfig`는 유지해 목 응답과 기존 화면 흐름을 보존한다.

`toServerInitialPageSelections`는 이를 231 내부 `DiaryInitialPages.Selection` 필드인 `templateCode`, `templateVersion`, `configurationJson`으로 변환한다. 중복 선택·페이지 순서·설정은 유지하고, 잘못된 코드/버전·방향·규격·에셋 매핑은 거부한다.

`localTemplateReference`는 서버 코드·버전을 기존 편집기 에셋 참조와 논리 규격으로 되돌린다. 매핑되지 않는 버전을 현재 버전으로 바꿔 표시하지 않는다.

이는 카탈로그와 페이지 선택의 매핑이다. 운영 HTTP 생성 DTO·경로·오류 처리기는 후속으로 연결했다. 회원 기본 앱은 서버가 발급한 다이어리·페이지 ID로 기기 문서를 만들고 기존 편집기로 진입한다. [회원 기본 앱 연결](./회원%20기본%20앱%20연결.md)을 참고한다. 캔버스 본문·미디어·페이지 편집의 서버 동기화와 최종 사용자 제한 확정은 별도다.

생성기는 버전 고정 JSON 계약과 V9 SQL을 함께 만든다. 배포된 마이그레이션은 불변이므로 이후 버전·규격 변경은 기존 V9을 다시 생성해 덮어쓰지 않고 새 마이그레이션과 버전 계약으로 추가한다.

프런트 테스트는 288개 매핑 왕복, 방향별 빈 속지, 날짜형·만년형 실제 생성 입력, 잘못된 참조 거부, SQL·JSON 원본 일치를 검사한다. PostgreSQL 테스트는 실제 V6→V9 업그레이드·재실행·기존 자료 보존·충돌 시 전체 롤백을 확인하고, 프런트 매퍼로 만든 288개 Selection을 제품 JDBC 생성 모듈에 전달해 실제 페이지를 생성한다.

## 페이지 추가의 속지 코드 저장 (V35)

다이어리를 만들 때 생기는 페이지(`JdbcDiaryInitialPages`)는 `pages.template_id`에 속지 행을 연결하지만, 편집기 "페이지 추가"(`POST /api/v1/diaries/{diaryId}/pages`)는 `templateId` 없이 `templateConfig`의 `templateCode`·`templateVersion` 글자만 보냈고 서버는 그 글자를 확인 없이 저장했다. 그래서 같은 속지가 페이지마다 행 연결 또는 글자로 갈렸고, 없는 코드도 저장될 수 있었다.

- 페이지 추가: 설정에 `templateCode`가 있으면 서버(`PageService.create`)가 코드·버전이 같은 활성 행을 찾아 `template_id`를 채운다. 없는 코드·버전, 비활성 행, 버전 없는 코드, `templateId`와 어긋난 코드는 400 `INVALID_PAGE_REQUEST`다. 보낸 `canvasWidth`·`canvasHeight`가 그 행의 크기와 다를 때도 400이다(V35와 같은 기준). 만든 뒤 크기를 바꾸는 수정(PDF 쪽 크기 맞추기)은 허용한다. 같은 코드·버전의 활성 행이 여럿이면 사용자 오류가 아니라 500 `PAGE_TEMPLATE_CATALOG_INVALID`로 응답하고 서버 로그에 코드·버전을 남긴다. 앱 요청 형식은 그대로다.
- 페이지 수정: 설정의 `templateCode`는 지금 속지(또는 함께 보낸 `templateId`의 행)와 같아야 한다. 속지 변경은 `templateId`로만 한다(빈 종이 → 속지, 원격 ↔ 일반, 원격 방향 바꾸기 포함).
- 기존 페이지: V35가 `template_id`가 비어 있고 설정에 코드·버전 글자가 있는 페이지를 연결하고 `version`·`updated_at`을 올린다. 후보는 코드·버전·캔버스 크기가 모두 같은 행이다. 활성 행이 하나면 그 행, 활성 행 없이 비활성 행만 하나면 그 행(만들 때는 쓰던 속지)에 연결한다. 맞는 행이 없거나 어느 행인지 정할 수 없으면 건드리지 않으며, 마이그레이션은 실패하지 않는다. 연결한 페이지와 이전 `version`·`updated_at`은 `page_template_v35_links`에 남는다(되돌리기: 그 페이지의 `template_id`를 NULL로, `version`·`updated_at`을 이전 값으로).
- 설정의 `templateCode`·`templateVersion`은 지우지 않는다. 옛 앱이 이 값으로 속지를 찾는다.
- 앱이 보내는 속지 코드·버전(V9 288개, 플래너 4개, 원격 2개)마다 활성 행이 정확히 하나여야 페이지 추가가 된다. `(code, template_version)`에는 유니크 제약이 없으므로, 운영 배포 전에 아래 조회가 0행인지 확인한다. 제약을 마이그레이션으로 추가하지 않은 것은 운영에 겹치는 행이 있으면 배포 자체가 멈추기 때문이다. 운영에서 이 조회가 0행인 것을 확인한 뒤에는 활성 행에 한정한 부분 유니크 인덱스(`(code, template_version) WHERE is_active`)를 별도 마이그레이션으로 추가할 수 있다.

  ```sql
  select code, template_version, count(*) from page_templates where is_active group by code, template_version having count(*) > 1;
  ```

- 페이지 추가가 실패하면 편집기가 알림을 띄운다(`EditorScreen`의 속지 고르기 `onSelect`). HTTP 층은 상태 코드마다 같은 문구를 쓰므로, `createServerPage`가 `INVALID_PAGE_REQUEST`는 "이 속지를 서버에서 확인하지 못했어요. 앱을 최신 버전으로 업데이트한 뒤 다시 시도해 주세요.", `PAGE_TEMPLATE_CATALOG_INVALID`는 "서버의 속지 목록을 확인하고 있어요. 잠시 뒤 다시 시도해 주세요."로 바꿔 보인다.
- 같은 `clientPageRequestId` 재시도는 찾은 행으로 비교한다. 이 서버 배포 전에 `template_id` 없이 만든 페이지(V35가 연결하지 못한 페이지 포함)는 `templateId` 없이 온 재시도라면 설정(코드·버전 포함)이 같은지로 같은 요청인지 판단해 그 페이지를 돌려준다.
- 검증: `PageApiTests.pagesAddedByTemplateCodeAreLinkedToTheTemplateRow`(H2), `PageCatalogPostgresTests.V35LinksPagesThatOnlyNamedTheirTemplateByCode` · `everyTemplateCodeTheAppSendsHasExactlyOneActiveRow`(PostgreSQL 17).
