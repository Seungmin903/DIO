# 휴지통 30일 보관

관련 Jira: [165](https://ssafy.atlassian.net/browse/S15P31F106-165). 기존 휴지통 이동·복원·수동 영구 삭제(147)에 기한을 보강한다.

## 동작

- 삭제하면 기존처럼 휴지통으로 이동한다. `trashedAt`부터 정확히 30×24시간(720시간) 동안 복원할 수 있다.
- 휴지통에 다시 이동시키는 중복 요청으로 기한을 연장하지 않는다. 정상 복원 후 다시 삭제하면 새 보관 기한이 시작된다.
- 휴지통에 남은 일수와 영구 삭제 예정 날짜를 표시한다. 기한 이상인 항목과 영구 삭제 중인 항목은 복원할 수 없다.
- 앱 시작 및 포그라운드 복귀 때, 실행 중에는 1분마다 기한을 확인한다. 앱이 종료된 동안에는 실행되지 않으며 다음 실행 때 정리한다. 시각은 기기 시계를 따른다.
- 날짜가 손상된 기존 항목은 임의로 영구 삭제하지 않고 자동 정리를 보류한다. 사용자는 복원하거나 수동 영구 삭제할 수 있다.

## 저장과 실패

- MVP1 로컬 저장 정책이다. Spring 서버 삭제 API나 서버 스케줄러를 변경하지 않는다.
- 기존 목록 키와 `trashedAt`을 유지한다. 삭제 작업의 중단 복구를 위해 선택 필드 `purgePending: true`를 추가한다. 이전 목록에는 이 필드가 필요 없다.
- 삭제 표식을 먼저 목록에 저장하고 문서를 삭제한 뒤 목록에서 제거한다. 중간 종료·저장 실패 시 표식 항목을 다음 실행에서 재시도한다. 삭제 중 표식은 기기 시계가 되돌아가도 복원하지 않는다.
- 목록 자동 저장·새 다이어리 등록·영구 삭제는 같은 큐에서 실행한다. 자동 정리와 신규 생성이 동시에 목록을 덮어쓰지 않게 한다.
- 삭제 실패 항목을 휴지통에 남기고 안내와 다시 시도 버튼을 제공한다. 수동 영구 삭제 확인은 유지한다.
- 다른 문서(휴지통 포함), 예전 단일 문서, 사용자 꾸미기 보관함이 참조하는 미디어는 보존한다. 참조 JSON이 손상돼 확인할 수 없으면 미디어 정리를 건너뛴다.
- 미디어 파일 정리가 실패하면 문서 삭제는 되돌리지 않고 고아 파일을 보존한다. 완전한 미디어 GC, 여러 앱 인스턴스 간 동시 변경, 서버 동기화는 이번 범위 밖이다.

## 검증

`cd frontend` 후 `pnpm test:trash` 실행. 날짜 경계·중단 표식·저장/삭제 실패·공유 미디어 보존, 실제 useDiaries 훅의 시작/복귀/주기 점검·복원·신규 등록과 기존 목록 정규화 등 19개 테스트 통과 (2026-10-21, develop `fe9a0fd` 기준, 테스트 보고 시간 약 841ms).

`node node_modules/expo/bin/cli export --platform ios --no-bytecode --output-dir .expo/trash-retention-mr-ios` 성공. iOS JS·에셋 번들 검증이며 설치 빌드·실기기 실행 결과는 아니다. `git diff --check` 및 App/휴지통 JSX 문법 검사도 통과했다.

훅 테스트는 React 및 저장소·AppState를 대체한 이벤트 시뮬레이션이다. 실제 iPad 검증은 아직 하지 않았다.

## iPad 확인

1. 테스트 다이어리를 만들고 사진·필기를 추가한 뒤 휴지통 이동 → 홈에서 숨김과 30일 안내 확인.
2. 휴지통 복원 → 편집 내용 보존 → 다시 삭제 → 남은 기간 확인.
3. 테스트 다이어리만 수동 영구 삭제 → 앱 재실행 후 되살아나지 않는지 확인.
4. 30일 경계는 자동화의 가상 시각으로 검증한다. 실제 개인 데이터가 있는 기기 시계를 바꿔 만료를 시험하지 않는다.

구현은 리뷰 대상이며 실제 iPad 검증 전까지 Jira는 진행 중으로 유지한다.
