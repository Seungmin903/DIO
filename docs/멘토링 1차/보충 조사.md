# DIO 1차 멘토링 보충 조사

자료 기준: 2026-10-27 / 목적: 첨부 멘토링 PPT의 프로젝트·사업화·검증·질문 내용을 보완한다.

## 1. 사용한 원본과 발표 범위

원본 PPT는 「별첨1_멘토링 진행자료_F000_1차 (1).pptx」 10장이다. 기존 표지·목차·팀 소개·마무리를 유지하고, 4~9쪽의 빈 내용과 안내 문구를 실제 발표 내용으로 채운다. 팀원과 역할은 원본에 적힌 값을 유지한다. 날짜는 실제 멘토링 일정을 추정하지 않고 ‘자료 기준 2026.10.27’로 통일한다.

핵심 기획 근거는 「01 트렌드 조사.md」와 「속지 에셋 아이디어.pdf」다. PDF 56쪽에서 일반 속지 37종, 온라인 속지 24종, 오프라인 에셋 33종, 온라인 에셋 23종으로 나뉜 카탈로그와 추천안을 확인했다. 합계 117종은 **아이디어·목업 수**이며 구현 완료 수·판매 상품 수가 아니다. 검토안의 우선 추천은 빙고·질문 릴레이·교환일기·출석·타임캡슐 등이다.

현재 개발·검증 수준은 저장소 README, 편집기 통합 QA(2026-10-21), 초대·공유 화면 문서로 보완했다. 기존 문서의 테스트 결과를 인용하는 작업이며 이번 PPT 작성 중 앱 테스트를 새로 수행한 결과가 아니다. 앞서 진행한 스터디 플래너 목업은 이번 발표 근거에 포함하지 않았다.

## 2. 핵심 기획과 문제 가설

DIO는 사진을 바탕으로 손글씨·텍스트·스티커를 얹고, 가까운 사람들과 같은 다이어리를 꾸미는 서비스를 지향한다. 기존 자료의 장점은 재료의 종류뿐 아니라 ‘함께 채우는 칸’, ‘다음 순서’, ‘봉인 해제’처럼 재방문의 이유를 속지에 넣으려는 점이다.

고객 문제는 아직 가설이다. 꾸미기 작업과 친구에게 기록을 나누는 일이 여러 도구에 흩어져 있고, 빈 종이부터 시작하기 어렵거나 교환 기록이 끊길 수 있다고 본다. 따라서 기능 수보다 첫 공동 페이지 완성까지의 수고와 다시 방문할 이유를 검증해야 한다.

초기 타깃은 **기존 기획의 10~20대 다꾸 관심 여성**이다. 첫 모집은 태블릿 필기 경험이 있고 친구와 기록을 나누려는 20대 친구 쌍으로 좁히는 안을 제안한다. 이는 시장 전체의 성별·연령 분포를 입증한 결론이 아니라 검증할 고객군이다. 10대의 캐릭터·포카, 20대의 필사·독서라는 구분도 탐색 관찰로만 다룬다.

TAM·SAM·SOM은 이번에 숫자를 만들지 않았다. 향후 국내 대상 사용자 수, 지원 기기 보유, 최근 유료 디지털 속지 구매 경험, 친구와 기록을 나눌 의향을 분리 조사한 뒤 산정한다. 서로 다른 플랫폼의 거래액 성장률을 합산하지 않는다.

**원본에서 수정해야 하는 표현:** ‘Goodnotes는 혼자 쓴다’, ‘스티커를 매번 잘라야 한다’, ‘교환일기 앱은 꾸밀 수 없다’는 일반화는 현재 자료와 맞지 않는다. Goodnotes Elements/Marketplace는 스티커를 바로 사용하는 경로가 있고 공동 작업도 제공한다. 다이어링에도 꾸미기 기능이 있다. ‘경쟁이 없는 빈 시장’보다 **이미 있는 기능 사이에서 우리 사용 흐름이 더 편한가**를 물어야 한다.

Goodnotes의 공동 작업 지원 문서는 공개 링크 중심 설명을 포함하지만, 최신 요금제 비교 문서는 Pro의 비공개 링크·실시간 공동 작업도 안내한다. 구형 설명으로 모든 공유가 공개라고 단정하지 않는다. 구독 금액은 국가·스토어 차이와 정책 변동이 있어 이번 PPT의 가격 비교표에서 제외했다.

삼성 공식 안내에는 가로/세로 방향 설정과 PDF 방향 제약이 명시돼 있다. 과거 커뮤니티 답변의 ‘가로 템플릿 미제공’을 현재 제품의 보편적 제한으로 쓰지 않는다. 직접 제품을 같은 환경에서 비교 사용한 결과는 아니므로 기능 부재를 추정하지 않는다.

## 5. 개발 현황과 기술 검증

현재 코드·문서에는 손글씨·텍스트·스티커·테이프·사진 편집, 속지 선택, 페이지·레이어, 로컬 저장과 내보내기 경로가 존재한다. 백엔드 기본 CRUD와 PostgreSQL 검증 문서도 존재한다. 다만 기능별 환경·연동 수준은 다르므로 서비스 전체가 운영 완료됐다고 표현하지 않는다.

초대·공유는 화면과 메모리 기반 시연 모델을 제공한다. `sharingPreview`와 `dio.example` 링크는 예시이며 실제 서버 초대 발급·권한·동시 편집 동기화·푸시는 후속 연결 범위다. 117종 카탈로그와 온라인 속지의 상태/알림 설계 역시 기획 제안이며 구현 완료로 표기하지 않는다.

2026-10-21 편집기 통합 QA 기록에는 201개 단위 테스트, 웹·Android 번들, 독립 웹 컨텍스트의 시나리오별 3/3 성공과 저장·재진입 6/6 결과가 있다. 해당 시점 코드·작은 문서·웹 터치 모사에 한정된다. 실제 태블릿·스타일러스·iOS·장시간 다량 획은 미검증이며 최종 Android 직접 조작도 별도 확인이 필요하다고 기록돼 있다. PPT에는 이 한계를 함께 명시한다.

고객 인터뷰 수, 유료 고객 수, 재방문율, 매출, MAU를 입증하는 자료는 제공되지 않았다. 따라서 ‘기술 기능 확인’과 ‘고객 수요 검증’을 별도로 표시한다.

## 6. 초기 제품과 사업모델 제안

일반 속지·정적 재료는 기본 사용성을 확보하는 바탕이다. 초기 차별화 검증은 질문 릴레이·교환일기처럼 ‘친구를 부를 이유’가 있는 속지 1종으로 좁히고, 상대가 참여한 상태와 다음 행동을 명확히 보여 주는 안이 적절하다. 온라인 자동 채움·외부 데이터·작가 마켓을 한꺼번에 완성해야만 출시할 수 있는 구조는 피한다.

원본 BM의 기본 방향은 무료 기본 소재, 유료 테마 팩의 낱개 판매와 구독 병행이다. 초기에는 테마 팩 한 번 구매로 결제 의사를 먼저 확인하고, 반복 구매·재방문이 나타나면 구독을 비교한다. 작가 입점·수수료·실물 인쇄는 후속 확장 후보로 둔다. Goodnotes의 디지털 소재 판매와 구독은 모델이 존재한다는 근거일 뿐 DIO의 수익성을 입증하지 않는다.

원본 메모의 광고 제거 990원, 친구 초대 1주 무료는 확정 가격·정책이 아니다. 가격·결제 대상·콘텐츠 권리·동일 방 사용 범위는 팀이 검증 후 결정한다. 광고는 핵심 수익 가정으로 계산하지 않는다. 이미 유료 소재를 산 사람과 무료 멤버가 같은 페이지를 꾸밀 때의 이용 권한을 멘토링 질문으로 남긴다.

매출 가정은 ‘유료 구매자 수 × 구매 빈도 × 평균 결제액’으로 나누고, 앱마켓 비용·결제 비용·창작자 정산·미디어 저장/전송 비용을 제외해 공헌이익을 계산한다. 비용률과 전환율은 확인 전이므로 임의의 매출 전망치를 PPT에 넣지 않는다.

## 7. 검증 계획과 질문

**아래는 실행 결과가 아닌 제안 계획이다.** 20대 친구 6쌍 정도를 모집해 14일 동안 질문 릴레이나 교환일기 한 종류를 사용하게 하는 소규모 파일럿을 제안한다. 인원이 작아 통계적 일반화는 하지 않고 어느 단계에서 멈추는지 관찰한다. 공유 서버 연결 전에는 진행자가 기록을 전달하는 시연으로 과업을 평가하고, 연결 후 실제 재방문을 측정한다.

| 확인할 가설 | 측정 방법 |
|---|---|
| 첫 페이지를 쉽게 완성한다 | 처음 진입부터 첫 페이지 완성까지 시간, 도움 요청, 포기 지점 |
| 친구를 초대할 이유가 있다 | 초대 화면 진입·발송·수락·양쪽 첫 편집을 서로 다른 이벤트로 기록 |
| 함께 기록하면 다시 방문한다 | 7일 내 양쪽 모두 재편집한 친구 쌍 / 활성화된 친구 쌍 |
| 테마 팩에 지불할 의사가 있다 | 기존 유료 구매 경험, 같은 팩의 가격 후보 선택, 결제 화면 진입과 실제 결제를 구분 |

사전 모집과 테스트 수행에 필요한 사람은 팀이 직접 섭외한다. 이번 작업에서 연락하거나 설문을 발송하지 않았다. 성공 목표 수치는 근거 없이 정하지 않고 첫 파일럿의 기준선을 확보한 뒤 다음 실험에서 합의한다.

멘토링 질문은 네 가지다. ① 첫 고객을 10대까지 넓히기보다 20대 친구 쌍으로 좁히는 것이 적절한가? ② 자유 공동 캔버스와 턴 기반 교환일기 중 어떤 흐름을 먼저 검증할까? ③ 반복 사용 전에는 낱개 팩과 구독 중 무엇으로 결제 의사를 검증할까? ④ 사용자 필기·사진과 구매 소재의 소유권, 공유방 퇴장 후 접근 범위를 어떻게 단순하게 정할까?
