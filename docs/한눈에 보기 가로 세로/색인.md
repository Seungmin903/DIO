# 한눈에 보기 가로 세로

> 작성일: 2026-11-01 · 상태: **코드 반영(커밋 전)** · 화면 판단: 코덱스 · 조사 · 계산 · 구현 · 확인: 클로드
> 범위: 보관함(내 다이어리 · 공유된 다이어리) · 검색 결과 · 휴지통의 태블릿 표지 격자. 폰(퍼센트 2열)과 편집기의 페이지 넓게 보기는 손대지 않았다.

질문: "가로 모드 ↔ 세로 모드에서 한눈에 보기를 어떻게 할지, 굿노트 · 삼성 노트는 어떻게 하는지 조사해서 코덱스와 다시 논의해 반영하자."

## 2. 다른 앱은 어떻게 하나

어느 앱도 공식 도움말에 가로 · 세로 열 수를 밝히지 않았다. 숫자는 굿노트 피드백 포럼에 사용자가 올린 스크린샷에서 직접 셌다.

<figure><img src="이미지/굿노트 가로 반쪽 창 3열.jpg" width="420"><figcaption>굿노트 · 가로 반쪽 창</figcaption></figure>
<figure><img src="이미지/노터빌리티 가로 4열.jpg" width="420"><figcaption>노터빌리티(구버전) 보관함 · 가로</figcaption></figure>

- **굿노트(iPad)** — 페이지 썸네일은 세로 전체 화면 4열, 11인치 가로 반쪽 창 3열. 썸네일 크기는 거의 그대로(약 122~133pt)이고 폭에 따라 **정수 열 수만** 바뀐다. 남는 폭은 칸 사이로 고르게 나눈다. 12.9인치 4열 → 13인치 5열 보고(2026-03). 2019~2025년 내내 "썸네일 사이 빈 공간이 너무 크다 · 열 수나 크기 설정을 달라"는 요청이 있지만(23표, 공식 답 없음) 크기 설정은 없다. 보관함은 격자 / 목록 전환만.
- **삼성 노트(갤럭시 탭)** — 보기는 목록 / 격자 / 간단히 목록. 2021년 업데이트 공지에 격자 크기 작게 / 중간 / 크게가 있었다는 검색 요약(본문은 403으로 못 읽음), 2023년 "격자 가장 크게도 작다" 불만. 열 수는 확인 못 했다.
- **노터빌리티(2020 구버전, iPad 가로)** — 보관함 4열. 가로 노트와 세로 노트가 섞여도 같은 칸 안에 놓고 제목 줄 높이를 맞춘다(조사 에이전트는 3열로 셌으나 왼쪽 열이 팝오버에 가려진 것이라 클로드가 4열로 바로잡음).
- **Noteful** — 보관함 미리보기를 핀치로 키우고 줄인다. **Google Play 북** — 목록 / 작은 격자 / 큰 격자(비공식 보도). **Apple Files** — 아이콘 / 목록 / 열 보기, 아이콘 크기 조절은 못 찾음.
- 회전할 때 스크롤 위치를 지키는지, 사이드바가 저절로 접히는지는 어느 앱에서도 확인하지 못했다.

공통점: 표지(썸네일) 크기는 좁은 범위 안에 두고 **폭이 넓어지면 열을 늘린다**. 세로라고 큰 표지 2권으로 줄이는 앱은 찾지 못했다.

## 3. 코덱스 안과 반영

원문: `작업/코덱스 요청 완성.md` → `작업/코덱스 출력.md`, 검수: `작업/코덱스 검수 요청.md` → `작업/코덱스 검수 출력.md`.

| 코덱스 안 | 반영 | 이유 |
|---|---|---|
| 굿노트처럼 칸 크기 범위 유지 + 정수 열 수만 늘리는 방향 유지 | 채택 | |
| **세로 창(높이 > 폭)만 최소 칸 208 → 180**, 가로 · 최대 264 · 간격 32 그대로 | 채택 | 800 · 744 세로도 3열. 180 칸이면 세로 표지 폭 약 133 |
| (검수) 세로 180 은 **3열까지만**, 4열은 칸이 208 이상일 때만 | 채택 | 1024 세로가 4열 197 이 되면 834 세로 3열 210 보다 넓은 화면에서 표지가 더 작아진다 → 3열 264 |
| (검수) 칸 200 미만에서 표지 안 제목 10px · 띠 34px 아래로 줄이지 않기 | **기각** | 표지는 264 로 한 번 그려 비율대로 줄이는 축소판이고(무늬 · 글자 비율이 보기마다 같다), 폰 격자 표지(약 143)가 이미 180 보다 작다. 글자만 따로 키우면 칸마다 표지 디자인이 달라진다. 이름 줄은 이미 14px 고정 · 한 줄 말줄임 |
| 회전하면 스크롤 좌표 대신 **맨 위 줄의 첫 다이어리 + 줄 안 비율**을 지켜 즉시 이동(애니메이션 없음) | 채택 | |
| 표지 크기 조절은 이번엔 넣지 않음(나중이면 핀치 대신 작게 / 보통 / 크게 버튼) | 채택(안 넣음) | 핀치는 스크롤 · 다꾸 손짓과 겹친다 |
| 좌측 바는 회전만으로 자동으로 접지 않음 | 채택(지금 그대로) | |
| 남는 폭은 가운데 정렬 | **기각** | 새 규칙에서 실제 기기 크기는 남는 폭이 0~16. 제목 왼쪽 선에 맞춘 왼쪽 정렬(원 페이저 02 결정)을 유지 |
| 세로 900 미만은 머리줄을 두 줄로 | **기각** | 이미 1줄 = 제목 + 보기 전환, 2줄 = 칩 + 검색 · 더보기다(코덱스가 화면을 한 줄로 읽음) |

## 4. 코드

- `frontend/src/diary/utils/gridLayout.js` — `GRID_CELL_MIN_PORTRAIT = 180`(3열까지), `gridColumns(width, portrait)` · `gridMetrics(width, portrait)`, 회전 위치 계산 `gridScrollAnchor` · `gridScrollY`
- `frontend/src/diary/utils/useDiaryGrid.js` — 폭과 세로 여부를 같이 재고(방향만 먼저 바뀐 프레임에 권수가 튀지 않게), 감싼 ScrollView 에 `scroll`(ref · onScroll)을 준다. 창 크기가 바뀌며 끝에 걸려 밀린 스크롤은 기억하지 않고, 같은 줄 안이면 처음 기억한 다이어리를 지켜 가로 → 세로 → 가로에서 한 줄씩 밀리지 않는다.
- `LibraryScreen.js` · `LibrarySearchScreen.js` · `TrashScreen.js` — `useDiaryGrid(..., { count, padTop })` 와 `{...grid?.scroll}`
- 테스트: `tests/grid-layout.test.js`(8개 창 크기 표, 세로 칸 범위, 회전 위치)
