지금 방향은 맞습니다. 굿노트처럼 “칸 크기는 일정 범위로 유지하고, 폭이 충분해지면 정수 열 수만 늘리는” 방식이 다이어리 표지를 가장 안정적으로 보이게 합니다. 다만 현재 `세로 최소 208` 때문에 800dp에서 2열·264칸으로 튀는 것이 문제입니다.

해법은 세로 전용 최소 칸을 `180dp`로 낮추고, 남는 폭은 반드시 가운데 정렬하는 것입니다. 180칸이면 세로 표지 폭도 약 133dp라 제목·표지 질감을 충분히 읽을 수 있습니다. 반대로 간격을 키우는 것은 이미 존재하는 빈 공간만 더 커지므로 권하지 않습니다.

한 가지 확인할 점: 명시한 `본문 폭 = 창 폭 − 138`, `간격 32`와는 “1366 가로 → 5열 237” 및 “1024 세로 → 오른쪽 빔 54”가 산술적으로 함께 성립하지 않습니다. 아래 표는 폭 식을 기준으로 계산한 값입니다.

| 창 | 권장 열 | 칸 | 간격 |
|---|---:|---:|---:|
| 1280×800 가로 | 4 | 261 | 32 |
| 800×1280 세로 | 3 | 199 | 32 |
| 1194×834 가로 | 4 | 240 | 32 |
| 834×1194 세로 | 3 | 210 | 32 |
| 1024×1366 세로 | 4 | 197 | 32 |
| 744×1133 세로 | 3 | 180 | 32 |
| 1366×가로 | 5 | 220 | 32 |
| 1133×가로 | 4 | 224 | 32 |

핵심은 800·744 세로에서도 3열을 보장해, “커다란 2권과 넓은 오른쪽 빈칸”처럼 보이지 않게 하는 것입니다. 가로 표지는 칸 너비에 맞춰 선반 아래에 붙이고, 세로 표지는 `칸 × 0.74` 폭을 유지하면 됩니다.

회전 시에는 스크롤 좌표를 보존하지 말고, **화면 상단에 걸린 첫 다이어리의 ID와 그 항목의 화면 내 Y 오프셋**을 보존하세요. 회전 후 그 ID가 속한 새 행을 찾아 같은 상대 위치로 즉시 이동합니다. 이렇게 하면 2→3열, 3→4열로 바뀌어도 사용자가 보던 다이어리를 잃지 않습니다. 격자 재배치와 스크롤 이동 모두 애니메이션 없이 즉시 처리하는 편이 맞습니다.

표지 크기 조절은 1차에서는 넣지 않는 편을 권합니다. 이번 세로 규칙으로 가장 큰 불균형이 해소되고, 핀치는 스크롤·다꾸 제스처와 충돌하며 안내 문구도 금지되어 발견성이 좋지 않습니다. 나중에 요구가 확인되면 핀치 대신 보기 전환 옆에 크기 버튼 하나만 두고 `작게 / 보통 / 크게` 3단계로 제공하면 충분합니다. 각 단계도 같은 식에서 최소 칸만 바꾸고, 선택 상태는 버터 노랑, 나머지는 네이비·페리윙클 계열만 사용합니다.

머리줄은 정보 자체는 유지하되, 세로 900dp 미만에서는 한 줄 고정을 버리세요. 첫 줄은 `내 다이어리 + 보기 전환`, 둘째 줄은 `칩 + 검색`으로 두 줄 배치가 좋습니다. 1024 세로 이상은 현재 한 줄 구성을 유지해도 됩니다. 좌측 바는 회전만으로 자동 접지 않는 것이 좋습니다. 접힘까지 일어나면 격자와 보던 항목의 위치가 동시에 바뀌기 때문입니다.

최종 규칙은 다음 하나로 옮길 수 있습니다.

```js
const rail = 78;
const inset = 30;
const gap = 32;
const infoHeight = 58;

const usableWidth = windowWidth - rail - inset * 2;
const minCell = windowHeight > windowWidth ? 180 : 208; // 세로 3열 보장
const columns = Math.max(
  2,
  Math.floor((usableWidth + gap) / (minCell + gap)),
);
const cell = Math.min(
  264,
  Math.floor((usableWidth - gap * (columns - 1)) / columns),
);

const usedWidth = columns * cell + (columns - 1) * gap;
const gridLeft = rail + inset + (usableWidth - usedWidth) / 2; // 가운데 정렬
const rowPitch = cell + infoHeight + gap;
```

즉, 기존의 `32 / 최대 264`는 그대로 지키고, 세로에서만 최소값을 `208 → 180`으로 바꾸는 것이 이번 문제에 가장 작은 변경입니다.
