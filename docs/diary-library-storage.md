# 다이어리 목록 로컬 저장 (S15P31F106-121)

백엔드 연결 전까지 보관함의 다이어리 목록을 기기 저장소(AsyncStorage, 웹은 localStorage)에 저장하고 앱을 시작할 때 복원한다.

## 저장 형식

| 키 | 값 |
| --- | --- |
| `dio:diary:list:v1` | 다이어리 목록 배열. 먼저 만든 다이어리가 앞에 오는 생성 순으로 저장한다. 불러올 때 `createdAt` 기준으로 다시 정렬하고, `createdAt`이 없는 이전 다이어리는 ID(`diary-<생성 시각>`)의 시각을 쓴다. |
| `dio:editor:doc:v4:<diaryId>` | 다이어리별 편집 문서. 목록 저장 실패 뒤에도 생성 순서를 복구할 수 있도록 새 문서는 목록과 같은 `createdAt`을 함께 저장한다. |

목록 항목은 `{ id, title, color, type: '개인' | '공유', favorite, createdAt, updatedAt, trashedAt, pattern, pageSize, firstPage, firstPageDate }`이다.

- `pattern`: 표지 무늬 `linen | leather | dot | gingham | stripe`. 무늬가 없던 이전 다이어리는 `null`(무늬 없음)로 둔다.
- `pageSize`: 새 생성은 `landscape`만 지원한다. 기존 `portrait` 메타데이터는 그대로 보존하며 생성 화면의 세로형은 준비 중으로 비활성화한다.
- `firstPage`: 첫 페이지 서식 `monthly | weekly | blank | lined | grid | dot`. 값이 없으면 `blank`. 새 다이어리의 편집 문서는 이 서식의 속지 한 장으로 시작한다.
  - `blank | lined | grid | dot` → 공용 속지 `2026-reusable-note-{plain|ruled|grid|dots}-landscape`
  - `monthly` → `firstPageDate`가 속한 달의 `2026-monthly-MM-landscape`
  - `weekly` → `firstPageDate`가 포함된 주(월요일 시작)의 `2026-weekly-blocks-<월요일>-landscape`
- `firstPageDate`: `YYYY-MM-DD`, 먼슬리·위클리일 때만 저장하고 나머지는 `null`. 속지 자료가 2026년뿐이라 2026년 날짜만 허용한다. 값이 없거나 잘못되면 속지를 만들 때 `2026-01-01`을 기준으로 한다.
- `id`: 새 다이어리는 UUID v4다. 나중에 서버로 올려도 기기끼리 겹치지 않게 하려는 것이며, 페이지·요소 ID(`createId`)도 같은 UUID를 쓴다. 이전 버전이 만든 `diary-<생성 시각(ms)>` ID는 그대로 둔다.
- `createdAt`: 다이어리를 만든 ISO 시각. 생성 순 정렬에 쓴다. 이전 다이어리에는 없다.
- `trashedAt`: 휴지통으로 옮긴 ISO 시각, 보관함에 있으면 `null`.
- 허용되지 않은 값은 위 기본값으로 바꾼다.

`updatedAt`은 ISO 시각이며 화면에서 `formatUpdatedAt`으로 "방금 전 / N분 전 / N시간 전 / N일 전 / YYYY.MM.DD"로 표시한다. 이전 버전처럼 표시용 문자열이 들어 있거나 값이 없으면 "기록 없음"으로 표시한다.

## 복원 규칙

- 앱 시작 시 목록을 읽기 전에는 보관함을 비워 두어 빈 보관함 안내가 깜빡이지 않게 한다.
- 잘못된 항목(빈 ID·제목, 중복 ID)은 버리고 색상·유형·즐겨찾기 기본값을 채운다. JSON이 손상됐으면 빈 목록으로 시작한다.
- **저장소 읽기 자체가 실패하면 이번 실행 동안 목록을 저장하지 않는다.** 일시적인 읽기 오류 때문에 기존 목록을 빈 목록으로 덮어쓰지 않기 위함이다.
- **목록에 없고 편집 문서만 남은 다이어리는 되살린다.** 이 수정 전에 만든 다이어리(목록이 저장되지 않던 시기)를 잃지 않기 위함이다. 문서의 `title`·`coverColor`·`createdAt`을 사용하며, 복구한 항목도 원래 생성 순서를 유지한다. 이전 문서에 `createdAt`이 없으면 기존 호환 규칙을 적용한다. 페이지가 없거나 JSON이 손상된 문서와 다이어리 ID가 없는 이전 단일 문서 키(`dio:editor:doc:v4`)는 복구하지 않는다.

## 휴지통

- 보관함 카드의 표지 아래 오른쪽 휴지통 버튼은 목록에서 지우지 않고 `trashedAt`만 기록한다. 홈·내 공간에서는 숨기고 휴지통에만 보인다. 수정 모달에는 삭제 동작을 두지 않는다.
- 복원하면 `trashedAt`을 `null`로 되돌리고 생성 순으로 다시 정렬해 원래 자리로 돌아온다.
- 영구 삭제하면 목록 항목과 편집 문서(`dio:editor:doc:v4:<diaryId>`)를 지운다. 문서가 쓰던 미디어 원본은 다른 다이어리 문서나 사용자 스티커(`customDecor`)가 참조하지 않을 때만 지운다. 미디어 정리에 실패해도 다이어리 삭제는 되돌리지 않는다.
- 휴지통 항목은 목록에 남아 있으므로 앱을 다시 열어도 고아 문서 복구로 되살아나지 않는다.
- 웹은 `Alert.alert`가 창을 띄우지 않아 확인 창을 브라우저 `confirm`으로 띄운다(`shared/dialogs.js`).

## 범위 밖

- 편집기에서 내용을 수정해도 목록의 `updatedAt`은 갱신하지 않는다(표지 수정·편집기 제목 변경 시에만 갱신).
- 휴지통 자동 비우기(보관 기간)는 없다.

## 검증

- `node --test tests/*.test.js`: 195개 통과(목록 정리·휴지통 필드·2026 날짜, 첫 속지 SVG ID 매핑과 연간 78쪽 빈 문서 이전 포함).
- Expo 웹·Android 번들 생성 통과.
- 웹 브라우저(1024×768, 빈 저장소)에서 확인한 흐름
  - 빈 홈 → 새 다이어리(위클리, 2026-12-31) → 편집기 1페이지 진입, 속지 `2026-weekly-blocks-2026-12-28-landscape`
  - 편집기에서 제목 변경 → 홈 카드·목록 반영 → 새로고침 후 재진입해도 제목 유지
  - 수정 모달에서 표지 패턴·색상 변경 저장, 첫 속지 값은 유지
  - 삭제 → 휴지통 이동 → 새로고침 후에도 휴지통 유지 → 복원 → 다시 삭제 → 영구 삭제 → 새로고침 후 목록·문서 모두 없음(고아 복구로 되살아나지 않음)
  - 홈 탭·사이드 메뉴에 공유 항목 없음
- 확인하지 못한 것: iOS/Android 실기기 AsyncStorage·확인 창, 기존 78쪽 문서 이전의 실제 기기 데이터, 미디어가 있는 문서의 영구 삭제 시 미디어 정리.

## 편집 후 홈 복귀 위치

- 편집기에서 홈으로 돌아오면 마지막으로 펼쳤던 다이어리 ID를 휴지통 제외 전체 목록에서 찾아 캐러셀 중심 위치를 복원한다. 즐겨찾기 목록의 인덱스를 그대로 쓰지 않으며, 새로 만든 다이어리도 동일하게 처리한다. 대상이 없으면 첫 위치를 사용한다.
- 기존처럼 홈 복귀 시 모든 다이어리 필터를 사용하고 보기 모드는 유지한다. 한눈에 보기로 돌아온 경우에도 스와이프 보기로 전환하면 해당 위치를 사용한다.
- 캐러셀의 초기 스크롤·애니메이션 위치와 고정 카드 좌표를 맞춰 뒤쪽 다이어리 복귀도 처리한다. 저장 문서·정렬·저장 키는 변경하지 않으며 앱 재시작 후 마지막 다이어리 복원은 이번 변경 범위가 아니다.
- 코드 문법·공백만 확인하며 테스트·빌드·화면·실기기 검증은 수행하지 않는다.

## 다이어리 생성 팝업의 입력 차단

- 생성·수정 팝업은 React Native Modal의 투명한 별도 표시 계층에서 연다. 팝업이 보이는 동안 보관함 카드·필터·스크롤·사이드 메뉴로 터치가 전달되지 않는다. 웹은 Modal의 포커스 관리도 사용한다.
- 팝업 내부 선택·입력은 유지하고 X·바깥 배경 터치로 닫는다. Android 뒤로가기도 취소로 연결하되 저장 중에는 닫지 않는다. 팝업 종료 후 보관함 상호작용을 다시 허용한다.
- 문법·공백 검사만 수행하며 앱 화면·실기기 동작은 미검증이다.

- 홈 복귀 위치 보정: 뷰포트 측정 후 카드 너비·간격·양쪽 여백으로 콘텐츠 최소 너비를 계산하고 다음 프레임에 scrollToOffset으로 실제 이동한다. 해당 오프셋으로 애니메이션 값도 동기화하며, 사용자의 스와이프·화살표 이동을 다시 덮어쓰지 않는다.

## MR !57 리뷰 반영

- 장우창 님은 웹에서 홈 복귀 시 선택 인덱스는 맞지만 실제 스크롤은 0에 남는 문제를 보고했다. `onContentSizeChange`의 너비를 기다리던 조건을 제거하고, `양쪽 여백 + 카드 개수 × 카드 너비 + (카드 개수 − 1) × 간격`을 콘텐츠 최소 너비로 사용한다. 홈 복귀는 뷰포트가 측정된 다음 프레임에 이동한다.
- `getItemLayout`의 카드 시작 좌표에는 왼쪽 여백을 포함해 가상화 계산과 실제 배치를 맞춘다. 중앙 정렬용 스크롤 좌표·스냅·애니메이션은 기존처럼 `인덱스 × CAROUSEL_STEP`을 유지한다.
- 리뷰어의 이전 검증 결과: develop 병합 상태의 테스트 226개 통과·기존 실패 6개, 웹 번들 생성, 화살표 이동·팝업 입력 차단 확인 및 홈 복귀 실패 재현. 이번 수정 후 에이전트가 새로 수행한 검증 결과와 구분한다.
- 이번 수정은 JavaScript 문법·공백·충돌 표시만 확인한다. 테스트·빌드·웹 화면·실기기 검증은 수행하지 않는다. 앞·중간·마지막 문서, 즐겨찾기·새 문서 복귀, 보기·필터·화면 크기 변경 및 화살표·스와이프 회귀는 미검증이다.
