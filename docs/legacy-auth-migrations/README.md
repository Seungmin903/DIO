# 새 initial schema 이전 인증 마이그레이션 원본

이 폴더는 기존 이메일 회원가입 브랜치에서 배포했던 V2·V3·V6 SQL을 바이트 변경 없이 보존한다. Flyway 자동 실행 대상이 아니다.

develop의 `V1__initial_schema.sql`이 회원·인증 계정·약관·refresh_tokens 테이블까지 생성하게 되어 기존 SQL을 그대로 조합할 수 없다. 새 체인은 V1 initial schema → V2 인증 제약 및 이메일 검증 → V3 세션 확장 → 기존 V4·V5 사진 저장으로 구성한다. 새 V1 파일과 다른 도메인의 테이블은 변경하지 않는다.

이미 새 initial schema V1을 적용한 DB는 V2 이후를 데이터 보존 방식으로 적용한다. 기존 닉네임(소문자 기준)·이메일·인증 계정·토큰 해시가 중복되어 제약을 추가할 수 없으면 적용이 실패하고 롤백된다. 중복 데이터는 관리자가 정책을 확인해 별도 처리하며 자동 삭제하지 않는다.

이전 `V1__create_diaries.sql`과 인증 V2~V6을 적용한 DB는 새 V1과 이력이 호환되지 않아 기동이 중단된다. 자동 repair·baseline·clean 또는 DB 초기화를 실행하지 않는다. 데이터가 필요한 환경은 먼저 백업하고 별도의 보존 전환 절차를 승인받아야 한다. 데이터를 폐기해도 된다는 명시적 팀 합의가 있는 환경에만 [기존 전환 runbook](../runbooks/production-schema-reset.md)을 적용한다.

현재 코드 통합 작업은 실제 로컬·공유·운영 DB의 데이터를 변경하지 않는다.
