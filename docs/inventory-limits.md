# 현재 보유 개수 제한

회원 서버가 아래 정책을 강제한다. 기기 내 게스트 UI는 변경하지 않는다.

| 대상 | 한도 | 집계 기준 |
|---|---:|---|
| 사진 | 200장/계정 | 삭제되지 않은 개인 PHOTO 이미지 |
| 사용자 생성 스티커 | 200개/계정 | 업로드·AI 생성 이미지와 스티커 보관함 이미지의 UUID 합집합. 기본 제공 항목 제외 |
| 사용자 생성 테이프 | 5개/계정 | 개인 보관함의 TapeItem.id. 같은 항목의 폴더 복사 중복 제외. 업로드 후 아직 보관함에 연결하지 않은 TAPE 이미지도 임시 보유 수에 포함 |
| 개인 다이어리 | 5개/계정 | 휴지통 제외, 본인 소유 |
| 공유 다이어리 | 2개/계정 | 휴지통 제외, 소유 또는 활성 참여. 초대 대기 수신자는 수락할 때 집계 |
| 공유 구성원 | 4명/다이어리 | 소유자 포함 |
| 페이지 | 150쪽/다이어리 | 삭제된 페이지 제외. 초기 속지·새 페이지·복사·PDF용 페이지 모두 포함 |

사진·스티커의 기존 파일을 캔버스에 다시 배치해도 보유 수는 늘지 않는다. 테이프의 서로 다른 자르기 결과는 서로 다른 id로 저장하므로 각각 집계한다. id 없는 기존 테이프는 폴더·항목 위치별로 집계한다. 같은 id로 서로 다른 테이프 내용을 보내면 400이다.

## 삭제·복원·공유 전환

- 삭제는 즉시 보유 수를 줄인다. 다이어리 휴지통도 제외한다.
- 사진 삭제는 `library_removed_at`으로 개인 목록에서 숨긴다. 캔버스·이력·공유 보관함에서 사용하는 원본은 유지한다. 참조가 사라진 숨긴 원본은 기존 보존 기간과 참조 검사 후 물리 정리한다.
- 스티커·테이프 보관함에서 마지막 연결을 제거하면 해당 종류의 원본도 개인 보유 수에서 제외한다. 공유 다이어리의 기존 참조는 유지한다. 원본 삭제 API의 다른 종류 참조 보호 정책은 유지한다.
- 다이어리 복원은 소유자뿐 아니라 복원되는 모든 활성 공유 참여자의 2개 한도도 확인한다. 한 명이라도 초과하면 복원 전체가 롤백된다.
- 최초 공유 링크/유효한 이메일 초대를 만들면 공유 다이어리로 전환하고 소유자의 공유 한도를 확인한다. 공유 전환으로 개인 슬롯은 반환된다. 이미 공유인 다이어리의 링크 갱신은 추가 슬롯을 요구하지 않는다.
- 공유 다이어리는 1명만 남아도 공유 유형을 유지한다(`inventory_shared`). 소유자가 나가면 가입 시각·사용자 ID 순으로 남은 구성원에게 소유권을 넘긴다. 마지막 소유자가 나가면 기존 영구 삭제 정책을 따른다.
- 기존 초과 데이터는 자동 삭제하지 않는다. 기존 문서의 정리·이름 변경·순서 변경은 허용하고 초과 상태에서 새 항목 추가는 거부한다. 기존 150쪽 초과 다이어리 복원도 페이지 증가가 아니므로 허용하되 추가·복사는 제한한다.

## 트랜잭션과 동시 요청

계정·다이어리를 함께 잠그는 경로는 **계정 행(여러 명이면 사용자 ID 오름차순) → 다이어리 행 → 개수 잠금(사용자 ID 오름차순)** 순서를 따른다. 휴지통·복원은 계정 잠금 후 다이어리를 잠그며, 링크 생성·초대 수락·이메일 발송·차단도 계정을 먼저 잠근다. 회원 탈퇴가 계정 → 다이어리 순서로 진행할 때 역순 교차 대기를 만들지 않는다. PostgreSQL 테스트는 계정 잠금으로 요청을 대기시킨 상태에서 다른 트랜잭션이 같은 다이어리 잠금을 즉시 얻을 수 있는지 확인한다.

초대 수락은 공개 범위와 메타데이터 수정 시각을 덮어쓰지 않고 공유 보유 분류만 유지한다. 이미 공유 분류이면 다이어리 버전도 올리지 않는다. 개수 제한 의존성은 생성자로 필수 주입한다.

`inventory_quota_locks`의 계정별 행을 DB 트랜잭션 잠금으로 사용한다. 여러 참여자를 검사할 때 사용자 ID 순서로 잠근다. 생성·참여·복원 변경을 같은 트랜잭션에서 flush한 뒤 집계·검증하므로 실패하면 생성 행·멤버십·초대 사용 횟수까지 롤백한다. 페이지 증가는 다이어리 행 잠금 뒤 집계하여 149쪽에서 동시 추가되어도 150쪽까지만 성공한다. 기존 생성 Idempotency-Key/페이지 요청 ID 재요청은 추가 슬롯을 소비하지 않는다.

미디어는 스토리지/AI 작업 전에 별도 짧은 트랜잭션으로 1칸을 예약한다. 15분 만료이며 성공·실패 시 반환한다. 최종 DB 저장 시 실제 보유 수와 진행 중 예약을 재검증한다. 예약 트랜잭션은 네트워크 작업 전에 종료하고 개수 잠금은 실제 DB 저장 이후에 획득한다. 기존 업로드 큐 행을 보호하는 GuardedMediaOperations의 스토리지 쓰기 트랜잭션은 유지한다. 이 예약은 저장 개수 제한이며 기존 업로드 메모리 admission과 별개다.

한도 초과는 HTTP 409 `application/problem+json`:

```json
{"status":409,"code":"INVENTORY_LIMIT_REACHED","limitType":"PHOTO","currentCount":200,"maxCount":200,"requestedCount":1}
```

4명 정원 초과의 기존 `DIARY_MEMBER_LIMIT_REACHED` 코드는 유지한다. 새 endpoint는 없으며 기존 쓰기 API에 적용한다. Swagger에 `InventoryLimitProblem`을 추가한다. 회원 목록 커서는 유형 판정 변경에 맞춰 v5로 갱신하며 이전 커서는 첫 페이지부터 다시 조회한다.

## 배포·검증

Flyway `V46__inventory_limits.sql`이 잠금/예약 테이블, `media_files.library_removed_at`, `diaries.inventory_shared`, 인덱스를 추가한다. 기존 공유 범위 또는 다수 멤버 다이어리는 공유 유형으로 이관한다. 서버 배포 시 통상적인 Flyway 적용이 필요하며 S3 설정 변경은 없다.

`InventoryPolicyTests`는 실제 서비스/HTTP 및 동시 트랜잭션으로 생성·삭제·복원·링크/이메일 수락·정원·초기 페이지·복사·미디어 예약·보관함 중복/정리를 검증한다. `InventoryPolicyPostgresTests`는 같은 계약을 실제 Flyway PostgreSQL에서 실행한다. 공유 DB를 사용하지 않는다.

```powershell
# 반드시 별도 일회용 loopback DB dio_inventory_qa를 생성한 후 지정한다.
$env:DIO_INVENTORY_POSTGRES_QA='true'
$env:DIO_INVENTORY_POSTGRES_URL='jdbc:postgresql://127.0.0.1:포트/dio_inventory_qa'
$env:DIO_INVENTORY_POSTGRES_PASSWORD='일회용 DB 비밀번호'
.\gradlew.bat test --tests com.f106.DIO.sharing.InventoryPolicyPostgresTests
```

2026-11-12 리뷰 보완 검증: 전체 백엔드 1,261건 중 853건 통과·407건 조건부 제외·기존 WebSocket 연결 시간 초과 1건. 해당 WebSocket 클래스 42건은 단독 재실행에서 모두 통과했다. 정책 계약은 H2 20건·실제 Flyway PostgreSQL 23건 통과(계정→다이어리 잠금 순서 포함). 실패했던 CI 다이어리 묶음의 PostgreSQL 생성 63건·상세 16건·회원 HTTP 계약 38건도 모두 통과했다. 검증용 PostgreSQL은 일회용 컨테이너였으며 공유 개발 DB는 사용하지 않았다.
