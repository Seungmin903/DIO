# 코덱스 자문 — 폰 화면 방향성 (2026-11-03)

질문 문서와 시행착오를 함께 보내고 받은 답입니다. 결정은 사용자가 합니다.

## 질문(요약)
태블릿 세로 배치를 폰 폭에 맞춰 줄이는 방향을 유지할지, 방향을 바꿀지.

## 코덱스 답변 원문

1) 추천: 부분 변경 — 태블릿 세로 구조는 유지하되, 폰에서는 “축소판”이 아니라 정보 우선순위가 다른 단일열 레이아웃으로 재조립하는 편을 추천합니다.  
기능·색·도구 체계는 태블릿과 같게 유지할 수 있습니다. 다만 411dp 폭에서 태블릿의 가로 병렬 구조와 큰 미리보기는 시선·터치 밀도를 해칩니다. 현재 발견된 5건은 방향 문제가 아닌 구현 버그이므로, 이를 고친 뒤에도 폰 전용 치수 규칙은 필요합니다.

2) 화면별 판단

| 화면 | 판단 | 방향 |
|---|---|---|
| 홈 | 유지 | 좌측 접힘 바 + 본문이라는 앱 정체성은 좋습니다. 단, 2열 카드는 폭을 보장할 때만 유지합니다. |
| 편집기 세로 | 부분 변경 | 상단 정보와 12개 도구는 유지하되, 도구막대의 “항상 전부 보이는” 기대를 버리고 가로 스크롤을 명확히 설계합니다. |
| 편집기 가로 | 유지·보정 | 정밀 편집 모드로 적절합니다. 좌·우 막대와 캔버스의 최소 폭을 명확히 나눠야 합니다. |
| 새 다이어리 | 부분 변경 | 현재의 태블릿형 ‘탭 → 큰 미리보기 → 옵션 시트’는 폰에서 세로를 너무 많이 씁니다. 탭과 미리보기 밀도를 낮춰야 합니다. |
| 시트류 | 부분 변경 | 폰은 화면 하단 시트보다 중앙 또는 상단 고정형 패널이 더 맞는 경우가 있습니다. 키보드와 편집기 도구를 침범하지 않는 규칙을 통일합니다. |

3) 바꾼다면 구체 수치

- 공통
  - 콘텐츠 좌우 여백: `14dp`, 주요 카드 내부 여백: `16dp`.
  - 최소 터치 영역: `44×44dp`; 아이콘 자체는 대체로 `22–24dp`.
  - 상태바는 앱 배경색과 같은 아주 옅은 남보라 틴트로 통일하고, 모든 상단 바는 safe area 아래에서 시작합니다.
  - 상단의 뒤로가기 `‹`는 화면 모서리 기준이 아니라 좌측 `14dp` 컨테이너 안에 둡니다. 현재 약 7dp는 부족합니다.

- 홈
  - 411dp에서 본문 실폭은 접힘 바 60dp를 제외하면 약 351dp입니다. 좌우 `14dp`, 카드 사이 `10dp`라면 카드 폭은 약 `156.5dp`이므로 2열을 유지할 수 있습니다.
  - 카드 최소폭을 `154dp`로 두고, 그보다 좁아지면 1열로 전환합니다.
  - FAB는 현재 `52dp` 유지 가능하나, 우측·하단 안전영역 포함 여백은 `16dp` 이상으로 둡니다.
  - 펼친 좌측 바 `236dp`는 화면을 과하게 잠식할 수 있으므로 폰에서는 `224dp` 권장. 본문은 오버레이로 어둡게 덮지 말고, 단순히 비활성 터치 영역으로만 처리해도 충분합니다.

- 편집기 세로
  - 상단 바: safe area 제외 높이 `52dp`; 좌우 `14dp`.
  - 이름/PAGE 표기는 한 블록으로 묶되, 이름은 한 줄 말줄임 처리. `PAGE n/m`은 보조 텍스트 `12dp` 정도로 낮춥니다.
  - 가로 도구 막대: 높이 `56dp`, 칩/도구 터치폭 `48dp`, 도구 간격 `4dp`, 좌우 끝 여백 `14dp`.
  - 12개 도구를 억지로 축소하지 말고 스크롤 유지. 오른쪽 끝에는 현재 가로 편집기에 적용하려는 것과 같은 `24–32dp` 흰색 그라데이션을 적용해 “더 있음”만 시각적으로 보입니다. 안내 문구는 필요 없습니다.
  - 설정 패널은 도구 막대 바로 아래에서 열되, 최대 높이 `min(360dp, 사용 가능 높이의 52%)`. 캔버스 전체를 덮는 모달보다, 캔버스가 남는 패널이 낫습니다.
  - 레이어 패널은 되돌리기 영역과 겹치지 않게 상단 시작점을 `top bar + toolbar + 8dp` 이후로 잡고, 최소 `48dp`의 조작 여백을 둡니다.

- 편집기 가로
  - 왼쪽 막대: `60dp`; 아이콘 행 높이 `48dp`.
  - 오른쪽 도구 막대: `64dp`; 도구 하나당 `48dp` 높이와 `4dp` 간격.
  - 양쪽 막대를 제외한 캔버스 폭을 우선 확보합니다. 가로 폭이 부족할 때는 오른쪽 도구만 스크롤하고, 끝부분 `28dp`에 옅은 흰 그라데이션을 유지합니다.
  - 집중 모드에서는 왼쪽 막대만 숨기고 오른쪽 도구는 유지하는 편이 “정밀 모드”의 의미를 지킵니다.

- 새 다이어리
  - 상단 탭 칩: 높이 `48dp`, 칩 간격 `8dp`, 좌우 스크롤. 선택 칩은 현재처럼 테두리 중심으로 두고, 채움색을 강하게 쓰지 않습니다.
  - 미리보기 판: 고정 `200dp` 권장(현재 240dp에서 40dp 축소), 상하 여백 `12dp`, 내부 책/페이지 최대 높이 `164dp`. 표지와 속지를 나란히 보여야 하는 의미는 유지됩니다.
  - 미리보기 판 아래부터 옵션을 별도 “큰 바닥 시트”처럼 보이게 하지 말고, 화면 배경 위의 일반 폼 섹션으로 이어 붙이는 편이 폰에서 덜 무겁습니다. 구분은 `1dp` 선 또는 `12dp` 간격이면 충분합니다.
  - 이름 입력: 높이 `52dp`; 라벨 폭 `64dp`; 글자수 표시는 입력창 우하단이 아니라 입력 행 아래 우측 `12dp` 보조 텍스트로 분리합니다.
  - 방향 선택: 각 버튼 높이 `48dp`, 간격 `8dp`; 두 버튼 동등 폭.
  - “PDF에서 시작하기”: 높이 `52dp`, 내용 폭 기준 버튼으로 두되 최소 폭 `200dp`. 선택 불가한 회색이 아니라 옅은 남보라 바탕과 남보라 아이콘으로 활성 상태를 분명히 합니다.

- 시트류
  - 단순 선택(색, 글꼴, 테이프 등): 하단 시트 최대 높이 `사용 가능 높이의 58%`, 상단 모서리 `24dp`.
  - 텍스트 입력·키보드 동반 시트: 키보드 상단에서 `8dp` 띄우고, 시트 높이는 `220–320dp` 범위. 버튼은 시트 내부 하단에 고정합니다.
  - 사진 자르기: 폰에서는 자르기 판을 화면 전체의 절반이 아니라 `min(300dp, 사용 가능 높이의 38%)`로 제한하고, 비율 선택·확인 영역에 최소 `132dp`를 남깁니다.
  - 색/테이프 줄은 컨테이너 내부 우측 여백 `14dp`를 넘지 않게 `overflow: hidden`과 마지막 칸의 우측 패딩 `14dp`를 함께 적용합니다.

4) 기각안과 이유

- 현 구조를 태블릿 비율 그대로 계속 축소: 기능은 유지되지만 폰에서 미리보기·시트·도구가 서로 세로 공간을 경쟁해 답답해집니다.
- 전면 변경(하단 탭 복귀, 편집기 도구 대폭 축소): 홈 공간 보호와 12개 동등 도구라는 이미 정한 원칙을 훼손합니다.
- 도구를 여러 단계 메뉴로 감추기: 공간은 절약하지만 펜·텍스트·사진처럼 자주 오가는 편집 흐름이 느려집니다.
- 도움말 문구·애니메이션으로 스크롤을 설명: 금지된 디자인 원칙에 맞지 않고, 끝 그라데이션만으로 충분합니다.
