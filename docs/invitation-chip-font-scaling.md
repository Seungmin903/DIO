# 초대 상태 칩 글자 확대 대응

## 원인과 수정

공유 알림·홈 알림·초대 상세가 공유하는 statusChip의 height:24 때문에 시스템 글자 확대 시 글자가 잘렸다. 고정 높이를 minHeight:24로 바꾸고 세로 패딩 3, 최대 너비 100%, flexShrink:1을 적용했다. 상태 글자는 줄 수 제한 없이 중앙 정렬한다. 공유 목록의 제목/칩 행은 wrap을 허용한다. 글자 배율을 제한하거나 글자를 축소하지 않는다.

## 검증

- `node --test tests/notification-presentation.test.js tests/diary-sharing-state.test.js`
- `PLAYWRIGHT_EXECUTABLE_PATH`에 브라우저 실행 파일을 설정한 뒤 `node qa/invitation-chip-font-scaling.cjs` 실행.
- 브라우저 검사 범위: 실제 sharingStyles를 CSS로 적용한 독립 레이아웃에 너비 320/800/1280, 글자 배율 1/2/3, 상태 문구 8개. 글자 영역이 칩 밖으로 나가지 않고 카드 내에 배치되는지 검사한다. React Native 전체 화면·OS 글꼴 확대를 직접 재현한 테스트는 아니다.
- `.expo/invitation-chip-font-scaling/`에 생성한 스크린샷으로 좁은 화면의 긴 상태 줄바꿈을 확인한다.
- 알림 모의 테스트는 기존 AuthenticationRecovery JSX 의존성을 다른 화면 컴포넌트처럼 mock 처리한다. 실제 로그인 복구 동작은 변경하지 않는다.

2026-11-05 관련 Node 40개 통과, 브라우저 3너비×3배율×8상태(72조합) 기하 검사 통과.

## 실기기 확인

태블릿 시스템 글자 크기를 최대로 설정하고 홈 알림 목록·초대 상세·공유의 다른 다이어리 알림에서 응답 대기/이미 수락/만료/정원 가득 등 상태 문구의 상하 잘림과 가로 넘침이 없는지 확인한다. 회전과 스크롤도 확인한다. 일반 글자 크기로 되돌렸을 때도 칩 배치가 정상인지 확인한다.

추가 실기기 사진에서 초대 링크 만들기 버튼도 마지막 글자가 잘리는 것을 확인했다. 버튼 영역의 고정 너비 76을 최소 너비로 바꾸고 축소를 막아 글자 크기에 맞게 늘어나도록 했다. 링크 행 역시 고정 높이 대신 최소 높이 48을 사용한다. 생성 후 아이콘 영역은 기존 44 너비를 유지한다. 관련 Node 테스트 40개 재통과.

## 링크 영역의 검증 범위와 표시 정책

- 링크 박스도 최소 높이 48과 세로 패딩 2를 사용해 확대된 한 줄 텍스트 높이에 따라 늘어난다.
- URL의 selectable 제거는 의도된 변경이다. Android 태블릿에서 selectable을 유지했을 때 한 줄 제한에도 다음 줄 일부가 비쳤고, 제거 후 한 줄 말줄임과 중앙 정렬이 정상 표시되는 것을 사용자 사진으로 확인했다. 전체 URL은 기존 복사 버튼으로 복사하며 실제 복사 성공도 확인했다. 링크가 없으면 복사할 URL도 없다. 웹에서도 직접 텍스트 선택 대신 복사 버튼을 사용한다.
- linkText의 12.5/600은 기존 s.text와 동일하다. 링크에는 고정 lineHeight:19를 적용하지 않기 위해 별도 스타일을 사용한다.
- 브라우저 72조합 검사는 상태 칩만 대상으로 한다. 링크 행·만들기 버튼·URL은 이 스크립트의 검증 대상이 아니다. 해당 영역은 Android 태블릿 최대 글자 크기의 사용자 실기기 사진 및 복사 동작으로 확인했다.
- Node 테스트는 공유 동작 회귀 검사이며 네이티브 글자 배치 검증을 대신하지 않는다. 링크 박스의 최소 높이·패딩 보완 후 실기기 재확인이 필요하다.
