# 나만의 폰트 만들기

손글씨 36자를 기기에 저장하고 Android에서 한글 11,172자 TTF를 생성하는 기능의 현재 사용 방법과 데이터 계약입니다. 버전별 실측과 검증 결과는 [손글씨 폰트 검증 기록](./personal-handwriting-validation.md)에서 확인합니다.

## 사용 흐름

내 공간 또는 텍스트 도구의 **나만의 폰트 만들기** → 내 폰트 홈 → 이름·36자 입력 → 실제 고정 샘플 확인 → 생성 확정 → 폰트 상세·자동 등록 → 텍스트 글꼴에서 선택. 단계별 화면·수정본·대기열의 현재 계약은 [폰트 생성 화면 흐름](./font-creation-flow.md)을 따른다.

- Expo Go: 작성, 초안 자동 저장·복원, 내 폰트 목록·상세, 완성 TTF 가져오기·등록·적용을 지원합니다. 가짜 생성 결과를 만들지 않습니다.
- Android 개발 빌드: 위 기능과 함께 기기 내 실제 FP32 추론·전체 TTF 제작을 지원합니다. 개발 APK는 `com.f106.DIO.dev`(앱 이름 DIO Dev)라 기존 DIO 앱을 덮어쓰지 않습니다.
- Expo Go와 개발 빌드는 저장소가 다릅니다. 개발 확인용 초안 JSON과 완성 폰트 JSON/TTF를 기기 내 파일로 옮길 수 있습니다. 자동 업로드·계정 동기화·공유 다이어리 폰트 배포는 없습니다.
- 개인 폰트는 Regular입니다. 굵게·기울임은 비활성화하고 밑줄·색·크기·간격 등 기존 텍스트 기능은 유지합니다. 앱 메뉴 전체의 폰트는 바꾸지 않습니다.

## 실행

`frontend/`에서 `pnpm install --frozen-lockfile`, `pnpm start:go`로 Expo Go 개발을 계속합니다. 기존 android/ios 실행 명령의 Expo Go 동작을 유지합니다.

네이티브 모델은 Git에 포함하지 않습니다. 추론 전용 소스의 변환·전체 동등성 검증을 통과한 두 FP32 ONNX 파일을 다음 명령으로 준비합니다. 변환과 검증 명령은 `frontend/model-tools/README.md`에 있습니다.

```powershell
pwsh scripts/prepare-handwriting-models.ps1 -SourceDirectory 'qa/handwriting-output/inference-v2/models'
```

모델 전체 약175MB이며 설치된 앱은 검증 후 앱 내부 저장소로 복사합니다. 개발 빌드와 모델 저장을 위한 여유 공간이 필요합니다. 새 묶음의 가중치 해시는 기존과 같으며, 변환 모델 해시·버전은 별도로 관리합니다.

```powershell
# 일반 Android 개발 빌드
pnpm android:font-dev

# 이미 만든 개발 APK를 설치했다면 JavaScript 서버만 실행
pnpm exec expo start --dev-client

# Windows의 긴 경로가 CMake 실행을 막으면 짧은 폴더에 빌드 사본 생성
# 정상 설치된 NDK가 기본값과 다를 때에만 이 환경변수를 지정
$env:DIO_ANDROID_NDK_VERSION = '28.2.13676358'
pwsh scripts/build-handwriting-android.ps1 -Architecture arm64-v8a

# 실행 중인 x86_64 에뮬레이터에 실제 모델→TTF 시험
pwsh scripts/build-handwriting-android.ps1 -Architecture x86_64 -Test
```

짧은 빌드 사본은 기본적으로 `%USERPROFILE%/.dfont`에 만들며 소유 표식이 없는 기존 폴더를 덮어쓰지 않습니다. APK는 클론의 `frontend/qa/handwriting-output/android/`에 복사합니다. `expo prebuild`가 실행 스크립트를 `run:android/ios`로 바꾸면 Go 확인에는 `pnpm start:go`를 사용합니다.

## 입력·생성 계약

- 원본은1024좌표의 획·굵기·확인 가능한 필압·시간입니다. 안내 글자는 원본에 합성하지 않습니다. 전처리로 원본 좌표를 덮어쓰지 않습니다.
- 공통 JS 전처리는4배 래스터화 후 면적 평균으로128px 입력을 만듭니다. 잉크 중심 고정, 긴 변 목표96px, 배율0.8~1.6, 최소4px 여백입니다. 경계에 너무 가까워 조건을 지킬 수 없으면 다시 쓰기를 안내합니다. 이는 기하학적 크기 맞춤이며 필체 유사도의 최적값을 보장하는 점수는 아닙니다.
- 모델 입력은`gray/127.5-1`입니다. 인코더는`[1,1,128,128]`에서16px 구성요소 특징과32px skip을 반환합니다. 같은 자모의 특징을 평균해68개 슬롯에 저장하고, 디코더에 요청 음절의 세 슬롯을 전달합니다. 기존 영구 메모리를 유지합니다. 추가64/8 경로·수동 자모 마스크·새 학습은 없습니다.
- 가중치는 원본 DM-Font `generator_ema` SHA256 `e5b28ca6793429b5e8bc77ed07ef166c7dfce91e089f068cc86318897700cae0` 기반입니다. 이전에 검증된 모바일 그래프의 상대위치 대수식 정리는 FP32 연산 순서 차이를 만들 수 있어 PyTorch 대조 결과를 따로 기록합니다. 양자화는 없습니다.
- 인코더/디코더 파일 SHA256은 번들의 manifest와 네이티브 실행 코드에서 확인합니다. ONNX Runtime Android1.23.2, CPU·배치1을 사용합니다. 개발 중 GPU/NPU 가속을 가정하지 않습니다.
- 새 모듈은 지원 조회, 작업 시작·최신/개별 상태 조회·일시 정지·재개·취소, 샘플 미리보기와 진행 이벤트를 제공합니다. API 서버는 추가하지 않습니다.

## 저장·중단·폰트

초안, 모델 버전, 전처리 버전, 원본·배율·입력 해시를 작업에 고정합니다. 이후 초안을 수정해도 기존 작업의 입력은 유지합니다. 여러 생성 확정은 앱 전역 FIFO 대기열에 저장하고 네이티브 생성기는 한 번에 하나만 실행합니다. 새 샘플 요청은 현재 전체 생성을 안전하게 정지한 뒤 실행하고 원래 작업을 이어갑니다. JS 저장 정보가 없어도 네이티브 최신 작업에서 복원합니다.

참조 특징은 입력 해시별 별도 파일에 저장하고, 완성형 U+AC00~U+D7A3를 순서대로 만듭니다.32자 묶음의 윤곽선 저장이 끝난 뒤 진행 위치를 확정합니다. 폰트 화면을 벗어나도 활성 앱에서는 계속 생성합니다. 앱이 백그라운드로 이동하면 안전한 구간에서 정지하고, 앱 복귀·재실행 시 마지막 확정 구간부터 자동 재개합니다. 직접 일시 정지한 작업은 사용자가 재개합니다. 일시 정지 중 덜 확정된 묶음은 재계산할 수 있습니다. 완료 폰트와 원본을 정리 대상으로 지우지 않습니다.

모델 버전은 입력 해시에 포함됩니다. 버전이 바뀌면 이전 특징 캐시를 새 작업에서 재사용하지 않습니다. 이전 모델의 미완료 작업은 상태를 바꾸기 전에 이어하기를 거절하고, 저장된 손글씨로 새 작업을 시작하도록 안내합니다. 이전 완성 작업의 폰트 등록과 이미 등록한 폰트의 UUID·문서 참조는 유지합니다.

원시 출력에 보정을 적용하지 않습니다. 윤곽선 추출용 사본만 임계값200으로 판별하고 픽셀 경계 윤곽선을 추적합니다. 속공간·분리 조각을 보존하고 자모 재조합·획 추가·윤곽선 smoothing은 하지 않습니다. UPEM2048, 공통 변환`x=16*x`, `y=1720-16*y`, 한글 advance2048, 공백1024입니다. 위치를 글자마다 다시 맞추지 않습니다.

완성 TTF는 파일 검증과 Android Typeface 로드 후 완료로 표시합니다. 이름은 표시용이며 렌더링 ID·family는 UUID로 유지합니다. 누락된 영문·숫자·문장부호·자모는 기기 기본 글꼴로 표시합니다. 글꼴 로드를 기다린 뒤 기존 공통 이미지 렌더러로 PNG·이미지 기반 PDF를 내보냅니다.

## 검증 방법

- `pnpm test:handwriting`: 자모68종 커버, 원본 불변·중심·여백, 입력 오류, Regular 정책, 로컬 이관 인코딩.
- `node --test tests/*.test.js`: 기존 편집·서식·저장·내보내기 회귀 검사.
- `pnpm exec expo export --platform web`: 네이티브 모듈 없는 번들.
- `pnpm qa:handwriting`: 새 브라우저 저장소에서 작성·Undo·재실행 복원, 생성 비활성화, 실제 TTF 가져오기·재실행 로드, 폰·태블릿 화면. 이는 Expo Go 실기기 시험과 구분합니다.
- `scripts/verify-handwriting-model.py`: PyTorch 대조, 실제 ONNX 전체 생성, 앱과 동일한 Java TTF 제작기, 전체 문자 매핑, 모델 출력과 TTF 렌더링 비교. PC 속도를 휴대폰 속도로 표시하지 않습니다.
- Android instrumentation: 실제 FP32 모델 실행, 특징 캐시의 반복 출력 일치, 생성 윤곽선으로 TTF 제작·Typeface 로드. 실기기 속도·메모리·발열의 과거 실측은 별도 검증 기록의 버전과 기기 범위로 한정합니다.

모델·개인 원본·생성 이미지·개인 TTF·Android 시험용 참조·검증 출력은 ignore 대상입니다. 모델 배포에 필요한 원저작권·NOTICE는 네이티브 assets에 보존합니다.

## 무손실 TTF 저장 최적화

`OutlineFont.java`는 같은 좌표 차이를 짧은 값·0 값·반복 flag로 인코딩하고, long loca를 사용해 글자 사이의 불필요한 패딩을 없앱니다. 반복되는 advance width는 hmtx 공통 폭으로 저장합니다. 점·윤곽선·on-curve 상태·명령·bounds·문자 매핑·bearing·실제 글자 폭은 변경하지 않습니다. 획 제거·곡선 단순화·좌표 반올림은 하지 않습니다.

새 체크포인트와 최종 제작에 같은 인코딩을 적용합니다. 이전/새 체크포인트가 섞여도 최종 TTF를 만들 수 있으며 기존 완성 폰트를 다시 쓰거나 폰트 ID·문서 참조를 바꾸지 않습니다. 검증 표본의 9.27MB는 특정 필체의 실측이며 모든 폰트가 같은 크기가 된다는 뜻은 아닙니다.

## 추론 소스와 고지

추론 패키지는 `frontend/model-tools/dio_dmfont/`에 있으며 원본 제한 모듈·학습 초기화·판별기·보조 분류기를 포함하거나 import하지 않습니다. 독립 구현한 차원 분리와 `w_norm='none'` 경로를 사용합니다. 현재 모델 버전은 `dmfont-fp32-e5b28ca6-inference-v2`입니다. 학습된 값·FP32 계산·16px/32px 특징 전달을 유지합니다.

- [소스 목록·원본 해시·수정 내역](../frontend/model-tools/dio_dmfont/PROVENANCE.json), [재사용 소스 MIT 전문](../frontend/model-tools/dio_dmfont/UPSTREAM_LICENSE), [현재 NOTICE](../frontend/model-tools/NOTICE)는 소스 저장소의 자료입니다.
- Android 모델 assets에는 `LICENSE`와 `NOTICE`를 제공합니다. NOTICE의 소스 목록·이전 고지 참조는 저장소 경로이며 설치 assets의 상대 경로가 아닙니다.
- 모델 준비 스크립트는 검증된 이전 번들을 사용해도 저장소의 현재 NOTICE를 복사합니다. 앱의 라이선스 화면과 통합 고지도 같은 원본으로 생성합니다.
- [이전 고지](../frontend/model-tools/license-history/DMFont-NOTICE-v1.txt)는 출처 이력으로 보존합니다. 이전 고지의 전체 구성요소를 새 추론 패키지의 의존성으로 간주하지 않습니다.

제한 모듈 의존성 제거와 추론 동등성 검증은 가중치·학습 데이터의 사용 및 배포 권리 검토를 포함하지 않습니다. Android·웹의 다른 구성요소 고지와 대응 소스는 [배포 고지 문서](./third-party-distribution.md)를 따릅니다.

## 검증 기록 관리

[검증 기록](./personal-handwriting-validation.md)은 과거 검사 결과와 한계를 버전별로 보관합니다. 새 코드·모델·기기의 성능으로 이전 결과를 대신하지 않습니다. 모델 전체 생성·실기기 발열 검증은 해당 기록에 명시된 버전과 기기에서만 수행한 것입니다.

공유 문서에는 실명·개인 폰트 표시 이름·개인 입력 및 폰트 해시·ADB serial·개인 데이터 화면을 기록하지 않습니다. 테스트 필체는 익명 표기를 사용하고, 재현에 필요한 모델·의존성 버전·기기 모델·OS·통계는 남깁니다. 개인 참조·초안·생성 이미지·폰트·원시 QA 기록은 Git ignore 대상입니다.

### 생성 작업 저장 및 복구 보완 (2026-10-31)

폰트 생성 완료와 앱 등록 완료를 구분하며, 완료 직후 종료된 작업과 구형 미등록 완료 항목도 등록을 재시도한다. sourceJob 기준 중복 방지를 유지한다. 생성 작업 v3는 AsyncStorage에 작은 참조만 저장하고 원본 획·미리보기와 색인은 네이티브 문서 파일/웹 IndexedDB에 저장한다. 기존 v2 목록은 새 저장 성공 후 이관하며 실패 시 원본을 보존한다. 세부 절차는 [폰트 생성 화면 흐름](font-creation-flow.md)의 MR !252 리뷰 수정 절을 따른다.
