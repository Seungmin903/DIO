# PDF 원본 보관과 확대 선명도

> 기준일: 2026-11-02 · 프론트 구현. 서버 다이어리(회원)도 PDF 속지를 쓰고, 원본 PDF 를 서버에 올려 친구 기기에서도 확대하면 선명하다(아래 "서버 다이어리 공유").

## 문제

PDF를 불러오면 쪽마다 긴 변 3000px 그림(PNG)으로 바꿔 쓴다. 한 장을 화면에 맞춰 볼 때는 충분하지만, 태블릿에서 확대해 글씨를 쓰거나 스티커를 붙이면 그림이 늘어나 흐려진다. 손글씨와 스티커는 벡터라 선명해서 밑의 PDF만 뭉개져 보인다.

## 해결

1. **원본 PDF 보관**: 불러올 때 원본을 앱에 같이 저장한다(`sourceId`). 앱은 `Paths.document/dio-pdf-source/<id>.pdf`, 웹은 IndexedDB `dio-pdf-source`. 이미지 보관소와 따로 둔다.
2. **쪽 요소가 원본 위치를 안다**: PDF 쪽 그림 요소에 `pdfSource: { sourceId, pageIndex, edge }`(edge = 기본 그림의 긴 변 픽셀)가 붙는다. `mediaFileId` 키를 쓰지 않으므로 이미지 불러오기·서버 동기화가 이 값을 이미지로 오해하지 않는다. 나의 속지에도 그대로 이어진다.
3. **확대하면 보이는 영역만 원본에서 다시 그려 얹는다**(`PdfDetail`): 기본 그림은 그대로 두고, 그 위에 선명한 조각을 별도 층으로 얹는다. 로딩 표시 · 페이드는 없다.

## PDF 쪽은 속지처럼 동작한다 (바탕 요소)

- **페이지 크기는 쪽 비율을 따른다**: A4 가로 PDF는 1024×724 페이지가 된다(긴 변 1024, 3 : 1보다 길쭉하면 3 : 1까지만). 예전에는 문서 방향의 고정 캔버스 안에 쪽을 넣고 남는 곳을 흰 종이로 두었다. 비율이 다른 쪽이 섞여 있으면 쪽마다 자기 크기를 가진다.
- **쪽 그림은 바탕 요소(`backdrop: true`)다**: 요소 목록에는 있어서 저장 · 내보내기 · 썸네일은 그대로 쓰지만, 눌러도 선택되지 않고(터치 · 올가미 · 영역 선택 · 전체 선택 제외) 레이어 패널에도 나오지 않으며, 다른 요소를 맨 뒤로 보내도 바탕 아래로 내려가지 않는다(`utils/backdrop.js`). 다른 필기 앱들도 가져온 PDF 쪽을 움직일 수 없는 바탕으로 두는 것으로 보인다(사용자 보고 기준).

- **표시 영역은 현재 페이지 크기를 따른다**. PDF 바탕은 원본 비율을 유지하며 페이지 안에 들어오는 가장 큰 크기로 가운데에 놓인다. 편집 화면, 페이지 썸네일, 내보내기에 같은 영역을 적용한다. 확대·축소하면 바탕과 필기가 같은 페이지 좌표에서 함께 움직인다.

- **미리보기와 페이지 열기**. 공방과 새 다이어리, 편집기의 페이지 추가에서 PDF 비율을 유지해 미리보기를 표시한다. PDF 속지 페이지로 이동하면 이전 페이지의 확대와 이동을 초기화하고 쪽 전체를 보여 준다.

- **iOS PDF 래스터 배율**. 새 네이티브 렌더러는 PDF 쪽 좌표에서 목표 픽셀 크기로 배율을 명시한다. 이전 개발 빌드에서는 쪽 크기 이내로 렌더링한 전체 이미지를 쓰고, 확대 영역을 별도로 그리지 않는다. 기기에 원본이 남아 있는 이전 속지는 표시 이미지를 캐시에 다시 만들며 기존 저장 파일과 좌표를 보존한다.

## 규칙 (`diary/utils/pdfSource.js`의 `planPdfDetail`)

| 항목 | 값 |
|---|---|
| 그리는 때 | 확대 · 이동이 멈추고 150ms 뒤. 움직이는 동안은 그리지 않는다 |
| 필요 판단(확대) | `zoom × 기기 픽셀비` 가 기본 그림 해상도(`edge ÷ 긴 변`)보다 크고, 조각이 기본 그림보다 1.1배 이상 선명할 때만 |
| 필요 판단(축소) | 기본 그림을 1.25배 넘게 줄여 보면(쪽 전체 보기) 그 화면 해상도로 원본에서 바로 그린다. 3000px 그림을 줄이면 달력 줄 같은 얇은 선이 흐려지거나 빠질 수 있어서다. 첫 조각은 바로, 바꿀 때는 150ms 뒤 |
| 영역 | 보이는 범위 + 사방 25% 여백, 쪽 밖은 자른다 |
| 해상도 | 화면 해상도까지, 한 조각 900만 화소 · 긴 변 4096 안 |
| 다시 그리는 때 | 보이는 곳이 조각 가장자리 10% 안까지 다가오거나, 더 확대해 해상도가 모자랄 때 |
| 치우는 때 | 기본 그림으로 충분해지면(축소) 비운다. 새 조각이 다 뜬 뒤에야 이전 조각을 치운다 |
| 안 그리는 곳 | 썸네일 · 내보내기(보이는 범위 정보가 없음), 회전하거나 뒤집은 쪽 |

편집기 확대 한도는 태블릿 3배 · 폰 4배라 조각 크기는 화면 크기 수준에서 멈춘다.

## 남은 일 · 알아 둘 것

- 네이티브 모듈이 바뀌었으므로 안드로이드 · iOS는 **개발 빌드를 다시 만들어야** 한다. 옛 빌드에서는 영역 그리기가 없어 기본 그림만 보인다(오류 없음).
- **공유할 때 5MB 넘는 쪽 그림**: 서버 이미지 업로드는 5MiB 까지라, 5MiB 를 넘는 PDF 쪽 PNG 는 올리는 순간에만 JPEG 로 낮춘다(`editor/utils/shareImage.*`, `shareImagePlan.js`).
  품질을 92%부터 낮추고, 그래도 크면 크기를 85 · 70 · 55%로 줄인다. 기기에 둔 PNG 원본과 내 화면 · 확대 선명도는 바뀌지 않는다.
  - 불투명하다고 표시된 쪽(`opaque`, 이 기능 이후에 불러온 PDF 쪽)만 대상이다. 투명할 수 있는 스티커 · 이전에 불러온 PDF 쪽은 그대로 5MB 를 넘으면 오류가 난다.
  - 친구 기기에는 JPEG 가 가서 글자 가장자리가 약간 흐릴 수 있다. 확대하면 서버의 원본 PDF 로 다시 그려 선명해진다(아래). 이 JPEG 변환은 그때도 필요하다(쪽 그림은 계속 이미지 업로드를 거친다). 크기를 줄이는 단계(85 · 70 · 55%)까지 간 쪽은 `pdfSource.edge`(3000)가 실제보다 커서 확대 때 조각이 늦게 뜰 수 있다.
- **지울 때의 정리**: 나의 표지 · 나의 속지를 지우거나 휴지통의 다이어리를 영구 삭제하면, 그 항목이 쓰던 쪽 그림과 원본 PDF 를 함께 지운다.
  다른 다이어리(휴지통 포함) · 기본 문서 · 내 꾸미기 소재 · 다른 나의 표지/속지가 아직 쓰고 있으면 남긴다(`diary/utils/libraryCleanup.js`, `trashRetention.js`).
  저장값을 읽다 실패하면 아무것도 지우지 않는다. 원본이 없어진 쪽은 오류 없이 3000px 기본 그림만 보여 준다.
- **고아 파일 점검**: PDF 를 불러올 때마다 `{ sourceId, 쪽 그림 id, 시각 }` 를 기록해 두고(`dio:diary:pdf-imports:v1`), 앱을 켠 뒤 한 번(보관함이 열리고 10초 뒤) 점검한다.
  표지로만 쓰고 남은 쪽, 다이어리를 지운 뒤 남은 표지 사진처럼 어디에도 담기지 않은 쪽 그림과 원본을 지운다(`diary/utils/pdfImportSweep.js` · `pdfImportRegistry.js`).
  - **쓰는 곳 판단**: 저장된 모든 값(다이어리 목록의 표지, 문서, 나의 표지 · 속지, 꾸미기 소재, 프로필 등)에서 id 글자가 한 번이라도 나오면 쓰는 것으로 본다. JSON 으로 해석하지 않으므로 값이 깨져 있어도 지우지 않는 쪽으로 기운다.
  - **하루 유예**: 하루가 안 된 기록은 건드리지 않는다(막 불러와 화면에서 저장 중일 수 있다).
  - **범위**: 이 기록에 있는 PDF 쪽 그림과 원본만 지운다. 다른 경로로 들어온 이미지는 건드리지 않는다. 기록 없이 이전에 불러온 PDF 는 점검 대상이 아니다.
  - 나의 표지 · 속지 삭제와 휴지통 영구 삭제의 정리도 다이어리 목록의 표지 사진을 쓰는 곳으로 센다.
- 내보내기는 아직 3000px 그림 기준이다. 쪽은 원본 PDF 그대로 두고 잉크 층만 얹는 방식은 후속 과제.

## 서버 다이어리 공유 (2026-11-02)

백엔드가 PDF 원본(`MediaType.DOCUMENT`, 25MiB 이하)을 받고, 같은 방 멤버(소유자 · 편집자)에게 내려 준다. 프론트는 이렇게 이었다.

| 단계 | 하는 일 | 파일 |
|---|---|---|
| 만들기 | 회원 다이어리도 PDF 를 속지로 쓴다. PDF 쪽 수만큼 서버에 **빈 페이지**를 만들고(`initialPages`, 서버 속지 목록에 PDF 가 없어서 크기는 빈 속지 규격), 만든 직후 쪽마다 `PATCH /pages/{id}` 로 **쪽 크기**를 맞춘다. 로컬 문서는 서버가 준 페이지 id 에 크기와 잠근 바탕 그림을 얹어 저장한다. 크기 맞추기에 실패하면 문서를 쓰지 않고 생성 요청을 남겨 같은 요청으로 다시 시도한다 | `diaryCreateInput.js` · `memberDiaryApi.js`(`setPageSizes`) · `memberAppStore.js` · `DiaryCreateModal.js` |
| 올리기 | 편집기가 쪽을 서버에 동기화할 때(`canvasMedia.prepare`) 요소의 `pdfSource.sourceId` 로 기기의 원본을 **DOCUMENT 로 한 번만** 올리고 받은 id 를 `pdfSource.mediaFileId` 에 단다. 올린 기록은 다이어리별로 남겨 재시작 뒤에도 다시 올리지 않는다. 원본이 없거나 25MB 를 넘으면 원본 없이 올리고(친구 화면은 기본 그림) 편집은 막지 않는다. 일시적 실패(연결 끊김 등)는 다시 시도한다 | `collaboration/canvasMedia.js` · `editor/services/canvasMediaFiles.*` |
| 모든 쪽 올리기 | 편집기는 보는 쪽만 동기화하므로, 열 때 아직 서버에 없는 PDF 쪽(바탕에 `pdfSource.mediaFileId` 가 없는 쪽)을 한 쪽씩 차례로 올린다. 안 그러면 친구에게는 방문하기 전까지 빈 쪽으로 보인다 | `useMemberCanvasCollaboration.js` |
| 받기 | 친구 기기는 쪽 그림(이미지)만 먼저 받는다. 원본은 **확대해서 영역 그림이 필요해질 때 처음** 받아 `sourceId` 로 보관하고(25MB 까지, `%PDF-` 확인) 다시 그린다. 받는 중이면 같은 요청을 함께 기다리고, 실패하면 30초 동안 다시 받지 않는다 | `canvasMedia.fetchDocument` · `editor/services/pdfSourceRemote.js` · `PdfDetail.js` |

- **서버 값을 믿지 않는다**: 파일 이름으로 쓰는 `sourceId` 는 영문 · 숫자 · `_` · `-` 64자까지만 쓰고, 받은 파일은 PDF 머리글(`%PDF-`)이 아니면 보관하지 않는다. 올릴 때 요소에 이미 붙어 있는 서버 id 는 이 다이어리에서 아는 id 일 때만 믿고, 아니면 이 기기의 원본으로 다시 올린다.
- **이미지와 PDF 는 서로 다른 자리**: 서버는 `pdfSource.mediaFileId` 를 DOCUMENT 로, 요소의 `mediaFileId` 를 IMAGE 로 확인한다. 이미지 불러오기(`hydrate`)는 `pdfSource` 를 이미지로 받지 않는다.
- **기기에만 있는 것**: 표지(사진 · 꾸밈)는 서버에 저장되지 않아 친구 기기에는 PDF 표지가 보이지 않는다. 나의 속지 · 나의 표지는 기기 보관함이다.
- **정리**: 친구가 받은 원본도 문서에 `sourceId` 가 남아 있어 고아 점검이 지우지 않고, 다이어리를 지울 때 다른 곳에서 쓰지 않으면 함께 지워진다. 서버에 올린 PDF 는 다이어리마다 따로 올라간다(다이어리 사이 중복 제거 없음).
- 서버가 올리기를 거절하면(예: 413) 그 쪽은 원본 없이 올라가 친구는 기본 그림을 본다. 같은 PDF 를 쓰는 다른 다이어리에서는 다시 시도한다.
