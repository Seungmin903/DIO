# 로컬 이미지 오류·재시도·표시 참조 수명 (S15P31F106-70)

## 사용자 동작

- 원본이 없으면 `MEDIA_NOT_FOUND`, 시그니처·저장 크기·형식 불일치 또는 표시본 디코딩 실패는 `MEDIA_CORRUPT`로 안내한다.
- 저장 공간 부족은 기존 `STORAGE_FULL` 오류를 사용하며 누락·손상 안내와 구분한다.
- 문서 내 실패한 이미지는 요소를 삭제하지 않고 자리를 표시한다. 상단 안내에서 오류 종류와 ‘다시 조회’를 제공한다. 여러 종류가 동시에 실패하면 각 안내를 함께 표시한다.
- 가져오기 실패는 2초 토스트 대신 유지되는 안내와 ‘다시 선택’·‘닫기’를 제공한다. 다시 선택하면 같은 작업(사진 추가/교체, 스티커/테이프 추가)의 파일 선택기를 연다. 실패한 파일의 임시 접근 권한에 의존해 자동 재저장하지 않는다.
- 조회나 가져오기 실패로 기존 페이지 요소를 제거하지 않는다. 기존 가져오기 배치의 실패 롤백 정책은 유지한다.

## 원본 및 표시 검증

- 웹과 네이티브 저장소에서 원본 존재 여부, 파일 앞부분 시그니처, 메타데이터가 있는 경우 크기·형식을 확인한다. 네이티브 메타데이터 JSON 손상도 구분한다.
- 세션 표시 URL을 만들기 전에 실제 사용할 표시본(없으면 원본)을 디코딩해 손상을 확인한다. 사진·스티커 렌더링 중 추가 오류도 레지스트리에 전달한다.
- 축소본이 있는 고해상도 원본 전체를 매번 다시 디코딩하지는 않는다. 원본 본문 일부의 손상이 크기·헤더를 바꾸지 않고 표시본은 정상인 경우, 이 단계만으로 원본 전체의 무결성을 보장하지 않는다.
- 자동 원본 삭제나 저장소 전체 정리 기능은 추가하지 않는다.

## 표시 URL 수명

- `useMediaUri`는 미디어 ID별 화면 구독을 등록하고 해제한다. 캔버스·썸네일·레이어·보관함이 같은 ID를 쓰면 참조 수를 공유한다.
- 마지막 화면 참조가 끝난 뒤 30초 동안 재사용을 기다리고, 다시 구독하면 해제 예약을 취소한다.
- 사용하지 않은 사전 조회/가져오기 표시 URL도 같은 유휴 정리를 적용한다. 진행 중인 조회는 완료 후 정리 예약을 건다.
- 해제 대상은 웹 Object URL과 세션 캐시뿐이다. 네이티브 원본·표시본 파일이나 IndexedDB의 영구 원본은 삭제하지 않는다.
- 페이지 이동, 되돌리기, 다른 페이지의 공유 참조는 다시 조회해 표시할 수 있다. 손상된 표시 URL의 재시도에서는 실패 URL을 새 URL로 대체한다.

## 리뷰 후속 수정

- 정상 로딩은 중립적인 ‘이미지 불러오는 중…’으로 표시하며, error 상태만 ‘이미지 확인 필요’로 표시한다.
- 유휴 정리는 표시 URL을 해제하되 오류 상태는 유지한다. 화면 밖 페이지의 오류도 재조회 성공 전까지 문서 안내에 남는다.
- 이미지 훅은 ID별 항목 스냅샷을 구독한다. 안내창은 안정적인 오류 목록 스냅샷만 구독하고 참조 ID 수집은 문서 변경 시에만 다시 계산한다.
- 안내창을 상단바 아래의 정상 레이아웃 흐름에 배치하고 기존 colors 토큰을 사용한다. 고정 top 좌표와 별도 노랑/갈색을 제거했다.
- 사전 디코딩은 유지한다. SVG 사진·테이프 경로의 로딩 오류 전파가 보장되는지 확인하기 전에는 표시 단계 오류만으로 대체하지 않는다. GIF/대량 사진의 중복 디코딩 비용은 실기기 측정 후 최적화할 항목이다.
- 69번 리뷰의 ID별 구독 및 사용하지 않는 전체 hydrate 경로 제거를 현재 70번 작업 트리에도 반영했다. 69번 리뷰 수정 커밋 c353a9c를 merge하여 70번에도 선행 이력을 연결했다.
- 70번 리뷰 수정에서 테스트 24개와 Web/Android 번들이 통과했고, 69번 리뷰 수정 병합 후 테스트는 총 25개가 통과했다. 브라우저에서 디코딩을 2초 지연시켜 로딩 문구가 나오고 경고 문구는 나오지 않는지 확인했다. 완료 후 문구/안내가 사라졌다. 오류 안내 하단 138px, 펜 도구 상단 173px로 겹치지 않음을 확인했다. 실기기 결과는 아니다.
