# 만료 로그인 세션·회전 이력 정리

구현됨. 이 문서는 이전 Jira 등록용 초안을 대신하는 현재 동작 설명이며, 실제 Jira 등록 여부는 별개다.

- 저장된 `expires_at <= 현재 시각`인 세션만 삭제한다. 폐기(revoked)되었어도 원래 만료일 전에는 세션과 회전 이력을 보존해 재사용 감지 의미를 유지한다.
- 기본 실행은 기동 5분 후부터 60초 간격이며 한 실행에 최대 500개를 처리한다. 과거 만료분이 많으면 다음 실행에서 이어서 처리한다.
- `expires_at, token_id` 인덱스를 새 V6로 추가한다. 이미 적용된 V1~V5는 수정하지 않는다.
- 재발급과 동일하게 세션 행을 먼저 잠그고 만료 여부를 재확인한다. 회전 이력을 지운 후 세션을 지우며 한 트랜잭션으로 처리한다. 정리 중 DB 오류가 나면 해당 배치를 롤백하고 다음 실행에서 재시도한다.
- 활성 세션·미만료 폐기 세션·회원·다이어리·이메일 인증 데이터는 삭제하지 않는다. 저장된 세션 만료 시각을 사용하므로 TTL 설정을 바꿔도 기존 세션의 보관 종료 시각을 임의 변경하지 않는다.
- 여러 인스턴스가 같은 후보를 골라도 행 잠금과 재검증으로 중복 삭제를 방지한다.

설정: `AUTH_SESSION_CLEANUP_ENABLED`(기본 true), `AUTH_SESSION_CLEANUP_DELAY_MS`(60000), `AUTH_SESSION_CLEANUP_INITIAL_DELAY_MS`(300000). 테스트에서는 스케줄만 끄고 서비스는 직접 검증한다.

검증에는 배치 500개 제한·반복 실행·유효 세션과 이력 보존·격리 PostgreSQL의 실제 FK/삭제 검사를 포함한다. CI의 `backend-postgres-test`는 이 검증을 필수로 실행한다. 실제 공유·운영 DB를 검증용으로 사용하지 않는다.
