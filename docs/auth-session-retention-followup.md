# 만료 로그인 세션·회전 이력 정리 후속 태스크 등록안

상태: Jira 미등록. Jira 연결 도구가 없고 브라우저 도구 초기화도 실패해 실제 중복 검색·등록은 수행하지 못했다. 아래는 등록용 초안이며 실제 이슈 키를 임의로 부여하지 않는다.

- 제목: [BE] 만료 로그인 세션 및 토큰 회전 이력 정리 구현
- 타입: 태스크
- SP: 3
- parent: 기존 인증 태스크 S15P31F106-217의 승인된 에픽 확인 후 지정
- 담당자: 기존 인증 태스크 담당자 확인 후 지정
- 관련 MR: !149

## 배경

Refresh Token 재발급 시 refresh_token_history가 누적된다. 현재 회원 물리 삭제 시 FK CASCADE가 동작하지만, 세션 자체의 정기 만료 정리는 구현하지 않았다. 보관 기간을 합의한 뒤 만료된 refresh_tokens와 연결 이력을 제한된 배치로 정리한다.

## 완료 기준

- [ ] 만료 후 보관 기간과 실행 주기를 합의하고 설정값으로 관리한다.
- [ ] expires_at이 보관 기준을 지난 세션을 한 번에 최대 1,000건씩 정리한다.
- [ ] 연결된 refresh_token_history는 기존 FK CASCADE로 함께 정리되며 다른 회원·다이어리·인증 데이터는 유지된다.
- [ ] 유효한 세션과 아직 보관 기준을 지나지 않은 세션·이력은 삭제되지 않는다.
- [ ] 보관 기간 경계값·배치 건수 제한·반복 실행·기존 로그인 및 재발급 동작에 대한 테스트가 통과한다.
- [ ] 전용 PostgreSQL 테스트 DB에서 삭제 수와 활성 세션 보존을 검증하고 실제 처리 건수·소요 시간을 기록한다.
- [ ] 필요하면 후속 Flyway로 조회 인덱스를 추가하고 이미 적용된 V6는 수정하지 않는다.

등록 전 확인: Jira 유사 이슈 검색, 승인된 parent·담당자 확인. 이 문서는 실제 Jira 등록이나 개발 완료를 뜻하지 않는다.
