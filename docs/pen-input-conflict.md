## 재현 및 수정

1. 펜·형광펜을 누른 채 이동해 획과 직선 보정 타이머를 만든다. 입력을 끝내기 전에 배율을 바꾸면 기존 코드는 이전 시작점과 새로운 배율을 섞어 획을 확정할 수 있었다.
   - 입력 View를 강제로 재생성하지 않고, 배율·페이지 크기·펜 종류·직선 보정 정책 변경 시 진행 중인 획과 타이머만 취소한다. 이미 저장한 획과 Undo/Redo는 변경하지 않는다.
   - 도구 전환으로 컴포넌트를 제거할 때의 기존 타이머 취소도 유지한다. 다음 획은 변경된 좌표계를 사용한다.
2. 두 손가락으로 확대하다 한 손가락을 떼고 다른 손가락을 다시 얹으면 이전 거리·배율이 남아 화면이 튀었다. 훅 시뮬레이션에서는 현재 2배가 0.5배로 바뀌는 상황을 재현했다.
   - 터치가 두 손가락 조건을 벗어나거나 손가락 해제 이벤트가 오면 확대 기준을 비운다. 다음 핀치는 최신 배율·거리에서 시작한다.

- 저장 스키마·펜 질감·프리셋·내보내기 처리에 변경 없음.

## iOS 환경 확인 및 남은 기기 검증

- 작업 호스트는 Windows이며 로컬 Xcode·iOS 시뮬레이터 실행 결과가 없다. iOS 실제 터치·Apple Pencil·손바닥 및 소프트 키보드는 미검증이다.
- 현재 iOS 입력 종류 구분은 기존 코드의 force 기반 추론을 유지한다. 모의 이벤트 테스트 통과만으로 실제 기기의 펜/손가락 식별 정확도를 확정하지 않는다.
- Android Expo Go에서 실제 스타일러스 식별은 보장하지 않는다. 기존 코드의 미식별 터치 대체 규칙과 개발 빌드의 포인터 이벤트 구분을 분리해서 확인한다.
- 기기 확인: 각 펜/형광펜으로 그리기 → 두 손가락 확대·이동 → 한 손가락만 떼고 재접촉 → 다시 필기. 손바닥을 먼저/나중에 대는 흐름과 도구 전환 후 잔여 획 생성 여부도 확인한다.

- 웹 QA는 앱 초기 로딩 전에 격리된 문서를 준비하고 ‘개인 다이어리’ 필터를 명시해 진입한다. 최신 보관함의 초기 필터 진입은 이번 입력 수정 범위에서 변경하지 않는다.

## 요소 증가 시 입력 지연 조사 (2026-10-21, 진행 중)

- Galaxy Tab S8+와 iPad에서 요소가 많아질수록 필기 지연·빈틈이 발생하고, 레이어를 열면 더 심해진다는 사용자 보고가 있다. 한 번의 Undo에서 일부만 삭제되는 현상은 아직 해결 확인 전이다.
- 마지막 move 없이 end/release 좌표만 도착하면 끝점이 누락되는 결함을 테스트로 재현했다. 수정 전 3개 회귀 사례가 실패했고, 수정 후 통과했다. 다른 터치의 해제 좌표와 취소 이벤트는 획에 추가하지 않는다.
- PenInput의 전체 좌표 변환을 입력마다 실행하던 것에서 프레임당 한 번으로 줄였다. 한 프레임 내 100회 move 테스트에서 101개 좌표를 보존하고 전체 획 변환은 1회 실행했다.
- 요소 그림과 레이어 썸네일은 동일 props일 때 재사용한다. 레이어 목록은 FlatList로 변경해 화면 밖 항목을 모두 생성하지 않는다. 행 높이·순서·그룹·선택 처리 규칙은 유지한다.
- 격리된 Chrome/1280×800, 기존 획 500개 + 새 획 10개 비교: 생성된 레이어 행 500→32, 50ms 이상 작업 17→4, 최대 작업 266→113ms. 각 실행에서 총 510개 저장 확인. 단일 웹 비교이며 태블릿 성능이나 실제 스타일러스 연속 입력 해결의 증거로 간주하지 않는다.
- 기존 진단의 Date.now()는 JS 처리 시각이다. 0~1ms 간격만으로 기기의 실제 터치 종료·재접촉을 단정할 수 없다. 기기 이벤트 timestamp를 함께 비교해야 한다.
- 최신 보관함에서 없어진 개인 다이어리 필터는 QA 진입 시 존재할 때만 누르도록 갱신했다.

- 레이어 목록 변경 후 격리된 웹 통합 QA 3/3 통과(필기·서식·지우기·Undo/Redo·저장·재진입). 실제 태블릿에서 보고된 중간 빈틈과 획 분리는 해결 확인 전이다.
