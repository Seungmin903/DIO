# 가입 전 연령·약관 확인과 게시 절차

추가 인증업체 비용 없이 운영하는 범위와 보완 조건은 [가입 연령 확인 무료 설계](signup-age-free-design.md)를 따른다. 자기확인을 실명·실제 연령 인증으로 표시하지 않는다.

## 반영한 범위

가입 전 확인 → 이메일·비밀번호 → 이메일 인증 → 프로필 완성 순서다. 기존 로그인·회원가입 API 경로를 유지한다. 생년월일·출생연도·실명·전화번호를 새로 받지 않고 새 API·테이블·컬럼도 만들지 않는다.

- ‘만 14세 이상입니다 / 만 14세 미만입니다’는 기본 미선택인 단일 선택 항목이다. 전체 동의로 연령을 대신 선택하지 않는다.
- 14세 미만 선택 시 입력·임시 가입 상태를 정리하고 시작 화면 복귀만 가능한 안내를 표시한다. 이메일 발송·소셜 인증 호출을 시작하지 않는다. 기존 소셜 진입 버튼도 공통 확인 화면을 거친다. 실제 OAuth 연동은 별도 개발 사항이다.
- SERVICE 이용약관과 PRIVACY 개인정보 수집·이용 동의는 각각 필수다. 내용 보기는 체크 상태를 바꾸지 않는다.
- 개인정보처리방침은 동의서와 별개의 보기 링크다.
- 가입 완료 요청(JSON 및 multipart의 signup JSON)에 `ageConfirmed: true`를 보낸다. 누락·null·false는 400이며 계정 생성·파일 업로드·인증 토큰 소비 전에 거절한다. 서비스 직접 호출도 검증한다.
- `ageConfirmed`는 실제 나이 인증 결과가 아니라 본인의 진술이다. 요청 검증에만 쓰며 생년월일이나 별도의 연령 기록을 DB에 저장하지 않는다. 서버 요청 본문을 로그에 남기지 않는다.
- 기존 `user_terms_agreements`에 SERVICE/PRIVACY **v2**와 서버가 가입을 처리한 시각을 저장한다. 이전 회원의 v1 기록은 고치거나 삭제하지 않는다. 기존 회원에게 v2 재동의를 일괄 강제하는 기능은 이번 변경이 아니다.
- 기존 MARKETING v1 기록·철회 API 호환은 유지한다. 새 가입 화면은 뭉뚱그린 마케팅 체크박스를 제거하고 MARKETING을 전송하지 않는다. 이메일·푸시·야간 광고 동의의 독립 기록과 철회 경로가 준비되기 전에는 광고 수신 동의로 사용하지 않는다.

## 문서 7종의 화면 구분 — 2026-11-02

가입 전 화면의 ‘생년월일은 받지 않아요’, 미성년 안내의 ‘답변은 서버에 보내거나 저장하지 않아요’ 문구는 제거했다. 연령 선택과 14세 미만 가입 중단 동작은 유지한다.

필수 동의 2종은 ‘필수 항목 전체 동의’와 개별 체크·보기로 묶는다. 개인정보처리방침은 체크박스 없이 별도 보기 행으로 둔다. 추가 4종은 ‘마케팅 관련 문서’를 펼쳐 열람한다. 프로필 완성 단계도 같은 SignupTerms 컴포넌트를 사용한다. 보기 버튼은 동의 상태를 바꾸지 않는다.

마케팅 문서에는 별도 열람 URL 4개를 연결할 수 있지만, 채널별 동의를 실제 저장·철회하는 기능은 아직 없다. 따라서 선택 체크박스나 수신 동의 완료 상태를 만들지 않는다. 이 문서들이 미게시 상태여도 필수 3문서가 게시되어 있으면 가입에는 영향을 주지 않는다. 선택 문서의 주소가 없으면 보기 시 준비 중 안내를 제공한다.

- `EXPO_PUBLIC_MARKETING_PRIVACY_CONSENT_URL`
- `EXPO_PUBLIC_AD_EMAIL_CONSENT_URL`
- `EXPO_PUBLIC_AD_PUSH_CONSENT_URL`
- `EXPO_PUBLIC_AD_NIGHT_PUSH_CONSENT_URL`

URL은 HTTPS와 자격증명 없는 주소만 허용하며 실제 게시 주소는 운영자가 설정한다. 앱 `.env`의 비공개 값은 수정하지 않았다. API·DB·약관 버전·연령 검증을 바꾸지 않는다.

## 생년월일 없이 확인하는 이유와 한계

생년월일도 개인과 연결되는 개인정보다. 이번에는 서비스에 불필요한 정확한 생년월일을 수집하지 않는다. 개인정보 보호법 제16조는 목적에 필요한 최소한의 수집을 요구한다.

**자기확인 체크만으로 실제 연령 확인 또는 출시 시 법적 요건 충족을 보장하지 않는다.** 개인정보보호위원회는 2023년 만 14세 이상 체크·생년월일 입력 절차가 있어도 실제 가입 연령 확인 절차가 부족한 사례에 개선을 권고했다. 출시 전 서비스 대상·아동 이용 가능성에 맞춰 실제 연령 확인 수단을 검토해야 한다. 외부 본인확인 연동은 이번 구현에 포함하지 않았다. 인증기관·저장 범위가 정해지지 않았는데 생년월일부터 더 받는 방식으로 대체하지 않는다.

만 14세 미만 이용이 확인되면 신규 가입을 중단하고 기존 계정·콘텐츠 처리 범위를 운영자가 확인한다. 법정대리인 동의를 받는 별도 아동 가입 경로는 제공하지 않는다. 연령 확인 수단이 바뀌어 추가 개인정보를 처리하게 되면 사전 안내·처리 근거·보유 기간도 함께 바꾼다.

- [개인정보 보호법 제16조](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029335671)
- [개인정보보호위원회 연령 확인 개선 권고 사례](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&mCode=C020010000&nttId=8776)

## 어디에 게시하는가

별도 사이트 없이 기존 배포 서버의 Nginx에서 정적 HTML을 제공할 수 있다. 경로 예시는 `/legal/v2/service.html`, `/legal/v2/privacy-consent.html`, `/legal/v2/privacy-policy.html`이며 **제안 경로로, 현재 게시된 주소가 아니다.**

1. [legal/v2](legal/v2/)의 Markdown 원문을 검토한다. 위탁업체·국외 이전·보관 기간 등 미확정 내용을 실제 인프라 정보로 확정한다. 현재 HTML은 검토용이다.
2. `python docs/legal/build_html.py`로 HTML을 다시 만든다. 인프라 담당자가 검토 표시·미확정 항목이 모두 정리된 공개본을 기존 Nginx 정적 디렉터리에 배치한다.
3. 문서 URL은 유효한 HTTPS이며 **Basic 인증·앱 로그인 없이** 열려야 한다. 모바일 네트워크의 브라우저에서도 확인한다. API용 Basic 보호 경로 안에 두지 않는다.
4. 아래 프론트 환경변수에 실제 절대 URL을 넣고 Expo를 재시작한다. 배포 앱은 다시 빌드/배포한다. EXPO_PUBLIC 값은 앱에 포함되므로 비밀정보를 넣지 않는다.
5. 서버 환경변수 SERVICE/PRIVACY 버전을 v2로 맞추고 함께 배포한다. 이미 설정된 `v1` 환경변수는 기본값 v2보다 우선하므로 반드시 바꾼다.
6. 가입 요청의 `ageConfirmed`가 새 필수 필드이므로 구형 앱은 업데이트가 필요하다. 기존 회원 로그인에는 이 필드를 요구하지 않는다.

```ini
# frontend/.env — 게시 후 실제 URL을 채운다. 예시 주소를 복사하지 않는다.
EXPO_PUBLIC_SERVICE_TERMS_URL=
EXPO_PUBLIC_PRIVACY_CONSENT_URL=
EXPO_PUBLIC_PRIVACY_POLICY_URL=

# backend / dev·prod Compose용 환경변수
SIGNUP_SERVICE_TERMS_VERSION=v2
SIGNUP_PRIVACY_TERMS_VERSION=v2
SIGNUP_MARKETING_TERMS_VERSION=v1
```

공개 URL 3개 중 하나라도 없거나 HTTPS가 아니면 가입은 이메일 입력 전에 ‘약관 준비 중’으로 막힌다. 이미 가입한 회원의 로그인은 가능하다. 임의 URL로 이 제한을 우회하지 않는다. 앱은 URL 접속 성공이나 원문과 버전의 일치까지 자동 검증하지 않으므로 게시 후 아래 QA가 필요하다.

기존 ‘앱 정보 → 개인정보 처리방침’ 행도 같은 `EXPO_PUBLIC_PRIVACY_POLICY_URL`을 사용한다. 미설정 시 기존 회원의 열람 경로를 끊지 않도록 기존 Google 문서 연결은 유지하지만, 이를 v2 가입 동의 문서로 대신 쓰지는 않는다. 해당 행의 UI는 바꾸지 않는다.

Nginx 설정 형태는 다음과 같다. 경로는 예시이며 실제 정적 파일 마운트 위치에 맞춘다. 이 설정은 API·Swagger의 인증 정책을 변경하지 않는다.

```nginx
location ^~ /legal/ {
    auth_basic off;
    alias /usr/share/nginx/html/legal/;
    autoindex off;
    add_header X-Content-Type-Options nosniff always;
}
```

정적 디렉터리에 `v2/service.html`, `v2/privacy-consent.html`, `v2/privacy-policy.html`을 배치한다. 컨테이너라면 해당 디렉터리를 읽기 전용으로 마운트한다. 공개본에는 검토 메모·미확정 표기를 남기지 않는다. 이미 동의를 받은 v2 본문을 덮어쓰지 말고 변경 시 새 버전 디렉터리를 만든다.

## 인프라 담당자에게 전달할 내용

> 첨부한 v2 약관 HTML을 기존 서버의 공개 HTTPS 정적 경로에 올려 주세요. 개인정보처리방침의 실제 수탁자·국외 이전·보유 기간 확인이 먼저 필요합니다. 이용약관, 개인정보 수집·이용 동의서, 개인정보처리방침은 별개 파일이며 인증 없이 열려야 합니다. 게시한 절대 URL 3개를 알려 주세요. 서버의 SIGNUP_SERVICE_TERMS_VERSION과 SIGNUP_PRIVACY_TERMS_VERSION도 v2로 설정해 주세요. 기존 v1 동의 기록은 보존합니다.

## QA

- 문서 미설정 상태에서 로그인은 유지되고 가입 시 이메일 입력칸으로 진행하지 않는다.
- 전체 동의만 누르면 연령 확인은 미선택이다. 연령·필수 동의를 모두 확인해야 다음으로 진행한다.
- 보기 버튼은 각각 올바른 v2 원문을 연다. 개인정보처리방침 링크는 별도다. 열기 실패를 동의 완료로 취급하지 않는다.
- 가입을 취소하고 로그인 화면으로 돌아왔다가 재진입하면 연령·동의가 초기화된다.
- 기존 이메일 인증 후 signupToken으로 v2 약관과 ageConfirmed=true를 보내 가입한다. 동의 버전·시각을 기존 테이블에서 확인한다.
- ageConfirmed 누락·false·null의 JSON/multipart는 400이며 같은 유효 토큰으로 정상 가입을 다시 시도할 수 있다.
- v1을 보낸 신규 가입은 INVALID_TERMS다. 기존 회원의 로그인과 과거 v1 기록은 유지된다.


## 2026-11-02 선택 마케팅 동의 항목 분리 (이 절이 이전 열람 전용 설명보다 우선)

기존 `POST /api/v1/auth/signup`의 agreements와 `PUT /api/v1/me/terms/{termsType}/{termsVersion}`을 그대로 사용한다. 새 API·테이블·컬럼·마이그레이션은 없다. 기존 VARCHAR(20) 약관 종류에 다음 항목을 저장한다.

| 종류 | 의미 | 버전 |
|---|---|---|
| MARKETING_PRIVACY | 마케팅 목적 개인정보 수집·이용 | v1 |
| AD_EMAIL | 광고성 이메일 수신 | v1 |
| AD_PUSH | 광고성 앱 푸시 수신 | v1 |
| AD_NIGHT_PUSH | 야간 광고성 앱 푸시 수신 | v1 |

네 항목은 각각 선택·철회할 수 있고 미동의나 생략으로 가입을 막지 않는다. UI는 기본 미선택이며 필수 전체 동의는 선택 항목을 변경하지 않는다. 개인정보처리방침은 열람만 제공한다. 각 행의 보기는 기존 HTTPS 문서 URL 설정을 사용한다.

기존 MARKETING 저장 행과 클라이언트 요청은 호환용으로 유지하며 신규 채널 동의로 복사하거나 간주하지 않는다. 새 항목 버전은 기존 SIGNUP_MARKETING_TERMS_VERSION(기본 v1) 설정을 공유하므로 프론트 v1과 일치시켜야 한다. 각 행은 버전·변경 시각을 기존 방식으로 기록한다.

이 변경은 동의 기록만 연결하며 광고 발송 기능을 추가하지 않는다. 추후 발송 시 개인정보 마케팅 동의와 해당 채널 동의의 교집합을 확인하고, 야간 푸시는 AD_NIGHT_PUSH도 확인해야 한다. 기존 일반 초대 알림 발송 정책은 변경하지 않는다.


### 문서 미게시 상태의 내부 테스트 (2026-11-02)
문서 URL 게시 여부로 가입 진행을 차단하지 않는다. 만 14세 이상 자기확인과 필수 약관 2개 동의 조건은 유지하며 가입 완료 단계도 URL 준비 여부와 분리한다. 미설정 문서의 보기는 기존 준비 중 안내를 제공한다. 실제 이용자 대상 공개 전에는 각 문서를 게시하고 URL을 설정한다. 미성년 제한 화면의 ‘만 14세가 된 후에 다시 가입해 주세요’ 보조 문구는 제거한다.
