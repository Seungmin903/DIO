# 회원 탈퇴

기존 명세 `DELETE /api/v1/me`, Bearer 인증 필수. 요청 본문 없음. 성공 204, 소유권 양도 필요 409 `OWNER_TRANSFER_REQUIRED`, 인증 실패 401.

## 처리

- 다른 멤버가 남아 있는 소유 다이어리는 양도 전까지 탈퇴를 거절한다. 일부 개인 다이어리만 먼저 지워지지 않도록 전체 롤백한다. 휴지통의 소유 다이어리도 검사한다.
- 혼자 소유한 개인·공유 다이어리는 기존 공유 영구 삭제 구현을 사용한다.
- 다른 소유자의 공유 다이어리는 나가기 처리하며 작성 요소·이력·공유된 원본 미디어를 삭제하지 않는다.
- 회원 행/ID는 작성자 참조를 위해 남긴다. 이메일은 null, 닉네임은 ‘탈퇴한 사용자’, 상태는 WITHDRAWN, deletedAt을 기록한다. 가입 계정·비밀번호 해시·토큰과 회전 이력·이메일 인증·약관·개인 알림은 정리한다. 기존 이메일로 재가입하면 새 사용자 ID를 받는다.
- 계정 사진은 즉시 조회 불가다. 기존 사진 메타데이터를 재시도 기록으로 사용하여 5분 주기(한 번에 최대 100건) 정리 작업이 로컬/S3 삭제 후 DB 행을 지운다. 저장소 실패 시 메타데이터를 남겨 다시 처리하며, 외부 I/O는 트랜잭션 밖에서 한다.
- 참조 없는 개인 미디어는 soft delete하여 기존 미디어 보존·삭제 큐 정책으로 정리한다. 공유/캔버스/폰트/다른 멤버 프로필이 참조하는 원본은 보존한다. 이 기능은 미디어 담당자의 기존 보관 정책을 변경하지 않는다.

## 구조

user/controller → user/service가 계정 탈퇴를 담당한다. 인증·공유 구현은 user의 처리 포트를 구현한 auth/service·sharing/service 어댑터로 연결한다. user에서 auth 구현을 import하지 않는다. DTO는 요청·응답 본문이 없어 추가하지 않는다. 새 API 경로·테이블·컬럼·마이그레이션은 없다.

## 기존 화면

내 공간의 회원 탈퇴 → 기존 ‘탈퇴합니다’ 입력 창을 재사용한다. 실제 서버 계정에 내 정보 수정 폼을 연결하지 않는다. 양도 오류는 창에 표시하고 세션과 확인 입력을 유지한다. 성공하면 메모리 인증 상태를 정리하고 로그인으로 돌아간다. 체험 계정 동작은 유지한다.

## 검증

인증 없이 거절, 익명화·재가입, 세션 폐기, 소유권 충돌 롤백, 양도 후 탈퇴, 개인 다이어리 삭제, 공유 캔버스 보존, 사진 조회 차단·정리, 기존 프론트 확인 창을 자동 테스트한다. 실기기와 실제 배포 S3는 별도 확인 대상이다.
