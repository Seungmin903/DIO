# V25 플래너 배포 순서

V25가 적용되기 전에는 DB에 `study-planner-*`·`day-planner-*` 행이 없다. 따라서
렌더러를 포함한 프런트를 먼저 내보내더라도 플래너 선택을 켜면 안 된다. 앱 빌드에
`EXPO_PUBLIC_PLANNER_TEMPLATES_ENABLED=0`을 넣으면 플래너를 열고 기존 페이지를 읽는
기능은 유지하면서, 새 다이어리/페이지에서의 선택과 서버 생성 요청만 차단한다.

- 값은 `frontend/eas.json`의 `preview`·`production` 프로필 `env`에 `"0"`으로 고정되어 있다. 셸 환경 변수를 빠뜨려도 릴리스 빌드는 꺼진 상태로 나간다. 값을 비운 로컬·development 빌드는 켜진다.
- 플래그가 꺼져 있는 동안에는 데일리·스터디 플래너 대신 예전 `하루 계획`(reusable-daily)을 메뉴에 그대로 보여 준다. 이 기간에 만든 하루 계획 페이지도 V25가 데일리 플래너로 옮긴다.

1. `studyPlanner.js`, `dayPlanner.js`와 플래너 선택 플래그를 포함한 프런트를 먼저 배포한다. 이 단계의 빌드는 반드시 `EXPO_PUBLIC_PLANNER_TEMPLATES_ENABLED=0`으로 만들고(eas.json 기본값), 새 다이어리·페이지 메뉴에 플래너가 없고 `하루 계획`이 있는지, 기존 reusable-daily 및 플래너 페이지가 열리는지 실제 기기에서 확인한다.
2. 편집 중이던 클라이언트에는 V25의 페이지 버전 증가로 충돌 표시가 나타날 수 있다. 현재 캔버스 협업 경로는 409에서 기기 편집을 보존하고 `캔버스 충돌 · 기기 보존` 상태를 표시한다. 사용자는 화면을 다시 열어 최신 속지를 받은 뒤 저장을 재시도해야 한다. 배포 공지와 점검 시간에 이 안내를 포함한다.
3. 그 뒤에만 백엔드 V25를 배포한다. 배포 전 `docs/page-template-v25-rollback.sql`의 preflight가 0행인지 확인한다.
4. V25 적용 및 기존 페이지 검증이 끝난 뒤, `eas.json`의 값을 `"1"`로 바꾸는 커밋을 병합하고 그 빌드를 배포해 플래너 선택을 연다. 앱 배포 사이에는 이 값을 바꾸지 않는다.
5. 회원·공유 구성원 계정에서 기존 reusable-daily 페이지와 새 플래너 페이지를 각각 열어 배경과 요소를 확인한다.
