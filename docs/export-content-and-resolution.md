# 72 필기·텍스트 출력 및 122 고해상도 정책

기준: develop 131a3a2(!39 포함). 작업 브랜치 feature/fe/export-content. 구현과 웹 QA 결과를 같은 MR로 검토한다.

## 72 연결

- 팀원의 ObjectContent/Text(textSegments·textStyle)/StrokeContent를 출력 surface에서도 그대로 사용한다. 새로운 필기·부분 색상 데이터 형식이나 별도 렌더러를 만들지 않는다.
- 현재 텍스트는 OS 기본 sans/serif/mono만 지원한다. 웹 캡처 직전에 실제 텍스트·굵기·기울임·크기를 FontFaceSet.load에 전달하고 fonts.ready까지 기다린다. 실패는 EXPORT_FONT_FAILED이며 기존 작업기의 시간 초과·재시도·정리 경로를 따른다.
- 네이티브는 다운로드 없는 OS 기본 폰트다. 사용자 폰트/폰트 파일 생성·다운로드는 이번 지원 범위가 아니다. 사용자 폰트가 추가되면 등록 완료와 웹 임베딩 계약을 별도로 연결해야 한다.
- 미확정 텍스트는 공유 진입 시 완료를 안내하며 내보내기를 시작하지 않는다. 자르기 편집 중 제한은 유지한다.
- 위치·크기·회전·크롭·레이어 순서는 기존 공통 surface와 영역 좌표계를 유지한다.

## 122 결정 및 구현

표시본으로 충분하면 기존대로 표시본을 사용한다. 부족하면 안전한 원본을 선택하되, 원본이 800만 화소를 초과하면 안전한 표시본으로 대체하고 화질 경고를 전달한다. 원본은 수정하지 않는다.

- 이미지 준비 자원의 qualityWarning을 snapshot.rasterWarnings → 출력 diagnostics → PNG 미리보기/PDF 생성·저장 전 경고로 전달한다.
- 안전한 표시본이 없으면 계속 실패한다. 원본 누락·손상·GIF 디코딩 오류를 성공으로 숨기지 않는다.
- 대형 원본 디코딩·추가 파생본 저장·영역 밖 요소 제거는 후속이다. 이번에는 디코딩 상한을 늘리지 않는다.
- PDF/영역 계약을 갱신했다. 113·119는 실제 12MP 사진으로 출력 성공 여부·생성 시간·파일 용량·메모리(측정 불가는 명시)를 확인해야 한다.

## 검증

- Node 전체 테스트 154개 통과. 실제 문자열과 스타일의 폰트 준비 대기/실패, 12MP 표시본 대체·경고·안전한 표시본 부재 시 차단을 추가 검증했다.
- 웹 QA는 frontend에서 pnpm qa:pdf / pnpm qa:region으로 재현한다. 결과와 스크린샷은 qa/.out에 생성되며 커밋하지 않는다.
- PDF fixture는 명조·굵게·밑줄·한글과 파랑/초록 부분 색상, 보라 펜, 반투명 형광펜을 포함한다. PDF 내 RGB 픽셀로 부분 색상·획 색상·형광펜 알파 합성을 확인한다.
- 12MP(4000×3000) 합성 JPEG와 2048 표시본을 IndexedDB에 저장하고 확대 크롭/PDF 2배 성공 및 미리보기 경고를 확인한다. 실제 카메라 사진의 성능을 대표하지 않는다.
- 기기 및 입력 종류별 네이티브 검증, 실제 사진·메모리 검증은 미완료다. 72·75·113·119·122를 최종 완료로 표시하지 않는다.

### 이번 실행 수치 (웹 Chromium 156 / Windows 10.0.26200)

- PDF QA 8/8 통과, 영역 PNG QA 11/11 통과. 웹 viewport는 실제 모바일 기기가 아니다.
- 합성 12MP JPEG: 2배 PDF 생성 1,223ms, 17,524 bytes, 부분 텍스트 파란 픽셀 1,592개·초록 1,096개. 형광펜 합성 RGB [133,153,154] 확인. 단일 실행값이며 평균/최댓값이나 실제 사진 성능이 아니다.
- 일반 현재 페이지 PDF 생성 1,052ms, 17,506 bytes. 입력 원본 문서 보존, 취소/실패/재시도, GIF 첫 프레임, 면 순서, 20장 성공과 21장 제한도 확인했다.
- 영역 회귀 baseline 307ms, 줌 변경 327ms. 기존 픽셀·해시 비교와 회전/크롭/겹침 테스트를 유지했다.
- 실제 사진 12MP/48MP·HEIC의 생성 시간, 성공률, 파일 크기 및 기기 메모리(측정 불가는 명시)를 75·113·119에서 추가한다.

- 웹 번들 및 Android JS/Hermes 번들 생성 통과. Android 번들 최초 샌드박스 임시 파일 권한 오류는 일반 실행 환경에서 재시도해 통과했다. 네이티브 기기 실행 성공을 뜻하지 않는다.
