# 리서치 — 성능 최적화 권장안 (기준일 2026-11-04)

> 공식 문서 fetch와 검색 요약 기준. 수치 대부분은 우리 기기에서 직접 측정하기 전까지 가설로 볼 것.

### 1. AsyncStorage 한계와 대안 저장소
- 출처: [AsyncStorage Limits](https://react-native-async-storage.github.io/2.0/advanced/Limits) · [Increase DB size](https://react-native-async-storage.github.io/async-storage/docs/advanced/db_size) · [MMKV README](https://github.com/mrousavy/react-native-mmkv) · [expo-sqlite SDK58](https://docs.expo.dev/versions/v58.0.0/sdk/sqlite/)
- 핵심: Android 전체 저장 기본 **6MB**(`AsyncStorage_db_size_in_MB`). 항목 하나 읽기는 CursorWindow **약 2MB** — 공식 문서는 우회 불가, "여러 항목으로 쪼개 `multiGet`/`multiSet`" 권고. 초과 시 `Couldn't read row 0, col 0 from CursorWindow`. MMKV v4는 Nitro 모듈(RN 0.76+, `react-native-nitro-modules`), 동기 API, AES 암호화, `ArrayBuffer` 저장, "AsyncStorage보다 약 30배"는 iPhone 11 Pro 1000회 읽기 벤치마크. expo-sqlite는 BLOB·WAL, `expo-sqlite/kv-store`는 AsyncStorage 동일 API.
- 우리 앱 적용: 단기 — 페이지 단위 키 `doc:{id}:meta`, `doc:{id}:page:{n}`. 중기 — expo-sqlite `pages(doc_id, page_no, updated_at, strokes BLOB)` 페이지 upsert. 첫 실행 마이그레이션(기존 JSON 분할 후 삭제).
- 주의: 먼저 `JSON.stringify(doc).length`를 로그로 재서 2MB 초과 여부 확인. MMKV는 prebuild·재빌드 필요. 어느 저장소든 페이지 분할은 필요.

### 2. 획 데이터 압축
- 출처: [perfect-freehand](https://github.com/steveruizok/perfect-freehand). Skia `Path.toSVGString`/`toCmds` 비용 문서 404.
- 핵심: perfect-freehand는 `[x, y, pressure]` 배열 입력, 객체 점은 내부 변환으로 성능 영향. 델타·Int16·base64 공식 권고는 없음(엔지니어링 판단).
- 우리 앱 적용: 획당 `{tool, color, w, pts: base64(Int16Array)}`, ×10~100 양자화 + 첫 점 이후 델타, 읽을 때 Float32Array로. 객체 JSON 대비 5~10배 감소 추정(실측 없음). 간격 가까운 점 제거·Douglas-Peucker 병행.
- 주의: 0.1px 양자화 오차 허용 여부, `version` 필드와 구형 읽기 유지, Hermes `atob/btoa` 큰 문자열 속도 측정.

### 3. 입력 지연 (gesture-handler + Reanimated 4 + Skia)
- 출처: [Expo SDK58 Reanimated](https://docs.expo.dev/versions/v58.0.0/sdk/reanimated/) · [Reanimated 문서](https://docs.swmansion.com/react-native-reanimated/docs/next) · [Skia + 제스처](https://shopify.github.io/react-native-skia/docs/animations/gestures) · [Hand drawing 튜토리얼](https://medium.com/react-native-rocket/building-a-hand-drawing-app-with-react-native-skia-and-gesture-handler-9797f5f7b9b4)
- 핵심: SDK 58 권장 `react-native-reanimated` **4.7.1**(`react-native-worklets` 버전 확인 못 함), Babel 설정 불필요(`babel-preset-expo`), New Architecture 전용. Shopify 문서는 Skia 입력에 gesture-handler + shared value를 권장, 튜토리얼은 `notifyChanges()`로 실시간 경로 갱신. React Compiler 호환 확인 못 함.
- 우리 앱 적용: `Gesture.Pan()` + worklet(`runOnUI`), 현재 획만 shared value `SkPath`에 쌓아 UI 스레드에서 그리고 획 종료 시 JS로 한 번 넘겨 저장. 멀티터치·펜/손 분리·핀치를 `Simultaneous`/`Exclusive`로 옮기는 것이 가장 큰 공수.
- 주의: 공수 L·위험 높음. 먼저 `react-native-performance`/Perfetto로 JS 스레드 프레임 시간을 재서 병목이 PanResponder인지 확인.

### 4. Skia 메모리
- 출처: [skia-discuss 텍스처 캐시](https://groups.google.com/g/skia-discuss/c/LI9KQUxCmz4) · [RN Skia discussion #2494](https://github.com/Shopify/react-native-skia/discussions/2494) · [issue #1811](https://github.com/Shopify/react-native-skia/issues/1811)
- 핵심: 텍스처 캐시 한도 약 **200MB**(초과 시 쫓겨나고 프레임마다 재업로드). 오프스크린 surface는 물리 픽셀(`width * pixelDensity`)로. iOS `makeImageSnapshot` 요소 누락 보고 → 오프스크린 후 스냅샷 우회. `MakeOffscreen` 상한·GPU 텍스처 상한·Canvas 다중 비용은 확인 못 함.
- 우리 앱 적용: 페이지 전체 큰 비트맵 지양, 완성 획 `Picture` 재사용, 현재 획 별도 레이어. 정지 Canvas는 스냅샷으로 대체 검토. 실기기(Android Studio Profiler Graphics/Native) 측정으로 결정.

### 5. 목록
- 출처: [FlashList v2 migration](https://shopify.github.io/flash-list/docs/v2-migration) · [v2 changes](https://shopify.github.io/flash-list/docs/v2-changes) · [expo-image recyclingKey](https://docs.expo.dev/versions/v58.0.0/sdk/image/)
- 핵심: v2는 New Architecture 전용, `estimatedItemSize` 폐지, `masonry` + `numColumns`, 항목 `key`가 바뀌면 재활용 깨짐. 성능 수치·RN 최소 버전 확인 못 함.
- 우리 앱 적용: 표지가 정지 상태면 PNG/WebP로 한 번 래스터해 `expo-file-system`에 저장 → `expo-image`. 표지 수정 시만 재래스터(캐시 무효화 로직 필요). Skia 오프스크린 vs view-shot 비교 근거 없음.

### 6. 글꼴
- 출처: [Expo Fonts](https://docs.expo.dev/develop/user-interface/fonts/) · [expo-font SDK58](https://docs.expo.dev/versions/v58.0.0/sdk/font/) · [Pretendard](https://github.com/orioncactus/pretendard) · [fonttools](https://github.com/web-alchemy/fonttools)
- 핵심: `expo-font` config plugin은 빌드 때 네이티브 내장 — 문서가 `useFonts`/`loadAsync`보다 효율적이라고 명시. ttf/otf(woff2는 iOS만), 글꼴 변경 시 재빌드, Expo Go 불가. Pretendard 공식 Variable·동적 서브셋(웹용). `pyftsubset --unicodes`. KS X 1001 서브셋 용량·Variable 용량·RN 로드 시간 실측 확인 못 함.
- 우리 앱 적용: ① 시작 로드를 필수(Pretendard 일부)와 선택(한글 TTF 11종, 사용자가 고를 때)으로 분리 ② 필수 글꼴 plugin 내장 ③ Pretendard 5종 → Variable 1개(RN weight 축 지원 플랫폼별 확인 필요) ④ 한글 TTF `pyftsubset` — 라이선스가 서브셋 배포 허용하는지 확인, 사용자 입력 글자가 빠지지 않게 완성형 11,172자(`U+AC00-D7A3`) 유지.
- 주의: plugin 내장은 OTA 불가, 가변 폰트 굵기 렌더 플랫폼 차이, 라이선스 JSON 갱신.

### 7. 시작 시간
- 출처: [RN Optimizing JavaScript loading](https://reactnative.dev/docs/optimizing-javascript-loading) · [Expo SplashScreen SDK58](https://docs.expo.dev/versions/v58.0.0/sdk/splash-screen/) · [Sentry 자동 계측](https://docs.sentry.io/platforms/react-native/tracing/instrumentation/automatic-instrumentation/)
- 핵심: 릴리스 Hermes 바이트코드는 파싱 없이 필요한 만큼 로드. RN 문서: "Expo는 `inlineRequires` 기본 아님, Metro `getTransformOptions`에 켜라" — Expo 58 기본값 확인 못 함(우리 `metro.config`와 번들로 확인). Splash는 "가능한 한 빨리 숨겨라"만. 측정: `react-native-performance`, `adb shell am start -W`, Perfetto.
- 우리 앱 적용: 라이선스 JSON 4.5MB를 지연 `import()`/에셋으로, 글꼴·큰 모듈을 splash 대기 경로에서 제거. 먼저 `am start -W` 콜드 스타트 기준선.
- 주의: 인라인 require 전체 적용은 부수효과 모듈 순서를 바꿔 깨질 수 있음 → 특정 모듈만 지연 require.

### 8. 이미지
- 출처: [expo-image SDK58](https://docs.expo.dev/versions/v58.0.0/sdk/image/)
- 핵심: `allowDownscaling` 기본 true(`contentFit` none/fill에서는 미적용), `cachePolicy` 기본 `disk`, Android `decodeFormat: 'rgb'`로 알파 제거, HEIC Android·iOS 지원.
- 우리 앱 적용: 목록·썸네일은 expo-image, 큰 사진은 파생본(표시 크기 2~3배 경험칙), 불투명 사진은 `decodeFormat="rgb"`.
- 주의: 캔버스에서 확대해 쓰는 사진은 다운샘플로 화질 저하 가능.

### 9. 네트워크
- 출처: [netinfo SDK58](https://docs.expo.dev/versions/v58.0.0/sdk/netinfo/)
- 핵심: `@react-native-community/netinfo` SDK 58 권장 **12.0.1**(`npx expo install`). `isInternetReachable` null 가능. WebSocket+적응형 폴링·ETag·AbortController 근거 확인 못 함.
- 우리 앱 적용: 서버에 revision만 돌려주는 가벼운 엔드포인트(백엔드 요청 → MM 마크다운), 5초 폴링은 값이 바뀔 때만 본문. 백그라운드·비편집 시 30초, 오프라인이면 중단. 재시도 지터.

### 10. 모니터링
- 출처: [Sentry Expo](https://docs.sentry.io/platforms/react-native/guides/expo/integrations/) · [Expo Atlas](https://docs.expo.dev/guides/analyzing-bundles/)
- 핵심: Sentry는 네이티브 시작~루트 마운트를 앱 시작으로 측정, 스플래시 긴 앱은 `Sentry.finishExtendedAppStart()`(미호출 시 30초 자동 종료), 느린/멈춘 프레임 측정. Atlas: `EXPO_ATLAS=true npx expo export` → `npx expo-atlas .expo/atlas.jsonl`(소스·`EXPO_PUBLIC_` 값 포함 주의).
- 우리 앱 적용: 4.5MB JSON·큰 모듈 번들 포함 여부를 Atlas로 즉시 확인. Sentry는 재빌드 필요, 다이어리 내용 수집 범위 먼저 결정.

### 11. 애니메이션 — 근거 문서 확인 못 함. 일반 원칙: `width`/`height` 애니메이션은 매 프레임 레이아웃, `transform`/opacity로 대체. 좌측 바(60↔236)는 폭 고정 + transform/클리핑 비교.

### 12. 자동 저장
- 출처: [RN requestIdleCallback](https://reactnative.dev/docs/global-requestIdleCallback) · [expo-file-system SDK58](https://docs.expo.dev/versions/v58.0.0/sdk/filesystem/)
- 핵심: `requestIdleCallback` 전역 존재(플랫폼별 주의점 없음 → 존재 확인 후 `setTimeout` 폴백). SDK 58 `File`/`Directory` API: `file.write()`, `writeSync`, `move`, `rename`, `bytes()`. 원자성·`rename` 원자적 여부 문서 없음. 옛 API는 `expo-file-system/legacy`.
- 우리 앱 적용: 디바운스 1~2초 + `AppState` 백그라운드 즉시 flush, 변경 페이지만 저장, 임시 파일 → `move` 교체(원자성은 기기에서 확인).

## 도입 우선순위 표
| 순위 | 조치 | 기대 효과 | 공수 | 위험 |
|---|---|---|---|---|
| 1 | 저장 크기 측정 + 문서를 페이지 단위 키로 분할 | Android 2MB 읽기 실패 예방, 저장 끊김 감소 | M | 낮음(구형 문서 마이그레이션) |
| 2 | 라이선스 JSON 4.5MB 지연 로드 | 시작 시간 | S | 낮음 |
| 3 | 글꼴 필수/선택 분리, 한글 TTF 11종 지연 로드 | 시작 시간·메모리 큰 폭 감소 | M | 중간(로딩 상태) |
| 4 | 획 포맷 압축(Int16 + 델타 + base64) | 문서 크기·직렬화 시간 | M | 중간(버전 필드) |
| 5 | 협업 폴링 → revision 확인 + 적응형 간격 | 네트워크·배터리 | M | 중간(백엔드) |
| 6 | 표지 래스터 캐시 + expo-image | 보관함 스크롤 | M | 낮음~중간 |
| 7 | 큰 사진 썸네일 파생본 + expo-image | 이미지 메모리 | M | 낮음 |
| 8 | Expo Atlas + `am start -W` 기준선 측정 | 효과를 숫자로 | S | 없음 |
| 9 | expo-sqlite(페이지 BLOB) 이전 | 큰 문서 안정성 | L | 중간 |
| 10 | 필수 글꼴 plugin 내장 | JS 글꼴 로드 제거 | S~M | 중간(재빌드, OTA 불가) |
