# 리서치 — Android 정책·규격 (기준일 2026-11-04)

> "확인함"은 1차 문서를 직접 읽은 것, "확인 못 함"은 검색 결과·2차 자료만 본 것. QA 보고서에 인용하기 전에 URL을 열어 확인할 것.

**먼저 알아둘 것**
- 가로 잠금이 무시되는 것은 버그가 아니라 **Android 16 정식 동작**이다. targetSdk 36 앱이 최단변 600dp 이상 화면(탭 S9 FE)에서 실행되면 방향·크기 조절·종횡비 제한을 무시한다.
- 임시 opt-out은 targetSdk 37부터 사라진다. Play가 37을 요구하는 시점은 2027-08(Google 블로그 기준).
- 16KB 마감은 Google Play 기준 **2027-02-01**(developer.android.com 현행 문구). 블로그에 흔한 "2025-11-01"은 옛 정보.

### 1. Android 16 대형 화면에서 방향·크기·종횡비 제한 무시
- 출처: [Behavior changes: Apps targeting Android 16](https://developer.android.com/about/versions/16/behavior-changes-16) · [Android 17 동일 항목](https://developer.android.com/about/versions/17/changes/ff-restrictions-ignored) · [Android Developers Blog 2025-01-23](https://android-developers.googleblog.com/2025/01/orientation-and-resizability-changes-in-android-16.html)
- 핵심: "For apps targeting Android 16 (API level 36), orientation, resizability, and aspect ratio restrictions no longer apply on displays with smallest width >= 600dp." 무시 대상: `screenOrientation`, `resizeableActivity`, `min/maxAspectRatio`, `setRequestedOrientation()`. 예외: 게임(`appCategory`), 사용자가 기기 설정에서 앱별 종횡비를 직접 고른 경우, sw600dp 미만. targetSdk 35 이하는 호환 모드 유지.
- opt-out: `<application>`/`<activity>`에 `<property android:name="android.window.PROPERTY_COMPAT_ALLOW_RESTRICTED_RESIZABILITY" android:value="true" />`. "The opt-out is temporary and won't apply when targeting API level 37." Android 17 문서: "removes the temporary developer opt-out". 블로그: "targeting API 36 required in August 2026, API 37 in August 2027".
- 우리 앱 영향: `expo-screen-orientation` LANDSCAPE 잠금은 탭 S9 FE에서 이미 무효(실측 `ignoreOrientationRequest=true`와 일치). 회전 시 액티비티 재생성·편집 상태 보존 점검 필요. 폰(sw<600)에서는 잠금이 계속 먹는다.
- 권장: ① 잠금에 의존하지 않고 창 크기 클래스로 분기, 회전 시 캔버스·선택·획 상태 유지 확인. ② 단기 가로 전용이 꼭 필요하면 커스텀 config plugin으로 위 `<property>` 삽입(Expo 설정 키 확인 못 함, targetSdk 37에서 반드시 사라짐). ③ `appCategory="game"` 우회는 비권장.

### 2. Google Play 16KB 페이지 크기 요건
- 출처: [Support 16 KB page sizes](https://developer.android.com/guide/practices/page-sizes) · [react-native-skia 이슈 #3362](https://github.com/Shopify/react-native-skia/issues/3362)(2025-09-11 종료) · [RN 토론 #921](https://github.com/react-native-community/discussions-and-proposals/discussions/921)(2025-08-11)
- 핵심: "all apps targeting Android 15 (API level 35) and higher must support 16 KB memory page sizes on 64-bit devices on Google Play. Starting February 1, 2027, if your app updates don't support 16 KB memory page sizes, you won't be able to release these updates."
- 검사: APK Analyzer Alignment 열 / `llvm-objdump -p x.so | Select-String LOAD`에서 `align 2**14` 이상 / `zipalign -c -P 16 -v 4 app.apk`(build-tools 35+) / AAB `bundletool dump config … | grep alignment` → `PAGE_ALIGNMENT_16K` / 16KB 에뮬레이터 `adb shell getconf PAGE_SIZE` = 16384.
- 빌드 도구: AGP 8.5.1+ · NDK r28+면 기본 정렬. NDK r27 이하 CMake는 `target_link_options(... "-Wl,-z,max-page-size=16384" "-Wl,-z,common-page-size=16384")`, `PAGE_SIZE`/4096 하드코딩 → `sysconf(_SC_PAGESIZE)`.
- Skia: 이슈 #3362는 v2.0.6 이후 해결로 닫힘(2.2.12/2.2.13 성공 댓글). 공식 릴리스 노트 명시 확인 못 함. RN 코어 0.79+ 16KB 지원(토론 #921). Expo SDK 58 기본 적용 여부 확인 못 함.
- 우리 앱 영향: 자체 CMake .so(DioHandwriting) + Skia + 서드파티 .so 전부 대상. 1순위는 자체 `CMakeLists.txt` 링크 옵션.
- 권장: 릴리스 AAB 빌드 후 arm64-v8a .so 전수 검사 → CMake 옵션 추가 → 16KB 에뮬레이터 실행 → Play Console 사전 검토 경고 확인. 기한 2027-02-01이지만 지금 검사.

### 3. Play targetSdk 요건과 Expo SDK 58 기본값
- 출처: [Target API level requirements](https://support.google.com/googleplay/android-developer/answer/11926878) · [Expo SDK 58 changelog](https://expo.dev/changelog/sdk-58)(2026-10-15) · [build-properties](https://docs.expo.dev/versions/latest/sdk/build-properties/)
- 핵심: API 35는 2025-08-31, **API 36은 2026-08-31**(연장 신청 시 2026-11-01). "New apps and app updates must target Android 16 (API level 36) or higher". SDK 58 기본 targetSdk는 변경 로그에 없음(확인 못 함). build-properties 예시는 `compileSdkVersion: 37`, `targetSdkVersion: 36`.
- 우리 앱 영향: 오늘(11-04)은 연장 기한도 지났다. 지금 올리는 업데이트는 targetSdk 36이어야 하고, 36이면 1번 방향 무시가 정상 적용된다.
- 권장: 빌드된 매니페스트 `aapt dump badging`으로 실제 targetSdk 확인. 고정하려면 `expo-build-properties` `android.targetSdkVersion: 36`.

### 4. Play "사진 및 동영상 권한" 정책
- 출처: [Photo and Video Permissions policy](https://support.google.com/googleplay/android-developer/answer/14115180) · [Expo MediaLibrary](https://docs.expo.dev/versions/latest/sdk/media-library/) · [Access media files](https://developer.android.com/training/data-storage/shared/media)
- 핵심: 2023-10 도입, 마감 **2025-05-28** "Full policy compliance is mandatory for all developers, including those who requested an extension." API 33+ 앱은 시스템 선택기로 부족할 때만 `READ_MEDIA_IMAGES/VIDEO` 요청 가능, "Apps that have custom pickers are not automatically qualified", Play Console 사유 선언 필요. `READ_MEDIA_VISUAL_USER_SELECTED`가 같은 범위인지는 확인 못 함. Android 10+는 자기 소유 미디어를 MediaStore에 쓸 때 권한 불필요(`WRITE_EXTERNAL_STORAGE`는 `maxSdkVersion="28"`).
- 우리 앱 영향: 플러그인이 넣는 읽기 권한은 쓰이지 않는 불필요 선언 → 심사에서 문제 삼을 수 있다.
- 권장: 가장 확실한 방법은 `android.blockedPermissions`(app.json 공식 키)로 최종 매니페스트에서 제거. 저장 호출은 `writeOnly: true`. 제거 후 Android 9 이하 저장은 minSdk 기준으로 확인.

### 5. 예측형 뒤로가기
- 출처: [Behavior changes: Android 16](https://developer.android.com/about/versions/16/behavior-changes-16) · [Predictive back 가이드](https://developer.android.com/guide/navigation/custom-back/predictive-back-gesture) · [Expo app config](https://docs.expo.dev/versions/latest/config/app/) · RN 토론 #921
- 핵심: "For apps targeting Android 16 (API level 36) or higher and running on an Android 16 or higher device, the predictive back system animations … are enabled by default. Additionally, `onBackPressed` is not called and `KeyEvent.KEYCODE_BACK` is not dispatched anymore." 임시 opt-out `android:enableOnBackInvokedCallback="false"`. RN 0.81부터 네이티브 뒤로가기 호환 작업 포함. Expo `android.predictiveBackGestureEnabled` "Default to false."
- 우리 앱 영향: RN 0.88 `BackHandler`는 동작해야 하지만 targetSdk 36에서 뒤로가기가 앱을 바로 종료한 커뮤니티 사례가 있다(공식 이슈 확인 못 함). 자체 네이티브 모듈·`onBackPressed` 오버라이드가 있으면 영향.
- 권장: Android 16 실기기에서 편집·모달·시트 뒤로가기 점검 → 문제 시 `predictiveBackGestureEnabled` 명시, 네이티브는 `OnBackPressedCallback`.

### 6. Edge-to-edge
- 출처: Android 16 behavior changes · [Display content edge-to-edge](https://developer.android.com/develop/ui/views/layout/edge-to-edge) · RN 토론 #921 (Expo edge-to-edge 가이드는 404)
- 핵심: "Edge-to-edge is enforced on Android 15 (API level 35) and higher once your app targets SDK 35." Android 16: "`windowOptOutEdgeToEdgeEnforcement` is deprecated and disabled, and your app can't opt-out". 바 숨김의 공식 방식은 `WindowInsetsControllerCompat.hide(systemBars())`, 스타일러스 가이드는 숨김 상태에서 하단 스와이프 오터치 방지로 `BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE` + `ACTION_CANCEL` 처리를 권고. RN 0.81 `edgeToEdgeEnabled` Gradle 속성.
- 우리 앱 영향: 바를 숨겨도 사용자가 스와이프로 불러내면 일시 표시되고 그 순간 캔버스 오터치 가능. 고정 가로 UI 하단·모서리 컨트롤이 제스처 영역과 겹치는지 확인.
- 권장: 숨김을 transient 모드로 명시, 캔버스 가장자리 컨트롤에 시스템 제스처 insets 반영.

### 7. 알림
- 출처: [Notification runtime permission](https://developer.android.com/develop/ui/views/notifications/notification-permission) · [Expo Notifications](https://docs.expo.dev/versions/latest/sdk/notifications/)
- 핵심: "If your app targets Android 13 or higher, your app has complete control over when the permission dialog is displayed." 좋은 시점은 알림 벨 탭·팔로우·주문 완료 직후. 플러그인 속성 `icon`(96×96 all-white png with transparency), `largeIcon`(SDK 58 추가), `color`(기본 #ffffff), `defaultChannel`, `sounds`. Android 8+ 채널 필수, 없으면 "Miscellaneous" 폴백, 권한 팝업은 채널 생성 전엔 안 뜸 → 토큰 호출 전 `setNotificationChannelAsync`. SDK 58: 포그라운드 알림 기본 표시.
- 권장: 플러그인 `icon`·`color`·`defaultChannel` 설정, 용도별 채널(초대·활동·시스템) 분리, 알림 설정 화면에서 권한 요청. 네이티브 재빌드 필요.

### 8. 대형 화면 품질 가이드·창 크기 클래스
- 출처: [Adaptive app quality](https://developer.android.com/docs/quality-guidelines/large-screen-app-quality) · [Window size classes](https://developer.android.com/develop/ui/compose/layouts/adaptive/use-window-size-classes)
- 핵심: Tier 3 = 전체 화면·레터박스 없음 + 키보드·마우스·스타일러스 기본, Tier 2 = 화면 크기별 레이아웃 최적화(대형 화면 뱃지), Tier 1 = 멀티태스킹·폴더블·드래그앤드롭. 테스트 기기: 폴더블 841×701dp, 8인치 1024×640dp, 10.5인치 1280×800dp. 너비 클래스 Compact <600 · Medium 600–840 · Expanded 840–1200 · Large 1200–1600 · Extra-large ≥1600, 높이 Compact <480 · Medium 480–900 · Expanded ≥900. "창 크기이며 기기 크기가 아니다", "isTablet 로직 용도가 아니다".
- 권장: 분기 기준을 600/840dp 공식 breakpoint로, 멀티윈도우·분할 화면 상태 보존 점검.

### 9. S펜/스타일러스
- 출처: [Advanced stylus features](https://developer.android.com/develop/ui/views/touch-and-input/stylus-input/advanced-stylus-features) · [Stylus overview](https://developer.android.com/develop/ui/views/touch-and-input/stylus-input)(2026-07-08 갱신)
- 핵심: `TOOL_TYPE_STYLUS`/`TOOL_TYPE_ERASER`, `AXIS_PRESSURE`(1 초과 가능 → 정규화), `AXIS_TILT`·`AXIS_ORIENTATION`·`AXIS_DISTANCE`(호버, 제조사별 상이). 팜 리젝션: `ACTION_CANCEL`·`FLAG_CANCELED`(API 33+)를 받으면 직전 획을 이력에서 제거. 저지연: `androidx.graphics:graphics-core` `GLFrontBufferedRenderer`(OpenGL, 소영역 필기용), 모션 예측 `androidx.input:input-motionprediction` `MotionEventPredictor`(예측 점은 최종 렌더에 쓰지 말 것), `requestUnbufferedDispatch()`. `BUTTON_STYLUS_PRIMARY` 문구 확인 못 함. RN pointer events 문서 404.
- 우리 앱 영향: `ACTION_CANCEL`/`FLAG_CANCELED` 처리와 바 숨김 상태 오터치 방지가 실제 결함 후보.
- 권장: Skia 위에서 front-buffer를 못 쓰면 예측 점 + 입력 비배치가 현실적.

### 10. 터치 타겟 48dp·비선형 글자 확대 — 공식 페이지 404로 확인 못 함(일반 지식: 48dp, Android 14+ sp 비선형 최대 200%). `maxFontSizeMultiplier`는 고정 크기 도구 UI에만 제한하고 본문은 확대 허용 권고(근거 문서 없음).

### 11. allowBackup과 dataExtractionRules
- 출처: [Auto Backup for Apps](https://developer.android.com/identity/data/autobackup) · Expo app config
- 핵심: "The default value is `true`, but we recommend explicitly setting the attribute in your manifest." 백업 상한 **25MB/앱**, 기본 대상 SharedPreferences·`getFilesDir()`·DB·`getExternalFilesDir()`, 제외 `getCacheDir()`·`getNoBackupFilesDir()`. targetSdk 31+ `dataExtractionRules`(`<cloud-backup>`, `<device-transfer>`, Android 16 QPR2 `<cross-platform-transfer platform="ios">`), Android 11 이하용 `fullBackupContent` 별도. 25MB 초과 시 클라우드 백업 자체가 안 됨. 일부 제조사는 `allowBackup=false`여도 기기 간 전송은 안 꺼짐. Expo `android.allowBackup` 기본 true.
- 우리 앱 영향: 로컬 사진·편집본·폰트 캐시가 `files/`에 있으면 25MB를 쉽게 넘어 백업 실패, 토큰이 SharedPreferences에 있으면 백업 포함.
- 권장: 토큰은 백업 제외(자격 증명은 Block Store 권장), 큰 미디어 디렉터리 `<exclude>`. Expo 설정 키 확인 못 함(config plugin 필요 가능성).

### 12. Android App Links
- 출처: [Expo Android App Links](https://docs.expo.dev/linking/android-app-links/)
- 핵심: `android.intentFilters`에 `action: "VIEW"`, `autoVerify: true`, `data: [{scheme: "https", host, pathPrefix}]`, `category: ["BROWSABLE","DEFAULT"]`. 서버 `/.well-known/assetlinks.json`(`delegate_permission/common.handle_all_urls`, `package_name`, `sha256_cert_fingerprints`), HTTPS + `application/json`. 지문은 `eas credentials -p android` 또는 Play Console 앱 서명 키(Play App Signing 시 업로드 키 아님). 검증 20초+, 웹 파일 변경 시 재빌드 필요. 커스텀 scheme은 `app.json` `scheme`.

### 추가 발견: Expo SDK 58 변경
- 릴리스 빌드에서 **R8 기본 활성화**(`android.enableMinifyInReleaseBuilds=true`). 리플렉션 쓰는 자체 네이티브 모듈·Skia JNI는 ProGuard keep 규칙 필요 가능. `expo-build-properties`로 끌 수 있음. **릴리스 빌드 실기 테스트 필수**.
- "`ScreenOrientation.lockAsync` may have no effect while the app is resizable"(iOS 27 설명). Android 대형 화면 무시는 Expo 문서에 명시 없음.
