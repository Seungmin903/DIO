# Android 플랫폼 규격 점검 (총 20건: P0 0, P1 2, P2 14, P3 2) — 코드 읽기만, 실기기 미검증

### [P1] expo-media-library 플러그인이 과잉 권한과 requestLegacyExternalStorage 를 주입 (Play 사진/동영상 권한 정책 위험)
- 위치: app.json:21-28, app.json:101-103, node_modules/expo-media-library/plugin/build/withMediaLibrary.js:40-46, 63-70
- 현상·근거: `granularPermissions: []`로 READ_MEDIA_IMAGES 등을 뺐지만 플러그인은 `READ_EXTERNAL_STORAGE`, `WRITE_EXTERNAL_STORAGE`, `READ_MEDIA_VISUAL_USER_SELECTED`를 항상 추가하고 `requestLegacyExternalStorage="true"`도 넣는다. 앱은 사진 "추가"만 한다(savePngFile.native.js:16-17, gifFileIO.native.js:39-40 writeOnly). 읽기는 expo-image-picker(시스템 Photo Picker)만.
- 영향: targetSdk 35+ Play 심사에서 READ_MEDIA_VISUAL_USER_SELECTED·READ_EXTERNAL_STORAGE는 "사진 및 동영상 권한" 정책 신고 대상. 핵심 기능이 아니면 반려 가능. WRITE_EXTERNAL_STORAGE는 API 29+ 무의미한 과잉 권한.
- 해결안: expo-media-library 뒤에 `withAndroidManifest` 커스텀 플러그인으로 세 권한 `tools:node="remove"`, `requestLegacyExternalStorage` 삭제. Android 10+는 MediaStore 추가에 권한 불필요 → `requestPermissionsAsync(true, [])`는 `Platform.Version < 29`에만.

### [P1] 예측형 뒤로가기 설정 미지정 + 화면별로 흩어진 BackHandler 등록
- 위치: app.json:99-110(`predictiveBackGestureEnabled` 없음), App.js:411-440, EditorScreen.js:1009-1037(1012줄 `if (colorPicker) return false`), AuthScreen.js:243, PinScreen.js:34, LibrarySearchScreen.js:19, EyedropperOverlay.js:45
- 현상·근거: App.js 전역 리스너는 `page === 'editor'`면 해제되고 EditorScreen이 따로 등록. 여러 리스너가 "나중 등록이 먼저 호출" 순서에 의존하고 `return false` 위임도 이 순서에 기댄다.
- 영향: Android 13~16 OnBackInvokedCallback 경로에서 JS BackHandler가 시스템 제스처 미리보기와 어긋날 수 있다(추정). 등록 순서가 뒤집히면 홈으로 튕겨 편집 상태가 날아갈 수 있다.
- 해결안: `android.predictiveBackGestureEnabled: false` 명시(현재 JS 우선 구조). 켠다면 탭 S9 FE(Android 16) 실기기 검증. 리스너는 App 단일 "뒤로 스택"(우선순위 레지스트리)으로 통합.

### [P2] 알림 거부 후 재허용 경로·요청 맥락 (POST_NOTIFICATIONS)
- 위치: src/notifications/nativePushAdapter.js:7-10
- 현상: `canAskAgain !== false`일 때만 요청, 아니면 DENIED 반환. `Linking.openSettings()` 안내 없음(추정).
- 영향: Android 13+ 두 번 거부 사용자는 앱에서 다시 켤 수 없다.
- 해결안: 거부 상태에서 알림 설정 화면에 `Linking.openSettings()` 버튼. 첫 요청은 맥락에서 사전 설명 후.

### [P2] 알림 아이콘·색상·채널 구성 미설정
- 위치: app.json:77(`"expo-notifications"` 문자열만), nativePushAdapter.js:7
- 현상: 플러그인 옵션(icon/color) 없음. 채널 'default' 하나, importance DEFAULT. 채널은 토큰 요청 때만 생성.
- 영향: 알림 작은 아이콘이 흰 사각형. 종류별 끄기 불가. 채널 생성 전 원격 알림이 오면 시스템 기본 채널.
- 해결안: `["expo-notifications", {"icon":"./assets/images/notification-icon.png","color":"..."}]`(96×96 흰색 투명 PNG). 앱 시작 시 채널 선생성. 용도별 채널 분리.

### [P2] 딥링크 scheme / intentFilters 없음
- 위치: app.json 전체(`expo.scheme`, `android.intentFilters` 없음)
- 영향: 프로덕션에서 `dio://`나 https 초대 링크로 앱을 열 수 없다. `exp+dio://`는 개발 클라이언트 전용.
- 해결안: `scheme: "dio"` + `android.intentFilters`(`autoVerify: true`, App Links, `assetlinks.json`).

### [P2] Android 빌드 설정 미지정 (allowBackup, 아이콘 monochrome, targetSdk, 16KB)
- 위치: app.json:99-110, eas.json:2-18, plugins/withHandwritingAndroid.js
- 현상: `allowBackup` 미지정(기본 true). `adaptiveIcon.monochromeImage` 없음. `expo-build-properties` 없음. 자체 네이티브 모듈 DioHandwriting(handwriting/generator.js:9)·CMake의 `.so` 16KB 페이지 정렬 설정 미확인.
- 영향: 로컬 다이어리·설정이 클라우드 백업에 포함되는데 SecureStore 키는 복원되지 않아 복원 후 오류 가능. 16KB 비정렬 `.so`는 Play 제출 거절·16KB 기기 크래시.
- 해결안: `android.allowBackup: false` 또는 dataExtractionRules. `monochromeImage` 추가. CMake `-DANDROID_SUPPORT_FLEXIBLE_PAGE_SIZES=ON`(NDK r27+), `llvm-readelf -lW`로 LOAD 정렬 0x4000 확인.

### [P2] API 기본 주소가 cleartext 에뮬레이터 주소, eas.json 에 URL 주입 없음

- 현상: `EXPO_PUBLIC_API_BASE_URL` 미설정 시 `http://10.0.2.2:8080/api`. preview/production env에 API URL 없음.
- 영향: 미주입 시 프로덕션 빌드가 서버에 못 붙음. http면 Android 9+ cleartext 차단.
- 해결안: eas.json production/preview env에 https URL 명시, 빌드 시 값 없으면 실패하는 검증.

### [P2] 몰입 모드(상태바·내비바 숨김) + 모달·가로 인셋 처리

### [P2] 키보드 처리가 edge-to-edge 와 맞지 않을 가능성 (behavior='height' 혼용)

- 현상: `softwareKeyboardLayoutMode` 없음. AuthScreen만 `keyboardDidShow` 수동 패딩, 나머지는 KAV `'height'`. AuthScreen KAV는 Android에서 behavior undefined.

### [P2] 태블릿 가로 고정 — Android 16 대형 화면 방향 잠금 무시 정책과 충돌
- 위치: src/shared/useOrientationLock.js:13-23, app.json:6, src/shared/layout.js:33-35, useFormFactor.js:5-8
- 현상: 최단변 600dp 이상이면 항상 `LANDSCAPE`, 폰은 `PORTRAIT_UP`(편집기 제외). 분할 화면에서 600dp 미만이 되면 폰 배치+PORTRAIT_UP 잠금 재호출.
- 영향: Android 16(targetSdk 36)은 최단변 600dp 이상 기기에서 앱의 방향·크기 제한을 무시한다. 분할 화면에서 회전 점프 가능(추정). Play 대형 화면 품질 등급에 불리.
- 해결안: 가로 강제 제거, 창 폭 구간(Compact <600, Medium 600-840, Expanded ≥840dp)별 레이아웃. 최소 `Platform.Version >= 36` 분기. 분할 화면·폴더블 QA.

## 잘 되어 있는 점
- 계정 삭제 기능(authApi.js:408-425 `withdraw`, ProfileEditScreen.js:26 확인 문구).
- 사진 읽기는 expo-image-picker(Android 13+ Photo Picker)라 읽기 권한 요청 없음. android.permissions 직접 선언은 POST_NOTIFICATIONS 하나.
- 33개 Modal 모두 onRequestClose 지정, 편집기 BackHandler가 열린 UI를 한 단계씩 닫음(EditorScreen.js:1009-1037).
- PDF 공유는 expo-sharing+캐시 복사본+lease 만료 정리(savePdfFile.native.js:3-60). 사진 저장 임시 폴더 finally 삭제.
- 폼팩터를 창 크기로 판단(useFormFactor.js:5-8), 네이티브 모듈 없을 때 안전 폴백(useHiddenNavigationBar.js:5-9).
