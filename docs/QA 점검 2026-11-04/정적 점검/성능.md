# 성능·최적화 점검 (총 15건: P0 0 / P1 4 / P2 7 / P3 4) — 정적 점검, 수치는 코드 상수 기반 추정

### [P1] 텍스트 글꼴 11종(TTF 약 31MB 이상)을 앱 시작 때 전부 등록
- 위치: src/diary/components/DiaryCreateModal.js:34(모듈 최상위 `preloadTextFonts()`), src/editor/screens/EditorScreen.js:92, src/editor/services/textFonts.js:6-37
- 현안·사유: App.js가 두 모듈을 정적 import 하므로 최상위 호출이 앱 시작 즉시 실행. `FONT_FILES` 11개를 `Promise.all(loadAsync)`. 고운바탕 Regular 8.4MB·Bold 8.2MB, 마루부리 8.0/8.3MB, 고운돋움 7.2MB → 한글 TTF 5개만 약 40MB(assets/fonts 합계 46MB). 시작 직후 I/O·메모리 경쟁(추정 수백 ms~1초, 상주 메모리 수십 MB).
- 영향: 탭 S9 FE·S20 콜드 스타트, 보관함 첫 렌더 직후 프레임 드랍. 기본 글꼴 사용자는 대부분 안 쓰는 파일.
- 해결안: 문서에 실제 등장한 `font`와 글꼴 선택 UI를 열 때만 `loadAsync`(지연 로딩). `expo-font` config plugin으로 네이티브 내장. 한글 서브셋(pyftsubset 2,350자+동적 서브셋)으로 8MB→1MB 안팎. 최상위 호출은 `InteractionManager.runAfterInteractions`나 첫 편집기 진입으로.

### [P1] 자동 저장이 문서 전체(모든 페이지·모든 획 좌표)를 한 AsyncStorage 키에 통째로 직렬화
- 위치: src/editor/hooks/useEditor.js:111-121, src/editor/services/storage.js:17-23, src/editor/utils/strokes.js:39, src/editor/services/editorDocs.js:63-78, PenInput.js:116-190
- 현안·사유: 편집마다 `state.doc` 전체를 1.2초 뒤(최대 5초) 한 키로 직렬화. 점마다 `{x,y,pressure,time,speed,(force,tiltX,tiltY),inkDistance}` 객체 → 획 하나 수 KB. 획 300개+ 페이지 몇 장이면 문서 수 MB(추정 2~10MB). 직렬화는 JS 스레드 동기, 청크 없음. 읽기도 동기 `JSON.parse`, 프리페치 8권 순차(App.js:692-706).
- 영향: 저장 시점마다 수십~수백 ms JS 정지(필기 끊김, 추정). Android AsyncStorage 단일 행 약 2MB(CursorWindow) 초과 시 읽기 실패 사례(미검증). 쓰기 실패 시 'error' 표시만.
- 해결안: (1) 페이지 단위 키 분리·변경 페이지만 저장(immutable reducer라 참조 동일성으로 dirty 판정) (2) 획 `points` 평면 숫자 배열(Float32/Int16 델타 base64)로 5~10배 압축 (3) MMKV(JSI 동기, mmap) 또는 op-sqlite/expo-sqlite (4) 필기 중 저장 연기·페이지 단위 청크.

- 위치: src/diary/components/CoverArt.js:63-79, 405, CoverPattern.js, src/diary/screens/LibraryScreen.js:375-400
- 현안·사유: 표지마다 SVG 노드(Defs·그라데이션·무늬) 네이티브 뷰 생성. 캐러셀은 `initialNumToRender=3 / windowSize=5 / getItemLayout`으로 양호. FlatList는 캐러셀뿐이고 "한눈에" 등은 FlatList/FlashList가 아닌 구조로 보임(검증 필요) → 100권이면 SVG 표지 100개 동시 마운트(추정 수백 ms).

### [P1] 시작 대기: Pretendard 5종(7.8MB OTF)을 첫 렌더 전에 모두 로드, 스플래시 상한 8초

### [P2] 구운 Skia 표면 풀의 메모리 상한과 해제
- 위치: src/editor/components/canvas/CompletedStrokeLayer.native.js:42-50, :136, src/editor/skia/rasterBudget.js:1-12
- 현안·사유: 표면은 256px 단위로 키우기만 하고 줄이지 않음. 태블릿 화면 1장 약 14MB(주석 실측), 줌 확대 시 `scale = zoom*PixelRatio`. 편집기 떠날 때 `pool` dispose 경로 없음(모듈 변수). `rasterBudget`은 시간 기준(24ms/40ms)이고 픽셀 상한 없음. `quantizeScale` 하한 0.25만 있고 상한 없음 → 4096² 급(RGBA 약 64MB) 가능(추정).
- 해결안: `bakeSurface` 최대 픽셀 상한(예: 2048×2048), 초과 시 타일링 또는 scale 클램프. 편집기 unmount·`AppState` memoryWarning에서 `pool.surface.dispose()`, 줌 아웃 시 풀 축소.
