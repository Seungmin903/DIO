## 1. 주요 버튼 글자 대비 — 접근성

**트렌드 · 근거**

- 접근성은 2026년에 "있으면 좋은 것"이 아니라 기본값이다. 유럽 접근성법(EAA)은 2025년 6월부터 새 디지털 서비스에 WCAG 2.1 AA 수준을 요구한다 ([Miquido](https://www.miquido.com/blog/accessibility-in-business/)).
- WCAG AA는 보통 크기 글자에 **4.5 : 1** 이상의 대비를 요구한다. 지금 주요 버튼(14 / 800 흰 글자)은 **3.19 : 1**로 기준에 못 미친다.

**지금 → 바꾸면**

- 지금: 채운 버튼 바탕 = `primary #6E92C6`
- 바꾸면: 채운 버튼에만 한 단계 진한 `#4F74AE`(4.73 : 1)를 쓴다. 선택 테두리 · 슬라이더 등 선에는 지금 `primary`를 그대로 둔다. 토큰은 `primaryStrong`처럼 하나 더 만든다.

| 지금 | 바꾸면 |
|---|---|
| ![지금](이미지/01%20대비%20변경전.png) | ![바꾸면](이미지/01%20대비%20변경후.png) |

① 왼쪽 레일 새 다이어리 버튼 ② "내지 구성 선택하기" 버튼

**검토 포인트:** 브랜드 하늘색 느낌이 줄어드는지. 대안은 버튼 글자를 18 이상 굵게(큰 글자 기준 3 : 1) 키우는 것이지만 버튼 크기가 커진다.

## 2. 앱 바탕 중립화 — 콘텐츠가 주인공

**트렌드 · 근거**

- 2026년 흐름은 감정이 담긴 콘텐츠를 앞세우고 화면 틀은 덜어내는 미니멀 구성이다 ([Designveloper](https://www.designveloper.com/blog/mobile-app-design-trends), [Apiko](https://apiko.com/blog/ux-design-trends/)).
- 다이어리 앱에서 콘텐츠는 **종이와 표지**다. 지금은 바탕 하늘색이 넓고 진해서, 하늘색 계열 표지 · 테이프 · 사진이 바탕에 묻힌다.

**지금 → 바꾸면**

- 지금: 홈 · 편집기 바탕 `surfaceSoft #CED9EE`
- 바꾸면: 바탕은 `#F1F3F7`(아주 옅은 회청색), 하늘색은 선택 · 강조에만. 리본의 선택된 도구 바탕도 `surfaceSoft`를 쓰므로 함께 조정한다(예: `primarySoft`).

① 편집기 바탕 전체

**검토 포인트:** 흰 종이와 바탕의 구분이 약해진다. 종이 그림자(`shadow.card`)를 조금 키우는 것과 같이 봐야 한다.

## 3. 떠 있는 상단 바 — 유리 캡슐

**트렌드 · 근거**

- Apple은 iOS · iPadOS 26의 Liquid Glass에서 막대를 화면에 붙은 띠가 아니라 **콘텐츠 위에 떠 있는 층**으로 다룬다. iPad에서는 버튼 대부분을 **캡슐 모양**으로 쓰고, 안쪽 모서리를 바깥 모서리와 맞추는(concentric) 것을 권한다 ([WWDC25 · Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/356/)).
- 우리 리본(도구 막대)과 실행 취소 바는 이미 떠 있는 카드다. 상단 바만 흰 띠로 남아 있어 한 화면에 두 가지 방식이 섞여 있다.

**지금 → 바꾸면**

- 지금: 높이 64 흰 띠(투명도 0.9), 버튼은 모서리 12
- 바꾸면: 띠를 투명하게 하고 `< 로고`, `페이지`, `레이어`를 각각 반투명 흰 캡슐(높이 44, 모서리 999, 흐림 16)로. `내보내기`도 캡슐로 맞춘다.

| 지금 | 바꾸면 |
|---|---|
| ![지금](이미지/03%20떠있는%20바%20변경전.png) | ![바꾸면](이미지/03%20떠있는%20바%20변경후.png) |

① 상단 바

**검토 포인트:** 캔버스를 위로 끌면 종이가 상단 바 뒤로 지나가며 비친다. 안드로이드 흐림 효과 성능(기기 테스트 필요).

## 4. 글자 굵기 덜어내기

**트렌드 · 근거**

- 2026년 흐름은 차분한 미니멀 구성이다 ([Designveloper](https://www.designveloper.com/blog/mobile-app-design-trends)). 위계는 굵기보다 **크기 · 간격**으로 나눈다.
- 지금은 거의 모든 제목 · 버튼 · 칩이 800 이상이라 어디가 가장 중요한지 오히려 흐려진다. 2026-10-22 정리로 중간 굵기는 없앴지만 전체 수준은 여전히 높다.

**지금 → 바꾸면**

- 지금: 홈 제목 29 / 900 (자간 -1.35), 칩 · 카드 제목 · 보기 전환 800
- 바꾸면: 홈 제목 800 (자간 -0.6), 나머지 800 → 700. 선택 상태만 800으로 올려 구분한다.

**검토 포인트:** 한글은 같은 굵기라도 라틴 글자보다 무거워 보인다. 기기(안드로이드 기본 글꼴)에서 너무 가벼워 보이지 않는지.

- 지금 가이드는 다크 모드를 지원하지 않는다고 정해 두었다(`userInterfaceStyle: light`).

**지금 → 바꾸면**

- 시안 색: 바탕 `#121620`, 막대 `rgba(32,37,50,0.95)`, 글자 `#E7EAF3`, 로고 먹색 → 밝은 색.

## 302 구현 기록

1·2·4번을 적용한다. primaryStrong #4F74AE를 CTA용으로 추가하고, surfaceSoft는 #F1F3F7로 변경한다. 선택된 도구·메뉴는 primarySoft로 유지해 선택 표시가 배경에 묻히지 않게 한다. UI 제목과 일반 버튼·메뉴 굵기만 낮추고 표지 인쇄 글자·꾸밈·사용자 콘텐츠는 유지한다. 로고와 네이티브 스플래시는 유지한다. 3·5·6번은 이번 작업에 포함하지 않는다.
검증: 프론트 단위 테스트 704개 통과. 배포 웹 빌드와 iOS·Android·웹 JS 번들 생성 성공. 브라우저 1280×800, 1024×768, 390×844, 844×390에서 CTA 대비 4.5:1 이상, 선택 표시, 보관함 두 보기, 페이지·레이어 패널, 속지 비율 및 저장 크기 유지와 브라우저 오류 없음을 확인했다. 네이티브 실기기 색상·굵기는 별도 확인한다.

재현 명령(frontend): `node --test --test-concurrency=1 tests/*.test.js`, `pnpm exec expo export --platform web --output-dir .expo/design-review-export`, `node tests/design-review-browser.cjs`.

리뷰 보완: 모바일 공통 헤더 자간·일반 UI 굵기를 기준에 맞추고, 강조 칩 및 흰 표시가 있는 체크·배지 색상을 정리했다. 기존 표지 호환 기본색은 FALLBACK_COVER_COLOR로 공통 참조한다. 보완 후 테스트 705개, 웹 빌드 및 4개 규격 브라우저 검증 통과.

### 디자인 브라우저 검증 준비

frontend에서 `pnpm install --frozen-lockfile`로 선언된 개발 의존성을 설치한다. playwright와 playwright-core는 package.json 및 pnpm-lock.yaml에 이미 등록되어 있다.

기본 실행은 Playwright Chromium을 사용한다. 최초 한 번 `pnpm exec playwright install chromium`을 실행한 뒤 웹 export와 `node tests/design-review-browser.cjs`를 실행한다. Linux CI에서 시스템 라이브러리까지 준비해야 하면 `pnpm exec playwright install --with-deps chromium`을 사용한다. 브라우저 설치가 불가능한 환경은 기존 Chromium 계열 실행 파일의 절대 경로를 PLAYWRIGHT_EXECUTABLE_PATH로 지정할 수 있다.

예: PowerShell에서 `$env:PLAYWRIGHT_EXECUTABLE_PATH = 'C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe'`를 설정하면 설치된 Edge로 검증한다. 스크립트 기본값은 특정 OS나 Edge 설치에 의존하지 않는다.

색 대비 단위 테스트는 순수 토큰·표지 기본색을 직접 import해 검사한다. 화면 스타일 파일의 소스 가공·동적 실행은 사용하지 않으며, 실제 글자색과 도형 추가 버튼 대비는 브라우저에서 검사한다.
