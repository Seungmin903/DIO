# 모바일 로그인 유지

Android·iOS는 `expo-secure-store`에 refresh 토큰, 제공자(email/google/apple), 계정 ID만 저장한다. 비밀번호·access 토큰·개발 서버 Basic 인증은 저장하지 않는다. AsyncStorage나 평문 저장소로 대체하지 않는다.

저장 키는 전체 API 기본 주소별로 분리한다. iOS Keychain은 잠금 해제 상태에서 접근하며 다른 기기로 이동하지 않는 `WHEN_UNLOCKED_THIS_DEVICE_ONLY`를 사용한다. 앱 삭제 후에도 iOS Keychain 값이 남을 수 있으므로 삭제·재설치를 로그아웃 수단으로 안내하지 않는다.

앱 시작 시 회원/게스트 보관함을 열기 전에 기존 `POST /api/v1/auth/refresh`로 복원을 시도한다. 성공하면 교체된 refresh 토큰을 저장하고 서버 응답의 사용자로 회원 보관함을 연다. 복원 요청도 일반 인증 요청과 같은 15초 제한을 사용한다. 복원 중에는 기존 시작 화면을 유지해 빈 화면이 생기지 않도록 한다. 저장된 정보가 없거나 복원에 실패하면 기존 게스트 보관함을 연다.

- refresh API의 명시적인 만료·폐기 응답인 `401 / INVALID_TOKEN`: 저장 정보를 삭제하고 기존 로그인 화면을 연다. 프록시·WAF 등의 일반 401/403은 유효한 토큰의 폐기 근거로 사용하지 않고 보존한다.
- 네트워크·서버 장애·요청 제한·개발 게이트웨이 Basic 인증 오류: 저장 정보를 보존하고 다음 앱 실행에서 재시도한다.
- 로그아웃, 비밀번호 변경 성공, 회원 탈퇴 성공: 저장 정보를 삭제한다.
- 비밀번호 재설정 성공: 현재 로그인 계정의 이메일이 재설정 대상과 일치할 때만 메모리 세션과 저장 토큰을 삭제한다. 다른 계정이거나 로그인 세션이 없어 저장 토큰의 계정을 확인할 수 없으면 저장 토큰을 보존하고 인증 초안만 정리한다. 대상 계정의 서버 세션은 서버에서 폐기하며, 보존된 토큰이 그 계정의 것이라면 다음 복원 시 거절·정리된다.
- 세션 종료 시에는 메모리 세션·인증 초안을 먼저 비운다. 보안 저장소 삭제 실패는 개인정보 없는 고정 경고 코드로 기록하며, 서버에서 완료된 탈퇴·비밀번호 변경/재설정·로그아웃의 성공 결과를 바꾸지 않는다. 서버에서 토큰 폐기가 성공한 경우에만 남은 토큰으로 복원할 수 없다고 보장한다.
- 서버 로그아웃과 보안 저장소 삭제가 모두 실패하면 `LOGOUT_INCOMPLETE`로 다음 실행에서 로그인이 복원될 수 있음을 기존 안내창에 알린다. 이때 기기에서 로그인 정보를 지웠다는 문구를 표시하지 않는다. 메모리 세션은 종료되지만 영구 저장된 토큰 삭제는 확인되지 않은 상태다.
- refresh·시작 복원의 `401 / INVALID_TOKEN`에서 보안 저장소 삭제에 실패해도 원래 인증 오류의 상태·코드를 보존한다. 안내 문구는 공통 만료 문구로 통일한다. 개발 서버 인증 오류와 일시적인 통신 오류는 이 정리 대상에 포함하지 않는다.
- 로그아웃이나 다른 로그인 이후 늦게 도착한 복원 응답은 적용하지 않는다.
- 최초 로그인·시작 복원의 저장소 쓰기 실패는 로그인 오류로 알린다. 평문 저장으로 우회하지 않는다.
- 이미 로그인한 사용자의 자동 갱신은 저장소 쓰기가 실패해도 교체된 토큰을 메모리에 유지하고 개인정보 없는 `SECURE_SESSION_SAVE_FAILED` 경고를 남긴다. 다음 갱신에서 저장이 성공하면 새 토큰을 다시 보관한다. 저장 성공 전 앱을 종료하면 기기에는 이전 토큰이 남아 있으므로 재로그인이 필요할 수 있다.

웹은 기존 메모리 세션만 사용한다. 브라우저 로그인 유지에 필요한 HttpOnly 쿠키 계약은 이번 변경 범위에 포함하지 않는다. 새 서버 API·테이블·환경변수는 없다.

개발 빌드가 Basic 인증으로 보호된 개발 서버에 연결된 경우, 앱 재실행 시 기존 개발 서버 접속 인증 화면을 자동으로 연다. 이 인증정보는 메모리에만 유지하므로 매 실행 다시 입력해야 한다. 접속 인증 후에는 회원 이메일·비밀번호를 다시 입력하지 않고 저장된 refresh 토큰으로 로그인 복원을 이어간다. 인증 오류·일시적인 네트워크 오류는 같은 화면에서 재시도할 수 있고, 실제 refresh 토큰이 만료·폐기된 경우에는 일반 로그인으로 돌아간다. 운영 서버에 Basic 인증이 없다면 이 단계는 없다. 개발 인증 입력 기능이 없는 설정에서 복원 모드가 전달되더라도 일반 이메일 로그인 화면을 표시한다.

## 실행 중 만료와 재로그인

- Access Token 만료는 기존 refresh API로 자동 갱신한다. 갱신 성공 시 로그인 화면을 열지 않는다.
- 실행 중 refresh가 `401 / INVALID_TOKEN`으로 거절되면 `subscribeSessionExpired`로 현재 세션 종료를 한 번 알리고, 앱 최상위에서 기존 로그인 오버레이를 연다. 안내는 **로그인이 만료됐어요. 다시 로그인해 주세요.**로 통일한다.
- 로그인 화면은 기존 이메일·비밀번호·소셜 로그인과 디자인을 재사용한다. 취소·뒤로가기로 닫으면 게스트 보관함으로 돌아간다. 성공하면 해당 계정의 회원 보관함을 새 세션으로 초기화한다. 이전 세션 요청을 새 계정으로 자동 재전송하지 않는다.
- 재로그인 화면을 여는 동안 기존 회원 화면은 아래에 유지한다. 같은 계정으로 다시 로그인해도 새 세션 키로 화면과 호출자를 갱신한다. 네트워크·서버·프록시 오류는 이 만료 전환을 유발하지 않는다.
- 이전 로그인에서 늦게 도착한 갱신 실패는 새 로그인에 적용하지 않으며, 구독은 앱 언마운트 시 해제한다. 로그아웃·탈퇴·비밀번호 변경의 정상 종료는 만료 알림을 발생시키지 않는다.
- 앱 시작 복원에서 토큰 만료가 확인돼도 같은 로그인 화면을 열며, 저장 토큰이 없으면 기존처럼 게스트로 시작한다.
- 만료 문구는 인증 모듈이 refresh 거절을 확인한 로컬 오류(`sessionExpired=true`)에서만 표시한다. 일반 API의 401이나 서버 오류 코드만으로 만료를 추정하지 않는다. 일반 401은 **인증을 확인하지 못했어요. 다시 시도해 주세요.**로 안내한다.
- 부팅 복원 실패로 이미 게스트 보관함을 연 상태라면 로그인 화면을 닫아도 게스트를 다시 초기화하지 않는다. 실행 중 만료로 회원 화면이 남아 있는 경우에만 게스트로 전환한다.
- 화면·보관함 저장소의 식별 키는 인증 모듈의 성공한 로그인 세대를 함께 사용한다. 만료 중에는 세대를 유지하고, 재로그인 성공 시 교체하며 렌더 중 ref를 변경하지 않는다. 이 키는 화면 식별용이며 요청 권한 검증에는 기존 활성 세션 키를 사용한다.

## 확인 방법

`pnpm test:auth`로 회귀 검증한다. 실기기에서는 로그인 → 앱 강제 종료 → 재실행 후 회원 보관함 복원, 로그아웃 → 재실행 후 게스트 시작을 확인한다. 오프라인 재실행은 게스트로 시작하며, 온라인으로 돌아온 후 앱을 다시 실행하면 복원을 재시도한다. 서버가 refresh 응답을 보냈지만 기기가 받기 전에 연결이 끊기는 경우는 기존 토큰 로테이션 정책의 영향을 받으며 재로그인이 필요할 수 있다.
