# 폰트 생성 화면 흐름

관련 태스크: [S15P31F106-396](https://ssafy.atlassian.net/browse/S15P31F106-396)

## 화면과 입력

공방(내 공간) 폰트 탭에서 내 폰트 홈을 연다(폰트 화면을 여는 입구는 이 탭 하나다). 소개와 폰트 목록을 태블릿에서는 좌우, 좁은 폰에서는 위아래로 표시한다. 목록에는 작성 중·생성 대기·생성 중·일시 정지·완료·실패·취소 상태를 표시한다.

새로 만들기는 이름·36자 필기 → 실제 고정 샘플 → 생성 확정 → 상세 순서다. 작성 글자를 선택하고 획 되돌리기·다시 쓰기·펜 굵기 변경을 지원한다. 자동 저장 실패 시 입력을 화면에 유지하고 다시 저장할 수 있다. 저장에 실패한 상태에서는 화면을 닫거나 샘플을 생성하지 않는다. 36자 작성과 기존 모델 입력 검증을 통과해야 미리볼 수 있다. 입력을 바꾸면 이전 샘플은 무효다.

기기당 손글씨 폰트 한 개를 생성할 수 있다. 생성 확정은 현재 입력 스냅샷을 고정하고 한도를 사용한다. 생성이 끝나기 전에 취소하거나 생성 자체가 실패하면 다시 시도할 수 있다. 가져온 폰트와 글자 간격 보정본은 한도에 포함하지 않는다. 상세에는 표시 이름·고정 샘플·원본 36자를 표시한다. 생성 진행은 현재/11,172자와 실제 단계를 표시하고, 마지막 글자 이후 파일 제작·등록이 끝나야 완료다.

## 수정본과 폰트 참조

취소한 폰트의 입력 수정은 원본 36자를 복사한 독립 초안이다. 이름이 겹치면 `이름 2`, `이름 3`처럼 아직 쓰지 않은 번호를 선택한다. 표시 이름은 1~30자이며 자동 접미사를 위한 길이를 확보한다. 이름 변경은 파일 ID·렌더링 family·기존 다이어리 참조를 바꾸지 않는다.

기존 폰트·초안·마지막 작업은 삭제하지 않고 새 목록으로 이관한다. 기존 네이티브 작업에서 해당 작업의 원본 입력을 읽을 수 있을 때만 연결한다. 현재 편집 초안을 과거 폰트의 원본이라고 추정하지 않는다. 원본을 복원할 수 없는 폰트는 샘플·사용·파일 저장을 제공하고 입력 수정은 막고 이유를 표시한다.

## 생성 대기열

대기열은 화면과 독립적인 앱 전역 관리자다. 현재 작업을 완료하면 확정 순서대로 다음 작업을 시작한다. 실패 항목은 재시도 가능하게 남기고 다음 작업을 진행한다. 일시 정지·이어 만들기·취소는 항목별로 적용한다. 완료 폰트는 네이티브 작업 ID를 기준으로 자동 등록하므로 재실행·재시도에도 중복되지 않는다.

전체 생성과 샘플 생성은 같은 생성기를 공유한다. 새 샘플 요청 시 현재 작업의 안전한 저장과 네이티브 점유 해제를 확인한 뒤 샘플을 만들고 원래 작업을 이어간다. pauseJob 반환만으로 정지 완료를 판단하지 않는다. 샘플 작업도 동시에 하나만 실행한다.

화면을 닫아도 활성 앱에서는 계속 생성한다. 백그라운드에서는 저장 후 정지하며 복귀·재실행 때 자동 재개한다. 사용자가 직접 정지한 작업은 자동 재개하지 않는다. 모델·전처리 버전이 달라진 미완료 작업은 재개하지 않고 새 수정본 생성을 안내한다.

## 저장과 네이티브 인터페이스

- 기존 폰트 키와 폰트 UUID를 유지한다. AsyncStorage의 `dio-handwriting-workflow-v3`에는 고정 크기의 색인 참조만 저장하고, 항목별 원본 획·미리보기와 작업 색인은 네이티브의 앱 문서 파일 또는 웹의 IndexedDB에 저장한다. 항목에는 초안/확정 원본·샘플·작업 ID·입력 해시·상태·정지 사유·완성 폰트 ID를 저장한다. 전처리 픽셀 전체는 목록에 중복 저장하지 않는다.
- 신규 네이티브 조회 `getJobDraft(id)`는 해당 작업의 immutable input.json에서 원본 draft를 반환한다. `isBusy()`는 실제 생성기 자원 점유 여부를 반환한다. 이전 개발 빌드에 이 메서드가 없으면 업데이트 안내를 표시한다.
- 생성 시작 직후 JS 저장 전에 앱이 종료돼도 최신 네이티브 작업의 입력 해시를 기존 항목과 대조해 복원한다. 파일 등록 후 목록 갱신 전에 종료돼도 sourceJob 기준으로 기존 등록을 재사용한다.
- 파일 가져오기·초안/폰트 내보내기·원본을 보존하는 간격 보정은 더보기 메뉴에 둔다. 네이티브 파일 저장은 임시 파일을 검증한 뒤 이동하고 실패한 신규 파일은 정리한다.
- 서버 API·계정 동기화·다이어리 문서 형식은 변경하지 않는다. 모델·전처리·기존 TTF 생성 알고리즘을 유지한다.

## 지원 환경

실제 샘플과 전체 생성은 모델이 준비된 최신 Android 개발 빌드에서 지원한다. Expo Go·웹·iOS는 입력·목록·상세·완성 폰트 가져오기와 적용을 제공하고 생성에는 지원 환경을 안내한다. 테스트 전용 추론 어댑터는 tests/fixtures에만 있고 앱 진입점에서는 참조하지 않는다.

### 필기 중 화면 스크롤 방지

필기 responder가 활성화되면 입력 화면을 거쳐 상위 ScrollView의 scrollEnabled를 즉시 끄고 상태에도 반영한다. iOS의 canCancelContentTouches도 함께 끈다. 획 종료·취소·강제 종료·백그라운드·글자 변경·비활성화·입력칸 닫기 때 잠금을 해제한다. 필기 중 화면 위치 유지와 종료 후 바깥 영역 스크롤 복원을 Chromium 실제 터치 이벤트로 확인했고, 관련 필기·저장·대기열 검사 30건이 통과했다. Expo Go 실기기 확인은 별도다.

### 원고지 입력 배치

36개 입력칸을 스크롤이 없는 원고지 격자로 배치한다. 가로 공간이 부족하면 다음 행으로 줄바꿈하고 화면의 너비와 높이에 맞춰 모든 칸이 보이도록 정사각형 크기를 계산한다. 칸 한 변은 최대 100이며 행 사이 간격은 칸 크기의 1/4이다. 칸별 번호·입력 글자·작성됨 하단 표시는 없고, 빈 끝 칸은 입력을 받지 않는 종이 여백이다.

안내 글자는 입력칸 정중앙에 배치하며 폰트 크기는 border 반올림까지 반영한 실측 입력 영역의 절반이다. 사용자가 화면을 회전해 칸 크기가 변하면 미완료 획을 취소해 서로 다른 좌표계의 입력이 섞이지 않도록 한다. 한 칸에서 입력하는 동안 다른 칸의 입력과 바깥 화면 스크롤을 막는 소유권 검사를 유지한다. 수정 도구는 마지막으로 입력한 칸에 적용하고 별도 이전/다음 이동 버튼은 두지 않는다.

펜 굵기는 편집창 펜과 같은 굵기 막대(6~24, 처음 9)로 고른다(2026-11-03 최대 굵기 12→24 확대). 관련 단위 검사 32건과 320×740, 390×844, 844×390, 1024×768, 1280×800 브라우저 검사가 통과했다. 36칸 화면 내 배치, 중앙 정렬, 실제 칸과 글자 크기의 2:1 비율, 필기 중 스크롤 차단을 확인했다. Expo Go 실기기 확인은 별도다.

### MR !252 리뷰 수정 (2026-10-31)

- 네이티브 완료 상태와 앱의 폰트 등록 완료를 구분한다. 종료 후 복구된 완료 작업은 등록 전까지 `registering`이며, 과거에 잘못 저장된 `ready` + 빈 `fontId` 항목도 다시 조정한다. 구형 마지막 작업 이관에도 같은 규칙을 적용한다. 등록은 기존 sourceJob 기준으로 재사용하고 실패하면 다시 시도할 수 있다.
- v3 저장은 변경된 원본·미리보기를 UUID별 불변 레코드에 먼저 쓰고 검증한 뒤 새 색인과 마지막 참조를 저장한다. 진행률만 바뀌면 원본을 다시 쓰지 않는다. 참조 저장 완료 후에만 더 이상 참조되지 않는 파일을 정리한다. 웹은 Web Locks로 탭 간 저장·읽기·정리를 직렬화한다.
- v2 작업 목록은 새 저장이 확정된 후 기존 키를 정리한다. 파일·색인·참조 저장 실패 시 기존 키와 입력을 보존하며 재시도한다. 이미 구형 키를 플랫폼 제한 때문에 읽을 수 없는 경우에는 오류를 유지하며 데이터를 삭제하거나 빈 목록으로 덮어쓰지 않는다. 새 구조는 기기 디스크/브라우저 용량 한계 자체를 없애는 것은 아니다.
- 초안 가져오기도 구형 단일 AsyncStorage 초안 값에 중복 저장하지 않고 항목 저장 계층으로 전달한다. 서버 API·폰트 ID·기존 다이어리 참조는 변경하지 않는다.

검증 결과: `pnpm test:handwriting` 43건과 모달 회귀 1건이 통과했다. `node tests/handwriting-persistence-browser.cjs`는 실제 Chromium IndexedDB에 8,800,215바이트를 저장하고 AsyncStorage 참조값이 59자인 상태에서 새로고침 복원·진행률 갱신·이전 색인 정리를 확인했다. 실제 앱 웹 검사도 필기 저장·재실행·Undo·TTF 가져오기/손상 거부/재실행 로드·다이어리 적용·PNG/PDF 출력까지 통과했다. 웹·Android·iOS JS 번들 생성은 성공했으며 Android 파일 저장·실제 모델 및 실기기 강제 종료 복구 검증은 별도로 남아 있다.

## 입력 부하 개선 (2026-11-03)

획 시작/끝마다 나머지 35칸의 disabled를 바꾸던 갱신은 제거하고 입력 소유권 ref로 동시 입력을 계속 막는다. 긴 획은 48선분씩 고정하여 현재 꼬리 구간만 갱신한다. 완료 획도 각각 메모이즈해 이전 획의 경로를 매번 만들지 않는다. 표시 좌표만 소수점 두 자리로 줄이고 원본 좌표·필압·시간·굵기는 저장한다. 펜을 놓은 마지막 위치도 수집한다.

자동 저장은 입력이 멈춘 400ms 뒤 최신 초안으로 묶는다. 새 획 중에는 타이머를 중단하고, 샘플 확인·명시적 닫기·백그라운드·화면 종료 시 완료 획을 즉시 flush한다. 저장 실패 시 현재 입력을 유지하고 재시도한다. 강제 프로세스 종료 전에 아직 저장되지 않은 짧은 입력은 유실 가능하므로 종료 복구 완전 보장을 뜻하지 않는다.

최신 develop 병합 후 `npm run test:handwriting` 53개 통과. 실제 StudioContent+DrawingPad+workflow의 36자/18,432점 브라우저 fixture에서 연속 6획 중 저장 0회, 종료 뒤 최신 저장 1회, 굵기24·되돌리기·다시 실행을 확인했다. 긴 획 합성 테스트는 최근 경로 갱신량을 제한하는 구조 검증이며 실기기 FPS나 지연 시간 측정은 아니다. Android/iPad 실기기 체감과 선의 부드러움은 재검증이 필요하다.

## 2026-11-03 Android 개발 빌드 샘플 생성 확인

- 생성 지원 여부는 네이티브 모듈의 `capabilities()` 결과로 판단한다. 입력 화면과 중단된 작업 상세에 반환된 `reason`을 표시하고, 사유가 없으면 기존 공통 안내를 사용한다.
- 개발 모드에서는 `[DIO_FONT_SUPPORT]` 로그로 지원 여부·버전·사유만 출력한다. 원본 필기·입력 픽셀·계정 정보는 출력하지 않는다.
- 기존 설치본에서 모듈이 반환한 사유는 `개발 빌드에 모델 파일을 준비해 주세요.`였다. 이는 모델 자산 누락에 대한 확인이며, 과거 샘플 생성 강제 종료의 원인이 확정됐다는 뜻은 아니다.
- 네이티브 모듈을 포함한 APK라도 두 ONNX 모델이 없으면 생성할 수 없다. Expo Go는 네이티브 생성 모듈을 포함하지 않으므로 샘플 생성 검증 환경으로 사용하지 않는다.

### 재현 가능한 준비 순서

1. `frontend`에서 `./scripts/prepare-handwriting-models.ps1 -SourceDirectory <검증된 inference-v2 모델 번들 폴더>`를 실행한다. 스크립트가 인코더·디코더 해시와 번들 검증 결과 및 고지를 확인한다. 모델은 Git에 추가하지 않는다.
2. 모델 준비 후 Android 개발 APK를 다시 빌드한다. Debug 빌드는 두 모델이 없거나 해시가 다르면 중단한다. ONNX Runtime은 Android 네이티브 모듈의 Gradle 의존성으로 함께 패키징한다.
3. 생성한 APK에 `assets/dio_handwriting/encoder.fp32.onnx` 및 `decoder.fp32.onnx`가 포함되고 준비 스크립트에 고정된 SHA-256과 일치하는지 확인한다.
4. 개발 클라이언트는 `pnpm exec expo start --dev-client --lan`으로 Metro에 연결한다. 단독 실행 APK는 JavaScript 번들을 포함하므로 Metro가 필요 없다.
5. 폰트 작성 화면을 열어 지원 상태를 확인하고, 36자 작성 후 샘플 확인을 실행한다. 완성 샘플 표시와 앱 생존 여부를 확인한다. 기존 앱 데이터는 삭제하지 않는다.

EAS로 Android 개발 빌드를 만들 때는 검증된 모델을 준비한 `frontend`를 업로드 루트로 사용한다. `frontend/.easignore`는 손글씨 네이티브 모듈과 두 ONNX 파일을 포함한다. EAS development 환경의 `GOOGLE_SERVICES_JSON`에는 `com.f106.DIO.handwritingdev`용 Firebase 설정이 필요하다. PowerShell에서 `frontend`로 이동한 뒤 `$env:EAS_NO_VCS='1'`과 `$env:EAS_PROJECT_ROOT=(Get-Location).Path`를 설정하고 `eas build --platform android --profile development`를 실행한다.

### AI 생성 사실 안내 (2026-11-02)

- 입력 첫 화면의 하단 고정 바에 “입력한 손글씨를 바탕으로 AI가 나머지 글자를 생성합니다.”를 표시한다. 샘플 확인 버튼보다 먼저 보이며 별도 동의 체크는 추가하지 않는다.
- 샘플·생성 완료 화면과 공방/내 폰트/편집기 글꼴 목록에 “AI 생성 손글씨 폰트”를 표시한다. 외부 일반 폰트를 일괄 AI 생성물로 표시하지 않는다. 기존 DIO 폰트는 생성 작업 또는 검증된 DIO 제작 형식으로 식별한다.
- 현재 폰트 파일 저장은 TTF를 포함한 DIO JSON 이관 파일이다. 저장 메뉴에 AI 생성 안내를 표시하고 JSON의 선택 필드 `aiGeneration`에 `generated`, `label`, `notice`를 함께 기록한다. 기존 파일도 가져올 수 있고 TTF 바이트·이름·폰트 ID·다이어리는 변경하지 않는다. 안내는 TTF와 함께 제공되는 JSON에 남으며, JSON에서 분리한 원시 TTF에 표시가 내장된 것은 아니다. 원시 TTF 직접 다운로드를 추가한다면 파일 메타데이터 또는 함께 제공하는 안내 문서와 다운로드 안내를 구현해야 한다.
- 다이어리의 각 글자·페이지에 워터마크를 추가하지 않는다. PNG/PDF 등의 외부 내보내기 표시 방식은 별도 검토 대상이다. SAM 2/DM-Font 라이선스 고지와 AI 생성물 표시는 별개다.
