- **현재 상태는 진행 중이다.** 실제 기기 사진첩·권한·메모리와 72번 전체 검증은 남아 있다. 이번 웹 범위에서 새 제품 결함은 발견하지 않았으므로 별도 결함 태스크를 만들지 않았다.

## 재현

[QA 실행기 안내](../frontend/qa/README.md)를 따른다. 앱 의존성과 번들 Chromium 설치 후 `frontend/`에서:

```sh
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
pnpm qa:region
pnpm qa:media
```

기본 명령으로 웹 번들부터 새로 만들고 별도 Chrome 컨텍스트와 127.0.0.1의 가용 포트 서버를 사용했다. 포트·채널을 인자로 지정할 수 있다. 종료 시 브라우저와 서버를 정리하고 실패하면 코드 1을 반환한다. `.out`은 Git 제외이며 테스트 외 사용자의 브라우저 저장소를 읽거나 수정하지 않는다. 저장 키는 storageContract.js에서 직접 import한다.

원시 결과와 화면은 `frontend/qa/.out/region-results.json`, `.out/*.png`에 있다. 커밋에 고정 JSON을 넣지 않고 문서에는 이번 실행의 요약만 남긴다. 다음 실행은 원시 결과를 갱신하며 필요하면 Jira에 별도 첨부한다.

### 출력 픽셀·좌표·배율

- 동일 논리 영역 `{x:100,y:100,width:400,height:400}`은 800×800으로 출력됐다. 선택 화면 표시 배율은 48%, 24%, 117%, 작은 뷰포트 27%였다. 이는 에디터 논리 줌 0.5/1/2를 모두 UI로 설정했다는 뜻이 아니다. 논리 줌 0.5/1/2 좌표 연산은 기존 `region-selection.test.js`가 검증한다.
- 위 4조건의 RGBA 해시는 모두 `f644e971ac43deee6229569816806b9056991f0e7697524a1eb193f70e87a71d`로 같았다. 사분면의 내부 픽셀은 빨강/초록/파랑/노랑 RGBA와 정확히 일치했다.
- 확대 상태에서 가로 scrollLeft=120, 작은 뷰포트에서 scrollLeft=16으로 페이지 위치를 바꿔도 동일 해시였다. 스크롤이 없는 기본/축소 화면에서는 요청한 이동값이 실제로 0임을 기록했다.
- 자유 전체 영역 1280×800 → 2560×1600, 최소 32×32 → 64×64, 오른쪽 아래 경계 `{x:1248,y:768,width:32,height:32}` → 64×64. 31×32 수치 입력은 거부됐다.
- 정사각형 1080×1080, 세로 피드 1080×1350, 스토리 1080×1920을 확인했다. 스토리의 3배 초과 화질 확인을 누른 뒤 생성했다. 3배/6배 한도와 비율 오류는 별도 자동화 단위 테스트도 통과했다.
- 회전 30도·crop zoom 1.4/fx 0.35/fy 0.65와 겹침을 포함한 `{x:480,y:80,width:400,height:320}` → 800×640을 자유 전체 2배 PNG의 같은 구역과 비교했다. 2,048,000개 RGBA 채널에서 차이 최대 1, 허용 오차 2 초과 0개였다. 두 결과가 같은 공통 렌더러를 사용하므로 렌더러 자체의 모든 오류까지 독립적으로 증명하는 검사는 아니다.
- 빨강→파랑 GIF는 출력 중앙이 첫 빨간 프레임 [255,0,0,255]이었다. 기본 문자열과 펜 획의 실제 픽셀 존재를 확인했다. 이는 폰트·부분 텍스트·입력 확정 등 72번의 전체 검증을 대체하지 않는다(현재 Jira 72번 해야 할 일).
- 기존 전체 페이지 PNG 1280×800 출력과 공유 메뉴 복귀를 확인했다. 개별/연속 PDF 내용 검증은 113번 범위다.

### 조작·취소·저장·실패

- 사진 위 전용 오버레이에서 역방향 마우스 드래그로 400×400을 선택했다. 새 2px 드래그는 기존 유효 영역을 복원했다.
- Chromium CDP 터치 에뮬레이션에서 기본 화면 이동 모드의 한 손가락 가로 스크롤 결과 scrollLeft=714, viewport=380, scrollWidth=1110을 확인했다. 실제 태블릿/펜/세로 스크롤 검증으로 간주하지 않는다.
- 생성 후 영역 다시 선택은 같은 선택 상태로 돌아가며, 프리셋 변경 후 새 PNG를 생성했다. 영역 선택 취소는 공유 옵션 메뉴로 복귀했다.
- 브라우저 picker mock: 취소 1회, ENOSPC 실패 1회, 재시도 성공 1회. 저장 버튼을 연속 2회 눌러도 picker/write는 각 1회였고 저장 중 닫기·재선택 버튼이 비활성화됐다. 실제 OS 대화상자나 파일 쓰기를 통과했다는 의미는 아니다.
- 다운로드 fallback 1회: 실제 Playwright download 이벤트와 `_region_square_` 파일명, failure=null을 확인했다. 사용자 디스크의 영구 보관 여부는 브라우저가 보장하지 않는다.
- 영역 밖 누락 mediaFileId 1개를 추가했을 때 생성 실패 안내·저장 버튼 없음·같은 스냅샷 다시 만들기·영역 재선택을 확인했다. 문서와 원본을 지우지 않는 현 정책이며 영역 밖 소재 최적화는 후속 범위다.
