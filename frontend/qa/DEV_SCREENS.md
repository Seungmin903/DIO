# 개발 화면 확인

- 기준 develop: 0410973. 일반 앱의 화면과 API는 변경하지 않는다.
- 개발 빌드에서 `EXPO_PUBLIC_DIARY_SOURCE=mock-library`: 보관함과 알림 모의 테스트.
- 개발 빌드에서 `EXPO_PUBLIC_DIARY_SOURCE=mock`: 간단한 API 응답 검증.
- 환경변수를 지정하지 않으면 일반 앱 진입 경로를 사용한다. App.js의 기존 `__DEV__` 조건은 유지한다.
- 두 환경 모두 실제 서버 대신 메모리 모의 응답을 사용한다. 접힌 도구의 설정도 계속 적용되므로 시나리오를 바꾼 뒤 정상 응답으로 돌리거나 샘플 계정을 전환한다.
- 보관함의 응답 설정은 조회·계정, 목록 더 보기, 이동·복원·삭제, 만료 정리 순서다. 스크롤 영역 안에 모든 기존 조작을 유지한다.
- 알림 응답 설정 안에서 계정 전환, 공유 버튼 연결 검증, 종류별 오류, 새 알림 도착을 조작한다. 상세 이동은 전달 정보만 표시하며 실제 초대를 수락하지 않는다.
- API 응답 검증의 생성·변경 도구는 ‘테스트 도구 열기’로 펼친다. 목록 오류의 재시도는 도구를 닫아도 사용할 수 있다.

확인: 도구 열기/닫기, 작은 높이에서 마지막 도구까지 스크롤, 오류 재시도, 샘플 계정 전환, 초대 전달 확인. 기존 자동화가 도구 안의 버튼을 찾는 경우 먼저 도구를 펼친다.

## 자동 리뷰 후 보완

- API 검증 도구는 첫 열기 이후 마운트를 유지한다. 접어도 미확정 요청과 재시도 입력을 보존한다.
- 도구 높이 상한은 개발 전용 src/devtools/layout.js에서 240 또는 화면 높이의 32% 중 작은 값으로 통일한다.
- mock 번들: `node qa/dev-tools-browser.cjs`로 응답 유실 → 닫기 → 접기/펼치기 → 같은 입력 재시도를 검증한다.
- mock-library 번들: 기존 notification-browser.cjs에 보관함·알림 도구 접기 및 숨겨진 조작 재노출 검증을 포함한다.

## QA 브라우저 선택

두 브라우저 QA는 기본적으로 Playwright Chromium을 사용한다. 최초 실행 전에 `pnpm exec playwright install chromium`으로 설치한다. 설치된 Edge를 사용하려면 PowerShell에서 `$env:DIO_QA_BROWSER_CHANNEL="msedge"`를 지정한다. 설정하지 않으면 번들 Chromium을 사용하며 자동으로 다른 브라우저로 대체하지 않는다.
